# 游戏导演 / 制作人 状态

## 最后更新

2026-07-18

## 当前关注

本状态页取代旧 `PM / 版本规划` 活跃入口。游戏导演 Role 负责定义玩家体验主线、系统开放节奏、深渊包装、当前版本目标和完成口径，再把工作拆成可由 Owner 承接的完整模块或玩家结果。

Agent Role 入口已统一：`AGENTS.md` 负责选择游戏导演、Owner、剧情、策划、程序、美术或知识库 Role；`rules/02_智能体任务路由与完成协议.md` 负责稳定的 Owner 流水、验收和回写规则；职能视图只负责阅读导航。Owner 可以切换专业 Role，但 Owner 定位不变化。

当前宏观设计重点已从“8-12 小时候选版主循环”推进到“全游戏宏观大纲 + 全系统体验归位 + 全游戏模块宏观设计矩阵”：8-12 小时只作为候选版主循环门槛，不再作为完整游戏范围上限。现有 `GDD_01` 到 `GDD_12` 全部保留并纳入完整游戏大纲，后续只区分核心主线、阶段开放、表现 / 记忆层、制作门禁和制作冗余压缩。

`13` 现已补齐模块总谱：全局美术 / UI 体验语言、深渊层级、小镇、人偶、战斗 / 背包、经济 / 订单 / 势力、日程、叙事 / 房间和配置 / 验收都有宏观职责、包装关键词、玩法压力、模块连接、主负责设计、细化验收与实现接入口径。后续实现切片不只标注时长段和玩家结果，还必须引用对应模块宏观设计行。

2026-06-12 已修正全局美术 / UI 体验语言：正式主轴为“日系二次元地底奇幻冒险 + 低信息密度”。机械、工坊和旧工具只作为局部系统语义；黄铜、铜件、暖灯和蒸汽朋克不再作为全局风格关键词，也不作为实现切片默认美术验收方向或正向生图提示词方向。

剧情母线已有独立设计入口：`设计文档/剧情/00_剧情大纲.md` 将草稿中的没落工匠、零号魔偶、晶化病、记忆拼图、债务压力和多结局收束为 active 叙事母版。后续 T0-T4 细案、长期记忆内容包和实现切片都应把它作为“写什么故事”的上层参考，但具体事件触发、字段和验收仍回到 GDD / 规则卡 / 内容包。

后续开发节点已改为按玩家游玩时长横向切分：0-30 分钟、30 分钟-2 小时、2-5 小时、5-8 小时、8-12 小时、12-20 小时、20-35 小时、35 小时以后。每个时长段都包含深渊、战斗 / 背包、小镇、人偶状态 / 养成、日程、叙事反馈、UI / 美术和验证门禁，只是开放深度不同；当前最近实际目标是补齐 0-12 小时候选主循环。

0-12 小时候选主循环现在按游戏时长横向切分回到设计稿口径。`14` 维护的是 T0-T4 时长段设计索引和承接规则；具体细案存放在 `版本规划/0-12小时细案/`。当前 `T0` 已重规划为 `0-30 分钟` 的序章首次循环 V2：完整 T0 不以“进入第一层”为结束点，而以“第一次浅层行动后回到工坊并形成下一轮理由”为结束点。`T1` 已补为 `30 分钟-2 小时` 的第一层搜打撤成形设计稿，`T2..T4` 仍是待设计队列，未完成设计前不作为正式实现依据。

项目工作模式仍以 Owner 对完整模块负责为核心。游戏导演维护时长段入口，Owner 承接 T0-01 / T0-01A 等模块，并按 `证据审计 -> 阅读细案 -> 本切片具体方案设计 -> 配置源落地 -> UI/UX 与美术接入方案 -> 程序接入 -> Owner 自验 -> 对应专业 Role 验收 -> 状态回写` 推进；本轮只统一 Role 概念，不调整流程顺序。

Owner 自验只证明本切片已按玩家路径整理证据，不等于最终完成；最终完成仍需要对应剧情、策划、程序、美术或游戏导演 / 制作人的外部验收。

剧情、策划、程序和美术 Agent 可以独立处理对应 Role 的专业工作，也可以由 Owner 在处理模块时切换进入。图片生成、大批量素材处理、大规模配置填充等耗时工作可以单独委派给 Agent；这种专工式委派不是新 Role，必须由 Owner 提供明确输入、输出和验收标准。

当前导演判断：`T0-PRE` 商业化基线已补齐，`T0-01A` 已按 `T0-PRE-01..11` 补成 Owner 封板候选 V5，开发方案也已改为封板增量 V2。下一步不再重做叙事底座和主链，而是按 `SEAL-DES / ART / FLOW / UI / VAL` 完成漫画页排版、启动仪式、对白皮肤、FormalV2 半开放工坊、首潜许可卡和 11 张连续截图验收；然后再新增 `T0-01B / T0-01C` Owner 具体设计。

## 工作边界

- 游戏导演 / 制作人负责全局体验、开放节奏、优先级、细案 / 实现切片拆分和最终玩家结果判断。
- 游戏导演负责维护 `14` 的 T0-T4 时长段设计索引与承接规则；Owner 在 `版本规划/0-12小时细案/` 中逐段承接完整模块，未完成设计的时长段不作为 Owner 进入实现阶段的正式依据。
- 具体系统规则仍回写 GDD / 规则卡；程序契约仍回写开发文档；视觉规格仍回写美术文档；配置源仍以 `配置表(JSON)` 为准。
- Owner 可以切换剧情、策划、程序和美术 Role，但必须遵守细案、各专业事实来源和工程边界，并在完成时同步所有受影响状态页。
- Owner 自验是第一层证据整理，不替代剧情 / 策划 / 程序 / 美术 / 游戏导演的外部验收。
- 剧情、策划、程序和美术可以独立处理对应专业工作或参与验收；独立 Agent 被限定处理某个 Role 工作时属于专工式委派，不新增 Role。
- 旧 `agent_status/pm.md` 仅作为兼容入口保留，不再作为活跃派发角色。
