# PM / 版本规划 状态

## 当前关注

作为 PM 智能体管理正式版核心纵切的版本规划，维护 `09` 路线、`11` GDD 批次矩阵、项目总状态、阶段里程碑、系统纵切优先级和跨职能交接闭环。当前重点是按“配置 / Validator / 验收底座 -> 背包战斗 -> 深渊地图 -> 局外成长 -> 经济目标 -> 表现支撑”的功能优先级推进，而不是继续横向扩内容包。

## 工作边界

- PM 负责版本路线、阶段判断、里程碑拆分、优先级排序、跨职能交接和完成标准。
- PM 不替代策划、程序或美术事实来源；系统规则写入 GDD，程序边界写入开发文档，美术交付写入美术文档。
- 版本规划变更应同步 `版本规划/09_正式版核心纵切开发路线.md`、`PROJECT_STATUS.md`、本文件和受影响的职能状态页。
- 旧 MVP 规划文档只作为历史验证资料；当前阶段以 `09` 路线和当前 GDD 为准。
- PM 拆分工作包时应写清目标、范围外、涉及事实来源、职能交接和验收方式。

## 当前版本判断

项目处于正式版核心纵切阶段。这里的纵切是开发顺序，不是质量降级：被选中的系统按正式版标准完整处理。当前版本节点仍以 A1-A4 门禁管理，但近期功能开发优先级先看阻塞关系：先补配置 / Validator / 验收底座，再推进 A2 背包与战斗，随后推进 A3 深渊地图与局外成长，最后进入 A4 经济压力与候选版本。
