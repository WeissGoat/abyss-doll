# 正式纵切 UI 与素材覆盖矩阵

> **定位：** 把 `09` 路线和 `11` 批次矩阵翻译成美术侧 UI / 素材覆盖表。目标是先把需要的 UI 设计纳入系统，再按 Manifest 流程生产素材。

---

## 1. 当前覆盖结论

截至 2026-05-25，active `screen_layouts.json` 已覆盖 19 个 Formal V1 界面：

```text
workshop_main
combat_hud
inventory_loot
dungeon_map
settlement
sell_panel
prosthetic_panel
layer_select
safe_room
stairs_room
maintenance_panel
daily_bill_report
shop_staging
order_board
rumor_board
faction_shop
doll_interaction
scenario_event
doll_room
```

这些界面已经可以进入素材生产、程序接入或运行时截图验收。A4 出货分配、订单、传闻、势力商店、人偶交互、剧本事件和人偶房间界面已经进入 active 规格；已补齐对应 seed / Manifest / Prompt / Spec 入口，后续按可接入清单推进素材入库和程序接入。

近期执行不再新增与当前纵切无关的横向界面。先消化 latest 可接入素材清单中的 `program_integrate` 队列，并等待程序分批完成 Formal V1 接入后做 ArtAcceptance 验收。

素材覆盖、缺图生成和素材质量分开判断：`可接入素材清单.md` 回答“程序现在能接什么 / 美术还缺什么”；`缺图生成计划.md` 回答“哪些 generate_needed 新素材可以直接跑图”；`素材质量替换清单.md` 回答“哪些 Approved 素材仍是 local_v0 / placeholder，后续要同名替换”。当前缺图队列为 `generate_needed=0`，质量替换清单为 `technical_fix=0`、`visual_v2_replace=41`。

当前没有剩余 draft UI 队列。后续新增界面仍先写 `formal_v1/*.md` 设计草案，经确认后再进入 active `screen_layouts.json`、Manifest 和跑图队列。

## 7. 执行规则

1. 新 UI 或结构重做先写 `formal_v1/*.md` 草案，用户确认后再进入 `screen_layouts.json`。
2. active `screen_layouts.json` 更新后，先跑 `Validate-UIDesign.ps1`，再补 `art_requirements_seed.json`、Manifest 和提示词。
3. 每轮生成、预处理或 Approved 同步后，刷新 `可接入素材清单.*` 并留快照。
4. 每轮 `generate_needed` 队列变化或生成额度探测后，刷新 `缺图生成计划.*` 并留 `art_generation_plan_snapshots/` 快照。
5. 每轮技术修复或质量替换后，刷新 `素材质量替换清单.*` 并留 `art_quality_snapshots/` 快照；已接入素材的 Visual V2 替换必须通过 `CandidateBatchID` 和 `QualityTier` 记录，不回退原 `Status`。
6. 每轮 Visual V2 队列变化或生成额度探测后，刷新 `VisualV2生成计划.*` 并留 `visual_v2_plan_snapshots/` 快照。
7. 未进入 active 的 UI 不作为程序接入口，也不作为批量跑图入口。
8. Draft UI 队列进入 active 时必须同步更新本文、`screen_structure_review.md` 和 `versions/migration_log.md`。
