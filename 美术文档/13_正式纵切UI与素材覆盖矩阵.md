# 正式纵切 UI 与素材覆盖矩阵

> **定位：** 把 `09` 路线和 `11` 批次矩阵翻译成美术侧 UI / 素材覆盖表。目标是先把需要的 UI 设计纳入系统，再按 Manifest 流程生产素材。

---

## 1. 当前覆盖结论

截至 2026-05-24，active `screen_layouts.json` 已覆盖 15 个 Formal V1 界面：

```text
workshop_main
combat_hud
inventory_loot
dungeon_map
settlement
sell_panel
prosthetic_panel
layer_select
safe_room
stairs_room
maintenance_panel
daily_bill_report
shop_staging
order_board
rumor_board
```

这些界面已经可以进入素材生产、程序接入或运行时截图验收。A4 出货分配、订单和传闻界面已经进入 active 规格，新增 UI 图标已补齐 local_v0 可接入版，后续再替换正式 AI 美术版。

近期执行不再新增 active 界面。先消化 latest 可接入素材清单中的 `program_integrate` 队列，并等待程序分批完成 Formal V1 接入后做 ArtAcceptance 验收。

另外有 4 个 Formal V1 设计草案尚未进入 active：

```text
faction_shop
doll_interaction
scenario_event
doll_room
```

它们只作为设计审阅资料，不作为程序接入口，也不触发素材生成。用户确认后，再逐个写入 active `screen_layouts.json`。

## 5. 执行规则

1. 新 UI 或结构重做先写 `formal_v1/*.md` 草案，用户确认后再进入 `screen_layouts.json`。
2. active `screen_layouts.json` 更新后，先跑 `Validate-UIDesign.ps1`，再补 `art_requirements_seed.json`、Manifest 和提示词。
3. 每轮生成、预处理或 Approved 同步后，刷新 `可接入素材清单.*` 并留快照。
4. 未进入 active 的 UI 不作为程序接入口，也不作为批量跑图入口。
5. Draft UI 队列进入 active 时必须同步更新本文、`screen_structure_review.md` 和 `versions/migration_log.md`。
