# CG底图与漫画式播放演出工作流

> 定位：本文定义 Project P3 的 CG 底图 / 背景生产与漫画式播放演出工作流。它是现有美术流水线的叙事 CG 分支，不替代 Manifest、Approved、VisualAssetRegistry 或全局叙事播放系统。

## 1. 目标

P3 后续关键剧情不默认制作视频，也不默认生成一整张带文字的漫画页。标准方案是运行时漫画页拼装：

```text
叙事节点
  -> 漫画页 Page
  -> 多个 Panel VisualID
  -> UGUI 按 LayoutPreset 拼页
  -> 底部字幕条播放对白 / 旁白
  -> 按 RevealIndex 逐格显现
  -> 关键点出现单按钮动作
```

该方案用于低动画成本实现有镜头、有停顿、有读图顺序的商业化叙事演出。T0-01A 序章是第一批样板。

## 2. 参考结论

本工作流参考 `This Is the Police` 的演出组织方式，以及用户提供的两张漫画式剧情截图。P3 借鉴的是：

- 多格画面组织：黑色分隔、横长格与小格组合、远景和特写交替。
- 底部字幕条：对白和旁白由运行时文字承载，不烘进图片。
- 逐格显现：靠显隐、停顿、声音和切点制造观看节奏。
- 留白节奏：页面可以保留黑场或空格，服务停顿和下一格焦点。
- 短剧情段承接操作段：剧情页结束后尽快给玩家一个真实动作。

不借鉴：

- 警匪题材、noir 口吻、都市犯罪价值观。
- 长时间不可交互 cutscene。
- 把文本直接烘进图片。
- 把 P3 的日系二次元地底奇幻方向改成低多边形警匪风。

## 3. 方案边界

### 3.1 采用 B 方案：运行时拼装

每一页由多个独立 Panel 素材组成。Unity 负责拼格、黑边、逐格显现、字幕条、按钮和输入锁。美术侧负责 Panel 资产、构图、安全区、提示词、筛选和运行时截图验收。

### 3.2 不采用整页烘焙

默认不生成整张带格子、带字幕的 1920x1080 成图。整页烘焙会让文案、本地化、分镜调整和不同画面比例维护成本过高。仅当某个特殊演出必须使用整页插画时，才作为例外登记。

### 3.3 不改叙事事实来源

对白、节点、触发条件、状态写入仍归全局叙事播放系统和对应剧情 / 实现设计管理。本文只规定 CG 底图和漫画页怎么生产、接入和验收。

## 4. 运行时结构

### 4.1 Page 数据

漫画页数据由叙事节点引用，建议结构如下：

```json
{
  "PageID": "t0_01a_p02_workshop_establish",
  "LayoutPreset": "wide_top_two_bottom",
  "Panels": [
    {
      "Slot": "top_wide",
      "VisualID": "cg_t0_01a_p02_panel01_workshop_door",
      "RevealIndex": 1
    },
    {
      "Slot": "bottom_left",
      "VisualID": "cg_t0_01a_p02_panel02_debt_notice_close",
      "RevealIndex": 2
    },
    {
      "Slot": "bottom_right",
      "VisualID": "cg_t0_01a_p02_panel03_no0_hand_under_cloth",
      "RevealIndex": 3
    }
  ],
  "Caption": {
    "Speaker": "主角",
    "Text": "他们连坏掉的东西也收。"
  },
  "Action": null
}
```

字段口径：

| 字段 | 说明 |
|---|---|
| `PageID` | 稳定页 ID，用于叙事节点、截图和验收定位。 |
| `LayoutPreset` | 预置分格版式。不得在每页自由写绝对坐标作为首选。 |
| `Panels` | 本页需要显示的 Panel 列表。 |
| `Slot` | Panel 在版式中的格位。 |
| `VisualID` | 对应 Approved 资产的稳定视觉 ID。 |
| `RevealIndex` | 逐格显现顺序；相同数字可同时出现。 |
| `Caption` | 运行时字幕条，不写入图片。 |
| `Action` | 可选单按钮动作，例如 `start_doll`。 |

### 4.2 LayoutPreset

首批只维护少量稳定版式：

| Preset | 用途 |
|---|---|
| `single_wide` | 单张横向大格，适合黑屏后首次工坊建立。 |
| `two_horizontal` | 上下两条横格，适合环境对照。 |
| `wide_top_two_bottom` | 上方远景，下方两个特写，适合建立处境。 |
| `two_top_wide_bottom` | 上方两个信息点，下方大格落情绪。 |
| `left_tall_right_stack` | 左侧竖长主体，右侧两到三格补充细节。 |
| `four_panel_focus` | 四格信息推进，适合债务 / 手记 / 核心碎片类页面。 |

每个版式必须在 16:9 参考分辨率下成立，并兼容 16:10、21:9、4:3 的 `cover` 裁切。黑色 gutter 是运行时 UI，不属于图片内容。

### 4.3 UGUI 播放要求

运行时播放层应满足：

- 使用纯 UGUI，不引入 UI Toolkit、UXML、USS 或第三方 VN 默认 UI。
- 通过 `VisualAssetService` 解析 Panel VisualID。
- Panel 使用 `cover` 适配格子，关键主体必须在中心安全区。
- 字幕条位于底部安全区，正文由运行时文本显示。
- 播放期间锁住下层工坊 / 地图 UI。
- 只有 `Continue` 或指定 `Action` 可接收输入。
- `Action` 只用于关键动作，不把普通继续也做成剧情选择。

## 5. 美术资产规格

### 5.1 VisualID 命名

Panel VisualID 采用：

```text
cg_<scope>_p<page>_panel<index>_<subject>
```

示例：

```text
cg_t0_01a_p02_panel01_workshop_door
cg_t0_01a_p02_panel02_debt_notice_close
cg_t0_01a_p05_panel03_no0_core_close
```

命名规则：

- `scope` 对应剧情或实现切片，如 `t0_01a`。
- `p<page>` 对应该样板内页序。
- `panel<index>` 对应该页读图顺序，不等于 Manifest 排序。
- `subject` 描述画面主体，使用英文或稳定拼音 / 简短英文，不写中文文件名。

### 5.2 Manifest 分类

漫画 Panel 默认作为 preset 需求进入 Manifest：

| 字段 | 建议值 |
|---|---|
| `Domain` | `cg` 或 `background` |
| `SourceType` | `preset` |
| `PresetCategory` | `narrative_cg_panel` |
| `AssetType` | `cg_panel` |
| `Screen` | `narrative_comic_overlay` 或目标流程 |
| `Usage` | 说明页、格位和叙事用途 |

如果后续配置表正式出现剧情 VisualID 字段，可改为由配置扫描，但不改变 VisualID 和 Approved 路径。

### 5.3 图片规格

首批统一使用：

| 项 | 规格 |
|---|---|
| 源格式 | PNG |
| 推荐源尺寸 | `1920x1080` |
| 可接受源尺寸 | `1280x720`，仅限临时样板 |
| 背景 | 不透明场景图，禁止透明黑洞 |
| 适配 | 运行时 `cover` |
| 安全区 | 关键主体在中心 4:3 区域；字幕不在图内 |
| 文字 | 不烘焙对白、旁白、按钮、教程文字 |

道具特写也用横图规格，而不是 512 图标。它要像镜头特写，不像 UI 浮窗。

### 5.4 构图要求

每个 Panel 必须回答一个视觉问题：

| 类型 | 视觉问题 |
|---|---|
| 建立镜头 | 玩家现在在哪里？画面中心是什么？ |
| 道具特写 | 哪个物件改变了玩家判断？ |
| 角色近景 | 玩家应该看谁？看脸、手还是核心仓？ |
| 过渡格 | 画面从哪里切到哪里？ |
| 动作格 | 玩家刚做的动作带来什么变化？ |

禁止：

- 一格里同时解释多个系统。
- 把道具画成居中的 UI 图标。
- 在背景里放大量不可读小物件。
- 用厚金边、暖棕机械、蒸汽朋克材质作为默认风格。
- 生成随机文字、水印、签名、拟真照片感或低多边形警匪复刻感。

## 6. 美术工作流

### Step 1：分镜表

先写每页分镜，不直接跑图。分镜表至少包含：

| 字段 | 要求 |
|---|---|
| `PageID` | 稳定页 ID。 |
| `玩家感受` | 这一页要让玩家理解什么。 |
| `Panel 列表` | 每格主体、镜头距离、读图顺序。 |
| `字幕` | 每页 1-2 句，单句短。 |
| `交互` | 无、继续、或单按钮动作。 |
| `禁止项` | 不得出现的 UI、风格和误读。 |

### Step 2：Panel 清单

把每格拆成独立 VisualID，写入 `art_requirements_seed.json` 或等待专用叙事配置落地。Panel 清单不等于完成，只是素材需求准入。

### Step 3：Manifest / Prompt / Spec

运行美术流水线后，Panel 进入 Manifest。Prompt 只写画面语言：

```text
anime style underground fantasy workshop, cinematic comic panel, low visual noise, old workbench, rain-soaked paper near the door, dim cool light, clear silhouette, no text, no watermark
```

Prompt 不写：

- 对白文本。
- 项目名。
- `This Is the Police`。
- `comic page with Chinese subtitles` 这类会诱发烘字的词。
- 玩法黑话或 Unity / UGUI。

### Step 4：生成候选

每个 Panel 至少生成 3-4 张候选。叙事 Panel 默认作为普通运行时资产，由 Manifest Resolver 进入：

```text
UnityClient/Assets/Art/_IncomingAI/standard_assets/<VisualID>/
  raw/
  processed/
  selected/
  contact_sheet/
  manifest_snapshot.json
  generation.json
  notes.md
```

如果使用外部参考图，只作为风格和构图参考，不复制具体角色、地点、题材符号或可识别镜头。

### Step 5：预处理与 contact sheet

预处理重点：

- 裁切到统一源尺寸。
- 检查中心 4:3 安全区。
- 生成单格缩略图。
- 生成模拟漫画页 contact sheet，检查放进格子后是否仍能读懂。

### Step 6：筛选

筛选按页而不是只按单图好看判断：

| 维度 | 通过标准 |
|---|---|
| 读图顺序 | 玩家能按 reveal 顺序理解信息。 |
| 画面焦点 | 每格只有一个主要焦点。 |
| 情绪承接 | 上一页到下一页情绪不断。 |
| 安全区 | 放进格子后主体不被裁。 |
| 风格一致 | 符合日系二次元地底奇幻方向。 |
| 工程可用 | 无文字、水印、透明异常和随机噪点。 |

### Step 7：Approved 与交接

筛选后同步到 Approved，刷新：

```text
美术文档/_generated/可接入素材清单.md
美术文档/_generated/可接入素材清单.json
美术文档/_generated/art_integration_snapshots/
```

程序只接 `program_integrate` 队列。`_IncomingAI` 候选、contact sheet 和 raw 不作为程序接入口。

### Step 8：运行时验收

程序登记后，使用漫画页 overlay 跑截图。验收必须同时看：

- Panel 是否全部加载。
- 分格黑边和留白是否清楚。
- 字幕是否在安全区。
- 字幕是否遮挡关键主体。
- 逐格显现顺序是否符合分镜表。
- 按钮是否只在目标页出现。
- 播放结束是否进入真实玩家流程。

## 7. T0-01A 首批样板

T0 首批只做 6 页，先证明播放语法成立。

| PageID | 目标 | Panel 规划 | 交互 |
|---|---|---|---|
| `t0_01a_p01_black_wake` | 黑屏醒来，建立声音和处境。 | 无 Panel 或纯黑格。 | 继续 / 自动推进。 |
| `t0_01a_p02_workshop_establish` | 让玩家看到破败工坊和零号存在。 | 工坊远景、门缝纸、防尘布下的手。 | 无。 |
| `t0_01a_p03_debt_pressure` | 建立债务压力。 | 债务纸近景、可抵扣器械阴影、工作台残件。 | 无。 |
| `t0_01a_p04_repair_clue` | 建立浅层材料和最后核心碎片。 | 手记页、深渊暗门冷光、工具匣核心碎片。 | 无。 |
| `t0_01a_p05_find_no0` | 发现零号，聚焦脸和核心仓。 | 残件扫过、零号半身、核心仓弱光。 | 无。 |
| `t0_01a_p06_start_no0` | 玩家第一次输入：启动零号。 | 零号近景、核心碎片接入、核心仓微光。 | `启动人偶`。 |

首批不做完整下潜、结算或回声。P06 之后进入既有零号苏醒、状态小卡、擦灰和半开放工坊流程。

## 9. 验收截图

T0 样板完成后至少生成：

| 截图 | 要求 |
|---|---|
| `t0_comic_p01_black_wake.png` | 黑屏 / 字幕安全区成立。 |
| `t0_comic_p02_workshop_establish.png` | 三格读图顺序成立。 |
| `t0_comic_p03_debt_pressure.png` | 债务纸语义明确，不像 UI 小卡。 |
| `t0_comic_p04_repair_clue.png` | 手记、暗门、核心碎片三者关系清楚。 |
| `t0_comic_p05_find_no0.png` | 零号成为画面焦点。 |
| `t0_comic_p06_start_no0.png` | 只有 `启动人偶` 一个动作按钮。 |

验收失败条件：

- 任一截图仍像普通对白框叠背景。
- Panel 为空、missing sprite 或蓝屏。
- 字幕遮挡关键脸部、核心仓或道具。
- `启动人偶` 页出现其他功能按钮。
- 运行时拼页无法回到真实 T0 流程。

## 10. 状态回写

每次完成漫画式 CG 工作后必须回写：

- `agent_status/art.md`：最近完成、当前关注、下一步建议、阻塞和证据入口。
- T0 样板影响序章体验时，同步 `版本规划/0-12小时细案/T0-VAL-01_最终实际效果优化文档.md` 或对应 T0 实现设计。
- 如新增或调整 Manifest / seed / Approved / 可接入清单，按美术流水线刷新生成物并留快照。
- 如只写分镜和规格，不能标记为素材完成或画面验收通过。

## 11. 完成口径

漫画式 CG 工作分四层记录：

| 层级 | 可声明内容 |
|---|---|
| 规格完成 | 分镜、Panel 清单、VisualID、验收口径已写入事实文档。 |
| 素材完成 | Panel 已进入 Approved，清单和快照已刷新。 |
| 接入完成 | VisualID 已登记，运行时漫画页可显示。 |
| 验收通过 | 截图 / Play 路径证明玩家能看到正确漫画页并进入真实操作。 |

当前本文完成后只能声明 `规格完成`。T0 Panel 尚未生成、Approved、登记或运行时验收。
