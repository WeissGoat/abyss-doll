# 零号立绘素材设计与交付清单

> 定位：本文把零号人设转成可生产、可筛选、可接入的立绘素材体系。本文定义候选资产，不代表已进入 Approved、Manifest、VisualAssetRegistry、DollPuppet 包或运行时验收。

## 1. 当前设计结论

零号后续立绘以 Gemini 版本为视觉母版。

- Gemini 负责锁定：娇小但非儿童化的身体比例、银白长发散发、白布遮眼、灰披肩与浅色内衬裙、裸腿裸足、安静冷感的整体轮廓。
- ChatGPT 只作为补充参考：灰披肩体块、人物占画面比例、磨损细节和较完整的概念图完成度。
- NovelAI 只作为结构和动作备选，不继承其罩裙化披肩、橙红眼罩、鞋袜漂移或比例漂移。

## 2. Gemini 母版修正规则

现有 Gemini 图只锁方向，正式母图必须做以下修正：

1. 角色从大面积白底中放大，完整全身占画布高度约 `85%–90%`。
2. 灰披肩必须是独立披肩，不与内衬裙融合成罩裙；完整覆盖双肩、胸和上臂。
3. 内衬裙保持简单短裙轮廓，但不得通过贴身曲线、仰视或夸张腿部构图制造性感感。
4. 银白长发自然散发，后发长度锁在腰下至大腿上段；禁止扎发、双马尾、辫子和厚重卷发。
5. 白布眼罩必须是柔软旧布，不是绷带眼妆、金属面罩或发光红色眼罩。
6. 常态红眼完全隐藏；启动、低 SAN 和受损状态只能让红光透过白布，不直接露出完整瞳孔。
7. 裸足必须完整可见，不生成鞋、袜、脚环或靴子。
8. 人偶关节只在手腕、膝、踝出现细小接缝，不做大型球形关节或骨架机械肢体。

## 4. 资产架构

采用“少量独立整图 + 可复用状态图层”。姿势改变轮廓时使用独立整图；嘴型、红光、磨损和披肩状态优先使用差分层。

| PoseID | 构图 | 用途 | 优先级 |

| `stand_front` | 正面自然站立 | `doll_proto_0_stand` fallback、状态卡、基础验收 | P0 |
| `stand_dialogue_3q` | 3/4 朝向玩家 | 工坊、房间和对白主立绘 | P0 |
| `maintenance_sit` | 收束坐姿 | 维护、净化、受损回城 | P0 |

## 6. 可复用分层清单

DollPuppet 画布合同沿用 `1024x1536`。正式绘制源建议使用 `2048x3072`，清理后按同构比例导出 `1024x1536` 透明 PNG。

| 层组 | 层名建议 | 说明 |
|---|---|---|
| 身体 | `body_base`、`arm_l/r`、`leg_l/r`、`hand_l/r`、`foot_l/r` | 需要补齐披肩和头发遮挡区域 |
| 头脸 | `head`、`face_base`、`mouth_neutral/talk/soft/tight` | 眼部仍保留完整红眼源层 |
| 眼罩 | `blindfold_normal/glow/unstable/damaged/half_open` | 常态必须压住红眼层 |
| 红眼 | `red_eyes_hidden`、`red_eye_glow` | 默认隐藏；光效层与瞳孔层分开 |
| 头发 | `hair_back`、`hair_side_l/r`、`hair_front`、`bangs` | 长发分块支持轻微摆动 |
| 披肩 | `cloak_back`、`cloak_front_l/r`、`cloak_edge_damage` | 前后层必须能遮住核心仓 |
| 内衬裙 | `inner_dress` | 不与披肩烘焙为一体 |
| 人偶结构 | `joint_marks`、`joint_damage` | 细小接缝和受损差分分开 |
| 核心仓 | `core_hidden`、`core_dim`、`core_active`、`core_unstable` | 默认由披肩覆盖 |
| 状态 | `dust_light`、`wear_medium`、`hurt_cracks`、`san_condensation` | 支持按状态开关 |

## 7. 规格与构图

- 工作画布：`2048x3072`，竖版透明背景。
- 运行时 / DollPuppet 画布：`1024x1536`。
- 全身立绘角色高度：画布高度 `85%–90%`，脚底、发尾和披肩边缘不得裁切。
- 对话 3/4 立绘允许在 UI 中裁到膝上，但源文件必须保留完整全身。
- `combat_hud` 小尺寸展示必须仍能读出白布眼罩、灰披肩和长发轮廓。
- 不烘焙背景、阴影、文字、状态图标或 UI 框。
- 既有运行时 fallback 仍保留 `doll_proto_0_stand`；正式静态套组使用 `AssetSetID=zero_dialogue_portrait_v1`，当前 14 个运行时成员已写入 Manifest。进入 Manifest / selected 不等于已同步 Approved 或替换既有运行时绑定。

## 8. 首轮生产顺序

1. 重绘 Gemini 正面母版，产出透明 `concept.png` 与 `base_flat.png`。
2. 产出 `stand_dialogue_3q`，锁定常用对白构图。
3. 产出 `maintenance_sit`，锁定 T0 照看和维护姿势。
4. 在三个基础姿势上补眼罩、红光、嘴型、披肩和磨损差分。
5. 先交付 P0 六态静态 PNG，做工坊 / 房间 / 维护 / 战斗 HUD 尺寸检查。
6. P0 静态验收后再拆 DollPuppet 分层，不从未经确认的 AI raw 图直接拆层。
7. 最后制作 P2 cut-in，不让特殊演出拖慢常驻立绘落地。

## 9. 验收清单

- 同一角色身份稳定：脸型、发型、体型、披肩剪裁和脚部比例一致。
- 第一眼仍是美少女与轻型人偶，不是儿童、病号、幽灵或重机械。
- 常态白布不透红眼；状态红光不变成红色眼罩或血泪。
- 灰披肩完整覆盖双肩，不露单肩，不与裙子融成罩裙。
- 裸足、膝关节、手腕关节清楚，但不强调身体局部或色情视角。
- P0 六态在缩小到工坊和战斗 HUD 实际容器后仍可区分。
- 所有候选先进入 `_IncomingAI`，有 metadata、contact sheet 和人工筛选结论后才允许进入 Approved。
