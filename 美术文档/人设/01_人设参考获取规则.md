# 人设参考获取规则

> 定位：本文件记录人设 Owner 在搜索 Danbooru 或其他二次元作品角色时的资料获取、过滤、归并和报告生成规则。它只约束“怎么找参考、怎么解释参考”，不定义零号最终造型。

## 1. 基本原则

1. 参考不是照搬。报告只拆解角色传播符号、标签共现、作品语义和可转译设计语言，不复制角色服装、脸、配色、构图或专属符号。
2. 未定稿阶段不预设发色、瞳色、服装款式和饰品轮廓。`blue_eyes`、`white_hair`、`white_dress`、`frills`、`cloak` 等强外观词只能作为后续追加检索，不进入默认关键词体量。
3. 零号参考的第一目标是“美少女吸引力 + 玩家照看动机”，人偶关节、核心仓、损伤、低 SAN、维护后放松等只作为局部语义叠加。
4. 不下载、不嵌入、不复刻 Danbooru 图片。默认只拉公开 tag / post 元数据，保存 raw JSON 与 Markdown 报告。
5. 生成报告不是人设定稿，也不是 Approved 素材、Manifest、Registry、DollPuppet 包或 ArtAcceptance 证据。

## 2. 当前工具入口

脚本入口：

```powershell
.\tools\美术工具\Generate-DanbooruCharacterReference.ps1 -Fast
```

Python 实现：

```text
tools/美术工具/danbooru_character_reference.py
```

默认输出：

```text
美术文档/_generated/danbooru_character_reference/
  zero_doll_reference_report.md
  zero_doll_reference_raw.json
```

## 3. 默认关键词体量

关键词体量来自 Danbooru `tags.json` 的全站 tag 投稿量，用来判断某个视觉词是否是常见视觉语言。它不代表零号应该采用该外观。

默认只保留身份、结构和状态词：

```text
doll
doll_joints
joints
android
robot_girl
robot_joints
mechanical_halo
mechanical_arms
cracked_skin
expressionless
blank_stare
bandages
```

其中：

| 标签 | 用途 |
|---|---|
| `doll_joints` | 观察人偶关节如何在美少女身上保持可读但不过度机械化。 |
| `android` | 观察人工生命 / 情感觉醒语义。 |
| `robot_girl` | 只作为检索池，不放在母图 prompt 前排。 |
| `mechanical_halo` | 可转译为核心仓启动环、背部小装置或修复光圈。 |
| `mechanical_arms` | 只作为战损、维修、义体差分参考，不主导零号母图。 |
| `cracked_skin` / `bandages` | 用于初见损伤、维护、hurt 差分。 |
| `expressionless` / `blank_stare` | 用于刚苏醒、低 SAN 或 weak 状态，不做冷酷人设。 |

## 4. 默认主题搜索组

所有默认主题搜索组必须包含：

```text
1girl rating:g
```

目的：

- `1girl`：降低男性角色、多人图、机体或怪物 tag 混入概率。
- `rating:g`：只取安全样本，避免高风险内容污染人设参考。

当前默认搜索组：

```text
doll_joints 1girl rating:g
android 1girl rating:g
robot_girl 1girl rating:g
joints 1girl rating:g
mechanical_halo 1girl rating:g
mechanical_arms 1girl rating:g
```

完整 profile 可以追加：

```text
doll_joints expressionless 1girl rating:g
doll_joints cracked_skin 1girl rating:g
```

## 5. 候选榜二次过滤

Danbooru 原始 tag 不能直接作为“可参考角色榜”。生成候选榜前必须二次过滤。

### 5.1 排除项

排除以下类型：

- 已知男性角色。
- 玩家头像、指挥官、老师、提督等非角色参考 tag。
- 怪物、宠物、机体、机器人本体、纯物件。
- meme、cosplay 或明显不稳定的临时 tag。
- 与 P3 人设方向不符的成人化、军武化或硬机械主体 tag。

当前脚本使用显式 denylist，不靠字符串猜测完成全部判断。后续如果报告里出现新的误入角色，优先补 denylist。

### 5.2 归并项

同一角色的以下变体应归并回 canonical 角色：

- 睡衣、体操服、一设、特殊服装。
- 机器人形态 / 人类形态。
- 觉醒形态、活动形态、皮肤 tag。
- 同一角色的 Mod、改造、别名。

示例：

| 原始 tag | 归并到 |
|---|---|
| `noa_(pajamas)_(blue_archive)` | `noa_(blue_archive)` |
| `yuuka_(pajamas)_(blue_archive)` | `yuuka_(blue_archive)` |
| `yuuka_(track)_(blue_archive)` | `yuuka_(blue_archive)` |
| `cecilia_immergreen_(1st_costume)` | `cecilia_immergreen` |
| `aria_(robot)_(zenless_zone_zero)` | `aria_(zenless_zone_zero)` |
| `aria_(human)_(zenless_zone_zero)` | `aria_(zenless_zone_zero)` |

报告候选榜必须显示 `合并来源` 列，便于复查哪些 tag 被归并。

## 6. 中文名规则

报告必须包含：

- 中文角色名。
- 中文作品名。
- 中文 tag 语义。

中文名来源按优先级处理：

1. 项目内人工确认映射。
2. 中文圈稳定通用译名。
3. 官方中文名。
4. 未确认时显示 `未确认`，不得硬翻。

脚本内维护：

```text
TAG_CN_NAMES
CHARACTER_CN_NAMES
COPYRIGHT_CN_NAMES
```

如果后续发现中文名错误或缺失，优先补映射表并重跑报告。

## 7. 报告解释口径

报告包含以下层级：

| 层级 | 来源 | 解释方式 |
|---|---|---|
| 关键词体量 | Danbooru `tags.json` | 判断标签常见度，不代表定稿方向。 |
| 总角色投稿榜 | character tag 投稿量排序 | 观察二创传播符号，不直接决定零号造型。 |
| 主题搜索组 | `posts.json` + `counts/posts.json` | 只在 `1girl rating:g` 安全样本内看主题共现。 |
| 可参考角色候选榜 | 主题样本角色 tag 共现 | 看哪些角色经常出现在目标语义附近，二次过滤后才可读。 |
| 作品共现榜 | 主题样本 copyright tag 共现 | 看哪些作品池贡献了相关视觉语义。 |

候选榜不是“推荐照抄榜”。它只回答：

```text
哪些已有角色经常出现在 doll_joints / android / robot_girl / mechanical_halo 等语义附近？
```

## 8. 转译到零号的规则

生成报告后，进入零号人设交付包前必须再做人工转译：

1. 保留可转译语义：人偶关节、人工生命、核心仓、损伤、空洞凝视、维护后放松。
2. 丢弃原角色专属符号：发型、发色、制服、武器、阵营标志、光环样式、构图套路。
3. 不让 `robot_girl` 主导母图。母图建议使用 `living doll`、`subtle doll joints`、`small glowing core` 等更克制的表达。
4. 不让 `mechanical_arms`、`robot_joints` 把零号推成重武装或硬机械角色。
5. 先产出 2-3 个方向稿，再决定发色、瞳色、服装款式和主识别符号。

## 9. 完成口径

一次人设参考报告完成至少满足：

- 已保存 Markdown 报告和 raw JSON。
- 默认搜索组包含 `1girl rating:g`。
- 候选榜已进行男性 / 非目标对象过滤。
- 重复角色和形态 tag 已归并。
- 报告包含中文角色名和中文作品名。
- 报告明确参考不是照搬，并区分生成报告、设计定稿和素材入库。
- `agent_status/art.md` 回写本轮证据、限制和下一步建议。
