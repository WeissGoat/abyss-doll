# 资源规格与接入规范

> **定位：** 规定 Unity 工程中的美术资源目录、命名、规格和接入边界。
> **更新时间：** 2026-06-13

---

## 1. 核心原则

* 程序不引用 AI 原始产物。
* JSON 负责玩法事实，Unity 资源负责表现。
* JSON 写 `VisualID`，程序通过 `VisualAssetRegistry` 找到 Sprite、Prefab、AudioClip 或 VFX。
* Prefab 只负责表现结构，不保存物品价格、怪物 HP、掉落池等玩法数据。

---

## 2. 目录结构

初期只保留两个美术素材目录：

* `_IncomingAI`：工作区，放 AI 原始图、预处理候选、筛选记录和批次信息。
* `Approved`：正式区，放已经筛选、整理、稳定命名、可以接入 Unity 的素材。

通用静态素材暂不设置 `Runtime` 目录。`VisualAssetRegistry`、材质、图集等工程资产按 Unity 现有工程规范放置，不参与美术素材从生成到筛选的流转。Live2D / Spine 角色动画是例外，正式试点目录和 Runtime 包结构见 `16_Live2D角色动画资产接入规格.md`。

```text
UnityClient/Assets/Art/
  _IncomingAI/
    standard_assets/
      <VisualID>/
        raw/
          YYYYMMDD_001.png
          YYYYMMDD_002.png
        processed/
          1/
            decision.json
        selected/
        contact_sheet/
        notes.md
        manifest_snapshot.json
        generation.json
    character_portraits/
      <VisualID>/
        raw/
        processed/
          1/
            decision.json
        selected/
        contact_sheet/
        asset_contract.json
        production_plan.json
        reference_inputs.json
        generation.json
        production_decision.json
    _legacy_runs/
  Approved/
    Items/Icons/
    Monsters/Portraits/
    Nodes/Icons/
    Prosthetics/Icons/
    Chassis/
    Dolls/
    Backgrounds/
    UI/
    VFX/
    Audio/
    DollsLive2D/
```

`_IncomingAI` 先按生产 Profile、再按 `VisualID` 分类；`Approved` 必须稳定命名，并与 Manifest 的 `OutputPath` 对齐。`BatchID` 和 `AssetSetID` 都不作为目录层级，只写入 Manifest / 运行证据。`_legacy_runs` 只保存历史非生产工作。

### 2.1 `_IncomingAI`

用途：

* AI 原始产出。
* 预处理候选。
* 初筛候选。
* contact sheet。
* 生成记录和 Manifest 快照。

规则：

* `standard_assets/` 和 `character_portraits/` 的直接子目录名必须是 Manifest 中的 `VisualID`。
* `ProductionProfile=standard_asset` 映射到 `standard_assets/<VisualID>/`；`ProductionProfile=character_portrait_set` 映射到 `character_portraits/<VisualID>/`。
* Profile 表达工作区、编排、交互和验收差异，不表达生成方法；Agent 根据需求、来源证据和当前工具选择实际能力。
* `_legacy_runs/` 永不参与 Manifest 生产、预处理、Approved 同步或可接入队列扫描。
* 允许废稿和多个候选版本。
* `raw/`、`selected/` 内文件名可以临时；`processed/` 的直接子目录必须是正整数并按整数排序，候选文件位于 `processed/<number>/`。
* 每个数字轮次必须包含 `decision.json`；已发布轮次不可覆盖或改写，后续修复进入下一个整数轮次。
* 推荐文件名：`YYYYMMDD_001.png`、`YYYYMMDD_002.png`。
* `manifest_snapshot.json` 保存生成时该资产的 Manifest entry 快照。
* `generation.json` 保存生成服务、模型、种子、批次 ID、输出文件和错误记录。
* 程序、Prefab、Registry 禁止引用这里。

### 2.2 `Approved`

用途：

* 已筛选通过。
* 已按规格裁切、缩放、去底或统一背景。
* 已稳定命名。
* 准备进入 `VisualAssetRegistry` 的正式素材。

规则：

* 文件名必须稳定。
* 路径必须与 Manifest 的 `OutputPath` 对齐。
* Unity 表现层只引用这里的素材，或引用由这些素材制作出来的 Prefab。

### 2.3 自动同步规则

Approved 自动同步脚本入口：

```text
tools/美术工具/Sync-ApprovedArt.ps1
```

同步规则：

* 按 Manifest entry 的 `ProductionProfile + VisualID` 通过统一 Resolver 定位工作区。
* 不扫描 `_IncomingAI` 根目录猜测 VisualID，也不扫描 `_legacy_runs/`。
* 正式生产优先使用 Manifest `SelectedPath`，其次兼容 `selected/` 第一张；两者都不存在时，只允许解析最新数字轮次中唯一且通过、且 hash/尺寸/格式一致的候选。
* 最新轮次为 `failed`、`decision_required`、`legacy_unverified` 或有多个通过候选时，禁止回退更早轮次或自动晋级 Approved。
* `-AllowProcessedFallback` 仅保留 CLI 兼容，安全数字轮次解析已自动执行，不能绕过缺失或失败的决策证据。
* 复制到该 entry 的 `OutputPath`。
* 更新 `SelectedPath`、`ApprovedPath` 和 `Status=approved`。
* 覆盖已有 PNG 时保留 Unity 已生成的 `.meta` 文件。
* 使用 `CandidateBatchID` 做 Visual V2 同名替换时，目标 PNG 和目标 `.meta` 必须已经存在；同步前后 `.meta` 必须保持字节一致。

已被程序接入的临时图升级为正式图时，只允许替换 PNG 内容，不能改变 `VisualID`、Manifest `OutputPath`、Unity `.meta` / GUID、DisplaySpec 或程序绑定。满足这些条件时，程序侧无需重新登记资源，只需要按常规运行时验收查看更新后的画面。

同步脚本不负责 AI 生成、不负责预处理、不负责 Registry 注册。

### 2.4 版本管理建议

版本库只追踪正式资产，不追踪工作区过程文件。

规则：

* `UnityClient/Assets/Art/Approved/**` 进入 Git。
* `Approved` 下的二进制资源建议走 `Git LFS`。
* `Approved` 下的 Unity `.meta` 文件继续走普通 Git，不进 LFS。
* `UnityClient/Assets/Art/_IncomingAI/**` 不进入 Git。
* `_IncomingAI` 下的 `raw`、`processed`、`selected`、`contact_sheet`、`generation.json`、`process_report.json` 都视为工作过程文件。

这样可以保留正式版本、减少仓库膨胀，并避免 AI 候选图和临时中间产物污染 Git 历史。

## 3. 命名规范

推荐格式：

```text
<domain>_<config_id_or_name>_<usage>.<ext>
```

示例：

```text
item_gear_tactical_blade_icon.png
monster_mob_scavenger_bug_portrait.png
node_safe_room_icon.png
bg_workshop_day.png
ui_missing_sprite.png
vfx_item_repair_use.prefab
sfx_item_repair_use.wav
```

禁止：

```text
最终版.png
长刀好看版2.png
ChatGPT Image 2026-05-05.png
repair_new_new_final.png
```

## 4. 美术显示标准

正式开发以 Unity 显示容器和适配规则为主，图片源尺寸只负责清晰度和后处理余量。

全局基准：

* 参考分辨率：`1920x1080`。
* 主支持比例：`16:9`。
* 兼容比例：`16:10`、`21:9`、`4:3`。
* UI 缩放：以参考分辨率下的 `ui_px` 定义容器，运行时交给 Canvas Scaler 和布局系统缩放。
* 背景适配：背景使用 `cover`，核心内容必须放在中心安全区；边缘只放可裁切的环境延展。
* 图标与立绘适配：图标、头像、立绘使用 `contain`，不允许运行时裁切主体。

标准分层：

| 层级 | 决策方 | 作用 |
|---|---|---|
| 显示容器 | 美术侧定义，程序侧实现 | Unity 中实际摆放的框。 |
| 适配规则 | 美术侧定义，程序侧实现 | `contain`、`cover`、锚点、基线、安全区。 |
| 源图规格 | 美术侧定义，脚本执行 | AI 生成、预处理和 Approved 入库尺寸。 |
| 构图检查 | 美术侧执行 | 主体占比、留白、小尺寸识别。 |

## 5. 素材规格

| 类别 | 格式 | 尺寸 | 背景 | 用途 |
|---|---|---|---|---|
| 物品图标 | PNG | 512x512 | 透明 | 背包、战利品、工坊列表、结算 |
| 怪物头像 | PNG | 1024x1024 或 1024x1536 | 透明或统一暗底 | 战斗敌人卡片、地牢预览 |
| 节点图标 | PNG | 512x512 | 透明 | 地图节点按钮 |
| 义体图标 | PNG | 512x512 | 透明 | 工坊制造、义体槽 |
| 魔偶立绘 | PNG | 1024x1536 | 透明 | 工坊展示、战斗站位 |
| 背景图 | PNG | 1920x1080 | 不限 | 工坊、战斗、地图 |
| UI 面板 | PNG | 1024x768 / 768x384 | 透明 | 弹窗、信息面板、结算面板 |
| UI 按钮 | PNG | 512x160 | 透明 | 主按钮、次按钮、危险按钮 |
| UI 列表行 | PNG | 1024x128 | 透明 | 出售、义体、层选择列表 |
| UI 背包格 | PNG | 256x256 | 透明 | 背包 100x100 玩法格子的状态皮肤 |
| UI 状态条 | PNG | 512x96 | 透明 | HP、护盾等横向状态条 |
| VFX | Prefab | 按表现需要 | 透明/粒子 | 使用、命中、护盾、污染 |
| Live2D 角色动画 | Prefab + Runtime package | 按角色规格 | 透明/RenderTexture | 魔偶立绘待机、表情、维护、受击 |
| SFX | WAV/OGG | 短音效 | - | 使用、命中、UI 反馈 |

物品图标要求主体居中，留 8%-12% 安全区，64x64 仍能识别类别。

### 5.1 Unity 显示容器标准

| 类别 | 源图规格 | Unity 显示容器 | 适配 | 对齐 | 构图要求 |
|---|---:|---:|---|---|---|
| 物品图标 | 512x512 | 64x64 | `contain` | `center` | 主体占比 74%-84%，安全边距 10%。 |
| 节点图标 | 512x512 | 80x80 | `contain` | `center` | 主体占比 68%-80%，安全边距 12%，轮廓强。 |
| 义体图标 | 512x512 | 80x80 | `contain` | `center` | 主体占比 72%-84%，安全边距 10%。 |
| 缺失占位图 | 512x512 | 64x64 | `contain` | `center` | 高对比、低细节、不可出现随机文字。 |
| 怪物头像 | 1024x1024 | 320x320 | `contain` | `center` | 头胸像，主体占比 78%-92%，边缘不裁头。 |
| 魔偶立绘 | 1024x1536 | 420x720 | `contain` | `bottom_center` | 全身站姿，脚底基线约 94%，高度占比 86%-94%。 |
| 背包底盘 | 1024x1024 | 512x512 | `contain` | `center` | 中心开放区清楚，框体占比 82%-94%。 |
| 背景图 | 1920x1080 | 1920x1080 参考视口 | `cover` | `center` | 核心信息在中心 4:3 安全区，边缘可裁切。 |
| 主弹窗面板 | 1024x768 | 960x640 | `stretch/9-slice` | `center` | 中心区域必须空，文字和列表由程序叠加。 |
| 小信息面板 | 768x384 | 480x240 | `stretch/9-slice` | `center` | 低噪声，中心空。 |
| 按钮皮肤 | 512x160 | 220x64 | `stretch/9-slice` | `center` | 不烘焙文字，中间留标签区。 |
| 列表行底板 | 1024x128 | 720x72 | `stretch/9-slice` | `center` | 横向可拉伸，中间不放文字纹理。 |
| 背包格状态 | 256x256 | 100x100 | `contain` | `center` | 玩法格容器为 100x100；状态差异主要靠边框、亮度和色相，不放文字。 |
| 状态条皮肤 | 512x96 | 220x28 | `stretch/9-slice` | `center` | 只做轨道和边框，数值填充由程序控制。 |

这里的显示容器是参考分辨率下的设计值，不是锁死玩家设备上的实际像素。运行时分辨率变化时，程序按布局和 Canvas Scaler 等比例缩放。

### 5.2 UI 九宫格标准

面板、按钮、列表行和状态条优先做可拉伸 Sprite，避免不同界面重复切图。

| 类别 | 推荐源图 | 建议 Border | 说明 |
|---|---:|---|---|
| 主弹窗面板 | 1024x768 | L/R/T/B 96 | 四角装饰保留，中心拉伸。 |
| 小信息面板 | 768x384 | L/R/T/B 64 | 适合提示和摘要区域。 |
| 按钮 | 512x160 | L/R 72，T/B 48 | 横向可拉伸，中间不带文字。 |
| 列表行 | 1024x128 | L/R 80，T/B 36 | 横向可拉伸，可做普通/选中两套。 |
| 状态条 | 512x96 | L/R 48，T/B 28 | 轨道和外框可拉伸，填充条由程序控制。 |

九宫格 border 会写入 Manifest 的 `Spec.ProcessSpec.NineSlice`，程序接入时以该字段为准。AI 原图如果边缘装饰太复杂，预处理或人工筛选时应优先淘汰。

### 5.3 背景安全区标准

背景图需要同时兼容不同宽高比：

| 比例 | 策略 | 美术要求 |
|---|---|---|
| `16:9` | 基准视口 | 画面完整展示。 |
| `16:10` | `cover` 后轻微横向或纵向裁切 | 重要物件避开上下 8%。 |
| `21:9` | `cover` 后裁切上下 | 顶部和底部只放环境延展，不放关键主体。 |
| `4:3` | `cover` 后裁切左右 | 关键主体、路线、视觉焦点放在中心 4:3 区域。 |

背景不为每个分辨率单独出图。确实需要宽屏专用构图时，后续再增加独立 `Variant`，不作为 MVP 默认标准。

## 6. Unity 导入建议

完成状态分开判断：

```text
approved：正式文件已落盘并通过 meta/GUID 门禁
unity_imported：当前 Unity Editor AssetDatabase 已识别正确类型和导入设置
registered：live Registry 能按 VisualID 取到目标资源
runtime_bound：目标 Prefab / UGUI 实际消费该资源
runtime_validated：运行时画面和技术证据通过
```

Approved 后必须刷新 live Unity，等待导入 / 编译完成，并检查 Console delta。只解析磁盘 YAML 或看到 `.meta` 文件不等于 `unity_imported`。

静态 Sprite 的正式接入使用 `tools/美术工具/Invoke-ArtApprovedUnityRegistration.ps1` 三阶段入口。脚本负责 Approved 计划、权限、hash、`.meta` / GUID、evidence 终验和生成清单；Agent 在中间使用 Unity MCP 获取 live importer 和 Registry 内容。通过后主 `Status` 保持 `approved`，接入轴写 `RegistryStatus=registered`。

Sprite：

* Texture Type：`Sprite (2D and UI)`
* Sprite Mode：`Single`
* Alpha Is Transparency：开启
* Max Size：图标 512，头像 1024 或 2048
* Compression：MVP 可用 `Normal Quality`
* Filter Mode：UI 图标优先 `Bilinear`

Prefab：

* 根节点命名稳定，例如 `MonsterVisual_<MonsterID>`。
* 可包含 `SpriteRenderer`、UGUI `Image`、Animator、受击点、特效挂点。
* 不包含玩法数值、掉落、背包占格、道具效果。

UI：

* 背景、装饰图、标题文本默认不阻挡射线。
* 背包拖拽、敌人选择、节点点击区域优先保证交互。

## 7. 接入流程

1. AI 或美术产出素材到 `_IncomingAI`。
2. 在 `_IncomingAI` 内完成预处理、缩略图和初筛。
3. 生产决策明确绑定唯一 SelectedPath、批次 / RunID 和 hash，通过 Approved 门禁后同步到 Manifest `OutputPath`。
4. 静态 Sprite 通过 `Invoke-ArtApprovedUnityRegistration.ps1` 建立 ArtImportRunID，Unity MCP 刷新并确认导入类型、`.meta`、GUID 和 importer 设置。
5. 按资源类型分流：Sprite Registry、Prefab / 动态立绘、Live2D / DollPuppet、VFX、Audio 使用各自接入器。
6. Registry 校验目标 VisualID 在原始 Entries 中唯一、`TryGetEntry` 成功、Sprite 非空且路径 / GUID 与 Approved 一致；重建成功或总数变化不能代替目标证据。
7. UI 或表现层通过 `VisualID` 获取资源，并检查 contain / cover、Mask、CanvasGroup、raycast 和引用目标。
8. 使用 `p3-art-validation` 做受影响目标的运行时检查；正常玩家路径另行提供真实入口证据。
