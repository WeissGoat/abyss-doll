# AI 图片生成能力与网关契约

> **定位：** 规定图片如何生成或编辑，以及 raw 结果和 generation evidence 如何返回。Agent 执行入口为 `.codex/skills/p3-generate-image/SKILL.md`。正式资产准入、候选选择、Approved、Unity 和验收由 `p3-art-asset-production` 负责。

## 1. 能力边界

图片能力负责：

- text-to-image；
- image-to-image；
- 角色 / 状态 / 姿态差分；
- mask inpaint；
- provider / model / capability 选择；
- provider-specific Prompt；
- smoke、重试、退避和 fallback；
- raw 图片和 generation evidence。

图片能力不负责：

- 需求是否准入；
- VisualID / OutputPath 决策；
- Manifest 状态推进；
- 候选 selected；
- Approved 同步；
- `.meta` / GUID；
- Registry / UGUI；
- ArtRun、ArtAcceptance 或玩家路径结论。

## 2. 工具层级

1. Codex 内置 `image_gen`：新设计图 / 概念图首选。
2. `tools/ai-image-gateway`：OpenAI Images、Gemini chat image、NovelAI generation / inpaint 等可配置后端。
3. `tools/美术工具`：P3 Manifest 到 gateway 请求的适配脚本和 backend smoke。

设计图 / 概念图默认优先 `image_gen`；当前环境未暴露时直接使用 `openai_images`。正式 Manifest 批量、参考图差分、固定 provider 或要求落盘证据的任务使用网关。

## 3. 能力路由

| 任务 | 首选 | 备选 | Prompt 形式 |
|---|---|---|---|
| 新设计图 / 概念图 | `image_gen` | `openai_images` | 自然语言 |
| 通用正式候选、背景、CG | `openai_images` | `gemini_chat_image` | 自然语言 |
| 保身份 / 构图、状态差分、参考图编辑 | `gemini_chat_image` | NovelAI inpaint | 自然语言 + 保持 / 改变 / 禁止改变 |
| 二次元 tag 特化、原生 negative prompt | `novelai` | `openai_images` | Danbooru tags + negative tags |
| 有明确 mask、允许一定漂移的局部重绘 | NovelAI inpaint | Gemini 图生图 | tags + mask |

`grok_chat_image` 仅作显式实验后端，先 smoke，不进入默认生产路由。

整体构图和身份已经成立、仅局部有问题时，不得默认整张重做。严格身份、位置或形状控制优先 Gemini 图生图；NovelAI inpaint 不作为像素级修图工具。

## 4. Provider Prompt 契约

### 4.1 OpenAI Images

使用结构化自然语言：

```text
任务 / 画面类型
-> 主体和身份
-> 构图 / 镜头
-> 风格 / 材质 / 色板
-> 必须保留
-> 必须避免
-> 输出要求
```

negative 内容并入自然语言约束，不假设存在原生 negative 通道。

### 4.2 Gemini Chat Image

文生图写清主体、构图和禁项。图生图必须明确：

- 必须保持；
- 允许改变；
- 禁止改变。

不得只写“优化一下”或“修复问题”。当前 Flow2API 的 Gemini image alias 只接受
`generationConfig.imageConfig` 中的画幅别名与尺寸档位：

```json
{
  "generationConfig": {
    "responseModalities": ["IMAGE"],
    "imageConfig": {
      "aspectRatio": "three-four",
      "imageSize": "2k"
    }
  }
}
```

网关按请求宽高选择最近的 `landscape / portrait / square / four-three / three-four`，
并选择 `2k / 4k`。像 `1024x1536` 这种 relay 不原生支持的精确比例和像素尺寸，必须
在后处理阶段规范化，不再把尺寸句追加到 Gemini Prompt。

角色立绘最终需要透明 PNG 时，不假设 Gemini 能可靠输出 Alpha。Prompt 应请求单一、
饱和、无地面、阴影、渐变、纹理或棋盘格的分割背景，再由显式 segmentation/rembg
mask 生成最终 Alpha。是否请求原生透明由具体后端能力决定，不能把假棋盘格视为透明。

### 4.3 NovelAI

使用短 Danbooru tags：

```text
主体数量, 身份 / 属性, 姿态, 服装, 构图, 背景, 风格, 质量
```

负面内容走独立 negative tags。不得发送项目剧情、玩法黑话、项目名或长篇自然语言。

### 4.4 通用禁项

Prompt 不写：

- 项目名或直接 IP 模仿；
- `Unity`、`UGUI` 等引擎词；
- “按钮可读性”“站位空间”等抽象交互要求；
- 正式字幕、随机文字、签名或水印。

抽象需求必须翻译成视觉语言，例如 `large negative space`、`low visual noise`、`bold silhouette`。

## 5. 配置与凭据

本地配置：

```text
tools/ai-image-gateway/config.local.yaml
```

模板：

```text
tools/美术工具/ai_image_gateway.example.yaml
```

真实 token、API key、cookie 或授权信息不得进入文档、状态页、日志、提交或命令示例。

配置或 endpoint 变化后先运行：

```powershell
.\tools\美术工具\Test-AIImageBackends.ps1 -CheckConfigOnly
.\tools\美术工具\Test-AIImageBackends.ps1 -Backend chatgpt,gemini,novelai -Attempts 1
```

smoke 默认写系统临时目录，不进入 `_IncomingAI` 或任何正式资产状态。

## 6. 请求协议

批量数量统一由本地循环实现：

```text
Variants=N / COUNT=N
-> N 次串行请求
-> 每次 count=1
```

不依赖 provider 原生 `n`。正式批量保留合理间隔，避免并发、限流和结果关联混乱。

Manifest 适配请求示例：

```python
GenerateRequest(
    provider=provider,
    prompt=resolved_prompt,
    negative_prompt=resolved_negative_prompt,
    width=asset_contract["SourceSpec"]["Width"],
    height=asset_contract["SourceSpec"]["Height"],
    count=1,
    seed=resolved_seed,
    output_format=asset_contract["SourceSpec"]["Format"],
    extra={"visual_id": visual_id, "asset_type": asset_type},
)
```

provider 特有模型、采样、CFG、quality、画幅别名和近似尺寸档位等放网关配置或请求
参数，不污染 Manifest 的通用视觉事实，也不重复写进已发布 Prompt 文本。

## 7. 输出契约

正式 P3 请求由上游生产 Profile Resolver 指定工作区，图片能力只写 raw。图片能力不得从资产类型或生成方式自行推断 Profile：

```text
UnityClient/Assets/Art/_IncomingAI/<profile-directory>/<VisualID>/raw/
UnityClient/Assets/Art/_IncomingAI/<profile-directory>/<VisualID>/generation.json
UnityClient/Assets/Art/_IncomingAI/<profile-directory>/<VisualID>/manifest_snapshot.json
```

其中 `<profile-directory>` 由上游解析为 `standard_assets` 或 `character_portraits`。角色立绘可以使用文生图、图生图、局部编辑、导入素材或未来能力；输出契约不把这些方法写死到目录或稳定 ID。

探索任务可以写任务指定目录，但必须声明不进入正式资产链。

`generation.json` 至少记录：

- provider、model、capability；
- provider prompt、negative prompt 和格式；
- 参考图 / mask；
- 请求次数和每次 `count=1`；
- seed、请求尺寸、输出格式；
- 每张输出路径和实际尺寸；
- generation params、错误和时间。
- 实际 provider 专属参数，例如 Gemini `generationConfig.imageConfig`；正式 v2 证据
  同时写入 `ProviderRequest.ProviderImageParameters`。

图片能力返回：

```yaml
status: succeeded | partial | failed | blocked
provider: ...
model: ...
images: []
evidence: generation.json
errors: []
```

返回后控制权交还 `p3-art-asset-production`。

## 8. 错误与 fallback

| 情况 | 处理 |
|---|---|
| 401 / 403 | 凭据阻塞，不盲目重试 |
| 429 | 串行、降低批次、指数退避 |
| 502 / 503 / 504 | 有限重试后按允许范围 fallback |
| 524 / 长超时 | 降低单次复杂度、尺寸或切后端 |
| 0 张图 | 失败，不推进任何生产状态 |
| 部分成功 | 返回 `partial` 并完整记录失败 |
| 空图 / 纯色图 / 损坏图 | 技术失败，不冒充候选 |

单个资产失败不应自动中断整个批次，但正式生产上游必须决定该 VisualID 是重试、fallback、limited 还是 blocked。

## 9. 完成口径

图片能力完成只证明：

1. 请求与 provider 路由符合本契约；
2. raw 文件存在且可解码；
3. generation evidence 完整；
4. 错误和部分成功没有被隐藏。

不得由本能力声明 processed、selected、Approved、registered、runtime validated 或 player-path complete。
