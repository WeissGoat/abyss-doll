# 正式版核心纵切美术路线

> **更新时间：** 2026-05-25
> **定位：** 将美术侧从 MVP 补素材模式切换到“正式版核心纵切”的 UI、资源和验收路线。顶层阶段以 `版本规划/09_正式版核心纵切开发路线.md` 为准。

---

## 1. 阶段判断

当前美术侧已经完成 MVP 验证所需的基础链路：

* 配置表、推导需求和 preset 需求可以进入 Manifest。
* AI 提示词、批量出图、预处理、筛选和 Approved 接入流程已经建立。
* 运行时美术验收工具已经可以导出关键界面截图和 UI 快照。
* 工坊、战斗、拾取、地图、结算、安全屋、阶梯房间等主流程已有可运行画面。

因此后续不再以“哪里缺图就补哪里”为主线。正式版核心纵切阶段，美术侧目标是：

```text
正式 UI 骨架
  -> 稳定组件系统
  -> 可扩展界面布局
  -> 资源 Manifest 管理
  -> 运行时验收门禁
  -> 当前批次按正式标准验收
```

也就是说，美术侧通过批次控制“本轮处理哪些界面和资源”，不通过降低质量标准来推进。进入当前批次的 UI 结构、组件契约、VisualID、资源接入和截图验收必须按正式版标准完成；未进入批次的界面和资源不抢跑。

---

## 2. 总原则

### 2.1 UI 先正式，素材可迭代

UI 不能再只作为功能验证色块。后续被纳入核心纵切的界面，必须先明确：

* 页面目标和信息层级。
* 可复用组件。
* 参考分辨率下的区域、锚点和安全区。
* 交互状态、禁用状态、选中状态、警告状态。
* 程序绑定字段和 VisualID。
* 截图验收标准。

具体图片可以在后续批次继续精修，但进入当前批次的资源必须达到 Approved 可接入标准，并且同名 VisualID 的替换不得改变布局、组件边界或程序契约。

### 2.2 可替换，不可推翻

允许替换更高质量图片、增加动画、增加特效、增加状态层。但以下内容不应频繁推翻：

* `ScreenID`。
* 核心 `VisualID`。
* 背包 100x100 玩法格标准。
* 通用组件分类和使用边界。
* UI 布局的主区域结构。
* Manifest 字段和资源目录规则。

### 2.3 用组件系统承托正式 UI

正式 UI 不是为每个界面画整张大图，而是用一套组件系统承托不同流程：

| 组件层 | 目标 |
|---|---|
| 背景层 | 表达场景氛围，使用 `cover` 适配多比例，不承载关键文字。 |
| 面板层 | 承载信息区、列表区和确认区，优先九宫格。 |
| 控件层 | 按钮、列表行、页签、锁定/装备/警告图标。 |
| 玩法层 | 背包格、物品图标、怪物卡、状态条、行动点。 |
| 反馈层 | hover、valid、invalid、selected、disabled、danger。 |
| 动效层 | 后续逐步添加转场、受击、拾取、出售、制造、撤离反馈。 |

## 3. 正式版纵切美术范围

### 3.1 当前批次必须正式化的部分

| 模块 | 正式化目标 |
|---|---|
| 工坊主界面 | 局外主入口，明确整备、出售、义体、出发、金币/压力信息和魔偶展示区。 |
| 背包与物品生命周期 | 背包格、物品图标、拾取、丢弃、出售、制造消耗都要有稳定视觉反馈。 |
| 战斗 HUD | 玩家状态、敌人意图、AP、HP、护盾、SAN、行动按钮必须可读。 |
| 深渊地图与层级入口 | 节点、路线、锁定、当前层、可进入层要形成正式版可扩展骨架。 |
| 安全区与阶梯房间 | 安全区休整、继续深入、撤离、层间风险和背包整理要形成正式房间节点结构。 |
| 结算界面 | 撤离、战败、带出、损失、收益总结要有正式信息层级。 |
| 通用 UI 皮肤 | 主面板、信息面板、按钮、列表行、标题分隔、图标状态成为长期复用组件。 |
| 运行时验收 | 每次 UI 接入后必须能导出截图、Registry 快照和 UI 快照。 |

### 3.2 后续批次处理的部分

| 模块 | 批次口径 |
|---|---|
| 角色与怪物动画 | 未进入当前批次时不抢跑；进入动画批次后按正式动效规格、触发时机和验收截图/录像完成。 |
| VFX | 未进入当前批次时只保留接口意识；进入 VFX 批次后按命中、护盾、腐蚀、SAN、拾取、出售、制造等场景逐项验收。 |
| 背景精修 | 当前批次的背景必须消除占位和透明问题；更多层级/房间主题按后续批次完整处理。 |
| 音效 | 当前只保持 AudioID / VisualID 协作边界；进入音效批次后按高频交互点完整接入。 |
| 大量内容图标 | 随配置扩展分批生成；每个进入批次的图标都必须达到 Approved 接入标准。 |

## 4. UI 设计流调整

正式版核心纵切阶段，UI 新增或重做必须先走 `美术文档/ui_design/`，而不是直接跑图。

标准顺序：

```text
design_tokens.json
  -> component_catalog.json
  -> screen_layouts.json
  -> Validate-UIDesign.ps1
  -> art_requirements_seed.json / Manifest
  -> Prompt / Spec
  -> AI Generation
  -> Refresh Integration Candidates Snapshot
  -> Preprocess / 9-slice Check
  -> Refresh Integration Candidates Snapshot
  -> Approved
  -> Refresh Integration Candidates Snapshot
  -> Unity Registry / Layout
  -> ArtAcceptance
```

每个进入 正式版纵切的界面，至少要有：

| 字段 | 要求 |
|---|---|
| `ScreenID` | 稳定，不随文案变化改名。 |
| `Priority` | 当前主链路使用 `P0` 或 `P1`。 |
| `Status` | `planned -> draft -> handoff -> integrated -> validated`。 |
| `BackgroundVisualID` | 没有背景也要显式写 `null` 或说明复用背景。 |
| `Zones` | 写清主区域、列表、按钮、背包、角色/怪物展示区。 |
| `RequiredComponents` | 引用组件目录，避免散落的临时 Sprite。 |
| `ControllerBindings` | 明确程序脚本字段和 UI 对象关系。 |
| `UnityHierarchy` | 明确新增/换皮节点路径。 |
| `SpriteAssignments` | 明确每个 VisualID 分配到哪里。 |
| `AcceptanceCriteria` | 能被运行时截图验收的标准。 |

## 6. 与程序侧的协作口径

美术侧在要求程序推进前，应先提供：

1. `screen_layouts.json` 中对应界面的正式布局和组件引用。
2. `component_catalog.json` 中新增或修改的组件定义。
3. Manifest 或 seed 中对应的 VisualID。
4. Approved 中可用的 PNG，或明确使用 fallback 的临时 VisualID。
5. ArtAcceptance 的验收标准。
6. 最新 `美术文档/_generated/可接入素材清单.md/json`；如本轮发生生成、预处理或 Approved 同步，必须同时提供 `art_integration_snapshots/` 快照。

程序侧接入完成后，美术侧负责：

1. 触发运行时美术验收。
2. 查看截图、`report.json`、`ui_snapshot.json`、`registry_snapshot.json`。
3. 在 `09_运行时美术验收记录.md` 记录通过、条件通过、返修项。
4. 将新增缺口回填到 `art_requirements_seed.json` 或 `screen_layouts.json`。

### 7.1 与 P0-P5 路线的执行对齐

美术侧当前不单独横向铺界面，而是作为 `09` 路线中 P0-P4 的表现支撑和验收门禁。具体推进口径如下：

| 版本优先级 | 美术侧处理口径 | 当前动作 |
|---|---|---|
| P0 配置 / Validator / 验收底座 | 配合统一验收报告，把 ArtAcceptance 截图、Registry 快照和缺图结果纳入质量门禁。 | 等程序 P0 报告底座稳定后，美术侧按 latest 截图做结论记录。 |
| P1 背包 / 物品生命周期 / 战斗可读性 | 优先保证背包格、物品图标、战斗实体、意图反馈、血条和失败原因可读。 | P1 战斗可读性新增素材已有 local_v0 Approved；等程序接入后验收 `combat_hud`、`inventory_loot`、`sell_panel` 的 Formal V1 运行时效果。 |
| P2 深渊地图 / 层级 / 房间节点 | 优先保证地图节点、路线、层级入口、安全区、阶梯房和撤离/继续深入信息可读。 | 新增节点图标已有 local_v0 Approved；等程序接入后验收 `dungeon_map`、`layer_select`、`safe_room`、`stairs_room`。 |
| P3 局外成长 | 只补当前成长主线需要的工坊、义体、底盘升级、维护、下潜许可、基础人偶交互和房间视觉日记入口。 | `workshop_main`、`prosthetic_panel`、`maintenance_panel`、`chassis_upgrade_panel`、`doll_interaction`、`doll_room` 已进入 active，先做接入准备和后续验收，不扩展完整房间经营。 |
| P4 经济压力 | 只补当前压力链需要的出售、结算、账单、出货、订单、传闻和势力交易入口。 | A4、势力商店、剧本事件相关图标已有 local_v0 可接入版；正式 AI 版进入 Visual V2 质量替换队列。 |
| P5 表现支撑 | 不是独立铺量目标。只有进入当前功能纵切的界面和资源才进入 active、Manifest 和跑图。 | 当前 20 个 active 界面均已纳入 UI / Manifest / 可接入清单；后续只补当前纵切需要的表现缺口。 |

后续执行顺序：

1. 程序侧先按 latest 可接入素材清单登记 `program_integrate` 素材；`ProgramCanUseCurrent=yes` 的 local_v0 素材不阻塞程序接入。
2. 程序侧按 active 规格分批接入 20 个 Formal V1 界面；美术侧每次基于最新 ArtAcceptance 验收结构、缺图、黑块、射线遮挡和列表有效数据。
3. 验收通过后，将对应界面的 `LayoutStatus` 推进到 `integrated` / `validated`，并记录到 `09_运行时美术验收记录.md`。
4. 美术侧持续运行 `Generate-ArtQualityBacklog.ps1`；若出现 `technical_fix`，先修技术问题，再处理视觉精修。
5. 缺图生成计划 latest 当前为 `planned=0`；后续新增 `generate_needed` 时再按 `Generate-ArtBatchPlan.ps1` 生成批次计划。
6. NovelAI Anlas 恢复后，按 `visual_v2_replace` 队列替换 44 个 local_v0 素材；替换使用 `PreserveStatus -> CandidateBatchID -> QualityTier=formal_ai_v2` 流程，不得改变同名 VisualID、DisplaySpec 或程序绑定。
7. 特效、动画、音效和更高质量背景作为表现增强逐步进入，不改变已确认的主结构和 VisualID 契约。

## 8. 非目标

当前批次不抢跑：

* 未进入本批次的图标、怪物、背景、动画和 VFX。
* 未形成 DisplaySpec 和接入目标的分辨率专项资源。
* 需要烘焙文字、数值、价格、物品名的图片方案。
* 会在后续被废弃的临时验证界面。
* UI 骨架未定、无法进入程序接入和截图验收的大量图片。
