# 美术风格基准

> **定位：** 统一 AI 出图和人工筛选时的视觉方向。
> **更新时间：** 2026-10-05（M4 重定方向；制作人选了暖色小镇养成 + 《来自深渊》式深渊。锚点图在 `docs/specs/2026-10-05-m4-art-audio-plan.md` 里列着）

---

## 1. 风格定位

```text
日系二次元地底奇幻 · 暖色小镇养成
```

游戏有两个世界，画面要让玩家一眼分清：

* **地上：小镇和工坊，是家。** 深渊边缘的阶梯小镇：暖木、白墙、红瓦、布篷、晾衣绳、花盆和香草、纸灯笼；货运吊笼和滑轮垂进深渊。午后的琥珀色阳光，生活感、安全感，"回来就能喘口气"。情绪参考《火山的女儿》。
* **地下：深渊，是外面。** 巨大的垂直空间、层层岩壁、古树根、矿工留下的木脚手架和吊桥、发光的蘑菇和孢子，光从很远的上方斜着落下来。好奇、壮阔、安静的危险，可爱和残酷并存。情绪参考《来自深渊》。
* **规则：上暖下冷。** 地上是琥珀、蜂蜜、奶油、陶红、鼠尾草绿；深渊越往下越青、越蓝、越暗。深渊里唯一的暖色是人造物：灯笼、绳索、木头、零号的斗篷。
* **画法**：干净线条，柔和赛璐珞（两阶阴影），背景是手绘感的动画背景；角色和场景带温度。不要欧美黑暗奇幻、厚重写实、油画质感、冷硬科幻面板，也不要满屏齿轮的蒸汽朋克。
* **角色比例**：零号约 5.5–6 头身，娇小但不是 Q 版（战斗样张里偏 Q 的那张不用）。人设见 `人设/03_零号初版人设方案.md`。

注意：AI 绘图提示词不写作品名，拆成视觉语言（见第 4 节）。

### 1.1 调色板

| 用途 | 颜色 | 说明 |
|---|---|---|
| 小镇光 | 琥珀 `#F2B864`、蜂蜜 `#E8A04A` | 午后阳光、灯笼 |
| 小镇体 | 奶油 `#F4E6CC`、暖木 `#9A6A42`、陶红 `#C5623F`、鼠尾草绿 `#8FA876` | 墙、木结构、屋瓦、植物 |
| 深渊第 1 层 | 青绿 `#3FB8A8`、苔绿 `#4E7A4A`、深蓝影 `#14304A` | 荧光蘑菇和孢子、苔藓、远处的暗 |
| 深渊第 2 层 | 冰蓝 `#7CC6E8`、紫影 `#2C2A4E` | 结晶层，更冷、更硬 |
| 零号强调色 | 褪色红线 `#B5402F` | 全身唯一的强调色；界面主行动也用它 |

### 1.2 界面材质

界面像一个被细心缝补过的旅行包，而不是机器的仪表盘：

* **面板**：燕麦色亚麻布面（`#E9DCC3`），边缘一圈虚线缝线，外面皮革包边（`#7A5236`）。深色背景（深渊、战斗）上的亚麻面板最醒目。
* **文字**：深胡桃色（`#3B2A1E`），次要文字 `#6B5544`。不用纯黑。
* **按钮**：主行动是茜红布面（`#B5402F`）配奶油色字，次要按钮是亚麻色。黄铜只用在小扣子、铆钉、AP 宝石的框上，不做大面积黄铜框。
* **数值和状态**：AP 是嵌在铜框里的蓝宝石（`#3FA7D6`，和深渊的青蓝呼应）；敌人意图是红色圆章加图标和数字；正面用鼠尾草绿，警告用蜂蜜色。
* **背包格**：缝在亚麻上的格子，像布包的分隔袋。
* 面板和按钮做成九宫格，可拉伸；概念图里不出现能读的假文字。

## 2. 英文提示词锚点

以下是已经出过好图的锚点（2026-10-05 第一轮），按资产类型取用，再补具体内容。不必机械原样发送，NovelAI 要改写成 tag（见 2.5）。

### 2.1 小镇 / 工坊（地上）

```text
Japanese anime game background art, hand-painted look, soft cel shading, clean linework. A cozy small town built on wooden terraces and stone steps around the rim of a gigantic vertical chasm. Warm late-afternoon sunlight, gentle pastel-warm palette of honey, cream, terracotta and sage green. Lived-in details: cloth awnings, laundry lines, potted herbs, paper lanterns, rope lifts and pulleys going down into the chasm. Mood: warm, safe, slice-of-life, a place you come home to. No text.
```

### 2.2 深渊（地下）

```text
Japanese anime game background art, soft painterly anime background, clean shapes. An enormous vertical cavern in a vast underground abyss, layered rock strata, giant ancient roots, old miners' wooden scaffolding and rope bridges clinging to the walls, glowing mushrooms and drifting luminous spores, faint shafts of daylight from far above, hazy depth falling away into blue darkness. Sense of huge scale, wonder and quiet danger, storybook adventure feeling. Teal and moss-green palette with small warm lantern accents. No text, no characters.
```

第 2 层把"glowing mushrooms, teal and moss-green"换成"pale blue crystal growths, ice-blue and violet shadows"。

### 2.3 界面概念图

```text
2D Japanese anime-style game UI, warm handcrafted interface: panels of oatmeal linen cloth with dashed stitching and dark leather edging, small brass buttons and rivets only as accents, soft rounded shapes, readable and cute, low information density, no real text other than numbers.
```

### 2.4 角色

先给参考图（零号标准设定），再写：

```text
Japanese anime game character art, soft cel shading, clean confident lines, light warm palette.
```

外貌描述按 `人设/03_零号初版人设方案.md` 的提示词段落写，不在这里重复。

### 2.5 NovelAI tag 锚点

```text
anime coloring, cel shading, soft lighting, warm colors, scenery, town, cliff, wooden bridge, lantern, laundry, potted plant, sunset
anime coloring, cel shading, cave, abyss, giant roots, rope bridge, glowing mushroom, light particles, light rays, teal theme, depth of field
```

## 3. 中文审阅描述

`VisualIntent` 用于人类审阅和 PromptRevision authoring，不直接作为绘图工具请求。中文描述应回答：

* 这个资产看起来是什么？材质、形状、颜色和气质是什么？
* 它属于地上还是地下？颜色有没有守住"上暖下冷"？
* 零号出现时，和标准设定是不是同一个人（发型、遮眼布和红线、斗篷、衣服、脚）？

## 4. 禁止项

正负提示词里禁止出现：

* 项目名或作品名：`魔偶深渊`、`来自深渊`、`Made in Abyss`、`火山的女儿`、`Volcano Princess`
* 玩法黑话：`搜打撤`、`塔科夫like`
* 引擎词：`Unity`、`UGUI`
* 直接风格仿写：`in the style of ...`、`same characters as ...`

转换示例：

| 不要写 | 改成 |
|---|---|
| 类似来自深渊 | `vast vertical underground abyss`, `wonder and quiet danger`, `storybook adventure feeling` |
| 类似火山的女儿 | `cozy slice-of-life town`, `warm late-afternoon sunlight`, `honey, cream, terracotta and sage green` |
| 日系二次元 | `Japanese anime game art`, `soft cel shading`, `clean linework` |
| 手作感界面 | `oatmeal linen panels`, `dashed stitching`, `leather edging`, `small brass accents` |
| 留 UI 空间 | `large negative space`, `low visual noise` |

## 5. 负面风格基准

由 Agent 按资产需求判断后写进负面提示词，provider adapter 不自动追加：

```text
western dark fantasy, grimdark, hyperrealistic, photorealistic, oil painting, heavy realistic armor, gritty sci-fi console, cyberpunk UI, dominant steampunk machinery, gears everywhere, large brass frames, dark brown steampunk interface, dense button wall, cluttered text, fake readable text, ocean background, floating disconnected map nodes
```

角色额外加：`chibi, super deformed, mature female, cleavage, revealing clothes, nsfw`。

## 6. 可执行风格合同

Manifest 的风格不再由 VisualID、文件名或单段 Prompt 推断，而由以下层级显式解析：

```text
GlobalStyle -> Profile -> Family -> Role -> ContextAccent -> VisualIntent
```

当前稳定语义 ID：

| 层级 | ID | 语义 |
|---|---|---|
| GlobalStyle | `p3_global_v1` | 日系二次元地底奇幻 · 暖色小镇养成，上暖下冷（见第 1 节）。 |
| UI Profile | `ui_v1` | 低噪声、可读、缝补亚麻材质的手作 UI（见 1.2）。 |
| Character Profile | `character_portrait_v1` | 保持身份、比例、画布基线的角色立绘。 |
| Button Family | `ui_button_core_v1` | 连续边框、干净中心和可拉伸结构。 |
| Primary Role | `primary` | 茜红主要行动语义。 |
| Neutral Accent | `none` | 不覆盖基础风格。 |

UI 的颜色角色合同（2026-10-05 起）为：

```text
燕麦亚麻底板 + 皮革包边和缝线 + 茜红主行动
青蓝只用于 AP、选中和能量反馈；黄铜只做小扣件
```

`design_tokens.json` 还是旧的"墨灰 / 月白 / 绯红"，M4 批 4 换皮时一起改。

这些语义由 `design_tokens.json` 的 `ColorRoleAliases` 提供机器可读映射，编译器只把它们解析进 Prompt authoring context；最终 Prompt 由 Agent 结合资产类别和证据创作。任何生成器不得从 `ui_button_primary` 的字符串内容猜测颜色或组件角色。

角色立绘另使用 `character_portrait_set` Profile 和 AssetSet 身份合同；角色成员的 `SetRole` 表达母版、姿态或差分关系，不等于 UI Family/Role，也不规定文生图、图生图或具体 provider。

## 7. Requirement 编译与 PromptRevision

`VisualIntent` 是单项资产最终需求。编译器将风格层、VisualIntent、Spec 和角色 AssetSet 合并为 `PromptAuthoringContext + TechnicalRequest + PreservationContract`，并计算稳定 `RequirementFingerprint`；它不创作最终 Prompt。

Agent 读取上述上下文、参考图和历史证据，按当前工具能力独立创作一个不可变 PromptRevision 的两个格式槽位：

| PromptFormat | 默认后端 | 结果 |
|---|---|---|
| `natural_language_v2` | OpenAI/GPT image edit、Gemini image/chat image | Agent 判断后的自然语言正面与负面 Prompt。 |
| `danbooru_tags_v2` | NovelAI | Agent 独立设计的结构化 tag、weight、负面 tag。 |

完整 Requirement 与 PromptRevision 保存到 `美术文档/_generated/art_generation_requests.json`。两个格式共享需求和硬约束，但不要求机械互译；各自可以根据 provider 表达能力组织内容。ready Variant 必须用 `ConstraintMapping` 覆盖全部硬约束。需求、风格、Spec 或编译器版本变化后先重新编译 Requirement，再由 Agent 审核、复用或发布新 Revision；执行器只读取已发布 Revision，不能临时拼 Prompt，provider adapter 也只能序列化。
