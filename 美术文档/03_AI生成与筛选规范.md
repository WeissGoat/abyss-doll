# AI 美术资产质量与筛选准入规范

> **定位：** 定义 Project P3 图片候选“什么算合格”。图片如何请求由 `generate-image` 和 `05` 负责；Agent 如何循环、停问和自动执行由 `p3-art-asset-production` 负责。

## 1. 准入原则

AI 产物不是一次生成即成为正式资产。质量状态必须逐级成立：

```text
raw
-> technically_valid
-> visually_reviewed
-> selected
-> approved
-> runtime_validated
```

- raw 只证明图片生成成功；
- processed / contact sheet 只证明可进入评估；
- selected 证明当前候选被选中；
- Approved 证明正式素材完成；
- Registry / UI 绑定证明接入；
- 运行时和玩家路径证据证明实际效果。

## 2. 技术硬门禁

出现以下任一情况，候选直接失败，不进入视觉评分：

- 文件损坏、无法解码、空图、纯色图；
- 与其他候选实质重复；
- 尺寸、格式或 alpha 不符合 SourceSpec 且无法安全修复；
- 随机文字、签名、水印、伪 UI 文案；
- 主体数量、资产类型或核心身份明显错误；
- 关键主体被裁切或违反安全区；
- 透明背景合同无法满足；
- 包含 Manifest / 专项规格明确禁止的内容；
- UI 皮肤中心烘焙文字、数字或无法拉伸的复杂装饰；
- 同 VisualID 替换将改变 OutputPath、`.meta`、GUID、DisplaySpec 或既有绑定。

技术门禁应优先使用脚本处理尺寸、alpha、透明像素、安全区、哈希重复和九宫格；随机文字、身份、主体数量和禁项由 Agent 结合图片实际内容检查。

## 3. 通用视觉评价维度

每张通过硬门禁的候选至少评估：

| 维度 | 判断问题 |
|---|---|
| 语义 / 玩法识别 | 玩家能否快速理解它是什么，是否表达了正确用途和状态？ |
| 风格一致 | 是否符合 `04_美术风格基准.md` 和资产专项锚点？ |
| 身份 / 主体一致 | 角色、怪物、物件轮廓和关键标识是否稳定？ |
| 构图与安全区 | 主体比例、留白、视线、裁切和显示容器是否成立？ |
| 小尺寸可读 | 缩放到实际 UI 容器后是否仍能辨认？ |
| 工程可用 | 是否便于 contain / cover / 9-slice、去底、压缩和复用？ |

不得只看单张原尺寸图。正式评估至少查看：

- 原图；
- contact sheet；
- 实际 DisplaySpec 尺寸预览；
- 必要的身份 / 风格参考；
- 同组资产的并排一致性。

## 4. 类型专项准入

### 4.1 图标

- 轮廓强，主体单一；
- 64x64 或 80x80 下仍能区分类别；
- 不依靠细小文字和碎装饰表达功能；
- 主体通常占源图 68%-84%，按具体 DisplaySpec 为准；
- 透明边缘干净，不出现明显白边或黑洞。

### 4.2 角色 / 怪物立绘

- 脸、发型、服装主体、体型和关键身份锚点稳定；
- 姿态和表情变化不得破坏角色身份；
- 全身立绘脚底基线、头部安全区和透明边缘符合容器；
- 不得把局部差分意外变成角色重设计；
- 同角色一组差分必须做并排一致性检查。

### 4.3 背景

- 核心信息位于中心安全区；
- `cover` 到 16:9、16:10、21:9 和 4:3 时不丢失关键主体；
- 有足够负空间承接 UI；
- 场景语义与具体系统 / 时段 / 地层一致；
- 不得用高噪声装饰抢走交互焦点。

### 4.4 UI 皮肤

- 不烘焙文案、数字和玩法事实；
- 中心内容区低噪声；
- Border、角装饰和边缘允许 9-slice；
- 普通、选中、危险、禁用状态可通过边框、亮度和色相区分；
- 不制造射线遮挡或把装饰误当交互元素。

### 4.5 叙事 CG / 漫画 Panel

- 角色、场景和风格锚点先锁定；
- 单 Panel 叙事动作清楚；
- 同页阅读顺序、镜头变化和角色位置连续；
- 图片中不生成正式字幕或可读文本；
- 运行时字幕条、gutter、逐格 reveal 和按钮由 UGUI 负责；
- 关键剧情事实不得因“画面更华丽”被改写。

## 5. 评价权重事实

默认 100 分基线：

| 维度 | 默认权重 |
|---|---:|
| 语义 / 玩法识别 | 25 |
| 风格一致 | 20 |
| 身份 / 主体一致 | 20 |
| 构图与安全区 | 15 |
| 小尺寸可读 | 10 |
| 工程可用 | 10 |

按类型调整：

- 图标：提高语义和小尺寸权重；
- 角色：提高身份和风格权重；
- 背景：提高场景语义、构图和安全区权重；
- CG：提高叙事语义、身份连续和阅读构图权重；
- UI 皮肤：提高工程可用和拉伸安全权重。

正式自动选择使用以下稳定阈值：

- 总分 `>= 88`、无硬失败、且领先第二名 `>= 5`：允许自动 selected；
- 总分 `78–87`：不得直接 selected，优先修复最佳候选或追加两张针对性候选；
- 总分 `< 78`：不得 selected，必须重写 Prompt、调整参考或切换后端；
- 前两名差距 `< 5` 且代表不同设计方向：交互模式进入方向决策，全自动模式按事实一致性、身份、语义、工程安全、风格、构图、装饰的顺序保守选择。

循环轮次、provider 切换次数、停问格式和恢复状态属于 Agent 执行策略，维护在 `p3-art-asset-production`，但不得降低本文件阈值和硬门禁。

## 6. selected 准入

候选处理使用不可变数字轮次：`raw -> processed/<number> -> selected -> Approved`。每轮 `decision.json` 必须逐候选记录 `File`、`Input`、`Status`、`SHA256`、`Width`、`Height`、`Format` 和 `Reasons`。最新轮次失败、待决策、未验证或存在多个通过候选时，必须继续修复/选择，不得回退旧轮次。

自动背景处理仅在 `BackgroundPolicy=auto_simple` 时允许，并且只能移除与画布边界连通的简单背景；不得用全局颜色替换删除白发、白布、皮肤、浅色服装等前景。`agent_required` 必须停下，由 Agent 选择当前合适的编辑能力并登记新轮次。

selected 至少要求：

1. 技术硬门禁全部通过；
2. 视觉评价有结构化记录；
3. 候选选择理由基于事实和显示用途；
4. 局部缺陷已明确进入修复或作为非阻塞风险记录；
5. 没有未解决的身份、方向或事实冲突；
6. `SelectedPath` 指向当前唯一采用候选。

如果两张候选分别代表不同方向，不能仅凭总分掩盖方向差异。交互模式按 Skill 停问；全自动模式按已锁事实选择更保守的一张。

## 7. Approved 质量准入

Approved 除 selected 条件外还要求：

- OutputPath 与 Manifest 一致；
- QualityTier 明确；
- SourceSpec / DisplaySpec 未被候选擅自改变；
- 同 VisualID 替换通过严格 `.meta` / GUID guard；
- 目标文件不存在随机文字、水印、签名或明显侵权照搬；
- 当前任务和执行模式具有 Approved 同步权限；
- 同步前后留下候选决策和文件哈希证据。

核心角色母版、首次场景风格锚点、首个 UI 皮肤族、关键 CG 和宣传图在交互模式下默认属于方向决策门禁；用户提前授权全自动时，Agent 可按锁定事实处理。

## 8. 返工分类

| 现象 | 推荐处理 |
|---|---|
| 整体成立，局部手部 / 服装 / 表情 / 物件错误 | 图生图局部修复 |
| 候选方向正确但完成度不足 | 同后端追加少量候选 |
| 所有候选重复同类错误 | 修正 Asset Contract 解释或 provider prompt |
| 身份、构图或尺寸持续不服从 | 切换后端 |
| 事实来源互相冲突 | 停止并请求 Owner 决策 |
| 达到循环上限仍无合格候选 | `blocked:art_generation_quality` |

不得因为预算或轮次耗尽而把硬失败候选推进到 selected / Approved。

## 9. 声明边界

| 证据 | 最多声明 |
|---|---|
| raw 图片 | 候选生成完成 |
| processed + contact sheet | 可进入评估 |
| production decision + selected | 候选选择完成 |
| Approved + 稳定 `.meta` | 素材完成 |
| Unity live import + Registry / UI | 接入完成 |
| runtime Profile | 运行时美术验证完成 |
| 正常玩家入口和操作闭环 | 玩家路径接入完成 |
