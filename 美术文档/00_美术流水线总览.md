# 美术流水线总览

> **定位：** 说明美术侧如何从配置表和预置需求发现资产、生成提示词、批量出图、预处理、筛选并接入 Unity。
> **更新时间：** 2026-05-21

---

## 1. 基本判断

程序侧的 `JSON Config -> VisualID -> VisualAssetRegistry -> Unity Asset` 方案作为运行时接入契约采用。美术侧负责它前面的生产链路：

```text
配置表 / 推导需求 / 预置需求
  -> Manifest
  -> AI 绘图提示词
  -> 批量生成
  -> 预处理
  -> 筛选
  -> Approved 素材
  -> Registry 登记
  -> 游戏内验证
```

玩法 JSON 只保存玩法事实和稳定 `VisualID`。Manifest 保存美术生产过程。`VisualAssetRegistry` 保存 Unity 资源引用。

当前阶段已经从 MVP 验证切换到正式版核心纵切。后续美术侧的判断口径是：用批次控制当前处理哪些界面和资源；进入批次的 UI 架子、资源契约、Approved 素材和运行时验收按正式版标准完成。

## 3. 流程步骤

### Step 1：扫描并更新 Manifest

执行：

```powershell
.\tools\美术工具\Update-ArtManifest.ps1
```

输出：

```text
美术文档/_generated/art_manifest.json
美术文档/_generated/视觉资产Manifest.md
```

Step 1 只做资产需求发现，不写正式提示词、负面提示词和尺寸规格。

来源分三类：

* `config`：配置表直接扫出，例如 `Items/*.json -> item icon`。
* `derived`：由配置表推导，例如 `Dungeon NodePool -> node icon`。
* `preset`：配置表无法扫出的预置美术需求，例如工坊背景、缺失占位图、UI 面板皮肤、程序缺口反馈。

`preset` 来源不再写死在脚本里，而是维护在：

```text
美术文档/art_requirements_seed.json
```

这个文件是美术侧的需求种子清单。它用于承接背景、通用 UI 皮肤、界面专属 UI、程序反馈缺图等“配置表没有但游戏必须有”的资产。扫描后这些资产仍然进入同一个 Manifest，并统一使用 `SourceType=preset`。

### Step 2：逐项补全提示词

读取 `Status=todo` 的 Manifest entry，逐项填写：

* `PromptCN`
* `PromptEN`
* `NegativePromptEN`
* 结构化 `Spec`

完成后将 `Status` 改为 `prompted`。

### Step 3：批量生成图片

后续脚本读取 `Status=prompted` 的 entry，按 `Domain`、优先级或显式列表批量出图。每个资产至少保留 3-4 张候选。

输出建议：

```text
UnityClient/Assets/Art/_IncomingAI/<VisualID>/
  raw/
    YYYYMMDD_001.png
    YYYYMMDD_002.png
  processed/
  selected/
  contact_sheet/
  manifest_snapshot.json
  generation.json
  notes.md
```

`BatchID` 只作为 Manifest 字段和 `generation.json` 记录存在，不作为 `_IncomingAI` 的目录层级。

### Step 4：图片预处理

按 `Spec` 做尺寸、裁切、透明背景、安全边距和缩略图/contact sheet。预处理结果仍留在 `_IncomingAI`，不直接进入 Registry。

### Step 5：筛选与接入

筛选通过后进入 `Approved`，然后登记 `VisualAssetRegistry`，最后游戏内验证。同步脚本按 `_IncomingAI/<VisualID>/selected` 的第一张图同步到 Manifest 的 `OutputPath`；如果 `selected` 为空且脚本启用 fallback，可取 `processed` 第一张作为当前 Approved 素材。非 `-DryRun` 同步完成后，必须刷新：

```text
美术文档/_generated/可接入素材清单.json
美术文档/_generated/可接入素材清单.md
```

这份清单是给程序侧自助接入用的固定交付物，按 `VisualID` 聚合，标出 `program_integrate`、`acceptance_needed`、`art_approve`、`art_select` 和 `generate_needed`。状态流转：

```text
todo -> prompted -> generated -> selected -> approved -> registered -> validated
```

废弃项使用 `rejected`，配置移除项使用 `deprecated`。

## 4. 正式版核心纵切优先级

P0：正式骨架必须稳定

* UI Tokens、组件目录、界面布局和程序交付清单。
* 工坊主界面、战斗 HUD、背包与战利品拾取界面的正式布局骨架。
* 背包 100x100 玩法格、格子状态、物品图标、拾取和拖拽反馈。
* 主面板、信息面板、按钮、列表行、标题分隔、锁定/装备图标等通用 UI 组件。
* 工坊、战斗、深渊地图、安全屋、阶梯房间、层选择、撤离/战败结算的基础背景接入。
* 运行时美术验收工具作为 UI/美术接入门禁。

P1：纵切体验明显提升

* 深渊地图、结算、层选择、出售、义体制造的正式布局骨架。
* 玩家魔偶正式立绘和战斗站位版本。
* 第一层、第二层核心怪物头像和战斗卡片变化。
* 物品稀有度边框、危险/诅咒/腐蚀状态图标。
* 结算页收益、损失、带出物品的细节装饰。

P2/P3：内容扩展和表现增强

* 怪物攻击/受击/死亡动画。
* 拾取、出售、制造、撤离、解锁层级的 UI 动效。
* 更细的层级背景变体。
* 音效和粒子特效。

当前 UI 正式化阶段的补充原则：

* 先定正式 UI 骨架，再跑图和切图。
* 先补可复用 UI 组件资产，而不是为每个界面都画一整张不可拆的大图。
* 首批重点收口工坊主界面、战斗界面、背包与战利品拾取界面。
* 通用面板、按钮、列表行、背包格子、状态条、敌人卡片框等资产进入 `art_requirements_seed.json`，由 Manifest 统一管理。
* UI layout、组件引用和程序交付信息进入 `美术文档/ui_design/`，并通过 `Validate-UIDesign.ps1` 校验。
* 同名 `VisualID` 可以用更高质量素材替换，但不要随意改动核心 `ScreenID`、布局主区和程序绑定契约。
