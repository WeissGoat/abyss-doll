# 美术流水线总览

> **定位：** 美术资产生产的端到端流程入口。当前规划和优先级放在 `10_正式版核心纵切美术路线.md`，UI 覆盖放在 `13_正式纵切UI与素材覆盖矩阵.md`。
> **更新时间：** 2026-05-25

---

## 1. 流水线边界

程序侧的 `JSON Config -> VisualID -> VisualAssetRegistry -> Unity Asset` 方案作为运行时接入契约采用。美术侧负责它前面的生产链路：

```text
配置表 / 推导需求 / 预置需求
  -> Manifest
  -> AI 绘图提示词
  -> 批量生成
  -> 预处理
  -> 筛选
  -> Approved 素材
  -> 可接入清单 / 质量替换清单
  -> Registry 登记
  -> 游戏内验证
```

玩法 JSON 只保存玩法事实和稳定 `VisualID`。Manifest 保存美术生产过程。`VisualAssetRegistry` 保存 Unity 资源引用。

## 3. 总流程

```text
Step 0 UI/配置需求确认
  -> Step 1 扫描并更新 Manifest
  -> Step 2 补全提示词和结构化 Spec
  -> Step 3 批量生成图片
  -> Step 4 预处理和 contact sheet
  -> Step 5 筛选并同步 Approved
  -> Step 6 生成可接入素材清单、质量替换清单和程序交接清单
  -> Step 7 程序登记和运行时验收
```

UI 资产有一个前置规则：新 UI 或结构重做必须先进入 active `ui_design/screen_layouts.json` 并通过 `Validate-UIDesign.ps1`，再进入 Manifest 和跑图。单纯替换同名 VisualID 的图片，可以直接走 Manifest / Approved 流程。

## 4. 流程步骤

### Step 0：确认需求入口

资产需求来自三类入口：

| 来源 | 维护位置 | 进入 Manifest 的方式 |
|---|---|---|
| 配置直接引用 | `配置表(JSON)` 同步到 `UnityClient/Assets/StreamingAssets/Configs` | `SourceType=config` |
| 配置推导 | Manifest 扫描规则 | `SourceType=derived` |
| 预置需求 | `美术文档/art_requirements_seed.json` | `SourceType=preset` |

UI 结构需求先写入：

```text
美术文档/ui_design/screen_layouts.json
美术文档/ui_design/component_catalog.json
```

配置同步命令：

```powershell
.\tools\config\Sync-Configs.ps1 -Clean
```

### Step 1：扫描并更新 Manifest

执行：

```powershell
.\tools\美术工具\Update-ArtManifest.ps1
```

输出：

```text
美术文档/_generated/art_manifest.json
美术文档/_generated/视觉资产Manifest.md
```

Step 1 只做资产需求发现，不写正式提示词、负面提示词和尺寸规格。Manifest 字段规范见 [01_Manifest规范.md](01_Manifest规范.md)。

来源分三类：

* `config`：配置表直接扫出，例如 `Items/*.json -> item icon`。
* `derived`：由配置表推导，例如 `Dungeon NodePool -> node icon`。
* `preset`：配置表无法扫出的预置美术需求，例如工坊背景、缺失占位图、UI 面板皮肤、程序缺口反馈。

`preset` 来源不再写死在脚本里，而是维护在：

```text
美术文档/art_requirements_seed.json
```

这个文件是美术侧的需求种子清单。它用于承接背景、通用 UI 皮肤、界面专属 UI、程序反馈缺图等“配置表没有但游戏必须有”的资产。扫描后这些资产仍然进入同一个 Manifest，并统一使用 `SourceType=preset`。

### Step 2：逐项补全提示词

读取 `Status=todo` 的 Manifest entry，逐项填写：

* `PromptCN`
* `PromptEN`
* `NegativePromptEN`
* 结构化 `Spec`

完成后将 `Status` 改为 `prompted`。

提示词必须使用英文视觉语言，中文只用于审阅；结构化规格必须写入 `Spec` 对象。细节见 [03_AI生成与筛选规范.md](03_AI生成与筛选规范.md)。

### Step 3：批量生成图片

后续脚本读取 `Status=prompted` 的 entry，按 `Domain`、优先级或显式列表批量出图。每个资产至少保留 3-4 张候选。

输出建议：

```text
UnityClient/Assets/Art/_IncomingAI/<VisualID>/
  raw/
    YYYYMMDD_001.png
    YYYYMMDD_002.png
  processed/
  selected/
  contact_sheet/
  manifest_snapshot.json
  generation.json
  notes.md
```

`BatchID` 只作为 Manifest 字段和 `generation.json` 记录存在，不作为 `_IncomingAI` 的目录层级。

非 `-DryRun` 生成完成后，`Run-ArtGeneration.ps1` 必须刷新当前可接入素材清单，并额外写入一份带时间戳和批次标签的清单快照：

```text
美术文档/_generated/可接入素材清单.json
美术文档/_generated/可接入素材清单.md
美术文档/_generated/art_integration_snapshots/YYYYMMDD_HHMMSS_generation_<BatchID>.json
美术文档/_generated/art_integration_snapshots/YYYYMMDD_HHMMSS_generation_<BatchID>.md
```

刚生成但还没预处理的素材在清单中标记为 `art_process`，表示美术侧下一步需要处理 raw 和 contact sheet，不能交给程序接入。

### Step 4：图片预处理

按 `Spec` 做尺寸、裁切、透明背景、安全边距和缩略图/contact sheet。预处理结果仍留在 `_IncomingAI`，不直接进入 Registry。

非 `-DryRun` 预处理完成后，`Optimize-ArtAssets.ps1` 同样刷新 `latest` 清单并写入 `processed` 快照。processed 已有候选但还没筛选时，清单中标记为 `art_select`。

### Step 5：筛选与同步 Approved

筛选通过后进入 `Approved`。同步脚本按 `_IncomingAI/<VisualID>/selected` 的第一张图同步到 Manifest 的 `OutputPath`；如果 `selected` 为空且脚本启用 fallback，可取 `processed` 第一张作为当前 Approved 素材。非 `-DryRun` 同步完成后，必须刷新：

```text
美术文档/_generated/可接入素材清单.json
美术文档/_generated/可接入素材清单.md
```

这份清单是给程序侧自助接入用的固定交付物，按 `VisualID` 聚合，标出 `program_integrate`、`acceptance_needed`、`art_approve`、`art_select`、`art_process` 和 `generate_needed`。同步脚本同时写入 `approved_sync` 快照，形成每轮美术交付记录。

`latest` 永远覆盖，供程序侧读取当前队列；`art_integration_snapshots/` 按时间留档，供美术侧追溯每轮生成、预处理和 Approved 同步后队列变化。状态流转：

```text
todo -> prompted -> generated -> selected -> approved -> registered -> validated
```

废弃项使用 `rejected`，配置移除项使用 `deprecated`。

### Step 6：生成交付清单

美术侧维护三份 latest 清单：

| 清单 | 面向谁 | 回答什么 |
|---|---|---|
| `美术文档/_generated/可接入素材清单.md/json` | 程序 | 现在有哪些 Approved 素材可以登记、接入或验收。 |
| `美术文档/_generated/程序接入交接清单.md/json` | 程序 | 程序下一步要登记哪些 VisualID、补哪些截图点、重跑哪些 ArtAcceptance 截图。 |
| `美术文档/_generated/素材质量替换清单.md/json` | 美术 | 哪些 Approved 素材还有技术风险，哪些只是 local_v0 / placeholder，需要后续同名替换。 |

`generate_needed` 缺图队列还应维护一份可执行计划：

```powershell
.\tools\美术工具\Generate-ArtBatchPlan.ps1 -Snapshot -SnapshotTag nai_missing_assets_20260525_01 -BatchID nai_missing_assets_20260525_01
```

输出：

```text
美术文档/_generated/缺图生成计划.json
美术文档/_generated/缺图生成计划.md
美术文档/_generated/art_generation_plan_snapshots/
```

这份计划只处理 Manifest 已有 Prompt / Spec、但尚未形成 Approved PNG 的新增素材。它和 `VisualV2生成计划` 分工不同：缺图生成计划处理 `generate_needed`；Visual V2 计划处理已入库 local_v0 / placeholder 的同名质量替换。

刷新质量替换清单：

```powershell
.\tools\美术工具\Generate-ArtQualityBacklog.ps1 -Snapshot -SnapshotTag manual_review
```

生成可执行 Visual V2 跑图计划：

```powershell
.\tools\美术工具\Generate-VisualV2Plan.ps1 -Snapshot -SnapshotTag nai_visual_v2_20260525_01 -BatchID nai_visual_v2_20260525_01
```

质量清单状态：

| 状态 | 责任方 | 下一步 |
|---|---|---|
| `technical_fix` | 美术 | 优先修复，例如不透明规格却有透明像素、素材尺寸和 SourceSpec 不一致。 |
| `visual_v2_replace` | 美术 | 当前素材可先给程序用，后续用同名 VisualID 替换正式版。 |
| `spec_review` | 美术 | 判断是图片不合格还是 Manifest Spec 需要修正。 |

Visual V2 替换不得改变 `VisualID`、Approved 目标路径、DisplaySpec、UI 绑定或程序读取契约。

已被程序接入的 Approved 素材做 Visual V2 替换时，必须保留原 `Status`，用候选字段承接新批次：

```powershell
.\tools\美术工具\Run-ArtGeneration.ps1 -Status approved -VisualID <VisualID> -PreserveStatus -BatchID nai_visual_v2_20260525_01 -Variants 4 -DelaySeconds 1
.\tools\美术工具\Optimize-ArtAssets.ps1 -Status approved -CandidateBatchID nai_visual_v2_20260525_01 -Overwrite
.\tools\美术工具\Sync-ApprovedArt.ps1 -Status approved -VisualID <VisualID> -CandidateBatchID nai_visual_v2_20260525_01 -AllowProcessedFallback -Overwrite -QualityTier formal_ai_v2 -ClearCandidate
```

同步完成后刷新 `可接入素材清单` 和 `素材质量替换清单`。如果 `QualityTier=formal_ai_v2/final/production` 且没有技术或尺寸风险，该素材会从 `visual_v2_replace` 队列消失。

当前需要批量替换但生成额度不足时，`VisualV2生成计划.md/json` 是美术侧的继续执行入口。它记录待生成 VisualID、每项命令、BatchID、最近一次 NovelAI 探测结果和前置条件；不得用 mock 输出冒充 `formal_ai_v2`。

当前需要批量补新素材但生成额度不足时，`缺图生成计划.md/json` 是美术侧的继续执行入口。它记录待生成 VisualID、每项命令、BatchID、输出目录和前置条件；不得用 mock 输出冒充 Approved 素材。

程序交接清单由两份 latest 队列合成：

```powershell
.\tools\美术工具\Generate-ArtProgramHandoff.ps1 -Snapshot -SnapshotTag manual_review
```

它读取 `可接入素材清单.json` 和 `ui_design/_generated/FormalV1验收队列.json`，输出：

```text
美术文档/_generated/程序接入交接清单.json
美术文档/_generated/程序接入交接清单.md
美术文档/_generated/art_program_handoff_snapshots/
```

这份清单是程序侧的最新交接入口；原始素材状态仍以 `可接入素材清单` 为准，逐屏验收细节仍以 `FormalV1验收队列` 为准。

### Step 7：交给程序接入

程序侧只需要读取 latest：

```text
美术文档/_generated/程序接入交接清单.md
美术文档/_generated/程序接入交接清单.json
美术文档/_generated/可接入素材清单.md
美术文档/_generated/可接入素材清单.json
```

其中：

| 状态 | 责任方 | 下一步 |
|---|---|---|
| `program_integrate` | 程序 | 登记 `VisualAssetRegistry` 并绑定 UI / 配置。 |
| `acceptance_needed` | 美术 + 程序 | 跑 ArtAcceptance 并确认截图。 |
| `art_approve` | 美术 | 同步到 Approved。 |
| `art_select` | 美术 | 筛选候选。 |
| `art_process` | 美术 | 预处理 raw。 |
| `generate_needed` | 美术 | 生成图片。 |

### Step 8：运行时验收和回填

程序接入后，美术侧用 ArtAcceptance 截图和快照验收：

```text
UnityClient/Logs/ArtAcceptance/latest/
```

验收结论记录到：

```text
美术文档/09_运行时美术验收记录.md
```

缺图、尺寸、透明黑洞、射线遮挡、布局溢出等问题回填到 `art_requirements_seed.json`、`screen_layouts.json` 或 Manifest。

## 5. 交付门禁

一次美术侧实际交付完成前，至少确认：

1. 相关 active UI 规格已通过 `Validate-UIDesign.ps1`。
2. Manifest / Prompt / Spec 已按当前需求刷新。
3. Approved 资源在 `UnityClient/Assets/Art/Approved` 下，必要 `.meta` 已存在。
4. `美术文档/_generated/可接入素材清单.md/json` 已刷新。
5. `美术文档/_generated/art_integration_snapshots/` 已留下本轮快照。
6. 若本轮涉及 Approved 文件修复或质量替换，`美术文档/_generated/素材质量替换清单.md/json` 已刷新，并在 `art_quality_snapshots/` 留快照。
7. 若本轮产生或改变程序接入队列，`美术文档/_generated/程序接入交接清单.md/json` 已刷新，并在 `art_program_handoff_snapshots/` 留快照。
8. `agent_status/art.md` 已记录最近完成、下一步和阻塞。
9. 本轮提交只包含美术相关文件，不混入程序、策划、子模块或无关生成物。
