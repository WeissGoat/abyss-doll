# 美术流水线总览

> **定位：** Project P3 美术资产生产的端到端事实入口。本文件定义阶段、Owner、状态和交付边界；Agent 的具体执行、交互停问、自动选择和重试由 `p3-art-asset-production` Skill 负责。

## 1. 事实来源与执行入口

| 主题 | 当前事实来源 / 执行入口 |
|---|---|
| 端到端阶段与职责 | 本文件 |
| Manifest 字段和 Spec | `01_Manifest规范.md` |
| 目录、尺寸、Approved、Unity 接入 | `02_资源规格与接入规范.md` |
| 质量门禁和筛选准入 | `03_AI生成与筛选规范.md` |
| 项目视觉方向 | `04_美术风格基准.md` 和资产专项文档 |
| 图片后端、Prompt、请求和 raw 证据 | `05_AI图片网关接入方案.md`、`generate-image` |
| 端到端 Agent 编排 | `.codex/skills/p3-art-asset-production/SKILL.md` |
| 运行时美术诊断和验收 | `.codex/skills/p3-art-validation/SKILL.md`、`开发文档/19_UnityMCP验收编排层设计.md` |
| 脚本参数和生成物 | `tools/美术工具/README.md` |

Skill 不是第二套事实来源。规则冲突时，以本文件和对应专项事实文档为准。

## 2. 总流程

```text
详细需求 / active UI / 配置源
  -> 需求审计与准入
  -> VisualID + Manifest + Asset Contract
  -> 图片候选生成或编辑
  -> 预处理与技术门禁
  -> Agent 视觉评估、选择与返工
  -> Approved 门禁与同步
  -> Unity 导入与 Registry
  -> 运行时目标验收
  -> 玩家路径证据（如任务要求）
  -> 清单、事实和状态回写
```

完成状态按三轴分开记录，不能塞进同一个 Manifest `Status`：

```text
生产轴（Manifest Status）
todo -> prompted -> generated -> selected -> approved

接入轴（Import / Registry）
not_imported -> unity_imported -> registered -> runtime_bound

验收轴（运行时证据）
not_validated -> runtime_validated -> player_path_verified -> regression_passed
```

现有脚本仍可能把 `registered / validated` 写入旧 `StatusFlow`；在字段迁移完成前，`RegistryStatus` 与实际 Unity / ArtRun 证据是接入和验收判断依据，不能仅看旧主状态。

`raw`、`selected`、Approved、Registry 和截图互不等价。

## 3. 阶段与 Owner

### 3.1 需求审计与准入

输入来源：

- 配置直接引用：`SourceType=config`；
- 配置推导：`SourceType=derived`；
- 背景、UI 皮肤、CG Panel 等预置需求：`SourceType=preset`；
- 已接入资源的同 VisualID 质量替换。

候选扫描：

```powershell
.\tools\美术工具\Scan-ArtRequirementCandidates.ps1 -Snapshot -SnapshotTag manual_review
```

候选报告只负责发现，不自动写 seed、创建 VisualID 或触发出图。正式生产必须有详细来源，并由 `p3-art-asset-production` 完成准入判断。同 VisualID 替换是 `Operation`，不是新的 `SourceType`；来源仍保持 `config / derived / preset`。

UI 新结构必须先写入 active `ui_design/screen_layouts.json` 并通过 `Validate-UIDesign.ps1`。未确认的 Formal V1/V2 草案不得触发正式素材生产。

### 3.2 Manifest 与 Asset Contract

配置变更后先同步：

```powershell
.\tools\config\Sync-Configs.ps1 -Clean
.\tools\美术工具\Update-ArtManifest.ps1
```

Manifest 管理 VisualID、来源、OutputPath、状态和 Spec。正式生产还必须锁定 Asset Contract：用途、源图规格、显示容器、构图、风格 / 身份锚点、必须保留、允许变化、禁止项和质量层级。

### 3.3 图片候选生成 / 编辑

`p3-art-asset-production` 将纯图片能力委托给 `generate-image`：

- 新图 / 概念图；
- 正式文生图；
- 图生图差分；
- 有 mask 的局部 inpaint；
- provider smoke、fallback 和 raw 生成证据。

图片能力只返回 raw 和 generation evidence，不负责 selected、Approved 或 Unity 接入。

正式工作区：

```text
UnityClient/Assets/Art/_IncomingAI/<VisualID>/
  raw/
  processed/
  selected/
  contact_sheet/
  manifest_snapshot.json
  generation.json
  process_report.json
  production_decision.json
```

程序、Prefab 和 Registry 禁止引用 `_IncomingAI`。

### 3.4 预处理、技术门禁与视觉评估

预处理使用：

```powershell
.\tools\美术工具\Optimize-ArtAssets.ps1
```

脚本负责尺寸、格式、alpha、安全区、小尺寸预览、九宫格和 contact sheet。Agent 按 `03` 的稳定硬门禁、评分维度和自动选择阈值检查语义、风格、身份、构图、小尺寸和工程可用性。

技术硬失败不得进入 selected。局部问题优先修复最佳候选；整体方向错误再重写 Prompt 或切换后端。稳定质量阈值以 `03` 为准；循环上限、交互问题格式和恢复状态由 `p3-art-asset-production` 定义。

### 3.5 Approved 门禁与同步

Approved 同步使用：

```powershell
.\tools\美术工具\Sync-ApprovedArt.ps1
```

准入至少要求：

1. selected 存在且有决策证据；
2. 技术门禁通过；
3. 质量准入通过；
4. VisualID、OutputPath、Spec 和质量层级明确；
5. 同 VisualID 替换保持 `.meta`、GUID、DisplaySpec 和程序绑定；
6. 当前执行模式具有同步权限。

Approved 是正式素材完成，不等于 Unity 已导入或运行时已验收。

### 3.6 Unity 导入、Registry 与运行时验收

Approved 变化后立即：

```text
Unity refresh
-> 等待 AssetDatabase / 编译
-> Console delta
-> 导入类型、路径、meta、GUID
-> 对应 Registry 接入
-> DisplaySpec / 引用校验
```

静态 Sprite 可使用：

```text
Tools/P3 Art/Rebuild Approved Sprite Registry
Tools/P3 Art/Validate Approved Display Specs
```

Prefab、Live2D、DollPuppet、VFX、Audio 使用各自专项接入器，不强塞进 Sprite Registry 重建。

日常验收使用 MCP live-first：

- 单目标：`art_focus`；
- 一组受影响界面：`art_runtime`；
- 持久化表现调整：`art_iteration`；
- T0 语义封板：`t0_art_seal`；
- 大范围资源 / UI 改动或发布：`art_regression`。

Runner 能构造界面不代表正常玩家路径可达。任务要求玩家路径完成时，必须追加真实入口和操作闭环证据。

## 4. 交付清单

每轮生成、预处理或 Approved 同步后，通过脚本刷新：

- `_generated/可接入素材清单.md/json`；
- `_generated/素材质量替换清单.md/json`；
- `_generated/程序接入交接清单.md/json`；
- 对应时间戳 snapshot；
- 必要的 Registry / 运行时状态报告。

主要动作：

| 状态 | Owner | 下一步 |
|---|---|---|
| `generate_needed` | 美术生产 | 锁定合同并生成 raw |
| `art_process` | 美术生产 | 预处理与 contact sheet |
| `art_select` | Agent / 用户决策 | 选择、修复或返工 |
| `art_approve` | 美术生产 | 通过 Approved 门禁并同步 |
| `program_integrate` | Unity 接入 | 导入、登记、绑定 |
| `acceptance_needed` | 美术 + Unity | 运行时检查和状态回填 |

所有 latest 输出必须晚于其输入；过期报告标记 `stale_*` 并通过所属脚本刷新，不手写生成物。

## 5. 完成门禁

一次正式资产生产完成前，至少确认：

1. 需求来源和 Asset Contract 足够详细；
2. Manifest / active UI / 配置没有冲突；
3. raw、预处理、评估和选择证据完整；
4. Approved 与 `.meta` / GUID 门禁通过；
5. Unity 导入和 Registry 状态有 live 证据；
6. 对应 runtime Profile 已完成；
7. 如要求玩家路径，已有正常入口证据；
8. generated latest / snapshots 已刷新；
9. `agent_status/art.md` 及受影响职能状态已回写；
10. 没有把较低状态扩大声明为完整接入或最终验收。
