# Inventory Loot Formal V2 方案

> **状态：** Formal V2 设计草案。本文用于给用户确认 `inventory_loot` 的正式化方向；确认并迁移到 active `screen_layouts.json` 前，不作为程序或素材生成规格。

---

## 1. Formal V1 问题

`inventory_loot` Formal V1 已有左背包、右战利品缓存和确认区，但正式感仍可能不足：

| 问题 | 表现 | V2 处理 |
|---|---|---|
| 拾取像弹窗 | 只是物品列表 + 背包格 | 改为战斗场景上叠加的半透明清点层，强调战后即时带出决策。 |
| 容量压力不够强 | 容量只是文字说明 | 容量、未带出损失和高价值物品成为主信息。 |
| 操作路径不清 | 拾取、丢弃、确认、返回权重接近 | 确认带出是唯一主行动，丢弃是危险行动。 |
| 详情弱 | 物品价值、用途、风险不够集中 | 选中物品只弹出轻量浮层，不做常驻详情面板。 |

---

## 2. 玩家目标

玩家在战利品清点界面的目标是：

1. 判断这轮战斗 / 节点拿到了什么。
2. 在有限背包容量内决定哪些物品带走。
3. 理解未带走物品的损失。
4. 确认清点并回到地图、房间或结算流程。

---

## 3. Formal V2 体验定位

`inventory_loot` 是战斗 / 节点结束后的半透明清点层，不是普通全屏物品页。

```text
战斗场景背景
  -> 半透明清点层
  -> 中央背包
  -> 背包外散落奖励
  -> 确认带出
```

视觉目标：

* 背后仍能看到战斗 / 节点场景，建立“刚打完正在清点”的连续感。
* 中央背包是主视觉和核心玩法对象。
* 奖励以实体图标散落在背包周围，而不是做成列表墙。
* 信息密度低，只保留容量、奖励重点和确认带出。
* 背包仍是玩法对象，`100x100` 格不缩放。

---

## 4. 主结构草案

参考分辨率 `1920x1080`。

```text
┌────────────────────────────────────────────────────────────┐
│ blurred battle / room scene remains visible                 │
│                                                            │
│      scattered rewards around the central backpack          │
│                                                            │
│                   Backpack Grid                             │
│                                                            │
│ reward badges / capacity hint             Confirm Carry     │
└────────────────────────────────────────────────────────────┘
```

| ZoneID | 建议位置 | 作用 |
|---|---|---|
| `scene_backdrop` | `0,0 1920x1080` | 战斗或房间截图 / 背景，轻微压暗或虚化。 |
| `loot_overlay` | `0,0 1920x1080` | 半透明遮罩，保证背包和奖励可读。 |
| `backpack_grid` | `620,210 680x620` | 中央背包，格子 `100x100`。 |
| `scattered_rewards` | `180,220 1560x590` | 背包外散落的奖励图标、钱币、材料、遗物。 |
| `capacity_hint` | `580,840 760x72` | 容量压力和未带出摘要，低文本密度。 |
| `confirm_area` | `1450,820 320x120` | 确认带出主行动。 |

---

## 5. 信息层级

默认阅读顺序：

1. 中央背包和已占用情况。
2. 背包外散落的奖励。
3. 容量压力和未带出摘要。
4. 确认带出主行动。

默认不使用战利品长列表。奖励优先表现为可点击 / 可拖拽的物品图标；选中后只弹出小型浮层，显示名称、价值 / 稀有度 / 任务标记中的 1-2 项。

---

## 6. 行动层级

| 层级 | 行动 | 表达 |
|---|---|---|
| Primary | `ConfirmCarry` | 右下唯一最高权重按钮。 |
| Core Interaction | 拖拽物品、自动放置、旋转、移出 | 中央背包和散落奖励区。 |
| Secondary | 排序、全部尝试放入、查看浮层 | 小按钮 / 图标。 |
| Danger | 丢弃已带物、放弃全部未拾取 | 低权重并二次确认。 |

---

## 7. 按钮合并 / 降级 / 隐藏策略

| 当前入口 | V2 策略 |
|---|---|
| 拾取单个 | 优先从散落奖励拖拽 / 点击放入，不做每行大按钮。 |
| 丢弃 | 降级为危险操作，不和确认带出并列。 |
| 返回 / 关闭 | 合并到确认带出或流程返回，不做同权按钮。 |
| 自动整理 | 次级按钮，放在背包区附近。 |
| 查看详情 | 选中物品自动显示，不单独占主按钮。 |

---

## 8. 场景隐喻

界面像“战斗刚结束后的现场清点”：

* 背后仍是战斗场景或节点场景。
* 半透明清点层覆盖其上。
* 中央背包摊开在画面中心。
* 奖励像刚掉落的实体物一样散落在背包外。
* 底部只保留容量提示和确认带出。

背景可以复用战斗或深渊氛围，但主 UI 应像“战后清点”，不是普通系统背包页。

---

## 9. 程序迁移影响

确认后建议层级：

```text
InventoryLootPanel
  SceneBackdrop
  LootOverlay
  BackpackGrid
  ScatteredRewards
  CapacityHint
  ConfirmArea
```

关键绑定：

| 绑定 | 来源 |
|---|---|
| 散落奖励 | 当前节点 / 战斗掉落缓存。 |
| 背包网格 | 全局背包对象和 `InventoryDisplaySpec`。 |
| 容量压力 | 背包占用和可放置计算。 |
| 未带出损失 | 掉落缓存中未放入物品。 |
| 任务 / 订单提示 | 物品标签或订单需求，只读提示。 |

约束：

* 不创建第二套背包数据。
* 不压缩 `100x100` 格。
* 丢弃和放弃未拾取必须有明确确认或流程后果。

| 候选 VisualID | 说明 |
|---|---|
| `ui_loot_value_badge` | 高价值 / 任务相关标记。 |
| `ui_loot_loss_warning_plate` | 未带出损失提示底板。 |

## 11. UX 验收标准

运行时截图需要满足：

1. 3 秒内能看出当前任务是“决定带走哪些战利品”。
2. 背包容量压力明显可读。
3. 确认带出是唯一最高权重主行动。
4. 战利品以背包外散落奖励表达，不退回长列表。
5. 背包格 `100x100`，拖拽和旋转不被装饰遮挡。
6. 未带出物品或损失有明确提示。
7. 危险操作不和确认按钮等权。

---

## 12. 用户确认问题

建议确认以下 3 点：

1. `inventory_loot` 是否采用“半透明清点层 + 中央背包 + 背包外散落奖励”的结构。
2. 是否同意默认不显示战利品长列表，优先用拖拽 / 点击放入表达。
3. 是否把“确认带出”作为唯一主行动，并把丢弃 / 放弃未拾取作为危险操作。
