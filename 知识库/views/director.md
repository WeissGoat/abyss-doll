# 游戏导演 / 制作人阅读入口

> 本页只负责游戏导演领域，以及跨领域交付（Owner 做法）和剧情相关的阅读顺序与上下文导航；稳定跨职能协议见 `rules/02_智能体任务路由与完成协议.md`，当前进度见 `agent_status/director.md`，专业事实以目标领域文档为准。

## 必读

1. `PROJECT_STATUS.md` 当前阶段、总优先级、跨职能交接和阻塞快照。
2. `agent_status/director.md` 当前判断、最近完成和下一步建议。
3. `版本规划/13_正式版全局体验总线与开放节奏.md`。
4. `版本规划/14_0-12小时候选主循环细案设计.md`。

## 按任务读取

- 目标 T0-T4 模块：读取 `版本规划/0-12小时细案/` 中的目标模块入口。
- 正式版路线或长期节点：读取 `版本规划/09_正式版核心纵切开发路线.md`。
- 需求承接和完成口径：读取 `版本规划/11_纵切批次与需求文档承接矩阵.md`。
- 剧情任务：转入 `知识库/views/narrative.md`。
- Owner 任务：转入 `知识库/views/owner.md`。
- 具体跨职能任务：只读取实际受影响的专业状态页当前快照和事实文档。

## 验收 / 恢复时

- Owner 自验、外部职能验收或全局完成口径变化时读取 `rules/02_智能体任务路由与完成协议.md`。
- 需要恢复历史判断时，回到目标细案、验收记录或 Git 历史，不通读所有状态页日期日志。

## 常用事实来源

| 任务类型 | 优先读取 |

| 0-12 小时 T0-T4 细案 / 实现切片 | `版本规划/14_0-12小时候选主循环细案设计.md` 与 `版本规划/0-12小时细案/` 目标细案 |
| 项目阶段 / 总优先级 | `PROJECT_STATUS.md` |

| 开发宏观路线 / 长期节点 | `版本规划/09_正式版核心纵切开发路线.md` |
| GDD 批次 / 需求文档门禁 | `版本规划/11_纵切批次与需求文档承接矩阵.md` |

## 工作模式

- 游戏导演负责体验总线和开放节奏；T0-01 / T0-01A 等完整模块或玩家结果按 Owner 做法跨领域交付；剧情、策划、程序、美术按专业范围参与。
- Owner 是做法，不是 Role：做事的会话可以切换领域视角，但每个领域的事实和状态写回各自文档。
- 完整责任流水、承接字段、自验 / 外部验收和状态回写规则统一读取 `rules/02_智能体任务路由与完成协议.md`，本页不重复维护。
- 旧 `agent_status/pm.md` 和 `知识库/views/pm.md` 只保留为兼容入口，不再作为 active 路由。
