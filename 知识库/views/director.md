# 游戏导演 / 制作人阅读入口

> 本页只负责游戏导演、细案 Owner 与实现 Owner 的阅读顺序和上下文导航；稳定跨职能协议见 `rules/02_智能体任务路由与完成协议.md`，当前进度见 `agent_status/director.md`，专业事实以目标领域文档为准。

## 开工顺序

1. `PROJECT_STATUS.md`：确认当前阶段、顶层目标、总优先级、跨职能交接和阻塞项。
2. `agent_status/director.md`：确认游戏导演 / 制作人侧当前判断、最近完成和下一步建议。
3. `版本规划/13_正式版全局体验总线与开放节奏.md`：确认玩家体验主线、系统开放节奏、深渊包装和任务 Owner 工作流。
4. `版本规划/14_0-12小时候选主循环细案设计.md`：确认 0-12 小时 T0-T4 细案索引、推进顺序和承接规则；实现 Owner 只承接已完成细案的实现切片。
5. `版本规划/0-12小时细案/` 中的目标细案：确认本切片玩家路径、系统开放、输入输出、UI / 美术表达和验收样例。
6. `版本规划/09_正式版核心纵切开发路线.md`：确认正式版核心纵切的开发优先级、长期节点、职能进度入口和防重复派发规则。
7. `版本规划/11_纵切批次与需求文档承接矩阵.md`：确认 GDD / 功能优先级的批次、完成口径和需求文档承接。
8. 按任务涉及范围读取 `agent_status/design.md`、`agent_status/program.md`、`agent_status/art.md`。
9. 进入具体系统事实来源：GDD、开发文档、美术路线、配置 README 或数值模型。

## 常用事实来源

| 任务类型 | 优先读取 |
|---|---|
| 玩家体验主线 / 系统开放节奏 | `版本规划/13_正式版全局体验总线与开放节奏.md` |
| 0-12 小时 T0-T4 细案 / 实现切片 | `版本规划/14_0-12小时候选主循环细案设计.md` 与 `版本规划/0-12小时细案/` 目标细案 |
| 项目阶段 / 总优先级 | `PROJECT_STATUS.md` |
| 游戏导演状态 / 下一步建议 | `agent_status/director.md` |
| 开发宏观路线 / 长期节点 | `版本规划/09_正式版核心纵切开发路线.md` |
| GDD 批次 / 需求文档门禁 | `版本规划/11_纵切批次与需求文档承接矩阵.md` |
| 系统规则落点 | `设计文档/GDD/GDD_00_系统关联总图.md` 和对应 `GDD_*.md` |
| 程序落地边界 | `开发文档/00_程序开发大纲.md` 和对应系统开发文档 |
| 美术 / UI 交付 | `美术文档/10_正式版核心纵切美术路线.md`、`美术文档/ui_design/README.md` |
| 配置源和数值假设 | `配置表(JSON)/README.md`、`数值模型设计/00_基准价值与空间本位模型.md` |

## 工作模式

- 默认按 `细案 Owner 统一设计 + 实现 Owner 纵切负责 + 职能总监验收` 推进。
- 补齐 T0-T4 时长段设计时选择细案 Owner；承接已完成细案中的单一玩家结果时选择实现 Owner；改变全局体验或优先级时选择游戏导演 / 制作人。
- 完整责任流水、承接字段、自验 / 外部验收和状态回写规则统一读取 `rules/02_智能体任务路由与完成协议.md`，本页不重复维护。
- 旧 `agent_status/pm.md` 和 `知识库/views/pm.md` 只保留为兼容入口，不再作为 active 路由。
