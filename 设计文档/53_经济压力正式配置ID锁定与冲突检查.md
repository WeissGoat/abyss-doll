# 经济压力正式配置ID锁定与冲突检查

> 本文是 `52_经济压力正式配置实现任务拆分.md` 中 `ECON-ID-LOCK` 的证据文档。它只锁定经济压力首批正式配置 ID、检查当前工作区 JSON 冲突和旧样例迁移边界；不直接修改 `配置表(JSON)`，也不代表经济压力配置已经完成。

## 4. 冲突结论

本轮 `ECON-ID-LOCK` 结论：

1. 阻塞性 ID 冲突为 0。
2. 已占用且与正式设计一致的 ID：`economy_town_v1`、`faction_mechanic_workshop`。
3. 旧样例但不阻塞正式 ID 的 ID：`rumor_mechanical_price_up`、`order_mechanic_scrap_drive`。
4. 其余锁定的 RumorID、FactionID、OrderPoolID 在当前 JSON 主 ID 中未发现直接冲突。
5. `OrderID` 已由 `55_经济压力订单ID最终锁定表.md` 锁定为 19 条正式订单模板；旧 `order_pool_*` 只作为草案迁移别名，不进入正式配置源。

## 5. 后续执行规则

1. 后续进入 `ECON-CORE-JSON`、`ECON-FACTIONS-JSON`、`ECON-RUMORS-JSON`、`ECON-ORDERS-JSON` 前，优先使用本文锁定 ID。
2. `economy_town_v1` 和 `faction_mechanic_workshop` 只能补字段、引用、Validator 和验收证据，不能重复创建同 ID。
3. `rumor_mechanical_price_up`、`order_mechanic_scrap_drive` 必须在配置实现证据中二选一：
   - 迁移为正式 ID / 正式订单池条目，并记录迁移关系。
   - 保留为 deprecated / test sample，并避免进入正式内容池。
4. 若实现时必须改名，先更新 `48` / `49` / `50` / `52` / `55` / 本文 / 对应配置 README / `agent_status/design.md`，如影响长期节点门禁再通知 PM 更新 `09`，然后再改 JSON。
5. README 中出现的正式 ID 只是字段口径或目标清单；冲突判断以当前 JSON 主 ID 为准。
