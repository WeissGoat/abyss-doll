# 战斗回合与怪物意图规则卡

> **定位：** 本规则卡把 `GDD_01` 中的“背包即战场”落实为正式战斗规则：玩家每回合如何行动、怪物如何预告意图、多个怪物按什么顺序行动、对包干涉如何与伤害结算互相裁决。它是策划设计事实来源，不替代程序侧 `MonsterActionAI` 架构文档。

---

## 1. 战斗体验目标

战斗的核心体验是“看懂下一回合会发生什么，然后用有限 AP 和背包空间做痛苦决策”。

| 目标 | 说明 |
|---|---|
| 可预判 | 怪物行动前必须展示意图，玩家能知道主要威胁。 |
| 可计算 | 伤害、护盾、AP、SAN、格子干涉都要有可读数值。 |
| 可取舍 | 玩家经常在输出、防御、整理、消耗品和保留战利品之间取舍。 |
| 可破坏 | 背包构筑会被怪物、战利品、消耗品和诅咒物不断打乱。 |
| 可复盘 | 战败后玩家应知道是贪、没防、没清干涉，还是目标选择错误。 |

---

## 2. 战斗回合状态机

一场战斗由多个回合构成，每回合固定经历以下状态。

```text
CombatStart
  -> RoundStart
  -> PlayerTurnStart
  -> PlayerActionLoop
  -> PlayerTurnEnd
  -> MonsterIntentResolve
  -> MonsterActionQueue
  -> RoundEnd
  -> Victory / Defeat / NextRound
```

| 状态 | 设计规则 |
|---|---|
| `CombatStart` | 生成敌方阵列、读取初始怪物意图、刷新玩家 AP、初始化护盾为 0。 |
| `RoundStart` | 处理回合开始效果，例如毒、流血、侵蚀、遗物触发。 |
| `PlayerTurnStart` | 恢复本回合 AP，刷新可用物品次数，展示怪物意图。 |
| `PlayerActionLoop` | 玩家消耗 AP 使用物品、使用消耗品、进行允许的背包整理。 |
| `PlayerTurnEnd` | 玩家主动结束或 AP 耗尽；结算回合末效果，默认清空临时护盾。 |
| `MonsterIntentResolve` | 锁定本回合怪物将执行的意图，死亡或眩晕怪物跳过。 |
| `MonsterActionQueue` | 按行动顺序依次执行怪物行动。 |
| `RoundEnd` | 处理回合末状态，生成下一回合意图。 |

胜负检查在每个关键状态后都可以触发，但表现上应收束到清晰节点：

*   所有怪物 HP <= 0：进入胜利搜刮。
*   魔偶 HP <= 0：进入战败结算。
*   魔偶 SAN <= 0：进入理智崩溃 / 特殊战败链路。

## 3. 玩家回合规则

### 3.1 AP

| 规则 | 说明 |
|---|---|
| AP 是局内战斗资源 | 不影响局外 Day / Week / Month。 |
| 每回合恢复固定 AP | 基础建议 3 点，可被底盘、义体、状态修改。 |
| AP 不跨回合保留 | 默认回合结束清零；特殊物品可允许保留，但必须明确写词条。 |
| AP 只由战斗动作消耗 | 使用武器、防具、技能型物品等消耗 AP。 |

### 3.2 玩家可执行动作

| 动作 | 默认成本 | 规则 |
|---|---:|---|
| 使用武器 | 1+ AP | 造成伤害或触发特殊效果。 |
| 使用防具 / 护盾物 | 1+ AP | 获得本回合护盾或减伤。 |
| 使用消耗品 | 0 或 1 AP | 由物品定义决定；使用后释放格子。 |
| 旋转 / 放置战利品 | 0 AP | 只在搜刮、整理窗口或允许调阵的战斗窗口进行。 |
| 丢弃物品 | 0 AP | 进入 `Lost`；若丢弃污染物可触发 SAN 代价。 |
| 结束回合 | 0 AP | 锁定当前状态，进入怪物行动。 |

### 3.3 护盾

护盾是“看懂意图后的主动防御”，不是自动血条。

| 规则 | 说明 |
|---|---|
| 默认本回合有效 | 玩家回合结束后保留到怪物行动，用于抵挡本轮攻击。 |
| 默认回合结束清空 | 怪物行动结束后未消耗护盾清零。 |
| 只抵挡物理伤害 | 魔法、侵蚀、真实伤害默认绕过护盾。 |
| 可以被怪物削弱 | 部分怪物意图可以破盾、穿盾或先污染后攻击。 |

设计意图：玩家看到“下回合 18 点攻击”时，需要决定是花 AP 叠盾，还是用 AP 抢杀，还是牺牲物品腾格用消耗品保命。

## 4. 怪物意图系统

### 4.1 意图定义

怪物意图是怪物下次行动的公开预告。正式版不允许怪物大多数行动完全黑箱。

| 字段 | 设计含义 |
|---|---|
| `IntentType` | 攻击、防御、对包干涉、SAN 压力、蓄力、召唤、未知等。 |
| `PowerPreview` | 可公开的数值，如伤害、护盾、封锁格数、塞入物大小。 |
| `TargetPreview` | 目标预告，如玩家、随机武器、空格、整行、未知目标。 |
| `Timing` | 本回合执行、下回合释放、持续效果或反应式。 |
| `Reliability` | 完全准确、范围预告、隐藏部分信息。 |
| `CounterHint` | UI 可用图标或文本暗示，例如“可被护盾抵挡”“优先清小怪”。 |

### 4.2 意图类型

| 意图 | UI 表达 | 玩家应读出的信息 |
|---|---|---|
| `Attack` 攻击 | 剑 / 爪 + 伤害数字 | 需要护盾、减伤或抢杀。 |
| `Defend` 防御 | 盾 + 护甲数字 | 怪物下回合更难杀，可能要先处理别的威胁。 |
| `Buff` 增益 | 上升箭头 / 光环 | 怪物会增强自己或同伴。 |
| `Debuff` 弱化 | 破碎 / 虚弱图标 | 会降低玩家输出、防御或 AP。 |
| `GridLock` 封格 | 格子锁 + 数量 | 会让背包格不可用。 |
| `AddJunk` 塞包 | 方块 / 毒液 + 形状 | 会往背包塞入垃圾或污染物。 |
| `MoveItem` 移位 | 交换 / 推移箭头 | 会打乱相邻或管线构筑。 |
| `SanPressure` SAN 压力 | 眼 / 噪声 + 数值 | 护盾无效，需要快速击杀或用 SAN 道具。 |
| `Charge` 蓄力 | 倒计时 + 下回合大招 | 当前回合是窗口期。 |
| `Unknown` 未知 | 问号 | 只用于少数怪物或特殊状态，不能滥用。 |

### 4.3 预告准确度

| 准确度 | 使用场景 |
|---|---|
| 完全准确 | 普通攻击、防御、基础塞包。 |
| 范围预告 | 随机目标、随机格、随机物品。 |
| 类型准确数值隐藏 | 精英 / Boss 的特殊技能。 |
| 未知 | 教学之后少量使用，用于制造恐惧，不作为常态。 |

原则：未知意图是调味，不是常规难度来源。玩家输掉应主要因为决策失误，而不是因为信息被系统藏起来。

## 5. 目标选择规则

### 5.1 玩家攻击目标

玩家使用武器时，目标选择分三类：

| 类型 | 规则 | 适用物品 |
|---|---|---|
| 手动指定 | 玩家点击怪物目标。 | 高价值单体武器、技能。 |
| 默认前排 | 不指定时攻击最前 / 最左存活怪物。 | 新手武器、快攻武器。 |
| 自动规则 | 按物品词条选择，例如最低 HP、最高威胁、随机。 | 特殊构筑物品。 |

设计边界：

*   基础武器应减少繁琐选目标；点击武器即可执行默认目标。
*   高影响技能应允许手动选择，避免玩家觉得系统替他做错决策。
*   目标选择失败时不消耗 AP。

### 5.2 怪物目标

当前核心纵切只有一个魔偶主体，但设计仍按可扩展目标写：

| 目标 | 使用场景 |
|---|---|
| 玩家主体 | 普通攻击、SAN 压力。 |
| 随机武器 | 腐蚀、缴械、降伤。 |
| 最高战斗价值物品 | 精英怪针对核心构筑。 |
| 空格 | 塞入垃圾、污染物。 |
| 边缘格 | 封锁、结晶蔓延。 |
| 指定标签物品 | 恐惧、诅咒、反制流派。 |

对包干涉必须遵守 `02_物品背包旋转与生命周期规则卡` 的容器和冲突优先级。

## 6. 多怪行动顺序

多怪战斗的行动顺序必须稳定可读。

### 6.1 默认顺序

```text
前排左 -> 前排右 -> 后排左 -> 后排右
```

若没有前后排表现，则按 UI 从左到右执行。

### 6.2 顺序修正

| 修正 | 规则 |
|---|---|
| 眩晕 / 冻结 | 跳过本次行动。 |
| 蓄力释放 | 按原行动顺序释放，不插队。 |
| 召唤物 | 当回合召唤的怪物默认下回合才行动。 |
| Boss 阶段切换 | 阶段切换可以中断队列，但必须有明显演出。 |
| 反击 | 反击是即时反应，不改变下一次常规行动顺序。 |

### 6.3 同回合冲突

多个怪物对背包同一区域产生干涉时：

1. 先执行顺序靠前怪物的行动。
2. 后续怪物重新检查目标是否合法。
3. 若目标失效，尝试备用目标。
4. 没有备用目标则行动失败或转为轻惩罚。
5. 不允许同一格在同一怪物行动队列中被永久封锁多次。

## 7. 对包干涉与意图结合

对包干涉是本战斗系统的特色，但必须可读。

| 干涉 | 意图预告 | 执行规则 |
|---|---|---|
| 封格 | 显示封锁数量或区域倾向 | 先锁空格；若命中物品，按规则弹出或禁用。 |
| 塞包 | 显示将塞入物的尺寸 / 类型 | 只放入合法空位；无空位时按怪物配置转惩罚或失败。 |
| 推移 | 显示方向或“扰乱” | 推移后若非法，尝试较短距离；仍非法则失败。 |
| 交换 | 显示交换图标 | 只交换可移动物；绑定物可被移动但不可销毁。 |
| 污染 | 显示污染类型 | 添加动态标签、降低耐久或引发 SAN 压力。 |
| 弹出 | 显示冲击 / 打飞 | 进入临时区或 Inbox，不直接等同丢失。 |

对包干涉的强度梯度：

| 层级 | 可用强度 |
|---|---|
| 浅层杂兵 | 1x1 塞包、低频封边缘格、低额 SAN 压力。 |
| 二层压力怪 | 可绕开的精英封格、腐蚀武器、塞污染物。 |
| 中层精英 | 多步骤干涉，例如先污染再攻击。 |
| Boss | 阶段性改变背包规则，例如周期封锁区域、点名核心物品。 |

## 8. 胜负结算

### 8.1 胜利

胜利后立即进入搜刮窗口：

1. 怪物死亡演出。
2. 清除本战斗临时效果。
3. 生成掉落到 `Inbox`。
4. 玩家可旋转、放置、丢弃和整理。
5. 离开窗口后，未带走的 `Inbox` 物品进入 `Lost`。

### 8.2 HP 战败

HP 战败表示机体被击倒：

| 结算项 | 规则 |
|---|---|
| 本轮新获未绑定物品 | 丢失。 |
| 绑定装备 / 情感锚点 | 保留，但可损坏、污染或触发情感后果。 |
| 安全收纳物 | 保留。 |
| 魔偶状态 | HP 清零，磨损上升，可能进入局外修复需求。 |

### 8.3 SAN 崩溃

SAN 崩溃不是单纯死亡，而是心理 / 深渊侵蚀事件：

| 结算项 | 规则 |
|---|---|
| 当场战斗 | 立即失控或强制失败，具体由当前系统阶段决定。 |
| 背包 | 按失败规则处理，但可额外污染情感锚点或深渊物。 |
| 局外 | 触发崩溃处置，占用后续当天核心抉择或进入强制疗愈。 |

### 8.4 双归零

如果同一次结算中 HP 与 SAN 都归零：

1. 先判定是否有好感 / 奇迹锁血。
2. 奇迹未触发时，按更严重的 `HP战败 + SAN崩溃` 复合后果处理。
3. 表现上优先播放更强的剧情反馈，不拆成两个弹窗。

## 9. 最小怪物行为集合

当前正式纵切至少需要以下 5 类行为，才能证明战斗系统方向成立。

| 行为 | 设计用途 | 示例 |
|---|---|---|
| 普通攻击 | 教玩家读伤害和护盾。 | 深渊狂犬：下回合攻击 8。 |
| 防御 / 蓄力 | 迫使玩家决定先杀谁。 | 石甲守卫：本回合加盾，下回合重击。 |
| 塞包 | 直接制造空间压力。 | 酸液软体：塞入 1x1 毒液。 |
| 封格 | 打断固定构筑。 | 结晶蜈蚣：封锁边缘 1 格。 |
| SAN 压力 | 绕过护盾制造短线倒计时。 | 窃魂虫：本回合 SAN -6。 |

第一批怪物组合建议：

| 怪物 | 行为组合 | 体验职责 |
|---|---|---|
| 深渊狂犬 | 普通攻击 | 教学读意图。 |
| 酸液软体 | 攻击 + 塞包 / 腐蚀 | 教空间压力。 |
| 结晶守卫 | 防御 + 封格 | 教优先级和构筑破坏。 |
| 窃魂虫群 | 低 HP + SAN 压力 | 教快速清小怪。 |
| 畸变融合体 | 多阶段 + 塞包 + 攻击 | 第一批精英压力验证。 |

## 10. 验收样例

### 10.1 基础回合

| 输入 | 期望 |
|---|---|
| 玩家 AP=3，怪物意图为攻击 12。玩家用 2 AP 获得 14 护盾并结束回合。 | 怪物攻击后护盾剩 2，HP 不变；回合末护盾清零。 |
| 玩家 AP=1，用 1 AP 击杀唯一怪物。 | 立即进入胜利搜刮，不再执行怪物行动。 |
| 玩家 AP=0，仍有怪物存活。 | 只能结束回合或使用 0 AP 允许动作。 |

### 10.2 意图可读

| 输入 | 期望 |
|---|---|
| 怪物下回合将塞入 1x1 毒液。 | UI 显示塞包意图和 1x1 / 毒液提示。 |
| 怪物下回合蓄力。 | UI 显示蓄力，并提示释放回合或倒计时。 |
| 怪物为未知意图。 | UI 显示问号，但该怪物类型必须在图鉴或表现上暗示危险类别。 |

### 10.3 多怪顺序

| 输入 | 期望 |
|---|---|
| 左怪攻击，右怪塞包。玩家击杀左怪后结束回合。 | 左怪不行动，右怪仍按顺序塞包。 |
| 两个怪物都想封锁同一格。 | 第一个成功后，第二个重新选目标或失败，不叠加封锁。 |
| 召唤物在怪物行动中生成。 | 默认下回合才显示意图并行动。 |

### 10.4 胜负结算

| 输入 | 期望 |
|---|---|
| 怪物攻击导致 HP=0。 | 进入 HP 战败结算，按物品生命周期规则处理背包。 |
| 怪物 SAN 压力导致 SAN=0。 | 进入 SAN 崩溃结算，触发局外危机处理。 |
| 玩家在搜刮窗口关闭前未拾取掉落。 | 掉落进入 `Lost`。 |

## 11. 文档同步要求

后续修改战斗系统时，同步检查：

*   `GDD_01` 是否仍准确描述战斗体验和怪物行为。
*   `02_物品背包旋转与生命周期规则卡` 是否仍覆盖对包干涉。
*   `00_策划文档开发交付审计` 是否需要调整交付状态。
*   如果新增怪物意图类型，必须补本规则卡的意图表、目标规则和验收样例。
*   如果新增战败 / 崩溃分支，必须补胜负结算规则。
