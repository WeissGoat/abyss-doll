# 剧本调度与事件队列规则卡

> **定位：** 本规则卡把 `GDD_05` 的世界观、事件钩子和对话节点落实为正式调度规格。它不负责写具体剧情文本量，而是定义事件如何被触发、如何排队、如何播放、如何跳过、如何重入，以及剧情如何安全地改写系统状态。

---

## 1. 设计目标

| 目标 | 说明 |
|---|---|
| 剧情嵌入系统 | 剧情由时间、地点、状态、物品、交互和结算触发，而不是独立章节播放器。 |
| 不打断核心节奏 | 强制事件、气泡轻语、图鉴文本、里程碑对话要按优先级进入合适表现层。 |
| 可复盘可存档 | 每个事件的触发、入队、播放、跳过、完成和奖励都必须记录。 |
| 跳过不丢指令 | 玩家跳过文本不应导致奖励、惩罚、旗标或状态变化漏执行。 |
| 支撑正式扩展 | 后续增加大量剧情内容时，只扩数据，不改调度规则。 |

---

## 2. 剧本事件定义

### 2.1 ScenarioEvent 字段

| 字段 | 类型 | 规则 |
|---|---|---|
| `EventID` | string | 全局唯一。 |
| `EventType` | enum | `MainStory`、`BondMilestone`、`DebtPressure`、`AbyssLore`、`ItemLore`、`AmbientBubble`、`Ending`、`SystemWarning`。 |
| `Trigger` | object | 触发表达，见第 3 节。 |
| `Priority` | int | 队列优先级，数值越高越先处理。 |
| `Presentation` | enum | `AVG`、`Bubble`、`LorePanel`、`RoomMemory`、`AutoLog`、`SystemModal`。 |
| `DialogueTreeID` | string | 对话树引用，可为空。 |
| `CommandList` | array | 完成或节点执行时触发的系统指令。 |
| `RepeatPolicy` | enum | `Once`、`Repeatable`、`Cooldown`、`UntilFlagSet`、`PerRunOnce`。 |
| `CooldownDays` | int | 冷却天数，`RepeatPolicy=Cooldown` 时必填。 |
| `BlockPolicy` | enum | `Blocking`、`NonBlocking`、`QueueUntilIdle`、`LogOnly`。 |
| `AvailabilityCondition` | string | 额外可见条件，用统一条件表达式。 |
| `SetFlagsOnStart` | string[] | 事件开始时写入旗标。 |
| `SetFlagsOnComplete` | string[] | 事件完成时写入旗标。 |
| `FailureFallback` | string | 指令失败或目标不存在时的 fallback。 |
| `Tags` | string[] | 用于筛选、统计和调试。 |

### 2.2 EventInstance 字段

| 字段 | 类型 | 规则 |
|---|---|---|
| `InstanceID` | string | 单局唯一。 |
| `EventID` | string | 指向事件定义。 |
| `Status` | enum | `Triggered`、`Queued`、`Playing`、`Completed`、`Skipped`、`Suppressed`、`Expired`。 |
| `TriggeredAtDay` | int | 触发日。 |
| `TriggeredBy` | string | 触发来源，例如 `OnDayEnd`、`OnGiftAccepted`。 |
| `PrioritySnapshot` | int | 入队时优先级快照。 |
| `CurrentNodeID` | string | 当前对话节点。 |
| `ExecutedCommandIDs` | string[] | 已执行指令，防止重复执行。 |
| `QueueReason` | string | 入队原因。 |
| `CompletionReason` | enum | `Finished`、`Skipped`、`AutoCompleted`、`SuppressedByFlag`。 |

## 3. 触发器表达式

### 3.1 触发来源

| Hook | 触发时机 |
|---|---|
| `OnDayStart` | 新一天开始。 |
| `OnDayEnd` | 日结或夜晚结算。 |
| `OnWeekStart` / `OnMonthEnd` | 周 / 月节奏。 |
| `OnNodeEnter` | 进入深渊节点。 |
| `OnLayerReached` | 到达指定层。 |
| `OnItemObtained` / `OnItemInspected` | 获得或查看物品。 |
| `OnGiftAccepted` | 赠礼被接受。 |
| `OnSANChanged` / `OnBondLevelChanged` | 人偶核心状态变化。 |
| `OnMiracleTriggered` | 奇迹触发。 |
| `OnOrderCompleted` | 势力订单完成。 |
| `OnBusinessSettled` | 营业结算完成。 |
| `OnRoomEnter` | 进入人偶房间。 |

### 3.2 条件表达式

触发表达式由 `All`、`Any`、`Not` 组合。

```text
Trigger {
  Hook: OnDayEnd
  All:
    - Day >= 15
    - PlayerGold < 500
    - Flag:rental_warning_seen == false
}
```

允许引用：

| 引用 | 示例 |
|---|---|
| 时间 | `Day >= 15`、`Week == 3`、`Month == 2`。 |
| 人偶状态 | `SAN < 10`、`BondLevel >= 5`、`EmotionState == Broken`。 |
| 探索 | `ReachedLayer >= 3`、`CurrentNodeTag:SafeZone`。 |
| 物品 | `HasItemTag:OldWorldRelic`、`GiftItemID == relic_music_box`。 |
| 经济 | `PlayerGold < RentDue`、`DebtLevel >= 2`。 |
| 旗标 | `Flag:seen_truth == false`。 |
| 交互 | `LastInteractionType == Gift`、`InteractionTag:Night`。 |

表达式必须可被日志打印为可读文本，方便排查事件为什么触发或未触发。

## 4. 事件队列

### 4.1 队列规则

同一帧或同一阶段可能触发多个事件。事件不直接播放，而是先进入队列。

排序顺序：

1. `Priority` 高者优先。
2. `Blocking` 高于 `NonBlocking`。
3. 生存危机高于情感事件。
4. 主线高于支线。
5. 同优先级按触发时间排序。

推荐优先级：

| 优先级 | 类型 |
|---:|---|
| 1000 | 存档安全、死亡线、强制结局。 |
| 900 | 月租、债务、强制经济危机。 |
| 800 | 主线真相、Boss、深渊底层。 |
| 700 | SAN 崩溃、奇迹、重大创伤。 |
| 600 | Bond 里程碑、关键交互事件。 |
| 400 | 势力订单和社会反馈。 |
| 200 | 环境气泡、物品图鉴、房间记忆。 |

### 4.2 播放状态机

```text
Triggered
  -> Queued
  -> Playing
  -> Completed / Skipped / Suppressed / Expired
```

规则：

*   `Blocking` 事件播放期间暂停普通输入。
*   `NonBlocking` 事件可用气泡、日志或轻提示展示。
*   `QueueUntilIdle` 事件等待玩家回到工坊、房间或结算界面再播放。
*   已完成 `Once` 事件不能再次入队。
*   被更高优先级压后的事件必须保留，不应丢失，除非触发条件已过期且定义允许 `Expired`。

## 5. 对话树结构

### 5.1 DialogueNode 字段

| 字段 | 类型 | 规则 |
|---|---|---|
| `NodeID` | string | 对话树内唯一。 |
| `SpeakerID` | string | 说话者。 |
| `TextID` | string | 文本 ID，不直接把长文本写死在逻辑里。 |
| `EmotionHint` | string | 表情 / 语气提示。 |
| `NextNodeID` | string | 默认下一节点。 |
| `Choices` | array | 选项列表，可为空。 |
| `CommandsOnEnter` | array | 进入节点时执行。 |
| `CommandsOnExit` | array | 离开节点时执行。 |
| `SkipPolicy` | enum | `CanSkip`、`NoSkipUntilCommand`、`SummaryOnSkip`。 |
| `ReplayPolicy` | enum | `NoReplay`、`LogReplay`、`GalleryReplay`。 |

### 5.2 Choice 字段

| 字段 | 规则 |
|---|---|
| `ChoiceID` | 节点内唯一。 |
| `TextID` | 选项文本。 |
| `Condition` | 是否可见 / 可选。 |
| `NextNodeID` | 选中后进入节点。 |
| `CommandList` | 选项结果指令。 |
| `ToneTag` | `Gentle`、`Practical`、`Joke`、`Cruel` 等。 |

选项默认不制造指数级剧情分支。它们主要影响本次收益、语气、旗标、特质风险和后续权重。

## 6. 系统指令

系统指令用于让剧情安全地改写游戏状态。

| 指令 | 示例 | 规则 |
|---|---|---|
| `SetFlag` | `SetFlag seen_truth` | 写入全局或人偶旗标。 |
| `AddBond` | `AddBond 20` | 交给人偶核心状态系统裁决。 |
| `RestoreSAN` | `RestoreSAN 15` | 不能绕过 `SanityBroken` 处置规则。 |
| `GrantItem` | `GrantItem relic_music_box` | 物品必须存在。 |
| `RemoveItem` | `RemoveItem item_instance_id` | 失败时按 fallback。 |
| `AddGold` / `RemoveGold` | `RemoveGold 500` | 不足时需要定义失败分支。 |
| `UnlockRecipe` | `UnlockRecipe craft_x` | 引用必须存在。 |
| `AddTraitCandidate` | `AddTraitCandidate FearOfDeath` | 进入特质候选池。 |
| `AddRoomMemory` | `AddRoomMemory old_weapon_wall` | 接房间系统。 |
| `QueueEvent` | `QueueEvent event_debt_warning_2` | 不能形成无限递归。 |

所有指令必须幂等或记录 `ExecutedCommandIDs`，避免跳过、重进或读档导致重复发奖。

---

## 7. 跳过、重入与存档

### 7.1 跳过规则

*   玩家可以跳过可跳剧情文本。
*   `NoSkipUntilCommand` 节点必须先执行关键指令后才能跳。
*   跳过时所有已到达节点的 `CommandsOnEnter` 必须执行。
*   若跳过整段剧情，必须执行 `SummaryOnSkip` 中定义的最终指令和旗标。
*   跳过不应导致剧情奖励、惩罚、旗标或解锁丢失。

### 7.2 重入规则

| 情况 | 规则 |
|---|---|
| 播放中保存退出 | 保存 `EventInstance`、`CurrentNodeID` 和已执行指令。 |
| 读档后继续 | 从当前节点恢复，不重复执行已执行指令。 |
| 事件条件不再满足 | 若已开始播放，默认继续；未开始则可 `Suppressed`。 |
| 同事件再次触发 | `RepeatPolicy` 裁决，不能重复入队唯一事件。 |
| 指令执行失败 | 使用 `FailureFallback`，并写错误日志。 |

## 8. 表现层映射

| Presentation | 使用场景 | 规则 |
|---|---|---|
| `AVG` | 主线、里程碑、结局、重大危机 | 可阻塞输入。 |
| `Bubble` | 环境轻语、低 SAN 自语、安全区通讯 | 不阻塞核心操作。 |
| `LorePanel` | 物品考古、图鉴、世界观补充 | 玩家主动查看。 |
| `RoomMemory` | 房间纪念物、长期回忆 | 写入房间状态。 |
| `AutoLog` | 已发生但不需要打断的事件 | 只进日志。 |
| `SystemModal` | 账单、债务、强制选择 | 阻塞并要求确认。 |

表现层不能私自改状态，只能播放由事件系统裁决后的内容。

---

## 9. Validator 规则

| 校验项 | 规则 |
|---|---|
| 事件 ID | `EventID` 全局唯一。 |
| 触发器 | 必须有合法 Hook 和可解析条件。 |
| 队列 | `Priority` 必填；阻塞事件必须声明表现类型。 |
| 对话树 | 起始节点存在；所有 `NextNodeID` 和选项目标可达。 |
| 指令引用 | 物品、配方、特质、房间记忆、事件引用必须存在或有 fallback。 |
| 唯一事件 | `Once` 事件必须设置完成旗标。 |
| 跳过 | 带关键指令的节点必须声明跳过策略。 |
| 重入 | Blocking 事件必须能保存当前节点和已执行指令。 |
| 无限循环 | `QueueEvent` 和 `NextNodeID` 不能形成无出口循环。 |

## 10. 验收样例

### 样例 A：债务事件优先播放

输入：

```text
同一 OnDayEnd 触发：
event_debt_warning Priority=900 Blocking
event_bond_lv3 Priority=600 Blocking
```

期望：

*   债务事件先播放。
*   Bond 事件保留在队列。
*   债务事件完成后，Bond 事件在下一个 Idle 场景播放。

### 样例 B：跳过剧情不丢奖励

输入：

```text
对话节点含 CommandsOnExit: AddBond 20, SetFlag bond_lv3_seen
玩家按跳过
```

期望：

*   Bond 增加指令执行一次。
*   `bond_lv3_seen` 写入。
*   重进或读档不重复执行。

### 样例 C：物品图鉴不阻塞

输入：

```text
OnItemInspected item_tag=OldWorldRelic
Presentation=LorePanel
BlockPolicy=NonBlocking
```

期望：

*   玩家主动查看时显示 Lore。
*   不暂停当前整理或背包操作。
*   写入已读图鉴旗标。

### 样例 D：事件读档重入

输入：

```text
Blocking AVG 播放到 node_05 后保存退出
node_01 到 node_04 的指令已执行
```

期望：

*   读档后从 `node_05` 继续。
*   `node_01` 到 `node_04` 的指令不重复执行。
*   完成后事件进入 `Completed`。
