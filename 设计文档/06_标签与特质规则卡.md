# 标签与特质规则卡

> **定位：** 本规则卡把 `GDD_09` 的标签 / 特质系统落实为正式设计语法。标签用于表达“实体是什么”，特质用于表达“人偶经历了什么并如何主动改写规则”。它是跨系统条件判断、经济传闻、物品构筑、人偶状态、义体加成、订单需求和剧情触发的统一语言。

---

## 1. 设计目标

| 目标 | 说明 |
|---|---|
| 统一条件语言 | 物品、怪物、节点、订单、传闻、义体、天赋和剧情都能用标签表达筛选条件。 |
| 避免硬编码例外 | 系统不应为每个物品 / 怪物写特殊逻辑，而是通过标签、触发器和效果组合表达。 |
| 让经历变成规则 | 特质不是装饰文本，而是由玩家行为塑造并持续影响战斗、经营、互动和探索。 |
| 冲突可裁决 | 标签叠加、特质互斥、触发顺序和覆盖优先级必须稳定可复盘。 |
| 叙事可追踪 | 玩家能知道一个特质为什么获得、为什么生效、如何消除或转化。 |

---

## 2. 标签规则

### 2.1 标签定义

标签是实体的被动身份标记。它只表达“这是什么 / 属于什么条件”，不主动执行效果。

| 标签类型 | 附着对象 | 示例 | 用途 |
|---|---|---|---|
| `ItemTag` | 物品定义 / 物品实例 | `Melee`、`OriginStone`、`Contraband` | 构筑、出售、订单、制造、传闻。 |
| `MonsterTag` | 怪物定义 / 怪物实例 | `Insect`、`Elite`、`Abyssal` | 特攻、恐惧、掉落、事件。 |
| `NodeTag` | 深渊节点 | `SafeZone`、`HighRisk`、`OreRich` | 地图生成、事件、传闻目标。 |
| `FactionTag` | 势力 / 订单 | `Workshop`、`MageTower`、`BlackMarket` | 订单、商店、声望奖励。 |
| `StateTag` | 运行时状态 | `Corrupted`、`Bound`、`Damaged` | 临时裁决、UI 提示、失败结算。 |

### 2.2 命名规则

*   标签 ID 使用稳定英文 `PascalCase` 或项目已有格式，不在 ID 中写中文。
*   UI 显示名可以本地化，不能反向作为逻辑 ID。
*   同义标签必须合并，例如 `Melee` 和 `CloseCombat` 不能同时表达“近战”。
*   标签分组必须明确，不允许一个标签同时承担物品类型、风险和剧情状态三种含义。

### 2.3 静态标签与动态标签

| 类型 | 来源 | 生命周期 |
|---|---|---|
| 静态标签 | 配置定义，例如物品、怪物、节点原生标签。 | 随定义长期存在，不能被运行时普通事件移除。 |
| 动态标签 | 战斗、污染、剧情、订单绑定、怪物意图等运行时附加。 | 存在于实例上，必须有来源、持续时间和移除条件。 |

动态标签字段：

| 字段 | 规则 |
|---|---|
| `TagID` | 标签 ID。 |
| `SourceID` | 来源，例如特质、事件、怪物技能、物品效果。 |
| `DurationType` | `CombatOnly`、`RunOnly`、`UntilCleaned`、`PermanentInstance`。 |
| `StackPolicy` | `Replace`、`StackCount`、`RefreshDuration`、`IgnoreDuplicate`。 |
| `VisibleToPlayer` | 是否展示给玩家。影响核心决策的标签必须可见。 |

---

## 3. 标签查询与匹配

### 3.1 查询表达

系统筛选实体时使用标签条件：

| 表达 | 含义 |
|---|---|
| `AllOf` | 必须同时拥有全部标签。 |
| `AnyOf` | 拥有任意一个标签即可。 |
| `NoneOf` | 不能拥有指定标签。 |
| `CountAtLeast` | 指定范围内至少 N 个实体拥有标签。 |
| `SourceLayer` | 限定标签来源层或掉落池。 |

示例：

```text
订单需求：AllOf(ItemTag.Material, ItemTag.OriginStone), NoneOf(StateTag.Damaged)
传闻目标：AnyOf(ItemTag.Weapon, ItemTag.Melee), SourceLayer >= 2
橱窗套装：CountAtLeast(ItemTag.OriginStone, 2), Adjacent = true
```

### 3.2 匹配边界

*   标签匹配只看当前有效标签：静态标签 + 未过期动态标签。
*   `NoneOf` 优先用于排除违禁、损坏、剧情绑定等不可交付对象。
*   标签条件失败时，应能给出玩家可读原因，例如“该物品已损坏，不满足订单”。
*   经济传闻、订单、掉落目标必须确保游戏内存在可获得来源。

## 4. 标签共鸣

标签共鸣是背包构筑的“集合奖励”，不等于所有标签都自动有共鸣。

共鸣定义字段：

| 字段 | 规则 |
|---|---|
| `ResonanceID` | 共鸣 ID。 |
| `TagID` | 目标标签。 |
| `Threshold` | 触发数量。 |
| `Scope` | 统计范围，如背包、橱窗、当前战斗。 |
| `EffectRefs` | 触发效果。 |
| `ChassisModifier` | 底盘对共鸣强度的修正。 |
| `ConflictGroup` | 可选，避免同类共鸣无限叠加。 |

裁决：

*   同一物品最多为同一 `ResonanceID` 计数一次。
*   动态标签是否参与共鸣由标签定义决定；污染类动态标签默认不参与正向共鸣。
*   共鸣触发 / 失效时必须刷新 UI 提示。

## 5. 特质规则

特质是挂在人偶实例上的主动规则包。它可以监听事件、检查条件、执行效果，并留下叙事记录。

### 5.1 特质定义字段

| 字段 | 规则 |
|---|---|
| `TraitID` | 全局唯一。 |
| `Name` | UI 显示名。 |
| `Polarity` | `Positive`、`Negative`、`Neutral`、`DoubleEdged`。 |
| `Category` | 战斗、经营、情感、探索、维护、剧情等。 |
| `Trigger` | 监听的事件时机。 |
| `Conditions` | 生效条件。 |
| `Effects` | 生效效果。 |
| `AcquireRule` | 获取条件。 |
| `RemoveRule` | 消除条件。 |
| `TransformRule` | 转化条件。 |
| `ConflictGroup` | 互斥组。 |
| `Priority` | 同时触发时的优先级。 |
| `StackPolicy` | 同类叠加规则。 |
| `Visibility` | 是否公开、隐藏、剧情揭示。 |
| `NarrativeText` | 获得 / 生效 / 消除时的叙事说明。 |

---

## 6. 事件监听白名单

特质只能监听白名单事件，避免系统变成不可维护的任意脚本。

| 事件 | 用途 |
|---|---|
| `OnItemPlaced` | 物品放入背包、橱窗或订单槽时。 |
| `OnItemRemoved` | 物品移出、丢弃、出售或消耗时。 |
| `OnCombatStart` | 战斗开始。 |
| `OnRoundStart` / `OnRoundEnd` | 战斗回合边界。 |
| `OnMonsterSeen` | 遭遇特定怪物标签。 |
| `OnMonsterKilled` | 击杀统计和克服恐惧。 |
| `OnDamageTaken` | 创伤、恐惧和防死判断。 |
| `OnDungeonNodeEnter` | 深渊节点进入。 |
| `OnExtract` / `OnDefeat` | 撤离和战败。 |
| `OnBusinessSettlement` | 每日营业结算。 |
| `OnMaintenanceApplied` | 维护 / 净化 / 疗愈。 |
| `OnGiftGiven` / `OnInteraction` | 赠礼和互动。 |
| `OnDayEnd` / `OnWeekEnd` / `OnMonthEnd` | 日周月结算。 |

新增监听事件必须先补本文档，说明触发边界和可用字段。

---

## 7. 特质获取

### 7.1 经验计数器

特质获取依赖人偶经历记录，而不是临时猜测。

常用计数器：

| 计数器 | 示例 |
|---|---|
| `MonsterKillCountByTag` | 击杀虫类 50 次。 |
| `DefeatCountBySource` | 被某类 Boss 击败 2 次。 |
| `LowSanDays` | SAN 低于 20 的累计天数。 |
| `SuccessfulExtractCount` | 成功撤离次数。 |
| `ItemCarryHistory` | 同一物品连续带入深渊次数。 |
| `BusinessOutcomeHistory` | 连续经营失败 / 高价成交次数。 |
| `MaintenanceQualityHistory` | 廉价维护或高级护理频率。 |
| `BondMilestoneReached` | 好感等级突破记录。 |

### 7.2 获取裁决

```text
事件发生
  -> 更新经历计数器
  -> 评估候选特质 AcquireRule
  -> 检查互斥组和优先级
  -> 应用新特质 / 覆盖 / 延后
  -> 记录获得原因
```

规则：

*   特质不可由玩家直接手选。
*   多个候选同时满足时，先按 `Priority`，再按事件顺序。
*   隐藏特质可以延迟揭示，但其效果若影响核心决策，必须在首次生效时给提示。
*   获得特质必须记录 `AcquiredDay`、来源事件和关键参数。

---

## 8. 互斥、优先级与叠加

### 8.1 互斥组

互斥组用于表达“同一心理伤痕的不同阶段”。

| 规则 | 说明 |
|---|---|
| 同组唯一 | 同一 `ConflictGroup` 默认只保留一个特质。 |
| 转化优先 | 若新特质是旧特质的 `TransformRule` 结果，替换旧特质并保留历史记录。 |
| 强度覆盖 | 同组非转化特质按 `Priority` 覆盖，低优先级被拒绝或延后。 |
| 叙事保留 | 被覆盖的特质不再生效，但历史仍用于结局和对话。 |

### 8.2 优先级

同一事件上多个特质同时生效时：

```text
强制剧情 / 生死裁决
  > 负面限制
  > 防死 / 保护
  > 资源修正
  > UI / 表现
```

若两个特质都修改同一数值：

```text
AddFlat -> AddPercent -> Multiply -> Clamp
```

这与效果配置的通用结算顺序保持一致，避免列表顺序影响结果。

### 8.3 叠加

| `StackPolicy` | 规则 |
|---|---|
| `Unique` | 不叠加，重复获得只刷新叙事记录。 |
| `Replace` | 新特质替换旧特质。 |
| `StackCount` | 叠层，必须有上限。 |
| `RefreshDuration` | 刷新持续时间。 |
| `Transform` | 达成条件后转化为另一特质。 |

特质叠层必须谨慎使用。永久特质默认 `Unique`，不做无限叠加。

---

## 9. 消除与转化

特质消除是设计内容，不是普通清除按钮。

| 方式 | 适用 |
|---|---|
| 陪伴 / 心理疏导 | 轻中度负面特质。 |
| 专业治疗 / 维护 | 操作障碍、恐惧、侵蚀相关特质。 |
| 面对恐惧 | 将负面特质转化为正面特质。 |
| 剧情遗物 | 极端隐藏特质和结局级特质。 |
| 不可消除 | 正面里程碑、重大剧情烙印。 |

消除必须记录历史，不能把过去发生过的事从叙事和结局判断中抹掉。

---

## 10. 持久化规则

| 数据 | 保存位置 |
|---|---|
| 当前有效特质 | 人偶实例。 |
| 已消除 / 已转化特质历史 | 人偶经历日志。 |
| 标签定义 | 配置。 |
| 动态标签 | 对应实例，如物品实例、怪物实例、人偶状态。 |
| 经历计数器 | 人偶经历日志或统计状态。 |
| 周目继承 | 默认只继承制造师知识 / 天赋树，不继承人偶特质。 |

边界：

*   新周目新魔偶默认不继承特质。
*   如果剧情允许同一人偶延续，必须保留特质历史。
*   动态标签随实例生命周期走；物品出售、消耗、丢失后标签记录不再参与玩法裁决。

---

## 11. 玩家反馈

特质生效不能是黑箱。

| 场景 | 反馈要求 |
|---|---|
| 获得特质 | 显示特质名、极性、获得原因和一句叙事说明。 |
| 特质生效 | 在结算日志、战斗提示或 UI 气泡中说明来源。 |
| 特质阻止操作 | 明确提示“因某特质而不能做什么”。 |
| 特质转化 | 展示旧特质到新特质的变化和触发条件。 |
| 隐藏特质 | 可先隐藏名称，但首次影响核心规则时必须提示异常来源。 |

## 12. 验收样例

### 12.1 标签匹配

| 输入 | 期望 |
|---|---|
| 订单要求 `AllOf(Material, OriginStone)`，物品只有 `OriginStone`。 | 不满足，提示缺少 `Material`。 |
| 传闻目标 `Weapon`，物品动态获得 `Damaged`。 | 仍可涨价，但若传闻 `NoneOf(Damaged)` 则排除。 |
| 背包中 3 件 `Mechanical` 物品。 | 若存在机械共鸣定义，触发共鸣效果并显示。 |

### 12.2 特质获取

| 输入 | 期望 |
|---|---|
| 被虫型怪物击败，且 `DefeatCountBySource.InsectBoss >= 1`。 | 获得或推进 `FearOfInsects`，记录来源。 |
| 带着 `FearOfInsects` 击杀虫型 Boss。 | 触发转化为 `InsectSlayer`，旧特质进入历史。 |
| 同时满足 `FearOfInsects` 和 `InsectSlayer`。 | 按转化优先，最终只保留 `InsectSlayer`。 |

### 12.3 特质生效

| 输入 | 期望 |
|---|---|
| 拥有 `MeleeFear`，尝试放入 `Melee` 武器。 | 触发 SAN 代价或拒绝放入，并给出特质提示。 |
| 拥有 `StageFright`，营业遇到粗犷顾客。 | 自动降价或降低成交效率，日报说明来源。 |
| 拥有 `Hoarder`，尝试出售绑定旧物。 | 阻止出售，提示需心理疏导或解除绑定。 |

### 12.4 叠加与优先级

| 输入 | 期望 |
|---|---|
| 两个特质都修改 SAN 消耗，一个加固定值，一个乘倍率。 | 按 `AddFlat -> AddPercent -> Multiply -> Clamp` 结算。 |
| 同组低优先级特质尝试覆盖高优先级特质。 | 覆盖失败或延后，不改变当前有效特质。 |
| 特质叠层超过上限。 | 限制在最大层数，日志记录“已达上限”。 |

## 13. 文档同步要求

后续修改标签 / 特质规则时，同步检查：

*   `GDD_09` 是否仍准确描述标签与特质的概念边界。
*   `GDD_03` 的 Bond / SAN / 人偶状态是否与特质获取、消除和隐藏特质一致。
*   `GDD_06` 和 `02_物品背包旋转与生命周期规则卡` 是否覆盖动态标签和物品实例标签。
*   `GDD_04` / `04_小镇经济结算与压力链规则卡` 的传闻、橱窗和顾客筛选是否使用同一标签语言。
*   `GDD_08` / `05_局外成长与维护规则卡` 的义体、天赋、维护是否使用同一触发器和效果规则。
*   `GDD_10` 的订单条件是否使用统一标签查询表达。
*   `Dolls`、`Items`、`Effects` 配置 README 是否需要补字段或枚举说明。
*   `设计文档/00_策划文档开发交付审计.md` 是否需要调整 `GDD_09` 交付状态。
