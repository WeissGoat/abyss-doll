# 设计文档

游戏是什么、规则怎么定：长期有效的活文档。改了游戏就改这里，不另写一份新的。放文档的总规则见根目录 `AGENTS.md`「文档放哪」。

| 目录 | 内容 |
|---|---|
| `GDD/` | 系统设计。`GDD_00` 是系统关联总图，`GDD_13` 是游戏节奏和深渊结构（几层、每层多长、全程多久），其余一份一个系统。 |
| `数值/` | 数值模型：价值单位、伤害和生存、经济、产出。阶段 2 里程碑 1 会按回合 / AP 重写，并和检查脚本对齐，以脚本为准。 |
| `规则卡/` | 开发时遇到边界情况的裁决：状态机、算法、字段口径。 |
| `剧情/` | 剧情大纲、序章演出和对话节奏。 |
| `content_packs/` | 各层和各系统的内容包（物品、怪物、订单、事件），填内容时参考。 |
| `参考/` | 外部作品的方法参考，不是本项目的规则。 |
| `_archive/` | 不再维护的旧文档：`delivery/`、`config/` 是 2026-06 多角色工作流的交付和配置链路文档，`content_backlog/` 是旧草案。 |

## 怎么用

- 开发一个系统：先看 `GDD/` 里对应的 GDD 和 `规则卡/`，再看 `PROJECT_STATUS.md` 里这个系统所在的里程碑。
- GDD 是参考，不是合同（制作人 2026-11-01）。有更好的设计就重新设计，并直接改 GDD 本身；改动大时，在 GDD 对应章节写一行说明以哪份文档为准。不留两套口径。
- 某一批实现的取舍和验收写在 `docs/specs/`。做完后，系统的现行规则要回写到这里。
