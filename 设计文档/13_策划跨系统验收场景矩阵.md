# 策划跨系统验收场景矩阵

> **定位：** 本文档从玩家体验路径出发，定义正式版核心纵切必须成立的跨系统验收场景。它不替代单系统 GDD 或规则卡，而是检查这些规则组合起来以后，是否真的形成“搜打撤 + 背包构筑 + 局外成长 + 经济压力 + 人偶反馈”的整体体验。

---

## 1. 验收原则

| 原则 | 说明 |
|---|---|
| 以玩家路径验收 | 不只验单个功能按钮，而是验玩家从决策、执行、反馈到下一次决策的完整路径。 |
| 以设计结果验收 | 程序实现方式不在本文范围；本文只定义玩家应感知到什么、系统状态应如何变化。 |
| 以可复现状态验收 | 每个场景都要能给出前置状态、玩家行为、期望结果和失败信号。 |
| 以正式版口径验收 | 验收场景可以控制内容量，但不降低规则完整度。 |

---

## 2. 跨系统验收总表

| ID | 场景 | 覆盖 GDD | 验收目标 | 优先级 |
|---|---|---|---|---|
| `A-01` | 备战到下潜 | `GDD_01`、`GDD_02`、`GDD_06`、`GDD_07`、`GDD_08` | 玩家能在零时耗备战期整理背包、确认状态、选择层级并进入深渊。 | P0 |
| `A-02` | 战斗取舍与战利品拾取 | `GDD_01`、`GDD_06`、`GDD_09` | 玩家能读懂怪物意图，用 AP / 背包空间决策，并在胜利后处理战利品。 | P0 |
| `A-03` | 成功撤离与库存回流 | `GDD_02`、`GDD_04`、`GDD_06`、`GDD_07` | 深渊收益能带回地面，进入经营 / 出售 / 制造循环。 | P0 |
| `A-04` | 战败损失与人偶创伤 | `GDD_01`、`GDD_02`、`GDD_03`、`GDD_06`、`GDD_08`、`GDD_11` | 战败不是简单重开，而是物品、状态、维修和房间记忆共同反馈。 | P0 |
| `A-05` | 地图路线选择 | `GDD_02`、`GDD_07`、`GDD_10` | 玩家能在节点网络中选择风险、绕开精英、追逐委托目标或安全撤离。 | P0 |
| `A-06` | 每日营业与经济压力 | `GDD_04`、`GDD_06`、`GDD_07` | 出售、未售、传闻、维护费、月租和欠债压力形成可读账单。 | P1 |
| `A-07` | 成长制造与再挑战 | `GDD_01`、`GDD_02`、`GDD_06`、`GDD_08` | 玩家能用素材 / 金币升级底盘或义体，并在下一次下潜感到构筑变化。 | P1 |
| `A-08` | SAN 低谷与情感修复 | `GDD_03`、`GDD_07`、`GDD_08`、`GDD_12` | 人偶低 SAN 时限制下潜或改变反馈，玩家能通过保养 / 休息 / 交互修复。 | P1 |
| `A-09` | 标签特质影响决策 | `GDD_01`、`GDD_03`、`GDD_06`、`GDD_09`、`GDD_12` | 标签和特质不是装饰，能改变物品可用性、反馈和后续决策。 | P1 |
| `A-10` | 势力订单驱动路线 | `GDD_02`、`GDD_06`、`GDD_10` | 订单目标能改变玩家下潜路线、背包取舍和奖励规划。 | P2 |
| `A-11` | 剧情事件不破坏循环 | `GDD_03`、`GDD_05`、`GDD_07`、`GDD_12` | 剧情事件能触发、排队、播放、跳过和重入，同时不丢状态指令。 | P2 |
| `A-12` | 房间视觉日记 | `GDD_03`、`GDD_05`、`GDD_06`、`GDD_11`、`GDD_12` | 房间能记录经历、展示物品、反映人偶状态，并保持零压力空间定位。 | P2 |

## 3. P0 场景规格

### A-01：备战到下潜

| 项 | 内容 |
|---|---|
| 前置状态 | Day=N，玩家在备战期；至少有 1 件武器、1 件消耗品、1 个可进入层级。 |
| 玩家行为 | 整理背包、旋转物品、检查人偶状态、选择已解锁层级并确认下潜。 |
| 期望结果 | 备战操作不推进 Day；背包布局稳定进入深渊；下潜确认后进入地图或起始节点。 |
| 失败信号 | 整理背包推进日期；局外出现 AP 消耗；层级入口不说明锁定原因；背包状态进入深渊后丢失。 |

### A-02：战斗取舍与战利品拾取

| 项 | 内容 |
|---|---|
| 前置状态 | 玩家进入普通战斗；怪物有明确意图；背包有可用武器和有限空格。 |
| 玩家行为 | 根据怪物意图选择攻击、叠盾、使用消耗品、保留或丢弃物品。 |
| 期望结果 | AP 消耗、护盾、伤害、怪物行动和背包干涉均可读；胜利后进入拾取窗口。 |
| 失败信号 | 怪物行动无预告；玩家不知道为何受伤；掉落物去向不明；非法放置没有明确反馈。 |

### A-03：成功撤离与库存回流

| 项 | 内容 |
|---|---|
| 前置状态 | 玩家获得至少 1 件战利品，抵达撤离或层间安全区。 |
| 玩家行为 | 选择撤离，把背包中可带回物品转入地面库存。 |
| 期望结果 | 战利品、素材、记忆碎片和人偶状态按规则结算；进入营业或局外整备链路。 |
| 失败信号 | 安全区清空探索账本；撤离后物品丢失且无原因；记忆碎片和状态变化无日志。 |

### A-04：战败损失与人偶创伤

| 项 | 内容 |
|---|---|
| 前置状态 | 玩家在深渊战斗中 HP 归零或 SAN 崩溃。 |
| 玩家行为 | 接受战败结算，返回地面。 |
| 期望结果 | 新获战利品按规则丢失，绑定 / 安全盒 / 情感锚点按规则保留；人偶进入创伤状态；维修 / 保养压力出现；房间可记录首次战败纪念物。 |
| 失败信号 | 战败无代价；全部物品无差别丢失；人偶状态不变；玩家无法复盘战败原因。 |

### A-05：地图路线选择

| 项 | 内容 |
|---|---|
| 前置状态 | 深渊层级生成节点网络，至少有 2 条可达路线。 |
| 玩家行为 | 查看节点类型、连线、迷雾和路线风险，选择下一节点。 |
| 期望结果 | 所有节点可达且 Boss 可通；精英可绕开；路线主题和风险清楚；同 seed 结果可复现。 |
| 失败信号 | 单线推进；死路无提示；Boss 不可达；同 seed 反复变化；节点奖励或事件池引用缺失。 |

## 4. P1 场景规格

### A-06：每日营业与经济压力

| 项 | 内容 |
|---|---|
| 前置状态 | 玩家带回若干战利品，地面库存有可出售物，月租倒计时存在。 |
| 玩家行为 | 把物品放入出售通道，查看日终账单。 |
| 期望结果 | 售价来源、传闻倍率、支出、维护费、未售品和月租压力可读；Day 正常推进。 |
| 失败信号 | 金币变化无来源；传闻影响不可见；欠债裁决突然发生；未售 / 违禁物没有处理规则。 |

### A-07：成长制造与再挑战

| 项 | 内容 |
|---|---|
| 前置状态 | 玩家有金币、素材或图纸，且存在可升级底盘 / 义体 / 维护项。 |
| 玩家行为 | 制造或装备成长项，再次进入深渊。 |
| 期望结果 | 消耗清晰，成长结果改变背包、战斗行为、下潜许可或维护状态；下一次下潜能感知变化。 |
| 失败信号 | 成长只改数字无感知；材料缺口不明；装备后规则不生效；下潜锁定原因不清楚。 |

### A-08：SAN 低谷与情感修复

| 项 | 内容 |
|---|---|
| 前置状态 | 人偶 SAN 低、磨损高或侵蚀接近危险线。 |
| 玩家行为 | 尝试下潜、保养、休息、夜间对话或安抚。 |
| 期望结果 | 低 SAN 影响反馈和下潜风险；修复手段有材料 / 金币 / 核心抉择成本；交互反馈符合情绪状态。 |
| 失败信号 | 低 SAN 无影响；保养无成本；休息和轻互动边界不清；情感反馈与状态不一致。 |

### A-09：标签特质影响决策

| 项 | 内容 |
|---|---|
| 前置状态 | 人偶或物品拥有至少 1 个动态标签或特质。 |
| 玩家行为 | 放入相关物品、触发战斗、赠礼或尝试消除特质。 |
| 期望结果 | 标签查询、触发器、互斥优先级和反馈可复盘；玩家知道为什么规则被改写。 |
| 失败信号 | 特质无提示改写规则；互斥特质同时生效；标签来源不可查；消除途径不明确。 |

## 5. P2 场景规格

### A-10：势力订单驱动路线

| 项 | 内容 |
|---|---|
| 前置状态 | 玩家接取一个有限期订单，目标物可能占据背包空间。 |
| 玩家行为 | 为订单选择下潜层级、携带目标物或交付战利品。 |
| 期望结果 | 订单期限、目标、奖励、失败 / 放弃代价和声望变化可读；订单改变路线和背包取舍。 |
| 失败信号 | 订单只是额外金币按钮；目标物不占用空间；失败无代价；奖励引用不清。 |

### A-11：剧情事件不破坏循环

| 项 | 内容 |
|---|---|
| 前置状态 | 多个剧情 / 债务 / Bond / 房间记忆事件同时满足触发条件。 |
| 玩家行为 | 进入结算、工坊、房间或夜间窗口，播放或跳过事件。 |
| 期望结果 | 高优先级事件先播放；低优先级事件保留；跳过不丢系统指令；读档能重入。 |
| 失败信号 | 剧情打断核心循环后丢状态；跳过丢奖励；事件重复触发；强制事件无优先级。 |

### A-12：房间视觉日记

| 项 | 内容 |
|---|---|
| 前置状态 | 玩家经历战败、赠礼、Boss 战利品或 Bond 里程碑。 |
| 玩家行为 | 进入人偶房间，查看纪念物、展柜、窗外状态和人偶待机。 |
| 期望结果 | 房间不推进 Day；纪念物和展示品按规则出现；人偶待机受状态影响；日记本能回顾关键经历。 |
| 失败信号 | 房间成为数值强制投资；展示品阻止出售；状态变化不反映到房间；进入房间推进日期。 |

## 6. 验收通过标准

一个跨系统场景通过，需要同时满足：

1.  玩家行为有明确入口。
2.  系统状态变化能被记录或复盘。
3.  玩家能理解收益、代价和失败原因。
4.  涉及的 GDD / 规则卡没有口径冲突。
5.  涉及的配置字段和表现信息有明确承接文档。
6.  场景失败时不会产生悬空物品、悬空事件、不可解释状态或不可恢复流程。

如果某场景只能靠人工解释才能理解，视为设计未完全交付；应回到对应 GDD、规则卡、配置 README 或 UI / 美术规格补清楚。
