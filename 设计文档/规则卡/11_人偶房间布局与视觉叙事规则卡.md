# 人偶房间布局与视觉叙事规则卡

> **定位：** 本规则卡把 `GDD_11` 的人偶房间从氛围设想落实为正式开发规格。房间仍然是零压力、低数值影响的情感空间，但它需要有明确的数据结构、布局槽位、展示品规则、视觉状态来源、事件触发和验收样例，确保后续进入房间纵切时可以直接交付开发。

---

## 1. 设计目标

| 目标 | 说明 |
|---|---|
| 零压力休憩 | 进入、停留、观察、整理房间不推进 Day，不产生倒计时和失败惩罚。 |
| 视觉日记 | 房间记录深渊、赠礼、战败、好感、经济危机和结局前夜等经历。 |
| 情感优先 | 家具和陈列主要改变表现、台词、待机动作和少量休息效率，不成为强制战力系统。 |
| 数据驱动 | 房间布局、家具槽、纪念物、展示品、窗外状态和待机动作都必须可配置或可由存档状态还原。 |
| 可验收 | 同一存档状态进入房间，应稳定显示相同房间状态；触发、隐藏、替换和资源缺失都有明确 fallback。 |

---

## 2. 房间数据结构

### 2.1 RoomDefinition 字段

`RoomDefinition` 是房间静态配置，定义房间有哪些区域、槽位和默认资源。

| 字段 | 类型 | 规则 |
|---|---|---|
| `RoomID` | string | 房间配置 ID，默认 `attic_room_default`。 |
| `DollID` | string | 适用人偶，可为空；为空表示通用房间。 |
| `BackgroundVisualID` | string | 房间基础背景资源。 |
| `CameraProfileID` | string | 固定视角、全景窗外视角和特写镜头配置。 |
| `ZoneList` | array | 房间区域定义，见 2.2。 |
| `SlotList` | array | 家具、纪念物、展示品和待机点槽位。 |
| `DefaultFurnitureIDs` | string[] | 初始家具，例如破旧行军床、简易书架。 |
| `WindowProfileID` | string | 窗外时间 / 天气 / 世界状态规则。 |
| `FallbackVisualSetID` | string | 缺资源时使用的通用占位表现。 |

### 2.2 RoomZone 字段

| 字段 | 类型 | 规则 |
|---|---|---|
| `ZoneID` | enum | `Window`、`Living`、`Display`、`Desk`、`Wall`、`Floor`。 |
| `DisplayName` | string | UI 内部调试名，不要求玩家可见。 |
| `NormalizedRect` | rect | 在 2D 房间画面中的归一化区域。 |
| `LayerOrder` | int | 渲染层级，避免家具、人偶和窗外互相遮挡。 |
| `InteractionPolicy` | enum | `None`、`ClickObserve`、`OpenDisplayCase`、`DollIdlePoint`。 |

推荐初始空间比例：

| 区域 | 占比 | 用途 |
|---|---:|---|
| `Window` | 25% | 窗户、窗台、天气、外部世界状态。 |
| `Living` | 40% | 床铺、地毯、主待机点。 |
| `Display` | 25% | 展柜、纪念品、礼物剪影。 |
| `Desk` | 10% | 书桌、台灯、日记本和独处待机。 |

## 3. 槽位规则

### 3.1 RoomSlot 字段

| 字段 | 类型 | 规则 |
|---|---|---|
| `SlotID` | string | 房间内唯一，例如 `bed_main`、`display_01`。 |
| `ZoneID` | enum | 所属区域。 |
| `SlotType` | enum | `Furniture`、`Memento`、`DisplayItem`、`DollIdlePoint`、`WindowOverlay`。 |
| `Anchor` | vector2 | 归一化坐标。 |
| `SizeClass` | enum | `Small`、`Medium`、`Large`、`Wide`。 |
| `AllowedCategory` | string[] | 可放置家具 / 展示品类别。 |
| `ExclusiveGroup` | string | 同组互斥，例如床位只能有一张床。 |
| `DefaultContentID` | string | 初始内容，可为空。 |
| `SortOrder` | int | 同区域渲染顺序。 |

### 3.2 槽位约束

*   家具槽位固定，不允许玩家自由摆到任意像素坐标。
*   同一 `ExclusiveGroup` 同时只能激活一个内容；购买新床会替换旧床。
*   纪念物槽位由事件触发，不允许玩家出售、拆除或覆盖。
*   展柜槽位允许玩家调整展示内容，但展示的是物品剪影 / 复制表现，不转移物品所有权。
*   缺少资源时显示统一剪影或隐藏该槽，并记录 `MissingVisual` 日志。

## 4. 家具定义

### 4.1 FurnitureDefinition 字段

| 字段 | 类型 | 规则 |
|---|---|---|
| `FurnitureID` | string | 全局唯一。 |
| `FurnitureCategory` | enum | `Bed`、`Shelf`、`Lamp`、`Rug`、`WindowDecor`、`Music`、`DeskTool`。 |
| `AllowedSlotTypes` | string[] | 可放入的槽位类型 / 类别。 |
| `VisualID` | string | 运行时资源引用。 |
| `AcquireSource` | enum | `Initial`、`Shop`、`Craft`、`FactionReward`、`StoryReward`。 |
| `AcquireCost` | object | 金币、材料、声望或剧情旗标。 |
| `ReplacePolicy` | enum | `ReplaceOldNoRefund`、`KeepInCollection`、`UniqueOnly`。 |
| `RoomEffectPolicyID` | string | 微量效果或表现效果策略，可为空。 |
| `UnlockIdleActionIDs` | string[] | 解锁的人偶待机动作。 |
| `ComfortScore` | int | 房间舒适度，只用于表现和极微量效率。 |
| `Tags` | string[] | `Warm`、`Cold`、`Abyss`、`Mechanical` 等。 |

### 4.2 家具效果边界

家具可以影响：

*   停工休息 / 深度疗愈的 SAN 恢复量。
*   房间内待机动作、表情、BGM、灯光和窗边演出。
*   特定对话或房间观察反馈的触发权重。
*   极微量陪伴效率，例如 `Bond` 获取 `+5%` 以内。

家具不允许影响：

*   直接攻击力、防御力、战斗 AP、掉落倍率。
*   深渊地图节点生成概率。
*   主线结局硬条件，除非通过剧情旗标另行定义。

## 5. 纪念物与展示品

### 5.1 RoomMementoDefinition 字段

纪念物是由经历产生的房间痕迹，不等同于仓库物品。

| 字段 | 类型 | 规则 |
|---|---|---|
| `MementoID` | string | 全局唯一，例如 `wall_crack_first_defeat`。 |
| `Trigger` | object | 触发表达式，使用 `10_剧本调度与事件队列规则卡` 的条件系统。 |
| `TargetSlotID` | string | 纪念物出现槽位。 |
| `VisualID` | string | 纪念物表现资源。 |
| `Priority` | int | 同槽位冲突时的显示优先级。 |
| `CanHide` | bool | 默认 false。 |
| `CanRemove` | bool | 默认 false。 |
| `DiaryEntryID` | string | 写入日记本的回顾文本。 |
| `RelatedEventID` | string | 关联剧情事件，可为空。 |

纪念物触发示例：

| 纪念物 | 触发条件 | 槽位 |
|---|---|---|
| 墙上的裂痕 | 首次深渊战败 | `wall_left_crack` |
| 挂墙旧武器 | 首次替换累计使用最长的初始武器 | `wall_weapon` |
| 窗台干花 | 首次赠送花类礼物 | `window_flower` |
| 床头合影 | Bond 首次达到 Lv.5 | `bed_photo` |
| 星星贴纸 | Bond 首次达到 Lv.8 | `ceiling_stars` |
| 积灰木箱 | 触发破产危机后恢复 | `corner_box` |

### 5.2 DisplayItemInstance 字段

展示品是玩家主动放入展柜的视觉引用，不从仓库移走本体。

| 字段 | 类型 | 规则 |
|---|---|---|
| `DisplayInstanceID` | string | 展示记录 ID。 |
| `SourceItemInstanceID` | string | 来源物品实例。 |
| `SourceItemID` | string | 来源物品配置 ID。 |
| `SlotID` | string | 展柜槽位。 |
| `AddedDay` | int | 放入展示的日期。 |
| `SourceSummary` | string | 获取来源摘要，例如深渊层、Boss、赠礼。 |
| `SnapshotVisualID` | string | 展示剪影或图标。 |
| `SnapshotTags` | string[] | 放入时的物品标签快照。 |

展示品规则：

*   每个展柜槽位同时只能展示一件物品。
*   来源物品被出售、消耗或销毁后，展示品从展柜移除，但日记本保留“曾展示过”记录。
*   展示品不作为仓库、不防止出售、不锁定物品。
*   展示品组合可触发 `RoomMemory` 或 `AmbientBubble` 事件，但收益以叙事为主。

## 6. 窗外状态与世界反馈

### 6.1 WindowState 输入

窗外表现由时间、天气、世界事件和结局倾向共同决定。

| 输入 | 示例 |
|---|---|
| 时间阶段 | `PreparationMorning`、`AfterCoreChoiceDusk`、`BusinessNight`。 |
| 日期 | `Day`、`Week`、`Month`。 |
| 近期事件 | 刚战败、深渊重伤、经济破产、完成 Boss。 |
| 世界旗标 | 传闻、势力事件、真结局前置、红月预兆。 |
| 人偶状态 | 低 SAN、高 Bond、崩溃边缘。 |

### 6.2 WindowState 选择优先级

```text
A. 结局 / 强制主线预兆
B. 重大世界事件
C. 近期深渊或经济创伤
D. 月份季节
E. 当日时间阶段
F. 默认晴天
```

同一优先级多条命中时，使用 `Priority` 高者；仍相同则按 `EventID` 稳定排序，避免同存档反复进入房间闪变。

## 7. 人偶待机与观察反馈

### 7.1 DollRoomPoseRule 字段

| 字段 | 类型 | 规则 |
|---|---|---|
| `PoseRuleID` | string | 规则 ID。 |
| `Conditions` | object | Bond、SAN、磨损、刚返回深渊、房间家具、纪念物等条件。 |
| `IdlePointSlotID` | string | 待机点槽位。 |
| `MotionID` | string | 待机动作。 |
| `ExpressionID` | string | 表情。 |
| `DialoguePoolID` | string | 点击时反馈池，可为空。 |
| `Weight` | int | 多条命中时的权重。 |
| `Priority` | int | 强制状态优先级。 |

推荐优先级：

| 状态 | 待机表现 |
|---|---|
| `SAN < 10` | 蜷缩、沉默、抗拒观察。 |
| 刚从深渊重伤返回 | 坐在床边擦拭关节或低头休息。 |
| `Bond >= 8` 且 SAN 稳定 | 看见玩家进入时抬头微笑。 |
| 展柜有 Boss 战利品 | 偶尔站在展柜前端详。 |
| 有留声机 | 闭眼听曲。 |
| 默认 | 坐在窗边或桌前待机。 |

### 7.2 房间交互事件

房间允许的主动行为保持克制：

| 行为 | 输出 |
|---|---|
| 点击人偶 | 生成 `InteractionType=Touch-lite` 或 `RoomObserve` 反馈，不产出可刷 Bond。 |
| 点击展柜 | 打开展示品管理界面。 |
| 点击窗户 | 进入窗外全景观察，数秒后返回。 |
| 点击日记本 | 查看已触发纪念物、展示历史和关键事件时间线。 |
| 停留 30 秒 | 触发长待机动作或轻语事件。 |

房间内不开放赠礼、保养、义体装配和仓库整理；这些仍归工坊、背包或养成界面。

## 8. 与其他系统的边界

| 系统 | 边界 |
|---|---|
| `GDD_07` 时间日程 | 房间进入和观察零时耗；只有明确选择停工休息 / 深度疗愈才推进 Day。 |
| `GDD_12` 人偶交互 | 交互入口和反馈事件归交互系统；房间只提供观察场景和房间专属反馈上下文。 |
| `GDD_03` 人偶核心状态 | SAN、Bond、情绪和崩溃状态决定待机表现；房间不能私自改写核心状态。 |
| `GDD_05` 剧本调度 | 纪念物触发、房间轻语、日记本回顾和结局前夜使用事件队列。 |
| `GDD_08` 人偶养成 | 床、书架等家具可给休息 / 特训极微量修正；维护和义体装配仍在养成系统。 |
| `Dolls` 配置 | 提供人偶偏好、默认房间、表情 / 动作资源引用和房间专属反馈池。 |

## 9. 资源需求

### 9.1 VisualID 类型

| 类型 | 示例 |
|---|---|
| 房间背景 | `room_attic_default_bg` |
| 家具 | `furniture_bed_old_campaign` |
| 纪念物 | `memento_wall_crack_first_defeat` |
| 展示剪影 | `display_item_shadow_default` |
| 窗外覆盖 | `window_rain_night_overlay` |
| 待机动作 | `doll_idle_window_watch` |
| 表情 | `doll_expr_tired_soft` |

### 9.2 资源 fallback

*   家具资源缺失：显示通用家具剪影，并保留槽位。
*   纪念物资源缺失：隐藏视觉，但日记本条目仍可见。
*   展示品图标缺失：使用物品分类图标或通用剪影。
*   待机动作缺失：回退到默认坐姿待机。
*   窗外状态缺失：回退到默认夜晚 / 白天背景。

## 10. Validator 规则

| 校验项 | 规则 |
|---|---|
| 房间 ID | `RoomID` 全局唯一。 |
| 区域合法 | `ZoneList` 的 `NormalizedRect` 不得越界。 |
| 槽位合法 | `SlotID` 唯一；槽位必须引用存在的 `ZoneID`。 |
| 默认内容 | `DefaultFurnitureIDs` 必须能放入合法槽位。 |
| 互斥组 | 同一 `ExclusiveGroup` 的默认内容不能同时激活。 |
| 家具引用 | `VisualID`、`RoomEffectPolicyID`、`UnlockIdleActionIDs` 必须存在或有 fallback。 |
| 纪念物触发 | `Trigger` 必须可解析；`TargetSlotID` 必须存在。 |
| 展示品 | 展柜槽位数量必须与配置声明一致；来源物品不存在时必须能清理。 |
| 窗外状态 | 同条件命中必须有稳定优先级，不允许随机闪变。 |
| 待机规则 | 每个人偶至少有一条默认待机规则。 |
| 时间口径 | 房间观察类行为不得推进 Day。 |

## 11. 验收样例

### 样例 A：首次战败纪念物

输入：

```text
Day=8
Event=FirstDungeonDefeat
RoomID=attic_room_default
```

期望：

*   `wall_crack_first_defeat` 被写入房间状态。
*   目标槽位显示墙上裂痕。
*   日记本新增一次战败回顾。
*   重新进入房间后状态保持一致。

### 样例 B：展示品来源物品被卖出

输入：

```text
DisplaySlot=display_02
SourceItemInstanceID=item_abc
玩家在商店卖出 item_abc
```

期望：

*   `display_02` 自动清空。
*   日记本保留曾展示记录。
*   不阻止出售，不退回物品。

### 样例 C：低 SAN 待机优先级

输入：

```text
CurrentSAN=6
BondLevel=8
Room has gramophone
```

期望：

*   低 SAN 蜷缩 / 沉默待机优先于高 Bond 微笑和留声机听曲。
*   点击人偶只触发低 SAN 观察反馈。
*   不直接恢复 SAN。

### 样例 D：窗外红月预兆

输入：

```text
Flag=abyss_anomaly_tomorrow
TimePhase=BusinessNight
Weather=Rain
```

期望：

*   红月预兆优先于普通雨天。
*   窗外显示红月 / 不祥光色。
*   事件日志记录选择原因。

### 样例 E：房间零时耗

输入：

```text
Day=23
玩家进入房间，停留 5 分钟，查看展柜和日记本后退出
```

期望：

*   Day 仍为 23。
*   不触发营业结算或下潜许可变化。
*   只记录房间观察日志。
