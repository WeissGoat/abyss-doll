# 物品、背包、旋转与生命周期规则卡

> **定位：** 本规则卡把 `GDD_01` 的背包战斗与 `GDD_06` 的物品生命周期接成一套正式规则。它不替代两份 GDD 的体验设计，而是把“物品怎么定义、怎么放、怎么转、怎么丢、怎么带回、怎么卖掉、怎么被怪物干涉”统一成可开发、可验收的策划标准。

---

## 1. 设计目标

物品与背包系统的核心不是收集列表，而是空间压力。每一件物品都同时是收益、战力、风险和空间负担。

正式版必须满足以下目标：

| 目标 | 说明 |
|---|---|
| 空间可读 | 玩家一眼能看出物品占哪些格、能否旋转、能否放入。 |
| 后果清楚 | 拾取、丢弃、出售、撤离、战败都必须有稳定后果。 |
| 构筑可破坏 | 怪物、诅咒物、战利品诱惑都能迫使玩家重排背包。 |
| 旋转有意义 | 旋转不只是 UI 操作，而是改变空间缝隙、相邻关系和方向效果的策略行为。 |
| 生命周期闭环 | 物品从掉落到消耗、出售或丢失，每个状态都有去向，不出现“悬空物品”。 |

---

## 2. 物品的双层身份

### 2.1 物品定义

物品定义是配置层模板，描述“这类东西是什么”。

| 字段组 | 设计含义 |
|---|---|
| 身份 | `ItemID`、名称、稀有度、描述、图标或视觉 ID。 |
| 空间 | 基础形状、是否可旋转、可用角度、默认朝向。 |
| 标签 | 战斗标签、经济标签、风险标签、剧情 / 委托标签。 |
| 使用 | 主动使用、被动监听、消耗型、限次型、常驻型。 |
| 干涉 | 光环、方向连接、污染、封锁、推移抗性等。 |
| 经济 | 基础售价、素材价值、是否可出售、是否可拆解。 |
| 来源 | 掉落池、宝箱池、商店、制造配方、势力订单。 |

### 2.2 物品实例

物品实例是运行时实体，描述“这一件东西经历了什么”。

| 字段 | 设计含义 |
|---|---|
| `InstanceID` | 唯一实例标识。同类物品可以有多件不同实例。 |
| `DefinitionID` | 指向物品定义。 |
| `OwnerScope` | 当前属于本轮深渊、工坊库存、商店出货、展示、已消耗或已丢失。 |
| `ContainerType` | 当前所在容器，例如背包、Inbox、地面库存、出货箱。 |
| `GridPosition` | 当前左上角格坐标；不在格子内时为空。 |
| `Rotation` | 当前朝向。旋转属于实例状态，必须可保存和结算。 |
| `Durability` | 耐久 / 磨损。影响使用效果、维修需求或售价。 |
| `CorruptionLevel` | 污染 / 侵蚀等级。影响 SAN、标签和出售渠道。 |
| `DynamicTags` | 运行时新增标签，例如被诅咒、被绑定、被污染。 |
| `IsBinding` | 是否绑定。绑定物品战败不丢失，但仍可能损坏或产生代价。 |

## 3. 空间容器

物品只能存在于明确容器中。不同容器决定它是否参与战斗、是否安全、是否能出售。

| 容器 | 用途 | 是否参与战斗 | 失败后处理 |
|---|---|---|---|
| `Backpack` 背包网格 | 当前下潜 / 战斗中的真实空间。 | 是 | 未绑定新获物品丢失；绑定物品保留并承受损坏。 |
| `Inbox` 战利品暂存 | 战斗胜利或节点奖励的临时掉落区。 | 否 | 离开当前搜刮窗口时未取走则销毁。 |
| `SafeBox` 安全收纳 | 安全区少量保底空间。 | 否 | 战败保留；容量稀缺，不能作为第二背包使用。 |
| `GroundInventory` 工坊库存 | 地面长期持有物品。 | 否 | 不受单次深渊战败影响。 |
| `ShopBin` 出货箱 | 等待营业结算出售的物品。 | 否 | 营业结算后转为金币或退回库存，取决于经营规则。 |
| `DisplaySlot` 房间 / 橱窗展示 | 视觉展示或高价销售展示。 | 否 | 展示不复制真实收益；真实物品仍按所在系统结算。 |
| `Consumed` 已消耗 | 使用、制造、拆解后的终态。 | 否 | 不再回流。 |
| `Lost` 已丢失 | 战败、丢弃、Inbox 超时、事件吞噬后的终态。 | 否 | 不再回流，除非特定剧情明确找回。 |

设计边界：

*   不设计普通出售保护。玩家将物品放入出货或卖掉，就是自己的决策；系统只对委托物、剧情锁定物和明确不可出售物给硬限制。
*   安全收纳不是仓库扩容，而是搜打撤中的心理保底。容量必须小，且不提供战斗效果。
*   地面库存是局外整理和经营的物品池；若某个开发批次暂不做独立仓库界面，也不能改变物品生命周期含义。

## 4. 旋转与放置规则

### 4.1 旋转规则

| 规则 | 正式口径 |
|---|---|
| 可旋转性 | 由物品定义决定。`CanRotate=false` 的物品锁定朝向。 |
| 角度集合 | 由可用朝向决定，常用为 0 / 90 / 180 / 270 度。 |
| 旋转成本 | 默认不消耗局内 AP、局外天数、金币或耐久。 |
| 状态归属 | 当前角度写入物品实例。撤离、保存、重新进入背包时保持该角度。 |
| 效果刷新 | 旋转后重新计算占格、相邻、方向连接、光环和污染范围。 |
| 失败反馈 | 旋转导致当前位置非法时，物品保持拖拽 / 悬浮态，不自动挤开其他物品。 |

### 4.2 放置合法性

物品放入任何网格容器时，按以下顺序裁决：

1. 检查容器是否允许该物品进入。
2. 根据当前 `Rotation` 计算实际占格。
3. 检查所有占格是否在容器边界内。
4. 检查是否撞上永久死格、临时封锁格、已占用格。
5. 检查物品标签是否被当前状态拒绝，例如特质拒绝近战武器。
6. 检查方向性依赖是否允许放置。依赖不满足时，物品可以放入，但对应效果不生效；除非该物品明确写为“必须连接才可放置”。
7. 放置成功后刷新背包构筑状态。

### 4.3 交换与挤压

默认规则是“玩家手动管理优先”：

| 情况 | 规则 |
|---|---|
| 拖拽物品覆盖已有物品 | 默认非法，不自动交换。 |
| 玩家明确执行交换 | 仅当两个物品互换后都合法时允许。 |
| 怪物推移物品 | 按怪物技能规则执行；目标位置非法则触发弹出或失败效果。 |
| 背包格被封锁 | 原格上物品被弹出到 `Inbox` 或临时悬浮区；若战斗中无法安置，视为被怪物打乱。 |
| 玩家丢弃物品 | 立刻进入 `Lost`，除非当前规则指定可以回收。 |

## 5. 生命周期状态机

### 5.1 主状态

```text
Defined
  -> Generated
  -> InInbox
  -> InBackpack
  -> InSafeBox
  -> ExtractedToGround
  -> ListedForSale
  -> Sold
  -> UsedOrConsumed
  -> Lost
```

### 5.2 关键迁移

| 触发 | 起点 | 终点 | 规则 |
|---|---|---|---|
| 战斗 / 宝箱 / 事件掉落 | `Generated` | `InInbox` | 掉落先进入暂存，不直接塞入背包。 |
| 玩家拾取 | `InInbox` | `InBackpack` | 必须通过放置校验；可旋转后放入。 |
| 离开搜刮窗口 | `InInbox` | `Lost` | 未带走的物品永久消失。 |
| 安全区收纳 | `InBackpack` | `InSafeBox` | 占用安全收纳容量；离开安全区前可调整。 |
| 成功撤离 | `InBackpack/InSafeBox` | `ExtractedToGround` | 全部转入地面库存，保留实例状态。 |
| 战败 | `InBackpack` | `Lost` 或 `ExtractedToGround` | 未绑定新获物品丢失；绑定物品保留但损坏。 |
| 出售 | `ExtractedToGround/ShopBin` | `Sold` | 转为金币；无普通出售保护。 |
| 制造 / 维修消耗 | `ExtractedToGround` | `UsedOrConsumed` | 消耗后不回流。 |
| 主动丢弃 | 任意可丢弃容器 | `Lost` | 立即丢失，除非剧情或系统明确允许回收。 |

### 5.3 绑定与归属

绑定不是“永远安全”，而是“不会因普通战败直接丢失”。

| 物品 | 默认绑定规则 |
|---|---|
| 局前带入装备 | 默认绑定或半绑定，战败保留但耐久 / 磨损恶化。 |
| 本轮新获战利品 | 默认不绑定，战败丢失。 |
| 情感锚点物 | 自动绑定，战败保留，但可能触发情感或损坏后果。 |
| 委托物 | 默认不绑定，必须活着带出才算完成。 |
| 安全收纳物 | 不改变绑定状态，但战败保留。 |

## 6. 战斗中的背包干涉

怪物干涉背包时必须使用统一优先级，避免不同怪物各写一套规则。

### 6.1 干涉类型

| 类型 | 作用 | 设计用途 |
|---|---|---|
| 封锁格 | 将格子变为不可用。 | 破坏固定构筑，制造临场重排。 |
| 侵占物 | 往空格塞入垃圾、毒液、寄生物。 | 压缩空间，逼迫丢弃或消耗。 |
| 推移 | 将某件物品向指定方向移动。 | 干扰方向链路。 |
| 交换 | 交换两件物品位置。 | 针对相邻 / 管线构筑。 |
| 污染 | 给物品或格子附加风险标签。 | 制造高价值物品的长期代价。 |
| 弹出 | 使物品离开背包进入 Inbox / 悬浮区。 | 让玩家在战斗中做紧急处理。 |

### 6.2 冲突优先级

当多个干涉同时发生，按以下顺序裁决：

1. 战斗失败 / 胜利结算优先于普通干涉。
2. Boss 强制规则优先于普通怪物规则。
3. 封锁格优先于侵占物。
4. 已绑定或剧情锁定物品不被直接销毁，但可以被弹出、污染或损坏。
5. 如果目标格非法，优先寻找技能指定的备用格；没有备用格则技能失败或改为轻惩罚。
6. 同一回合内同一格最多承受一次永久性干涉，避免不可读的连锁灾难。

### 6.3 玩家可反制点

干涉必须有至少一种可预判或可反制手段：

| 干涉 | 可读信号 | 反制方式 |
|---|---|---|
| 封锁格 | 怪物意图标识显示格子图标。 | 击杀、护盾技能、提前挪开关键物。 |
| 侵占物 | 显示将塞入的形状或数量。 | 预留空位、使用清理道具、战后丢弃。 |
| 推移 / 交换 | 显示方向或“扰乱”意图。 | 用重型 / 锁定标签物品抵抗。 |
| 污染 | 显示诅咒 / 瘴气意图。 | 用净化道具、隔离容器或快速撤离。 |

## 7. 经济与出售规则

### 7.1 出售口径

| 规则 | 说明 |
|---|---|
| 普通物品可出售 | 玩家自行承担后果，不设计额外出售保护。 |
| 委托物默认不可普通出售 | 只能交付、放弃或因失败丢失。 |
| 情感锚点物允许配置为不可出售 | 若可出售，也必须给强烈情感反馈，而不是静默卖掉。 |
| 装备出售不返还养成投入 | 卖掉就是资源回收，不做复杂保险。 |
| 诅咒物可走黑市 | 普通渠道低价或拒收，黑市高价但可能带势力 / 剧情后果。 |

### 7.2 价值判断

物品价值不只看金币。

| 价值 | 说明 |
|---|---|
| 经济价值 | 出售或订单收益。 |
| 战斗价值 | 当前背包构筑贡献。 |
| 空间价值 | 占格数、形状难度、旋转兼容性。 |
| 情感价值 | 好感、锚点、房间展示、剧情记忆。 |
| 风险价值 | 诅咒、污染、活物移动、委托失败风险。 |

正式物品设计应避免“全维度最优”。一个好物品通常至少有一个明显缺口，例如高售价但形状极差、强战力但高侵蚀、情感强但占格。

## 8. 制造、拆解与消耗

### 8.1 制造

制造把地面库存中的素材实例转为新物品实例。

| 规则 | 说明 |
|---|---|
| 材料消耗 | 被消耗材料进入 `UsedOrConsumed`，不保留原实例。 |
| 新实例 | 制造成品获得新的 `InstanceID`。 |
| 继承污染 | 特殊配方可继承材料污染或标签，但必须在配方中明确。 |
| 失败 | 正式版一般不做随机制造失败；若做，失败产物也必须有明确实例和去向。 |

### 8.2 拆解

拆解是出售之外的资源回收。

| 规则 | 说明 |
|---|---|
| 装备拆解 | 返还部分素材，不返还全部成本。 |
| 诅咒物拆解 | 可产生净化材料，也可能污染工坊。 |
| 情感物拆解 | 原则上不鼓励；若允许，必须触发情感后果。 |

### 8.3 消耗品

消耗品的设计价值在于“使用后释放格子”。

| 规则 | 说明 |
|---|---|
| 主动使用 | 立即触发效果并进入 `UsedOrConsumed`。 |
| 被怪物销毁 | 不触发主动使用效果，只释放或污染格子。 |
| 战后使用 | 允许配置某些消耗品只能战斗中使用，避免战后无脑清空压力。 |

## 9. 设计验收样例

### 9.1 旋转放置

| 输入 | 期望 |
|---|---|
| 1x3 长刀，`CanRotate=true`，背包仅有竖向 1x3 空位。 | 旋转 90 度后可放入；相邻和方向效果按新朝向计算。 |
| L 形战利品旋转后压到封锁格。 | 放置失败，保持拖拽态，不改变原背包。 |
| 固定朝向诅咒遗物尝试旋转。 | 不旋转，给出锁定反馈。 |

### 9.2 搜刮与丢弃

| 输入 | 期望 |
|---|---|
| 战斗胜利生成 3 件物品，其中 1 件未拖入背包就离开节点。 | 未拖入物品进入 `Lost`。 |
| 玩家为了装高价雕像主动丢弃短剑。 | 短剑进入 `Lost`；系统不弹出售保护。 |
| 背包已满但安全收纳还有 1 格。 | 只能放入满足安全收纳形状 / 容量的物品。 |

### 9.3 撤离与战败

| 输入 | 期望 |
|---|---|
| 成功撤离，背包有 5 件物品，安全收纳有 1 件。 | 6 件全部进入地面库存，保留实例状态。 |
| 战败，背包有 3 件本轮新获未绑定战利品。 | 3 件进入 `Lost`。 |
| 战败，背包有绑定旧武器和情感锚点。 | 保留到地面库存，但可附加耐久下降、磨损或情感后果。 |

### 9.4 怪物干涉

| 输入 | 期望 |
|---|---|
| 怪物封锁已有物品占用的格子。 | 该物品弹出到临时区 / Inbox，背包构筑刷新。 |
| 怪物向背包塞 1x1 毒液，但没有空格。 | 技能失败或转化为轻惩罚，不凭空覆盖物品。 |
| 同回合两个怪物都试图封锁同一格。 | 只执行一次永久封锁，第二次改判或失败。 |

## 10. 文档同步要求

后续修改物品或背包时，同步检查：

*   `GDD_01` 是否仍能解释战斗中的空间决策。
*   `GDD_06` 是否仍能解释物品定义、实例和生命周期。
*   配置 README 是否覆盖新字段。
*   审计文档是否需要调整交付状态。
*   如果新增容器、终态或干涉类型，必须补本规则卡的状态机和验收样例。
