# 人偶交互事件与反馈规则卡

> **定位：** 本规则卡把 `GDD_12` 的触摸、对话、赠礼、保养和特殊交互落实为正式交互规格。它定义玩家能做什么、系统生成什么事件、事件如何限次和防刷，以及如何把结果交给 `08_人偶核心状态与好感双轨规则卡` 裁决。

---

## 1. 设计目标

| 目标 | 说明 |
|---|---|
| 交互有情感温度 | 交互不是纯数值按钮，需要有区域、时机、情绪和反馈差异。 |
| 交互可配置 | 触摸区、对话池、礼物偏好、保养档位和特殊事件都应能用数据表达。 |
| 防止刷数值 | 每日上限、边际递减、冷却和剧情条件要阻止无脑点击。 |
| 状态归属清楚 | 交互入口归本规则卡；SAN / Bond / 情绪最终裁决归 `08` 规则卡。 |
| 可验收 | 每类交互都要有输入、输出、失败原因和日志，方便后续实现与测试。 |

---

## 2. 交互事件结构

玩家的每一次有效交互都生成 `InteractionEvent`，再交给人偶核心状态系统结算。

| 字段 | 类型 | 规则 |
|---|---|---|
| `InteractionID` | string | 配置 ID，例如 `touch_head_basic`、`talk_daily_after_dungeon`。 |
| `InteractionType` | enum | `Touch`、`Talk`、`Gift`、`Maintenance`、`Special`、`AutoFeedback`。 |
| `DollInstanceID` | string | 目标人偶。 |
| `Day` | int | 发生日。 |
| `Scene` | enum | `Workshop`、`SafeZone`、`DollRoom`、`Preparation`、`Night`。 |
| `TargetRegion` | enum | 触摸 / 保养目标区域，可为空。 |
| `InputItemID` | string | 赠礼或保养消耗物品，可为空。 |
| `DialoguePoolID` | string | 对话池引用，可为空。 |
| `ContextTags` | string[] | 例如 `AfterDungeon`、`LowSAN`、`Night`、`Birthday`。 |
| `BaseOutcome` | object | 基础收益和表现引用。 |
| `LimitPolicyID` | string | 每日上限或冷却规则。 |
| `ResultPolicyID` | string | 交给核心状态系统的结算策略。 |
| `LogReason` | string | 日志原因，便于复盘。 |

交互执行顺序：

1. 校验当前场景允许该交互类型。
2. 校验人偶状态是否允许交互。
3. 校验物品、材料、对话池或触摸区域是否存在。
4. 校验每日上限、冷却、边际递减和剧情条件。
5. 生成 `InteractionEvent`。
6. 根据 `ResultPolicyID` 交给 `08` 规则卡裁决 SAN / Bond / 情绪 / 特质输入。
7. 播放对应反馈表现并写入日志。

---

## 3. 交互类型

### 3.1 Touch 触摸

触摸是最低成本的存在确认，收益极低，但反馈频率最高。

| 字段 | 规则 |
|---|---|
| `TargetRegion` | `Head`、`Face`、`Shoulder`、`Hand`、`Back`、`Hair` 等。 |
| `EffectiveDailyCount` | 默认每天前 5 次有效。 |
| `RepeatRegionLimit` | 同一区域连续 3 次后进入不耐烦反馈。 |
| `BaseBondDelta` | 默认 `+1..+3`。 |
| `LowSANPenalty` | SAN 低于阈值时可降收益、无收益或触发应激。 |
| `FeedbackSetID` | 按情绪状态切换台词、表情和动作。 |

触摸不会推进 Day，不消耗资源。若人偶处于 `Broken`，只允许少数安抚触摸，且不直接恢复可用状态。

### 3.2 Talk 对话

对话是日常陪伴和里程碑推进入口。

| 对话类型 | 时间口径 | 规则 |
|---|---|---|
| `DailyTalk` | 零时耗 | 每日有效次数有限，从日常池抽取。 |
| `ContextTalk` | 零时耗 | 根据深渊、经营、受伤、节日等上下文抽取。 |
| `MilestoneTalk` | 可占当天核心抉择 | 用于 Bond 等级突破或剧情节点。 |
| `TherapyTalk` | 推进 Day | 用于崩溃、噩梦、深度疗愈。 |
| `AutoFeedback` | 自动 | 进入场景、结算后或安全区通讯自动触发。 |

对话抽取必须有去重和冷却：

*   同一 `DialogueNodeID` 默认当天不重复。
*   高频日常台词可用变体池，但同一变体需冷却。
*   里程碑对话一次性，完成后写入旗标。
*   对话选项可影响本次收益和情绪标签，但不应制造大量不可控分支。

### 3.3 Gift 赠礼

赠礼把物品、偏好和情绪结合，不能只按金币价值折算。

| 字段 | 规则 |
|---|---|
| `GiftItemID` | 必须是玩家可消耗物品。 |
| `GiftCategory` | `BondItem`、`Trophy`、`TradeGood`、`Consumable`、`Cursed`、`Memorial`。 |
| `PreferenceTags` | 与人偶偏好标签匹配时加成。 |
| `DislikeTags` | 与厌恶标签匹配时降收益或拒收。 |
| `GiftHistoryKey` | 用于同类礼物边际递减。 |
| `ConsumePolicy` | `ConsumeOnAccept`、`ReturnOnReject`、`ConvertToRoomMemory`。 |

赠礼收益公式：

```text
FinalBondDelta =
  BaseGiftValue
  * PreferenceMultiplier
  * BondStageMultiplier
  * EmotionMultiplier
  * DailyDiminishMultiplier
  + SpecialBonus
```

最低规则：

*   拒收时不消耗物品。
*   诅咒物或厌恶物可以扣 Bond，但必须有明确提示。
*   同日第 2 件礼物默认收益 `x0.3`，第 3 件起 `x0.1` 或更低。
*   高价值贸易品不能无限刷好感；金币价值只提供有限加成。

### 3.4 Maintenance 保养

保养交互负责把 `GDD_08` 的维护操作包装成可感知的照料过程。

| 步骤 | 输入 | 输出 |
|---|---|---|
| `RepairWear` | 修复材料 / 金币 | 降低磨损，按材料档位产生 Bond 修正。 |
| `PurifyCorruption` | 净化材料 | 降低侵蚀，可能恢复 SAN。 |
| `StabilizeSAN` | 镇静剂 / 深度疗愈条件 | 恢复 SAN 或解除危机。 |
| `CarePresentation` | 是否观看完整动画 | 影响额外 Bond 或反馈质量。 |

保养普通档位为零时耗；深度手术、崩溃处置和疗愈分支可推进 Day。材料消耗、维护结果和下潜许可仍以 `05_局外成长与维护规则卡` 和 `08` 规则卡裁决。

### 3.5 Special 特殊交互

特殊交互由条件触发，不在普通菜单中常驻。

| 类型 | 触发 | 规则 |
|---|---|---|
| `WipeStain` | 深渊返回且有战损 / 污渍标签 | 小幅 Bond / SAN，表现优先。 |
| `NightmareComfort` | 夜晚 + 低 SAN + 冷却满足 | 可恢复 SAN，可能推进情绪修复。 |
| `Birthday` | 日期匹配 | 当日赠礼倍率提高，不送礼无硬惩罚。 |
| `FarewellNight` | 最终月最后一周 | 叙事反馈为主，可不产生数值。 |
| `CrisisIntervention` | SAN 崩溃或重大创伤 | 可推进 Day，解除锁定状态。 |

---

## 4. 场景权限

| 场景 | 允许交互 | 禁止交互 |
|---|---|---|
| `Workshop` | Touch、Talk、Gift、Maintenance、Special | 无。 |
| `SafeZone` | ContextTalk、AutoFeedback | Touch、Gift、Maintenance。 |
| `DollRoom` | Touch-lite、Observe、RoomMemoryFeedback | Gift、Maintenance。 |
| `Preparation` | AutoFeedback、短对话 | 深度交互。 |
| `Night` | Talk、Special、TherapyTalk | 普通刷取型交互。 |
| `Business` | AutoFeedback | 主动交互。 |

场景权限只限制入口；最终状态变化仍由核心状态系统裁决。

## 5. 上限、冷却与防刷

### 5.1 上限字段

| 字段 | 说明 |
|---|---|
| `DailyEffectiveCount` | 当天有效次数。 |
| `DailyHardCount` | 当天硬上限，超过后不能再触发。 |
| `SameTargetCooldown` | 同一区域、同一礼物、同一话题冷却。 |
| `DiminishCurve` | 边际递减曲线，例如 `1.0, 0.3, 0.1, 0`。 |
| `ResetTiming` | `NextDay`、`NextWeek`、`AfterDive`、`AfterStoryFlag`。 |

### 5.2 推荐默认值

| 交互 | 默认限制 |
|---|---|
| Touch | 每日前 5 次有收益；同区域连续 3 次触发不耐烦。 |
| DailyTalk | 每日 1 到 3 次有收益，之后只播放无收益闲聊。 |
| Gift | 不限次数，但第 2 件起严重递减。 |
| Maintenance | 受材料和状态限制；同一维护项当天重复收益下降。 |
| Special | 按触发条件和冷却限制，不能手动刷。 |

防刷原则：超过上限后可以保留表现反馈，但不得继续产出可观数值。

## 6. 偏好与反馈

### 6.1 人偶偏好字段

偏好可以配置在 Dolls 或后续交互配置中。

| 字段 | 说明 |
|---|---|
| `LikeTags` | 喜欢的物品 / 话题标签。 |
| `DislikeTags` | 讨厌的物品 / 话题标签。 |
| `HiddenPreference` | 是否初始隐藏。 |
| `RevealCondition` | 通过对话、赠礼次数或剧情揭示。 |
| `PreferenceStrength` | 偏好强度，影响倍率。 |

偏好揭示不是必须玩法，但应能被玩家通过反馈推断。

### 6.2 反馈选择

反馈由以下因素共同决定：

1. 交互类型。
2. 人偶主情绪状态。
3. BondLevel。
4. CurrentSAN 区间。
5. 最近事件记忆。
6. 物品或话题偏好。
7. 是否超过上限或冷却。

反馈结果至少包含：

| 字段 | 说明 |
|---|---|
| `FeedbackID` | 表现 ID。 |
| `DialogueLineID` | 台词或对话节点。 |
| `ExpressionID` | 表情。 |
| `MotionID` | 动作。 |
| `SfxID` | 可选音效。 |
| `ResultHint` | UI 可读提示，例如“她似乎很喜欢”。 |

## 7. 对话池规则

### 7.1 对话池字段

| 字段 | 说明 |
|---|---|
| `DialoguePoolID` | 对话池 ID。 |
| `PoolType` | `Daily`、`Context`、`Milestone`、`Therapy`、`Ending`。 |
| `Conditions` | Bond、SAN、情绪、场景、时间、近期事件、旗标。 |
| `Entries` | 候选对话节点。 |
| `WeightRules` | 权重修正。 |
| `RepeatPolicy` | 重复、冷却和一次性规则。 |
| `OutcomePolicy` | 对话完成后的收益策略。 |

### 7.2 抽取步骤

```text
1. 收集当前场景允许的对话池。
2. 过滤 Conditions 不满足的池。
3. 过滤已完成的一次性节点。
4. 过滤冷却中的节点。
5. 根据上下文标签修正权重。
6. 抽取节点，生成 Talk InteractionEvent。
7. 完成后写入对话日志、冷却和结果事件。
```

若无可用节点，返回兜底闲聊，不产生数值收益。

## 8. 与其他系统的边界

| 系统 | 边界 |
|---|---|
| `08_人偶核心状态与好感双轨规则卡` | 接收交互事件并裁决 SAN / Bond / 情绪 / 特质输入。 |
| `GDD_05` 剧本调度 | 提供里程碑、剧情对话节点和全局旗标；本规则卡只定义交互入口。 |
| `GDD_08` 局外成长 | 提供保养材料、维护结果和下潜许可；本规则卡负责保养交互表现和事件。 |
| `GDD_11` 人偶房间 | 接收纪念物、展示品和观察反馈；房间布局本身归房间系统。 |
| `GDD_07` 时间日程 | 决定哪些交互零时耗，哪些交互推进 Day。 |
| `Dolls` 配置 | 提供基础偏好、语音 / 表情资源引用和初始交互参数。 |

## 9. Validator 规则

| 校验项 | 规则 |
|---|---|
| 交互 ID | `InteractionID` 全局唯一。 |
| 类型合法 | `InteractionType` 必须在枚举内。 |
| 场景合法 | 每个交互必须声明允许场景。 |
| 上限完整 | 产出 Bond / SAN 的交互必须有上限或递减。 |
| 对话池引用 | `DialoguePoolID` 必须存在；一次性节点必须有完成旗标。 |
| 礼物规则 | 赠礼必须声明接受 / 拒收时是否消耗物品。 |
| 偏好引用 | `LikeTags` / `DislikeTags` 必须引用合法标签。 |
| 反馈引用 | `FeedbackID`、表情、动作和台词引用必须存在或有 fallback。 |
| 崩溃边界 | `Broken` 状态下允许的交互必须显式白名单。 |
| 时间口径 | 推进 Day 的交互必须标记为核心抉择或特殊处置。 |

## 10. 验收样例

### 样例 A：触摸上限

输入：

```text
Day=12
InteractionType=Touch
TargetRegion=Head
今日有效触摸次数=5
```

期望：

*   第 6 次触摸可播放反馈。
*   不再增加 Bond。
*   日志记录 `LimitReached`。

### 样例 B：赠礼偏好

输入：

```text
GiftItem Tags=[Mechanical, Trophy]
Doll LikeTags=[Mechanical]
当天第 1 件礼物
BondLevel=4
EmotionState=Calm
```

期望：

*   物品被接受并消耗。
*   偏好倍率生效。
*   生成喜欢礼物反馈。
*   输出 `InteractionEvent` 给 `08` 规则卡结算 Bond。

### 样例 C：低 SAN 拒绝触摸

输入：

```text
CurrentSAN=7
EmotionState=Panic
InteractionType=Touch
TargetRegion=Face
```

期望：

*   触发应激反馈。
*   不增加 Bond。
*   可写入近期事件记忆。
*   不把人偶从崩溃边缘直接治好。

### 样例 D：对话池兜底

输入：

```text
Scene=Workshop
PoolType=Daily
所有日常节点已冷却
```

期望：

*   返回兜底闲聊。
*   不产生 Bond / SAN 收益。
*   不报错，不推进 Day。
