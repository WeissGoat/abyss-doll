# 人偶核心状态与好感双轨规则卡

> **定位：** 本规则卡把 `GDD_03` 的人偶实体、SAN、Bond、奇迹机制和特质接入落实为正式设计规格。`GDD_12` 负责“玩家如何互动”，本规则卡负责“互动和战斗经历如何沉淀为人偶状态，以及状态如何反过来影响玩法裁决”。

---

## 1. 设计目标

| 目标 | 说明 |
|---|---|
| 人偶不是血条容器 | 人偶同时承载 HP、SAN、Bond、磨损、侵蚀、情绪、特质和长期记忆。 |
| 短线压力与长线关系分离 | SAN 是短线稳定度，会快速上下波动；Bond 是长线羁绊，默认不因普通失败倒退。 |
| 情感能改写规则但有边界 | 高 Bond 可触发奇迹，但奇迹有次数、条件和代价，不成为无限复活。 |
| 状态可复盘 | 每次 SAN / Bond / 特质变化都要有来源、数值、触发原因和日志。 |
| 与交互系统分工清楚 | 触摸、对话、赠礼、保养是入口；核心状态变化、阈值、异常和持久化归本规则卡。 |

---

## 2. 人偶实例字段

人偶定义来自 `配置表(JSON)/Dolls`，运行时实例需要额外保存以下状态。

| 字段 | 类型 | 规则 |
|---|---|---|
| `DollInstanceID` | string | 单局唯一人偶实例 ID。 |
| `DollID` | string | 指向人偶基础档案。 |
| `CurrentHP` | int | 当前机体耐久，范围 `0..MaxHP`。 |
| `MaxHP` | int | 由人偶基础、底盘、义体和效果共同计算。 |
| `CurrentSAN` | int | 当前理智，范围 `0..MaxSAN`。 |
| `MaxSAN` | int | 由人偶基础、成长和效果共同计算。 |
| `BondValue` | int | 当前羁绊经验值，最低 0。 |
| `BondLevel` | int | 由 `BondValue` 和里程碑解锁共同决定，建议缓存但不作为唯一事实来源。 |
| `BondMilestoneFlags` | string[] | 已完成的 Bond 突破事件。 |
| `EmotionState` | enum | 当前情绪状态，见第 5 节。 |
| `WearLevel` | int | 机体磨损，接 `05_局外成长与维护规则卡`。 |
| `CorruptionLevel` | int | 侵蚀 / 污染程度，接维护和深渊结算。 |
| `TraitInstanceIDs` | string[] | 当前特质实例，具体特质规则接 `06_标签与特质规则卡`。 |
| `DynamicStateTags` | string[] | 临时状态标签，例如 `Broken`、`Panic`、`Inspired`。 |
| `HasMiracleRevivedThisRun` | bool | 本次下潜是否已触发奇迹。下潜结束后重置。 |
| `RecentEventMemory` | array | 近期关键事件摘要，用于特质、对话和情绪裁决。 |
| `LastInteractionDay` | int | 最近一次有效交互日。 |
| `NeglectDays` | int | 连续忽视天数，用于情绪和特质风险。 |

## 3. SAN 短线稳定度

### 3.1 SAN 定义

SAN 表示人偶当前精神稳定度，不等于好感。它可以通过休息、保养、净化、安抚和部分道具恢复，也会因深渊探索、战损、污染、恐惧、诅咒物、过度压榨和特殊事件下降。

### 3.2 SAN 阈值

| 区间 | 状态 | 规则影响 |
|---|---|---|
| `80%..100%` | 稳定 | 可触发“状态良好”加成，例如武器充能或交互反馈更积极。 |
| `50%..79%` | 正常 | 无额外惩罚。 |
| `30%..49%` | 疲惫 | 交互反馈变慢；部分高压事件更容易触发。 |
| `10%..29%` | 压抑 | 深渊节点 SAN 消耗提高；触摸和对话可能出现抗拒反馈。 |
| `1%..9%` | 崩溃边缘 | 战斗、污染和恐惧事件触发特质风险；部分操作需要二次确认。 |
| `0` | 崩溃 | 触发 `SanityBreak`，进入强制处置流程。 |

### 3.3 SAN 变化来源

| 来源 | 变化 | 说明 |
|---|---|---|
| 普通深渊移动 | `-BaseMoveCost` | 可被地图、特质、物品或效果修正。 |
| 高风险节点 | 额外下降 | 由节点标签或事件配置决定。 |
| 战斗受伤 | 按伤害比例下降 | 大伤害比小伤害更容易制造精神压力。 |
| 战败 / 濒死 | 大幅下降 | 同时写入近期记忆。 |
| 基础维护 / 净化 | 恢复 | 接 `05_局外成长与维护规则卡`。 |
| 休息 / 深度疗愈 | 大幅恢复 | 推进 Day，是当天核心抉择之一。 |
| 安抚 / 对话 / 特殊交互 | 小到中幅恢复 | 入口由 `GDD_12` 定义，数值裁决归本规则卡。 |
| 诅咒物 / 恐惧特质 | 下降 | 必须记录触发来源。 |

### 3.4 崩溃处置

当 `CurrentSAN` 降到 0：

1. 立即添加动态标签 `SanityBroken`。
2. 中断当前普通交互入口，进入崩溃状态。
3. 若在深渊中，触发强制撤离、战败或特殊事件，具体由深渊结算规则裁决。
4. 回到局外后，普通触摸、赠礼和闲聊不能直接恢复可用状态。
5. 玩家必须选择深度疗愈、昂贵维护、剧情处置或休息分支之一。
6. 崩溃处置推进 Day；处置完成后移除 `SanityBroken`，但可留下特质风险或近期记忆。

## 4. Bond 长线羁绊

### 4.1 Bond 定义

Bond 表示人偶与玩家之间的长期关系。它不是短期心情，也不是 SAN。普通战败、受伤和维护不足不直接扣 Bond；只有背叛、极端忽视、奇迹被消耗后仍导致战败、剧情选择和连续虐待式行为会触发 Bond 惩罚。

### 4.2 Bond 等级与阈值

| 等级 | 建议阈值 | 规则意义 |
|---|---:|---|
| Lv.0 冷启动 | 0 | 只有基础服从，无信赖反馈。 |
| Lv.1 认识 | 50 | 解锁基础日常反馈。 |
| Lv.2 熟悉 | 120 | 对话池增加，保养反馈更柔和。 |
| Lv.3 信任 | 220 | 特定深渊通讯和安全区反馈增强。 |
| Lv.4 依靠 | 360 | 高压事件中出现主动提醒。 |
| Lv.5 羁绊 | 540 | 解锁奇迹机制资格。 |
| Lv.6 坚定 | 760 | 奇迹后惩罚降低，部分负面特质更容易转化。 |
| Lv.7 亲密 | 1020 | 高级情感事件和特殊对话池。 |
| Lv.8 共鸣 | 1320 | 部分特质获得正向共鸣分支。 |
| Lv.9 誓约 | 1660 | 终局倾向权重提高。 |
| Lv.10 灵魂连接 | 2040 | 最高亲密反馈和结局条件之一。 |

Bond 升级需要同时满足：

*   `BondValue` 达到阈值。
*   对应 `BondMilestone` 已完成，若该等级配置了里程碑事件。

### 4.3 Bond 变化来源

| 来源 | 规则 |
|---|---|
| 触摸 | 少量增加，有每日有效次数上限，入口由 `GDD_12` 定义。 |
| 普通对话 | 稳定增加，每日有效次数有限。 |
| 深度对话 / 里程碑陪伴 | 大幅增加，可推进 Day。 |
| 赠礼 | 按物品情感价值、偏好和边际递减计算。 |
| 高档维护 / 温柔照料 | 小幅增加。 |
| 忽视 | 普通短期忽视不扣；长期忽视可增加负面特质风险。 |
| 背叛 / 恶意行为 | 可直接扣 Bond 或锁定交互入口。 |
| 奇迹耗尽后仍战败 | 可扣 BondLevel 或写入重大创伤记忆。 |

### 4.4 Bond 不倒退原则与例外

原则：Bond 是长线积累，不能因为玩家一次操作失误轻易倒退。

例外必须非常少，且需要明确日志：

*   玩家主动选择伤害、抛弃或背叛人偶。
*   高 Bond 奇迹已触发，玩家继续贪进导致本次仍战败。
*   连续多次在 `SanityBroken` 后不处理，强行下潜或压榨。
*   剧情重大选择。

## 5. 情绪状态机

情绪是由 SAN、Bond、近期事件和特质共同推导的表现状态。它影响 UI、语音、交互反馈和少量规则修正，但不替代 SAN / Bond 本体。

### 5.1 状态表

| 状态 | 进入条件 | 退出条件 | 表现与规则 |
|---|---|---|---|
| `Energetic` 元气 | SAN >= 80%，Bond >= Lv.4，无近期创伤 | SAN 下降或创伤事件 | 主动反馈，轻微正向加成。 |
| `Calm` 平静 | SAN 50-79%，Bond >= Lv.2 | SAN 或 Bond 变化越界 | 默认状态。 |
| `Tired` 疲惫 | SAN 30-49% 或磨损偏高 | SAN 恢复或维护完成 | 动作和反馈变慢。 |
| `Depressed` 压抑 | SAN 10-29% 或近期重大失败 | SAN 恢复到 30% 以上 | 抗拒部分轻浮互动。 |
| `Panic` 崩溃边缘 | SAN 1-9% | 恢复 SAN 或进入崩溃 | 高风险特质触发窗口。 |
| `Broken` 崩溃 | SAN == 0 或强制事件 | 完成崩溃处置 | 锁定普通交互入口。 |
| `Cold` 冰冷抗拒 | Bond 极低且长期忽视 / 恶意行为 | 长期修复或剧情解锁 | 对互动冷淡，正向收益下降。 |

### 5.2 推导优先级

情绪推导按以下优先级裁决：

1. 强制剧情状态。
2. `SanityBroken` / `Broken` 动态标签。
3. SAN 阈值。
4. Bond 极低或极高修正。
5. 近期重大事件。
6. 特质修正。
7. 默认状态。

同一时刻只保留一个主情绪状态；可叠加动态标签表达细分状态，例如 `Ashamed`、`Inspired`、`FearOfInsects`。

## 6. 奇迹机制

### 6.1 触发条件

奇迹是高 Bond 对致死结果的一次性改写，不是普通护盾。

必须同时满足：

*   `BondLevel >= 5`。
*   当前处于深渊或战斗等会发生致死裁决的场景。
*   本次下潜 `HasMiracleRevivedThisRun == false`。
*   本次伤害会使 `CurrentHP <= 0`。
*   人偶没有 `MiracleBlocked`、`SanityBroken` 或剧情禁用标签。

### 6.2 结算步骤

```text
OnFatalDamage:
  1. Check normal damage prevention first.
  2. If CurrentHP would be <= 0, evaluate Miracle conditions.
  3. If pass:
       Cancel fatal result.
       Set CurrentHP = max(1, configured rescue HP).
       Set HasMiracleRevivedThisRun = true.
       Apply SAN cost or trauma memory.
       Emit MiracleTriggered event.
       Show high-priority presentation.
  4. If fail:
       Continue normal defeat / deathline settlement.
```

### 6.3 奇迹代价

奇迹触发后至少产生一种代价：

| 代价 | 规则 |
|---|---|
| SAN 大幅下降 | 默认下降 20% MaxSAN 或配置值。 |
| 写入重大记忆 | `RecentEventMemory` 记录 `MiracleUsed`。 |
| 本轮不可再次触发 | `HasMiracleRevivedThisRun=true`。 |
| 后续战败惩罚 | 若奇迹后仍战败，可触发 Bond 或特质惩罚。 |

### 6.4 奇迹后仍战败

如果奇迹已触发而玩家继续深入并战败：

*   正常执行战败结算。
*   写入重大创伤记忆 `MiracleWasted`。
*   可扣除 1 个 BondLevel 或大量 BondValue，但必须只在高难惩罚配置中启用。
*   必定进入特质风险判定，例如 `FearOfDeath`、`SelfSacrifice` 或 `ColdObedience`。

## 7. 特质与极端冲突

特质规则本体归 `06_标签与特质规则卡`。本规则卡只定义人偶状态如何给特质提供输入。

### 7.1 特质输入事件

人偶核心状态至少发布以下事件：

| 事件 | 触发 |
|---|---|
| `OnSANChanged` | SAN 变化。 |
| `OnBondChanged` | BondValue 或 BondLevel 变化。 |
| `OnEmotionChanged` | 主情绪状态变化。 |
| `OnSanityBreak` | SAN 降为 0。 |
| `OnMiracleTriggered` | 奇迹触发。 |
| `OnMiracleWasted` | 奇迹后仍失败。 |
| `OnNeglectThresholdReached` | 忽视天数达到阈值。 |
| `OnMajorTraumaRecorded` | 写入重大创伤记忆。 |

### 7.2 极端冲突判定

当长期高 Bond 与长期低 SAN 同时存在时，不应简单判为“高好感好结局”。需要进入冲突判定。

| 条件 | 风险 |
|---|---|
| Bond >= Lv.7 且最近 14 天平均 SAN < 30% | 产生“依赖但痛苦”的特质候选。 |
| Bond >= Lv.8 且多次触发崩溃 | 产生“坏掉的忠诚”或“过度服从”候选。 |
| Bond <= Lv.1 且长期满 SAN | 表示被当工具维护但没有情感连接，可产生“冰冷服从”。 |
| 高 Bond + 奇迹浪费 | 产生“死亡恐惧”或“自我牺牲”分支。 |

特质候选不必立即获得，可进入权重池，由剧情、对话或休息日事件确认。

## 8. 与 GDD_12 的分工

| 内容 | 归属 |
|---|---|
| 触摸区域、对话入口、赠礼操作、保养交互表现 | `GDD_12` |
| SAN / Bond 字段、阈值、变化裁决和持久化 | 本规则卡 |
| 情绪状态机与主情绪推导 | 本规则卡 |
| 每类交互的基础收益范围和每日上限 | `GDD_12` 提入口径，本规则卡做最终裁决 |
| 里程碑对话文本、剧情节点 | `GDD_05` / `GDD_12` |
| 奇迹机制 | 本规则卡 |
| 特质触发器、互斥、优先级 | `06_标签与特质规则卡` |

交互系统提交的是“行为事件”，例如：

```text
InteractionEvent {
  Type: Gift
  ItemID: relic_music_box
  Day: 23
  ContextTags: [Night, AfterDungeon]
}
```

人偶状态系统根据当前 SAN、Bond、偏好、边际递减、特质和剧情标记计算最终结果。

## 9. Validator 规则

| 校验项 | 规则 |
|---|---|
| 人偶基础字段 | `DollID`、`Stats.HP_Max`、`Stats.SAN_Max` 必填且大于 0。 |
| Bond 阈值 | 阈值必须递增，最高等级唯一。 |
| 情绪状态 | 每个状态必须有进入条件、退出条件和默认兜底状态。 |
| 奇迹配置 | 奇迹必须有触发条件、每轮次数限制和代价。 |
| 特质引用 | 状态事件引用的特质 ID、标签和效果必须存在。 |
| 交互收益 | 每种交互收益必须有每日上限或边际递减规则。 |
| 崩溃处置 | `SAN=0` 必须有至少一种恢复路径，不能让存档永久死锁。 |
| 负向惩罚 | Bond 扣减必须声明来源和上限，不能由普通失败隐式触发。 |

## 10. 验收样例

### 样例 A：SAN 阈值变化

输入：

```text
CurrentSAN=35
MaxSAN=100
事件：深渊高风险节点，SAN -10
```

期望：

*   `CurrentSAN=25`。
*   情绪从 `Tired` 或 `Calm` 进入 `Depressed`。
*   发布 `OnSANChanged` 和 `OnEmotionChanged`。
*   UI 反馈变为压抑状态。

### 样例 B：Bond 升级但等待里程碑

输入：

```text
BondValue 从 115 增加到 130
Lv.2 阈值=120
Lv.2 Milestone 未完成
```

期望：

*   `BondValue=130`。
*   `BondLevel` 暂不突破到 Lv.2，状态为“可突破”。
*   解锁对应里程碑对话入口。
*   完成里程碑后升级。

### 样例 C：奇迹触发

输入：

```text
CurrentHP=8
Damage=12
BondLevel=5
HasMiracleRevivedThisRun=false
CurrentSAN=60
```

期望：

*   致死伤害被取消。
*   `CurrentHP=1`。
*   `HasMiracleRevivedThisRun=true`。
*   SAN 按配置下降。
*   发布 `OnMiracleTriggered`。

### 样例 D：SAN 崩溃

输入：

```text
CurrentSAN=4
事件：恐惧特质触发，SAN -5
```

期望：

*   `CurrentSAN=0`。
*   添加 `SanityBroken`。
*   情绪进入 `Broken`。
*   普通交互入口被锁定。
*   局外必须通过崩溃处置恢复可用状态。
