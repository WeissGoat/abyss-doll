# 局外成长人偶特质房间正式配置落地设计

> 本文承接 `38_局外成长正式配置实现任务拆分.md` 的 `GROWTH-DOLL-TRAIT-ROOM`。它把人偶静态档案、运行时状态拆分、8 个特质、8 条交互反馈和 8 个房间纪念物转成 JSON 修改前字段级清单，供后续配置实现使用。本文不直接修改 `配置表(JSON)`，不代表 Dolls、Traits、Feedback 或 RoomMemory JSON 已完成。

---

## 1. 当前事实

当前 `配置表(JSON)/Dolls` 只有两个原型文件：

| 文件 | 当前用途 | 正式判断 |
|---|---|---|
| `doll_proto_0.json` | 原型人偶基础档案。 | 可作为旧数据迁移参考，不是正式静态档案完成。 |
| `doll_proto_0_test.json` | 测试人偶和测试初始装备。 | 只作为测试便利，不进入正式配置完成口径。 |

现有问题：

1. `Status.HP_Current`、`Status.SAN_Current`、`Status.WearAndTear`、`Status.Corruption` 混在静态 Dolls 配置里；正式版中这些属于运行时实例 / 存档。
2. `InitialItems` 直接写入静态档案，且内容明显服务测试便利；正式版应改为 `InitialLoadoutRef` 或新手载荷配置引用。
3. `DefaultChassisID=chassis_lv1_basic` 是旧 ID；正式设计应迁移到 `chassis_standard_frame`。
4. 当前没有独立 Trait、Feedback、RoomMemory / Memento 配置源；本文先定义字段和首批 ID，不假设它们已经存在。
5. 当前 `Dolls/README.md` 已说明静态档案边界，但还缺少把人偶、特质、反馈、房间纪念物落到 JSON 前的字段级清单。

---

## 2. 本轮目标

`GROWTH-DOLL-TRAIT-ROOM` 本轮处理 4 类配置设计：

| 类别 | 目标 |
|---|---|
| Doll 静态档案 | 只保存基础身份、上限、默认底盘、默认房间、偏好、交互入口和表现 fallback。 |
| 运行时状态拆分 | 明确哪些字段必须从静态 Dolls 移到存档 / 实例 / 运行时状态。 |
| Trait / Feedback | 把 8 个正式特质和 8 条交互反馈落到可配置字段，承接 `41` 的效果 / 特质规则。 |
| Room Memento | 把 8 个房间纪念物落到可配置字段，明确它们是视觉日记，不是仓库或物品复制。 |

设计原则：

1. 静态配置定义“她是谁”和“默认可引用什么”，不保存当前伤势、情绪、好感或经历状态。
2. 特质必须有来源、影响、反馈和转化 / 消除路径；负面特质不能永久死锁。
3. 反馈必须有规则裁决，不能只是一句文案。
4. 房间纪念物记录经历和表现，不占用背包，不防出售，不复制物品。
5. 如果程序暂不支持某字段，配置仍保留正式字段，Validator 先给 warning，不删除正式口径。

## 3. Doll 静态档案字段

正式 `Dolls` 静态档案建议使用以下字段。旧字段允许通过兼容映射迁移，但新 JSON 不应继续把运行时状态写入静态档案。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `DollID` | string | 是 | 人偶全局唯一 ID。 |
| `DisplayName` | string | 是 | 玩家可见名称。旧 `Name` 可兼容映射。 |
| `BaseProfileID` | string | 是 | 基础档案 ID，用于剧情、本地化和 UI。 |
| `DefaultRoomID` | string | 是 | 默认房间配置 ID，首批建议 `room_attic_default`。 |
| `BaseMaxHP` | int | 是 | 初始 HP 上限。旧 `Status.HP_Max` 可迁移。 |
| `BaseMaxSAN` | int | 是 | 初始 SAN 上限。旧 `Status.SAN_Max` 可迁移。 |
| `BaseBondCurveID` | string | 是 | Bond 曲线 ID，首批建议 `bond_curve_proto_default`。 |
| `DefaultChassisID` | string | 是 | 初始底盘 ID，正式迁移到 `chassis_standard_frame`。 |
| `InitialUnlockedBlueprints` | string[] | 否 | 初始已解锁图纸，原则上只放教学 / 初始必需项。 |
| `InitialLoadoutRef` | string | 否 | 初始装备 / 物品载荷引用，替代 `InitialItems` 直写。 |
| `EmotionStateSet` | string | 是 | 情绪状态集合 ID。 |
| `BondThresholds` | object/string | 是 | Bond 阈值配置或引用。 |
| `SanThresholds` | object/string | 是 | SAN 阈值配置或引用。 |
| `MiraclePolicyID` | string | 是 | 奇迹裁决策略 ID。 |
| `SanBreakPolicyID` | string | 是 | SAN 崩溃裁决策略 ID。 |
| `LikeTags` | string[] | 否 | 赠礼、对话、房间偏好的喜欢标签。 |
| `DislikeTags` | string[] | 否 | 抗拒标签。 |
| `AllowedInteractionRefs` | string[] | 是 | 允许的人偶交互配置 ID。 |
| `FeedbackSetRefs` | string[] | 是 | 反馈池引用。 |
| `RoomPreferenceTags` | string[] | 否 | 房间偏好标签。 |
| `DefaultIdlePoseRules` | object[] | 否 | 默认房间待机规则。 |
| `RoomFeedbackPools` | string[] | 否 | 房间观察 / 纪念物反馈池。 |
| `ExpressionVisualIDs` | object | 是 | 表情资源引用，必须含 fallback。 |
| `MotionIDs` | object | 否 | 动作资源引用。 |
| `FallbackVisualID` | string | 是 | 表现资源缺失时的 fallback。 |

首批正式人偶档案建议：

| 字段 | 建议值 | 说明 |
|---|---|---|
| `DollID` | `doll_proto_0` | 沿用原型 ID，避免程序和存档迁移成本过高。 |
| `DisplayName` | `原型机·零` | 保留现有展示名。 |
| `DefaultRoomID` | `room_attic_default` | 对应房间规则卡默认房间。 |
| `BaseMaxHP` | `100` | 沿用当前上限。 |
| `BaseMaxSAN` | `50` | 沿用当前上限。 |
| `BaseBondCurveID` | `bond_curve_proto_default` | 后续 Bond 曲线配置入口。 |
| `DefaultChassisID` | `chassis_standard_frame` | 替换旧 `chassis_lv1_basic`。 |
| `InitialLoadoutRef` | `loadout_tutorial_standard` | 替代 `InitialItems` 直写。 |
| `EmotionStateSet` | `emotion_set_proto_default` | 覆盖 Calm、Tense、Panic、Broken 等基础状态。 |
| `MiraclePolicyID` | `miracle_policy_bond_sacrifice_v1` | 与 `08` 规则卡一致。 |
| `SanBreakPolicyID` | `san_break_policy_proto_v1` | 与 `08` 规则卡一致。 |

## 4. 运行时状态拆分

以下字段不得写入静态 `Dolls` 配置：

| 禁止字段 | 正式归属 | 说明 |
|---|---|---|
| `CurrentHP` / `Status.HP_Current` | DollRuntime / 存档 | 当前 HP 是实例状态。 |
| `CurrentSAN` / `Status.SAN_Current` | DollRuntime / 存档 | 当前 SAN 是实例状态。 |
| `WearLevel` / `Status.WearAndTear` | DollRuntime / 维护系统 | 磨损由下潜和维护改变。 |
| `CorruptionLevel` / `Status.Corruption` | DollRuntime / 维护系统 | 侵蚀 / 污染由深渊和维护改变。 |
| `BondValue`、`BondLevel` | 关系系统 / 存档 | 好感是长期实例状态。 |
| `EmotionState` | DollRuntime | 当前情绪由事件裁决。 |
| `TraitInstanceIDs` | 存档 / 经历日志 | 特质获得、压制、转化是经历结果。 |
| `DynamicStateTags` | 存档 / 运行时标签 | 临时标签有生命周期。 |
| `MaintenanceHistory` | 维护日志 | 不能写入静态档案。 |
| `RoomMemoryState` | 房间记忆 / 存档 | 纪念物触发状态由经历生成。 |
| `InitialItems` | Loadout 配置或测试 fixture | 正式静态档案只引用 `InitialLoadoutRef`。 |

迁移原则：

1. `Status.HP_Max` -> `BaseMaxHP`。
2. `Status.SAN_Max` -> `BaseMaxSAN`。
3. `Name` -> `DisplayName`。
4. `DefaultChassisID=chassis_lv1_basic` -> `DefaultChassisID=chassis_standard_frame`。
5. `InitialItems` -> `InitialLoadoutRef`；测试专用载荷可保留在测试 fixture，但不计正式配置完成。

## 5. Trait 字段与 8 个首批特质

Trait 配置可落在 `Effects` 的 `traits` 分区，或后续独立 `Traits` 配置域；无论落点如何，字段必须一致。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `TraitID` | string | 是 | 特质唯一 ID。 |
| `DisplayName` | string | 是 | 玩家可见名。 |
| `Polarity` | enum | 是 | `Positive`、`Negative`、`Mixed`。 |
| `Category` | enum | 是 | `Trauma`、`Growth`、`Bond`、`Exploration`、`Workshop`。 |
| `SourceCondition` | object | 是 | 获得条件。 |
| `TriggerEvents` | string[] | 是 | 监听事件白名单。 |
| `Effects` | object[] | 是 | 引用 `EffectID`、`TagID` 或规则参数。 |
| `ConflictGroup` | string[] | 否 | 互斥 / 压制组。 |
| `TransformRule` | object | 是 | 转化、消除、压制或保留规则。 |
| `FeedbackRefs` | string[] | 否 | 关联反馈。 |
| `RoomMementoRefs` | string[] | 否 | 可触发的房间纪念物。 |
| `HistoryPolicy` | enum | 是 | `KeepHistory`、`RemoveOnTransform`、`HistoryOnlyAfterClear`。 |

首批 8 个特质：

| TraitID | 极性 | 来源 | 主要影响 | 转化 / 消除 |
|---|---|---|---|---|
| `trait_fear_of_spores` | `Negative` | 第二层孢雾 / 腐蚀类敌人导致 Broken 或战败。 | 孢雾、腐蚀节点预览时额外 SAN 压力或抗拒反馈。 | `maint_purification_flush` + 击败对应精英后转化为克服记录。 |
| `trait_grid_edge_anxiety` | `Negative` | 多次因边缘封格导致关键物品失效。 | 边缘格放关键装备时警告或小幅 SAN 压力。 | 装备 `prosthetic_anchor_left_arm` 并完成成功战斗后缓解。 |
| `trait_scrap_hoarder` | `Mixed` | 连续撤离保留大量低价废料。 | 废料识别 / 拆解收益；出售低价材料时抗拒。 | 完成订单交付或赠礼事件后转化为稳定拾荒习惯。 |
| `trait_steady_hands` | `Positive` | 低 HP / 低 SAN 下多次撤离成功。 | 本轮首次关键背包拖拽 / 旋转失误获得提示或宽限。 | 长期保留，可被重大创伤压制但历史不删除。 |
| `trait_miracle_afterglow` | `Mixed` | 高 Bond 触发奇迹后获得。 | Bond 反馈增强，同时 SAN 恢复或上限承受余波。 | 深层安抚或 Bond 里程碑后转为纪念历史。 |
| `trait_resolute_return` | `Positive` | 从第二层高压路线撤离并完成修复。 | 撤离节点识别或撤离后维护反馈增强。 | 长期保留，可被更高优先级剧情特质覆盖。 |
| `trait_fragile_trust` | `Negative` | 连续忽视低 SAN 警告并强行下潜。 | 交互收益降低，低 SAN 触摸更容易抗拒。 | 多日照料 + 不强行低 SAN 下潜后恢复信任。 |
| `trait_workshop_comfort` | `Positive` | 多次及时维护、赠礼和房间回访。 | 工坊中 SAN 反馈更稳定，温和台词更易触发。 | 长期保留，不直接提供战斗数值。 |

边界：

1. 负面特质必须有转化、消除或压制路径。
2. 正面特质不能无限叠加；每轮触发次数和叠加策略必须有上限。
3. 特质历史可以保留在存档 / 日记中，但不代表当前有效状态。

## 6. Feedback 字段与 8 条首批反馈

反馈配置可落在 `Dolls` 的反馈池、`Effects` 的 `feedbackEffects` 分区，或后续独立 `DollFeedback` 配置域；无论落点如何，必须能被交互事件和状态裁决引用。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `FeedbackID` | string | 是 | 反馈唯一 ID。 |
| `FeedbackType` | enum | 是 | `Touch`、`Gift`、`Maintenance`、`Milestone`、`SafeZone`、`Defeat`、`Room`。 |
| `TriggerCondition` | object | 是 | 触发条件。 |
| `ResultPolicy` | object | 是 | Bond / SAN / 情绪 / 特质输入裁决。 |
| `DialogueLineRef` | string | 否 | 台词引用或占位 key。 |
| `ExpressionID` | string | 否 | 表情引用，缺失时走 fallback。 |
| `MotionID` | string | 否 | 动作引用。 |
| `SfxID` | string | 否 | 音效引用。 |
| `LimitPolicyID` | string | 否 | 每日上限 / 冷却。 |
| `FallbackFeedbackID` | string | 是 | 资源或条件缺失时的 fallback。 |
| `LogReason` | string | 是 | 复盘日志原因。 |

首批 8 条反馈：

| FeedbackID | 类型 | 触发 | 裁决 |
|---|---|---|---|
| `fb_lowsan_touch_reject_face` | `Touch` | `CurrentSAN` 低于 Panic 阈值，玩家触摸 Face。 | 触发抗拒反馈，不增加 Bond，可写入近期事件。 |
| `fb_post_defeat_apology` | `Defeat` | 战败回城后首次进入工坊或对话。 | 小幅 Bond / SAN 反馈，可能触发修复目标提示。 |
| `fb_gift_miner_lamp_accept` | `Gift` | 赠送矿灯类纪念物且偏好匹配。 | 接受礼物，可触发 `memento_boss1_lamp` 或房间反馈。 |
| `fb_gift_core_fragment_silent` | `Gift` | 赠送 Boss 核心碎片或高压材料。 | 不一定增加 Bond，优先触发沉默 / 回忆反馈。 |
| `fb_maintenance_reassure` | `Maintenance` | 标准维护完成且人偶未 Broken。 | 小幅稳定 SAN，记录被照料感。 |
| `fb_deep_therapy_break_recover` | `Maintenance` | Broken 后深度疗愈完成。 | 解除或推进解除 Broken，可能推进 Day。 |
| `fb_bond_milestone_after_boss1` | `Milestone` | Boss1 后 Bond 达到指定阈值。 | 触发里程碑对话，写入房间 / 日记候选。 |
| `fb_safezone_after_layer2` | `SafeZone` | 第二层安全区全恢复后首次通讯。 | 只做上下文反馈，不额外恢复 HP / SAN。 |

关键边界：

1. 低 SAN 拒绝触摸不能增加 Bond。
2. 安全区反馈不能重复结算免费全恢复，安全区恢复仍由安全区服务处理。
3. 赠礼拒收时不消耗物品；接受后是否消耗由 `ConsumePolicy` 决定。
4. 反馈可触发房间记忆候选，但不能直接复制物品到房间仓库。

## 7. Room Memento 字段与 8 个首批纪念物

Room Memento 是经历痕迹，不是背包物品、仓库物品或防出售机制。它可以显示视觉、写日记、触发观察反馈，但不能提供强制战力收益。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `MementoID` | string | 是 | 纪念物唯一 ID。 |
| `DisplayName` | string | 是 | 玩家可见或日记可读名称。 |
| `TriggerCondition` | object | 是 | 触发条件。 |
| `TargetRoomID` | string | 是 | 所属房间，首批建议 `room_attic_default`。 |
| `TargetSlotID` | string | 是 | 出现槽位。 |
| `VisualID` | string | 否 | 视觉资源，缺失时走 fallback。 |
| `DiaryEntryID` | string | 否 | 日记条目。 |
| `FeedbackRefs` | string[] | 否 | 点击 / 观察反馈。 |
| `Priority` | int | 是 | 同槽冲突时优先级。 |
| `CanHide` | bool | 是 | 默认 false。 |
| `CanRemove` | bool | 是 | 默认 false。 |
| `InventoryLinkPolicy` | enum | 是 | 必须是 `NoInventoryDuplication` 或等价策略。 |
| `HistoryPolicy` | enum | 是 | 来源物品消失后是否保留历史。 |

首批 8 个纪念物：

| MementoID | 触发 | 房间职责 | 边界 |
|---|---|---|---|
| `memento_first_repair_patch` | 首次执行 `maint_basic_patch`。 | 记录第一次修补。 | 不返还修理材料。 |
| `memento_first_chassis_frame` | 首次安装或确认 `chassis_standard_frame`。 | 记录默认底盘 / 基础身体框架。 | 不等于额外底盘库存。 |
| `memento_first_prosthetic_case` | 首次制造或安装正式义体。 | 展示义体收纳盒 / 旧包装。 | 不复制义体。 |
| `memento_san_collapse_blanket` | 首次 SAN 崩溃后完成安抚。 | 记录崩溃恢复。 | 不提供免费 SAN 恢复。 |
| `memento_miracle_burn_mark` | 首次触发奇迹。 | 记录代价与余辉。 | 不能被玩家主动刷。 |
| `memento_boss1_lamp` | 第一层 Boss 后赠送矿灯或同等纪念物。 | 成为房间光源 / 回忆点。 | 若来源物品被消耗，只保留纪念表现。 |
| `memento_layer2_corrosion_vial` | 第二层腐蚀路线撤离并完成净化。 | 记录腐蚀压力与净化经历。 | 不作为材料库存。 |
| `memento_return_mark` | 高压路线撤离并完成修复。 | 记录“回来了”的长期记忆。 | 不提供撤离保底。 |

## 8. 跨配置引用

| 引用方向 | 规则 |
|---|---|
| `Dolls.DefaultChassisID -> Chassis.ChassisID` | 必须存在；首批正式值为 `chassis_standard_frame`。 |
| `Dolls.FeedbackSetRefs -> FeedbackID` | 必须存在或有占位 warning。 |
| `Dolls.RoomFeedbackPools -> FeedbackID / RoomFeedbackID` | 房间观察反馈必须有 fallback。 |
| `Trait.Effects -> Effects.EffectID / TagID` | 必须存在；负面特质必须有清除 / 转化路径。 |
| `Trait.FeedbackRefs -> FeedbackID` | 反馈不存在时 warning；核心裁决不能丢。 |
| `Feedback.ResultPolicy -> Bond / SAN / Emotion / Trait` | 必须能追到 `08`、`09` 的规则。 |
| `RoomMemento.TriggerCondition -> Event / Maintenance / Boss / Gift / Trait` | 触发条件必须可解析，不能只写自然语言。 |
| `RoomMemento.VisualID -> Art / VisualID` | 资源可缺失但必须有 fallback。 |
| `RoomMemento.InventoryLinkPolicy -> Items` | 只记录来源，不复制物品，不防出售。 |

## 11. 完成判定

`GROWTH-DOLL-TRAIT-ROOM` 只有在以下条件满足后，才能视为策划字段级设计完成：

1. Doll 静态档案字段、旧字段迁移和运行时拆分边界清楚。
2. 8 个首批 TraitID 有来源、效果、反馈、冲突和转化 / 消除路径。
3. 8 个首批 FeedbackID 有触发、裁决、表现 fallback 和防刷 / 无收益边界。
4. 8 个首批 MementoID 有触发、槽位、日记 / 反馈、优先级和不复制物品边界。
5. `CFG-DOLL-*`、`CFG-TRAIT-*`、`CFG-FEEDBACK-*`、`CFG-ROOM-MEMORY-*` Validator 建议明确。
6. 固定验收样例覆盖静态档案、特质、反馈和房间纪念物。

本文完成后，只能在 `26` / `38` / `agent_status/design.md` 中记录为 `GROWTH-DOLL-TRAIT-ROOM` 字段级设计完成。Dolls、Traits、Feedback、RoomMemory 的 JSON 配置源仍需后续实现；未修改 JSON、未同步配置、未跑 Validator 前，不能标记 `配置完成`。
