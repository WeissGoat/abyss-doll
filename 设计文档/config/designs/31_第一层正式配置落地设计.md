# 第一层正式配置落地设计

> **定位：** 本文是 `26_正式配置设计与填充推进计划.md` 中 W2「前三层正式配置补齐」的第一份落地产物。它只负责第一层 `Items` / `Monsters` / `Dungeons` / `Rewards` 的配置落地设计，把 `19` 内容包和 `27-30` 审计结论转成后续改 JSON 前的策划清单。本文不直接修改 JSON，不替代配置 README，也不表示配置已经完成。

---

## 1. 落地目标

第一层配置落地的目标不是“多加一些条目”，而是让第一层能稳定完成正式低压入口体验：

```text
备战 -> 第一层地图路线 -> 普通战斗 -> 战利品取舍 -> 可绕精英 -> Boss -> Boss 后安全区 -> 撤离 / 深入 -> 回城出售 / 制造 / 房间记忆
```

本轮第一层配置设计必须满足：

| 目标 | 完成口径 |
|---|---|
| 物品闭环 | 12 件第一层物品都有明确 `ConfigID`、形状、职责、来源和去向。 |
| 怪物闭环 | 5 个普通 / 精英怪 + 1 个 Boss 有独立职责、意图、奖励和反制方式。 |
| 地图闭环 | 2 个 MapProfile、至少 2 条有效路线、1 个可绕精英、Boss 后 SafeZone。 |
| 奖励闭环 | 普通怪、精英、Boss、宝箱、事件奖励职责拆开，Boss 保底从精英奖励中迁出。 |
| 验收闭环 | 至少能支撑 `V-L1-PACK-RUN-01`、`V-L1-PACK-RUN-02`、`V-L1-PACK-RUN-03`、`V-L1-PACK-FAIL-01`。 |

---

## 2. 本轮不处理范围

| 范围外 | 原因 |
|---|---|
| 第二层 / 第三层 JSON 落地 | 先把第一层作为模板跑通，再复制方法到二三层。 |
| 第四层及以后内容 | 当前不抢内容铺量。 |
| 程序字段实现 | 本文只给策划配置设计；程序是否支持由开发文档和代码事实判断。 |
| 美术资源生成 | 本文只写 VisualID / 表现需求，不生成素材。 |
| 实际 JSON 改值 | 后续单独进入配置实现批次时处理。 |

---

## 3. 第一层配置落地顺序

建议按以下顺序改配置，避免引用断裂：

1. `Items`：先补齐第一层物品 ID、形状、职责、来源和去向。
2. `Rewards`：补普通怪、宝箱、事件、精英和 Boss 奖励表，保证物品有来源。
3. `Monsters`：补第一层怪物和 Boss，并把 `RewardID` 指到奖励表。
4. `Dungeons`：补 MapProfile、节点池、BossNode、SafeZone 和固定 seed 样例。
5. Validator / 验收样例：最后把第一层固定路径纳入机械检查。

原因：怪物和地图会引用物品 / 奖励；先补物品和奖励能减少后续反复改引用。

### 5.2 Boss 保底迁移规则

当前 `reward_monster_elite_scrap_guard` 带有 `mat_core_tier1` 保底。正式落地时必须迁移：

```text
reward_monster_elite_scrap_guard.Guaranteed 移除 mat_core_tier1
reward_boss_gatekeeper_mk1.Guaranteed 新增 mat_core_tier1
```

迁移后：

| 来源 | 保底成长材料 | 说明 |
|---|---|---|
| `elite_scrap_guard` | 无 | 精英奖励更高，但不承担层级通关成长钥匙。 |
| `boss_gatekeeper_mk1` | `mat_core_tier1` | Boss 是第一层成长钥匙来源。 |

### 6.1 第一层怪物配置清单

| MonsterID | 落地动作 | MonsterRole | IntentList | RewardID | 投放 |
|---|---|---|---|---|---|
| `mob_scavenger_bug` | 保留并补字段 | `Tutorial`, `Pressure` | `AttackSmall`, `DefendSmall` | `reward_monster_mob_scavenger_bug` | 普通战斗池 |
| `mob_rust_hound` | 新增 | `Tutorial`, `CounterCheck` | `AttackSmall`, `ChargeAttack` | `reward_monster_mob_rust_hound` | 普通 / 冒险路线 |
| `mob_acid_slime` | 调整为一层轻塞包 | `PackInterference`, `Tutorial` | `AttackSmall`, `AddJunkSmall` | `reward_monster_mob_acid_slime_l1` | 后半程 / 事件路线 |
| `mob_lost_miner_echo` | 新增 | `SanPressure`, `Narrative` | `SanPressureSmall`, `AttackSmall` | `reward_monster_mob_lost_miner_echo` | 探索路线 / 事件路线 |
| `elite_scrap_guard` | 保留并回归精英 | `Elite`, `CounterCheck` | `Defend`, `HeavyAttack`, `GridLockEdgeSmall` | `reward_monster_elite_scrap_guard` | 精英池，可绕 |
| `boss_gatekeeper_mk1` | 新增 | `Boss`, `RouteGate` | `Attack`, `Defend`, `GridLockEdgeSmall`, `BossPhase` | `reward_boss_gatekeeper_mk1` | BossNode |

### 6.2 第一层意图边界

| IntentType | 第一层允许程度 | 说明 |
|---|---|---|
| `Attack` | 常规 | 基础伤害教学。 |
| `Defend` | 常规 | 教玩家不要无脑输出。 |
| `Charge` | 低频 | 只给锈牙犬使用，作为重击预告。 |
| `AddJunk` | 轻度 | 只塞 1x1 临时残渣，不覆盖已有物品。 |
| `GridLock` | 精英 / Boss 低频 | 只锁边缘 1 格，本战结束后解除。 |
| `SanPressure` | 低压 | 只做小额 SAN 压力和提示。 |
| `PolluteItem` / `CorrodeItem` | 不投放 | 留到第二 / 第三层。 |

### 6.3 Boss 行为模板

`boss_gatekeeper_mk1` 建议用两阶段：

| 阶段 | 条件 | 行为 |
|---|---|---|
| Phase 1 | HP > 50% | `Attack` 与 `Defend` 交替，偶尔重击预告。 |
| Phase 2 | HP <= 50% | 每 3 回合加入 `GridLockEdgeSmall`，锁边缘 1 格，本战结束解除。 |

Boss 不做召唤、不做永久污染、不做多目标复杂连锁。

## 8. 第一层验收样例

### 8.1 `V-L1-CONFIG-COVERAGE-01`

| 项 | 内容 |
|---|---|
| 输入 | 扫描第一层配置目标清单。 |
| 期望 | 12 个 Item、6 个 Monster、2 个 MapProfile、9 个 RewardID 都有配置或明确替代 ID。 |
| 失败 | 任一关键 ID 既不存在，也没有替代 ID 或后续批次标记。 |

### 8.2 `V-L1-SEED-1024-ROUTE-01`

| 项 | 内容 |
|---|---|
| 输入 | `LayerID=1`、`MapProfileID=layer1_tutorial_branching`、`RunSeed=1024`。 |
| 期望 | 至少 2 条有效路线；精英可绕；Boss 可达；Boss 后 SafeZone 存在。 |
| 失败 | 单线、精英必经、Boss 不可达、Boss 后没有撤离 / 深入选择。 |

### 8.3 `V-L1-BOSS-REWARD-01`

| 项 | 内容 |
|---|---|
| 输入 | 击败 `boss_gatekeeper_mk1`。 |
| 期望 | 保底获得 `mat_core_tier1`；额外奖励进入拾取面板；Boss 后安全区免费恢复 HP / SAN。 |
| 失败 | 保底仍挂在 `elite_scrap_guard`，或 Boss 只掉金币 / 空奖励。 |

### 8.4 `V-L1-PACK-PRESSURE-01`

| 项 | 内容 |
|---|---|
| 输入 | 玩家背包剩余 3-4 格，掉落 `loot_toxic_filter` 或 `trade_cracked_relic`。 |
| 期望 | 玩家必须在低价物、风险物和战斗装备之间做取舍。 |
| 失败 | 高价值物无体积压力，或风险标签不可见。 |

## 9. 配置实现前检查清单

进入 JSON 修改前，先确认：

1. `Items` README 已支持正式字段组。
2. `Monsters` README 已支持意图、Boss / 精英和对包干涉字段。
3. `Dungeons` README 已支持 MapProfile、SafeZone 和 seed 摘要字段。
4. `Rewards` README 已支持 BossDrop、EventNode、TreasureNode 和成长 / 记忆引用。
5. 本文列出的新增 ID 不与现有 JSON 冲突。
6. 如果程序字段暂不支持，先按 README 口径写 TODO / Validator warning，不把正式目标降级成旧字段。

## 10. 后续落地顺序

后续真正进入配置实现时，建议拆成 4 个小任务：

1. `L1-ITEMS`：补第一层 12 件物品的字段、形状和新增 ID。
2. `L1-REWARDS`：补第一层 9 个奖励表，拆出 Boss 奖励。
3. `L1-MONSTERS`：补第一层 6 个怪物 / Boss，回归精英职责。
4. `L1-DUNGEONS`：补第一层 2 个 MapProfile、节点池和固定 seed 验收。

完成后再进入第二层配置落地设计，而不是直接跳到第三层或局外成长。
