# 局外成长制造维护正式配置落地设计

> 本文承接 `38_局外成长正式配置实现任务拆分.md` 的 `GROWTH-CRAFT-MAINT`。它把义体制造、底盘解锁、维护方案和材料来源转成 JSON 修改前字段级清单，供后续配置实现使用。本文不直接修改 `配置表(JSON)`，不代表配方或维护 JSON 已完成。

---

## 1. 当前事实

### 1.1 CraftingRecipes

当前 `配置表(JSON)/CraftingRecipes` 只有两个旧原型配方：

| 文件 | 当前 ID | 输出 | 当前成本 | 正式判断 |
|---|---|---|---|---|
| `craft_pros_power_arm.json` | `craft_pros_power_arm` | `pros_power_arm` | 300 金币 + `loot_gear_scrap` x2 | 旧 MVP / 原型义体配方，可作为 `craft_prosthetic_charge_coil_arm` 的成本参考，但不能视为正式配方完成。 |
| `craft_pros_cooling_system.json` | `craft_pros_cooling_system` | `pros_cooling_system` | 1000 金币 + `loot_gear_scrap` x2 | 旧 MVP / 原型 SAN 义体配方，成本过重且缺少净化材料、疲劳和维护链引用。 |

现有问题：

1. 旧配方使用 `TargetProstheticID`、`Cost.Money` 和 `Cost.RequiredItems`，尚未落到正式 `RecipeType`、`GoldCost`、`OutputProstheticID`、`ConsumePolicy`、`CancelPolicy`。
2. 旧输出仍指向 `pros_*` 原型义体，不能连接 `42` 锁定的正式 `prosthetic_*` ID。
3. 当前没有底盘解锁配方，也没有维护方案配方或维护动作配置入口。
4. 当前配方没有图纸、层级、Boss / 精英材料、订单保护物、污染继承和取消策略。

### 1.2 Maintenance

当前 `配置表(JSON)/Maintenance` 已有两个维护方案：

| 文件 | 当前 ID | 当前效果 | 当前成本 | 正式判断 |
|---|---|---|---|---|
| `maint_basic_patch.json` | `maint_basic_patch` | Wear -40、HP +20 | 50 金币 + `loot_gear_scrap` x1 | ID 与正式设计一致，可继续补正式字段；当前效果数值方向可保留，但字段和边界不完整。 |
| `maint_purification_flush.json` | `maint_purification_flush` | Corruption -40、SAN +10 | 80 金币 + `loot_toxic_filter` x1 | ID 与正式设计一致，可继续补正式字段；当前已体现净化方向，但缺少标签清除、低 SAN 反馈和副作用边界。 |

现有问题：

1. 两个现有维护方案只有 `Name`、`Description`、`QualityTier`、`Cost`、`Effects`、`DailyLimit`、`RestoresDivePermit`，缺少正式 `DisplayName`、`DescriptionKey`、`TargetStates`、`EffectRefs`、`UnlockCondition`、`SideEffects`、`DiveReadinessImpact`、`TraitTransformRefs`、`FeedbackRefs`。
2. 还缺少 `maint_standard_overhaul`、`maint_deep_therapy`、`maint_field_tuning`。
3. 维护方案需要明确不能免费清除订单、污染物、背包满载和特质历史。

## 2. 本轮目标

`GROWTH-CRAFT-MAINT` 本轮处理以下配置：

| 类型 | 数量 | ID |
|---|---:|---|
| 义体制造配方 | 6 | `craft_prosthetic_focus_lens`、`craft_prosthetic_anchor_left_arm`、`craft_prosthetic_charge_coil_arm`、`craft_prosthetic_san_regulator_core`、`craft_prosthetic_salvage_fingertips`、`craft_prosthetic_mender_spine` |
| 底盘解锁配方 | 2 | `craft_chassis_compact_raider`、`craft_chassis_bulwark_carrier` |
| 维护方案 | 5 | `maint_basic_patch`、`maint_standard_overhaul`、`maint_purification_flush`、`maint_deep_therapy`、`maint_field_tuning` |

设计原则：

1. 制造和维护是深渊掉落回流局外成长的主要入口，不能只是金币扣除。
2. 每个配方必须能追到前三层材料、Boss 核心、精英材料、订单或图纸来源；暂不存在的材料 ID 必须标为待补，不假装已存在。
3. 维护方案要解决明确状态，但不能免费覆盖所有压力。
4. 旧 `craft_pros_*`、`pros_*` 可以作为迁移参考，不能作为正式主 ID。
5. 如果程序暂不支持某字段，配置仍保留正式字段，Validator 先给 warning，不删除正式口径。

## 3. 字段标准

### 3.1 Recipe 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `RecipeID` | string | 是 | 全局唯一 ID。正式 ID 使用 `craft_*`。 |
| `RecipeType` | string | 是 | `Prosthetic`、`ChassisUnlock`、`Maintenance`、`MaterialConvert`、`OrderProcess`、`ItemCraft`。 |
| `DisplayName` | string | 是 | 玩家可见名。 |
| `DescriptionKey` | string | 是 | 本地化描述 Key，说明输出、用途和风险。 |
| `RequiredItems` | object[] | 否 | 指定材料 ID，元素包含 `ConfigID`、`Count`、`SourceHint`。 |
| `RequiredTags` | object[] | 否 | 按标签输入，元素包含 `Tag`、`Count`、`AllowedItemIDs`。 |
| `GoldCost` | int | 是 | 金币成本。旧 `Cost.Money` 可兼容映射。 |
| `BlueprintCondition` | object | 否 | 图纸、层级、Boss、精英、订单或剧情解锁。 |
| `OutputItemID` | string | 否 | 输出物品 ID。 |
| `OutputProstheticID` | string | 否 | 输出义体 ID。旧 `TargetProstheticID` 可兼容映射。 |
| `OutputChassisUnlock` | string | 否 | 解锁底盘 ID。 |
| `OutputMaintenanceID` | string | 否 | 维护类配方引用的维护方案 ID。 |
| `OutputCount` | int | 否 | 默认 1。 |
| `ConsumePolicy` | string | 是 | `ConsumeAll`、`KeepQuestBound`、`KeepRiskTags` 等。 |
| `InheritTagsPolicy` | string | 否 | 污染、订单、纪念物等标签如何进入输出或副作用。 |
| `CancelPolicy` | string | 是 | `RefundUnstarted`、`NoCancelAfterComplete`、`PartialRefundAfterStart`。 |
| `UnlockCondition` | object | 否 | 层级、设施、订单、剧情或前置配方条件。 |
| `RiskTags` | string[] | 否 | 配方带来的风险标签，例如 `CorruptionCarry`。 |

### 3.2 Maintenance 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `MaintenanceID` | string | 是 | 全局唯一 ID。 |
| `DisplayName` | string | 是 | 玩家可见名。旧 `Name` 只作兼容别名。 |
| `DescriptionKey` | string | 是 | 本地化描述 Key，必须说明恢复对象和边界。 |
| `TargetStates` | string[] | 是 | `HP`、`SAN`、`Wear`、`Corruption`、`Broken`、`ProstheticStability`、`TraitTransform`。 |
| `EffectRefs` | object[] | 是 | 引用 `41` 中维护效果，例如 `effect_maint_restore_hp`。 |
| `RequiredItems` | object[] | 否 | 维护材料。旧 `Cost.RequiredItems` 可兼容映射。 |
| `GoldCost` | int | 是 | 金币成本。旧 `Cost.Money` 可兼容映射。 |
| `UnlockCondition` | object | 否 | 层级、状态、设施或事件条件。 |
| `SideEffects` | object[] | 否 | 疲劳、冷感、Day 推进、Bond 反馈等副作用。 |
| `DiveReadinessImpact` | object | 是 | 是否恢复下潜许可、恢复到什么条件。 |
| `TraitTransformRefs` | string[] | 否 | 推进或转化哪些特质。 |
| `FeedbackRefs` | string[] | 否 | 维护后交互反馈 ID。 |

## 7. 维护方案

### 7.1 总表

| MaintenanceID | 定位 | TargetStates | 材料 | 成本建议 | 边界 |
|---|---|---|---|---:|---|
| `maint_basic_patch` | 临时补片 | `Wear`、`HP` | `loot_gear_scrap` | 50 | 不处理侵蚀、Broken 或特质。 |
| `maint_standard_overhaul` | 标准整备 | `Wear`、`HP`、`SAN` | `loot_gear_scrap`、`loot_rusty_coil` | 120 | 日常恢复基准，刷新下潜许可。 |

| `maint_field_tuning` | 下潜前微调 | `ProstheticStability` | 义体相关材料 | 60 | 只持续一次下潜，不能叠加。 |

## 8. 消耗、取消和保护策略

| 策略 | 配方 / 维护使用 | 规则 |
|---|---|---|
| `ConsumeAll` | 普通材料、金币。 | 完成后完整消耗。 |
| `KeepQuestBound` | 所有义体、底盘配方默认使用。 | 订单绑定、剧情锁定、情感锚点物不能被普通制造消耗。 |
| `KeepRiskTags` | 污染材料参与制造或净化。 | 风险标签进入输出、副作用或维护反馈，不能静默消失。 |
| `RefundUnstarted` | 当前所有工坊配方默认。 | 未开始时全额返还。 |
| `NoCancelAfterComplete` | 完成后的义体、底盘解锁、维护。 | 已完成不能撤销，但可通过拆解、卸装或后续维护处理。 |
| `PartialRefundAfterStart` | 未来制造时间系统。 | 当前不默认启用；程序支持前不要使用。 |

硬边界：

1. 订单绑定物、剧情锁定物和情感锚点物不得被普通制造吞掉。
2. 取消制造不能复制材料或让金币变负。
3. 污染材料不能通过普通制造无成本洗白。
4. 维护不能免费清空所有状态；安全区全恢复只覆盖 HP / SAN，维护也要保留订单、污染物、背包压力和特质历史边界。

## 11. 完成判定

`GROWTH-CRAFT-MAINT` 只有在以下条件满足后，才能视为制造 / 维护配置域局部完成：

1. `配置表(JSON)/CraftingRecipes` 中存在 6 个正式义体制造配方和 2 个正式底盘解锁配方，或存在明确迁移后的等价结构。
2. `配置表(JSON)/Maintenance` 中存在 5 个正式维护方案，且 `maint_basic_patch`、`maint_purification_flush` 不重复创建。
3. 每个配方都有输入、输出、金币、图纸 / 解锁、消耗策略、取消策略和风险边界。
4. 每个维护方案都有目标状态、效果引用、成本、副作用、下潜许可影响、反馈和特质转化边界。
5. 配方输入材料能追到当前 Items、前三层内容包、Boss / 精英材料、订单或明确待补材料 warning。
6. 旧 `craft_pros_*` 不被误判为正式完成；旧 `pros_*` 输出不进入正式主配方。
7. `CFG-CRAFT-*`、`CFG-MAINT-*` 或人工等价检查通过。
8. 至少覆盖 `V-GROWTH-CRAFT-01`、`V-GROWTH-CRAFT-02`、`V-GROWTH-MAINT-01`、`V-GROWTH-MAINT-02`。
9. `agent_status/design.md` 的 `DES-V3-002` 追加本文证据；如影响长期节点门禁，PM 同步 `09`，但整个局外成长配置仍不能因此标记为 `配置完成`。
