# 局外成长正式配置落地设计

> 本文是 `26_正式配置设计与填充推进计划.md` 中 W3「局外成长与经济目标补齐」的第二份落地产物。它把 `36_局外成长正式配置承接审计.md` 的字段缺口和 `21_人偶成长修复内容包.md` 的内容条目转成 JSON 修改前策划清单。后续配置实现派发与证据口径见 `38_局外成长正式配置实现任务拆分.md`。本文不直接修改 JSON，不代表局外成长配置、程序服务或 UI / 美术表现已经完成。

---

## 1. 落地目标

局外成长配置落地的目标是让玩家在前三层深渊后形成稳定的回城决策：

```text
带回材料 / 核心 / 纪念物
  -> 修复 HP / SAN / 磨损 / 侵蚀
  -> 选择底盘 / 义体 / 维护方案 / 特质转化
  -> 看到下潜许可和新构筑方向
  -> 再次进入第二层或第三层
```

本轮不追求完整养成大系统铺量，优先把正式规则骨架落成可配置、可校验、可复盘的首批内容：

| 模块 | 本轮目标量 | 完成口径 |
|---|---:|---|
| 底盘 `Chassis` | 3 个 | 标准、轻装、重载三类构筑方向都有字段、成本、槽位、维护代价和验收路径。 |
| 义体 `Prosthetics` | 6 个 | 覆盖地图阅读、背包干涉抵抗、战斗爆发、SAN 稳定、材料转化、长线恢复。 |
| 配方 / 维护 `CraftingRecipes` | 义体配方 6 个 + 维护方案 5 个 | 前三层材料能进入制造、维护、污染处理和成长目标。 |
| 人偶 / 特质 / 反馈 / 房间 | 1 套基础档案边界 + 8 特质 + 8 反馈 + 8 纪念物 | 人偶状态、交互反馈和房间记忆能记录深渊经历。 |
| 验收 | 4 条联合路径 + 模块级 Validator | 覆盖修复、成长、情绪、房间四条主路径。 |

---

## 2. 本轮不处理范围

| 范围外 | 原因 |
|---|---|
| 完整义体池、完整天赋树、完整服装系统 | 属于后续正式内容扩展，不抢当前 W3 首轮落地。 |
| 实际 JSON 改值 | 本文只提供 JSON 修改前策划清单。 |
| 程序字段实现 | 由开发文档、代码事实和程序台账判断。 |
| UI / 美术资源生成 | 本文只给表现需求和 VisualID 预留，不产出素材。 |
| 房间仓库功能 | 当前口径下房间只记录经历，不承担仓库。 |

---

## 3. 推荐落地顺序

| 顺序 | 任务 ID | 目标 | 原因 |
|---:|---|---|---|
| 1 | `GROWTH-README` | 先同步五个配置 README 的正式字段、运行时边界、引用关系和 Validator 口径。 | 避免 JSON 先行后字段解释不一致。 |
| 2 | `GROWTH-CHASSIS` | 补 3 个底盘的 JSON 修改前清单。 | 底盘决定背包形状、义体槽和下潜许可，是成长骨架。 |
| 3 | `GROWTH-PROSTHETICS` | 补 6 个义体的槽位、触发、互斥、成本和反馈。 | 义体引用 Effects / CraftingRecipes，需要在配方前确定目标 ID。 |
| 4 | `GROWTH-CRAFT-MAINT` | 补制造配方、维护方案、材料转化、取消和污染继承口径。 | 让前三层战利品进入局外消耗。 |
| 5 | `GROWTH-DOLL-TRAIT-ROOM` | 补 Dolls 静态档案边界、特质、交互反馈、房间纪念物。 | 把成长结果沉淀到人偶状态和长期记忆。 |
| 6 | `GROWTH-VALIDATION` | 补 Validator、固定样例和台账回写证据。 | 防止 README / 策划清单被误判为配置完成。 |

## 4. `GROWTH-README` 字段同步清单

### 4.1 `Chassis` README

| 字段组 | 必须补充 | 说明 |
|---|---|---|
| 身份 | `DisplayName`、`DescriptionKey`、`ChassisRole`、`VisualID` | 底盘是构筑方向，不是单纯等级。 |
| 背包 | `GridWidth`、`GridHeight`、`GridMask`、`BaseSlotTags` | 允许异形背包和槽位语义。 |
| 义体槽 | `AllowedProstheticSlots` | 底盘决定义体槽上限和类型。 |
| 解锁 | `UnlockCondition`、`BlueprintRef`、`BuildCost`、`InstallCost` | 区分图纸、材料、金币和更换成本。 |
| 代价 | `AdaptationDays`、`MaintenanceModifier`、`RiskTags` | 强底盘必须带维护或适应期压力。 |
| 规则 | `RuleModifiers`、`EndingTags` | 支撑路线预览、封格抗性、结局倾向。 |

### 4.2 `Prosthetics` README

| 字段组 | 必须补充 | 说明 |
|---|---|---|
| 身份 | `DisplayName`、`DescriptionKey`、`VisualID`、`Tier` | 取代 MVP `Name` / `Level` 的模糊口径。 |
| 装配 | `SlotType`、`ConflictGroup`、`InstallCost` | 同槽互斥和跨槽冲突都走配置。 |
| 效果 | `EffectRefs`、`TriggerRules`、`Tags` | 说明何时生效，不只写 EffectID。 |
| 解锁制造 | `UnlockCondition`、`CraftRecipeRef`、`CraftCost` | 与配方表互相引用。 |
| 维护 | `MaintenanceModifier`、`WearImpact`、`CorruptionImpact` | 义体强度要有长期代价。 |
| 反馈 | `FeedbackRefs` | 生效时 UI / 文案 / 动效可读。 |

### 4.3 `CraftingRecipes` README

| 字段组 | 必须补充 | 说明 |
|---|---|---|
| 类型 | `RecipeType` | `Prosthetic`、`ChassisUnlock`、`Maintenance`、`MaterialConvert`、`OrderProcess`。 |
| 输入 | `RequiredItems`、`RequiredTags`、`GoldCost`、`BlueprintCondition` | 支持按 ID 和按标签消耗。 |
| 输出 | `OutputItemID`、`OutputProstheticID`、`OutputChassisUnlock`、`OutputMaintenanceID`、`OutputCount` | 支持多种工坊产物。 |
| 消耗 | `ConsumePolicy`、`InheritTagsPolicy` | 订单绑定、污染物和情感锚点不能误消耗。 |
| 取消 | `CancelPolicy` | 避免复制、吞材料或金币负数。 |

### 4.4 `Dolls` README

| 字段组 | 必须补充 | 说明 |
|---|---|---|
| 静态档案 | `DollID`、`DisplayName`、`BaseProfileID`、`DefaultRoomID` | 静态配置只定义基础档案。 |
| 基础上限 | `BaseMaxHP`、`BaseMaxSAN`、`BaseBondCurveID` | 运行时当前值不写进基础档案。 |
| 情绪 / Bond / SAN | `EmotionStateSet`、`BondThresholds`、`SanThresholds`、`MiraclePolicyID`、`SanBreakPolicyID` | 支撑情绪、奇迹和崩溃。 |
| 交互 | `LikeTags`、`DislikeTags`、`AllowedInteractionRefs`、`FeedbackSetRefs` | 连接赠礼、触摸、对话、维护反馈。 |
| 房间 | `RoomPreferenceTags`、`DefaultIdlePoseRules`、`RoomFeedbackPools` | 连接房间视觉叙事。 |
| 资源 | `ExpressionVisualIDs`、`MotionIDs`、`FallbackVisualID` | 所有可见状态必须有 fallback。 |

### 4.5 `Effects` README

| 字段组 | 必须补充 | 说明 |
|---|---|---|
| 效果字典 | `EffectID`、`TriggerTiming`、`ConfigSchema` | 继续作为底层效果词典。 |
| 标签 | `TagID`、`TagGroup`、`AttachableScope`、`VisibleToPlayer` | 标签不直接执行效果。 |
| 动态标签 | `DurationType`、`StackPolicy`、`ClearRule` | 支撑污染、恐惧、适应期等临时状态。 |
| 特质 | `TraitID`、`Polarity`、`Trigger`、`Conditions`、`Effects`、`ConflictGroup`、`TransformRule` | 支撑创伤、成长和转化。 |
| 维护 / 房间效果 | `MaintenanceEffectRefs`、`RoomFeedbackEffectRefs` | 不把所有反馈塞进数值效果。 |

## 5. `GROWTH-CHASSIS` 底盘落地清单

### 5.1 底盘配置目标

| ChassisID | ChassisRole | Grid 口径 | 义体槽 | 解锁来源 | 成本与代价 | 验收 |
|---|---|---|---|---|---|---|
| `chassis_standard_frame` | `Baseline`, `Tutorial` | 6x4 标准矩形或当前基础网格等价口径 | `CorePump`、`LeftArm`、`RightArm`、`HeadSensor` 基础槽 | 初始拥有 | 维护倍率 1.0，无适应期 | `V-PACK-DOLL-CHASSIS-01` 基准对照 |
| `chassis_compact_raider` | `Scout`, `Extract`, `RoutePreview` | 总面积低于标准，但边角更规整 | 优先 `HeadSensor` / `Legs`，手臂槽受限 | 第一层 Boss 核心 + 掠行图纸 | MaxHP 或负重能力下降；适应期 1 天 | `V-PACK-DOLL-BUILD-01` |
| `chassis_bulwark_carrier` | `HeavyCarry`, `Order`, `GridResist` | 面积高于标准，可承载长条 / 大件 | 优先 `LeftArm` / `RightArm` / `CorePump` | 第二层精英材料 + 承运图纸 | 维护倍率提高；适应期 2 天 | `V-PACK-DOLL-BUILD-02` |

### 5.3 Validator

| ValidatorID | 检查 |
|---|---|
| `CFG-CHASSIS-001` | 必填字段、唯一 ID、`ChassisRole` 非空。 |
| `CFG-CHASSIS-002` | `GridMask` 与宽高一致，至少 1 个可用格。 |
| `CFG-CHASSIS-003` | `BlueprintRef`、`RequiredItems`、`VisualID` 引用存在或有明确占位规则。 |
| `CFG-CHASSIS-004` | `AllowedProstheticSlots` 必须来自正式槽位枚举。 |
| `CFG-CHASSIS-005` | `AdaptationDays`、`MaintenanceModifier` 值域合法。 |

## 6. `GROWTH-PROSTHETICS` 义体落地清单

| ProstheticID | 槽位 | 构筑职责 | 触发规则 | 成本来源 | 代价 / 冲突 | 验收 |
|---|---|---|---|---|---|---|
| `prosthetic_focus_lens` | `HeadSensor` | 地图阅读、路线规划 | 进入地图时揭示相邻未探索节点类型倾向 | 第一层矿灯 / 镜片材料 | 与高级战斗传感器互斥 | `V-PACK-DOLL-PROSTHETIC-01` |
| `prosthetic_anchor_left_arm` | `LeftArm` | 抵抗塞包 / 封格 | 每场战斗首次降低背包干涉强度 | 第二层封格材料 | 与重型盾臂互斥，维护倍率提高 | `V-PACK-DOLL-PROSTHETIC-02` |
| `prosthetic_charge_coil_arm` | `RightArm` | 充能武器爆发 | 使用 `Charge` / `Electric` 标签物品后积层 | 线圈、源石、金币 | 与稳定盾臂互斥，连续触发加磨损 | `V-PACK-DOLL-GROWTH-01` |
| `prosthetic_san_regulator_core` | `CorePump` | 降低短线崩溃风险 | 单次 SAN 损失超过阈值时部分削减 | 冷却核心、净化材料 | 产生调节疲劳，不能免疫 Broken | `V-PACK-DOLL-PROSTHETIC-03` |
| `prosthetic_salvage_fingertips` | `RightHand` | 材料转化、拾荒收益 | 撤离结算时对机械 / 源石材料提供拆解增益 | 废料、精密零件 | 对战斗无直接收益 | `V-GROWTH-CRAFT-01` |
| `prosthetic_mender_spine` | `BackSpine` | 长线恢复、安全区后续修复 | 安全区全恢复后额外降低少量磨损或侵蚀压力 | 第二层精英材料 | 维护材料贵，不清除订单 / 污染物 | `V-PACK-DOLL-RECOVER-01` |

### 6.2 Validator

| ValidatorID | 检查 |
|---|---|
| `CFG-PROSTHETIC-001` | `ProstheticID`、`SlotType`、`Tier`、`TriggerRules` 或 `EffectRefs` 必填。 |

### 7.2 底盘制造 / 解锁配方

| RecipeID | RecipeType | 输出 | 输入重点 | 设计目的 |
|---|---|---|---|---|

| `craft_chassis_bulwark_carrier` | `ChassisUnlock` | `chassis_bulwark_carrier` | 第二层精英材料、承运图纸、金币 | 第二层订单 / 重载路线。 |

### 7.3 维护方案配置

| MaintenanceID | TargetState | 恢复 / 降低 | 消耗 | 副作用 / 边界 |
|---|---|---|---|---|
| `maint_basic_patch` | `Wear`, `HP` | 小幅降低磨损，恢复少量 HP | 少量金币 + `loot_gear_scrap` | 不能处理侵蚀和 Broken。 |
| `maint_standard_overhaul` | `Wear`, `HP`, `DivePermit` | 中幅降低磨损，恢复下潜许可 | 金币 + 机械材料 | 日常维护基准。 |
| `maint_purification_flush` | `Corruption`, `DynamicTags` | 降低侵蚀和污染相关标签 | 金币 + 净化材料 | 不解决磨损。 |
| `maint_deep_therapy` | `SAN`, `Broken`, `TraitTransform` | 解除 Broken 或推进特质转化 | 高金币 + 稀有材料 + 交互条件 | 可能推进 Day 或触发核心抉择。 |
| `maint_field_tuning` | `ProstheticStability` | 下一次下潜义体稳定 | 少量金币 + 对应义体材料 | 只持续一次下潜，同类不叠加。 |

### 7.4 消耗与取消规则

| 规则 | 口径 |
|---|---|
| `ConsumePolicy=ConsumeAll` | 普通材料和金币完整消耗。 |
| `ConsumePolicy=KeepQuestBound` | 订单绑定、剧情锁定、情感锚点物不能被普通制造消耗。 |
| `InheritTagsPolicy=KeepRiskTags` | 污染物参与制造时，风险标签需要进入输出或副作用。 |
| `CancelPolicy=RefundUnstarted` | 未开始制造可全额返还，已完成制造不能撤销。 |
| `CancelPolicy=PartialRefundAfterStart` | 如果未来支持制造时间，再定义部分返还；当前不默认启用。 |

### 7.5 Validator

| ValidatorID | 检查 |
|---|---|
| `CFG-CRAFT-001` | `RecipeID`、`RecipeType`、输入、输出和成本必填。 |
| `CFG-CRAFT-002` | 输入 ItemID / Tag / Blueprint 引用存在。 |
