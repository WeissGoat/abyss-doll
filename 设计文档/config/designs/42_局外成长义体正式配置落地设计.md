# 局外成长义体正式配置落地设计

> 本文承接 `38_局外成长正式配置实现任务拆分.md` 的 `GROWTH-PROSTHETICS`。它把首批 6 个正式义体转成 JSON 修改前字段级清单，供后续配置实现使用。本文不直接修改 `配置表(JSON)`，不代表义体 JSON 已完成。

---

## 1. 当前事实

当前 `配置表(JSON)/Prosthetics` 只有两个旧原型义体：

| 文件 | 当前 ID | 当前字段 | 正式判断 |
|---|---|---|---|
| `pros_power_arm.json` | `pros_power_arm` | `Name`、`Level`、`SlotType=Arm`、`Effects=DamageMultiplier`。 | 旧 MVP / 原型战斗增幅义体，可作为 `prosthetic_charge_coil_arm` 的方向参考，但不能直接视为正式义体完成。 |
| `pros_cooling_system.json` | `pros_cooling_system` | `Name`、`Level`、`SlotType=Core`、`Effects=RestoreSANOnCombatEnd`。 | 旧 MVP / 原型 SAN 稳定义体，可作为 `prosthetic_san_regulator_core` 的方向参考，但缺少疲劳、维护和触发反馈。 |

现有问题：

1. 旧 ID 使用 `pros_*`，与正式 `prosthetic_*` 命名不一致。
2. 旧槽位只有泛化 `Arm` / `Core`，无法与正式底盘的 `AllowedProstheticSlots` 精确匹配。
3. 缺少 `DisplayName`、`DescriptionKey`、`VisualID`、`Tags`、`TriggerRules`、`CraftRecipeRef`、`UnlockCondition`、`InstallCost`、`ConflictGroup`、`MaintenanceModifier`、`WearImpact`、`FeedbackRefs`。
4. 旧效果只表达数值结果，没有触发频率、玩家可见反馈和长期代价。
5. 旧 JSON 不覆盖地图阅读、背包干涉抵抗、材料拆解和安全区后续修复等正式局外成长需求。

---

## 2. 本轮目标

`GROWTH-PROSTHETICS` 本轮只处理 6 个首批正式义体：

| ProstheticID | 定位 | 玩家决策 |
|---|---|---|
| `prosthetic_focus_lens` | 地图阅读 / 路线规划 | 牺牲头部传感槽，换取相邻节点倾向信息。 |
| `prosthetic_anchor_left_arm` | 背包干涉抵抗 | 占用左臂槽，降低首次塞包 / 封格压力。 |
| `prosthetic_charge_coil_arm` | 充能武器爆发 | 占用右臂槽，用磨损和触发条件换取战斗爆发。 |
| `prosthetic_san_regulator_core` | SAN 稳定 / 崩溃缓冲 | 占用核心泵槽，降低短线崩溃风险但增加调节疲劳。 |
| `prosthetic_salvage_fingertips` | 材料拆解 / 拾荒收益 | 强化撤离结算材料转化，不提供战斗直接收益。 |
| `prosthetic_mender_spine` | 安全区后续修复 | 占用背脊槽，在安全区免费恢复后缓解少量磨损或侵蚀。 |

设计原则：

1. 义体不是纯属性加成，必须改变玩家的路线、背包、战斗、维护或结算判断。
2. 每个义体必须声明槽位、底盘适配、效果引用、触发时机、制造来源和长期代价。
3. 高收益义体必须有磨损、维护、冲突、冷却或触发频率限制。
4. 如果程序暂不支持某字段，配置仍保留正式字段，Validator 先给 warning，不删除正式口径。
5. 义体配置完成不等于配方、效果、UI 或程序完成；引用方必须单独验收。

---

## 3. 字段标准

### 3.1 必填字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `ProstheticID` | string | 全局唯一 ID，正式 ID 使用 `prosthetic_*`。 |
| `DisplayName` | string | 玩家可见名。旧 `Name` 只作为兼容别名。 |
| `DescriptionKey` | string | 本地化描述 Key，必须说明职责、触发和代价。 |
| `VisualID` | string | UI 图标或工坊展示资源 ID，可先使用 fallback。 |
| `Tier` | string | `Primary`、`Advanced`、`Rare` 等。旧 `Level` 只作兼容别名。 |
| `SlotType` | string | 安装槽位，必须能被至少一个正式底盘允许，或声明兼容别名。 |
| `Tags` | string[] | 玩法标签，例如 `RoutePreview`、`PackInterferenceResist`、`Charge`。 |
| `EffectRefs` | object[] | 引用 `Effects` 字典中的 `EffectID`，参数必须与 `41` 中 `ConfigSchema` 一致。 |
| `TriggerRules` | object[] | 说明何时生效、触发次数、条件、目标和失败处理。 |
| `CraftRecipeRef` | string | 对应制造配方 ID。初始赠送也要声明来源策略。 |

### 3.2 推荐字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `LegacyAliases` | string[] | 旧 ID 兼容，例如 `pros_power_arm`。 |
| `UnlockCondition` | object | 图纸、层级、Boss 核心、精英材料、订单或剧情条件。 |
| `InstallCost` | object | 安装 / 更换成本。 |
| `ConflictGroup` | string[] | 互斥组，同组不能同时生效。 |
| `MaintenanceModifier` | float | 维护费用、磨损或稳定性的倍率，默认 1.0。 |
| `WearImpact` | object | 触发、下潜或超频后产生的磨损影响。 |
| `CorruptionImpact` | object | 污染 / 侵蚀相关影响。 |
| `FeedbackRefs` | string[] | 触发、失效、安装、维护或过载时的反馈 ID。 |
| `SlotCompatibilityAliases` | string[] | 子槽或旧槽位兼容规则，例如 `RightHand` 兼容 `RightArm`。 |
| `RuntimeSupportPolicy` | string | 程序暂不支持时使用 `WarningNoOp`、`CompatEffect` 或 `RequiresImplementation`。 |

## 4. 槽位兼容策略

正式底盘 `40_局外成长底盘正式配置落地设计.md` 当前给出的槽位为：

| 底盘 | AllowedProstheticSlots |
|---|---|
| `chassis_standard_frame` | `CorePump`、`LeftArm`、`RightArm`、`HeadSensor` |
| `chassis_compact_raider` | `HeadSensor`、`RightArm`、`CorePump` |
| `chassis_bulwark_carrier` | `CorePump`、`LeftArm`、`RightArm`、`BackSpine` |

本轮 6 个义体中，`prosthetic_salvage_fingertips` 的设计槽位是 `RightHand`，但当前正式底盘没有直接列 `RightHand`。该问题必须显式处理，不能静默当作可安装。

推荐口径：

| 策略 | 处理 | 判断 |
|---|---|---|
| 兼容别名 | 保留 `SlotType=RightHand`，新增 `SlotCompatibilityAliases=["RightArm"]`。 | 推荐。保留“手指”语义，同时允许右臂槽承接。Validator 要求至少一个别名被底盘允许。 |
| 底盘扩槽 | 在后续底盘实现中为相关底盘加入 `RightHand`。 | 可选。会扩大底盘槽位枚举，需要同步 `40` 和 Chassis README。 |
| 降级为右臂 | 改为 `SlotType=RightArm`。 | 不推荐。会丢失“拾荒指”是精细手部工具的表现和扩展语义。 |

本文采用第一种：`prosthetic_salvage_fingertips` 使用 `SlotType=RightHand`，并声明 `SlotCompatibilityAliases=["RightArm"]`。后续 Validator 规则为：若 `SlotType` 不被任何底盘直接允许，但 `SlotCompatibilityAliases` 至少命中一个正式底盘槽位，则给 warning；若两者都不命中，则 error。

## 5. 正式义体清单

### 5.1 `prosthetic_focus_lens`

| 字段组 | 口径 |
|---|---|
| 迁移来源 | 新增正式 ID。 |
| 职责 | `RoutePreview`、`Scout`、`MapRead`。 |
| 槽位 | `HeadSensor`。标准底盘和轻装底盘可安装，重载底盘默认不可安装。 |

| 触发 | 打开地图或进入节点预览时，揭示相邻未探索节点的类型倾向。 |
| 解锁 | 第一层 Boss 后图纸或浅渊矿灯相关事件。 |

### 5.6 `prosthetic_mender_spine`

| 字段组 | 口径 |
|---|---|
| 迁移来源 | 新增正式 ID。 |
| 职责 | `SafeZoneRecovery`、`LongTermRepair`。 |
| 槽位 | `BackSpine`。重载底盘默认可安装，标准 / 轻装底盘默认不可安装。 |
| 效果 | `effect_safezone_wear_ease`。 |
| 触发 | 安全区免费恢复 HP / SAN 后，额外缓解少量磨损或侵蚀压力。 |
| 解锁 | 第二层 Boss 后安全区事件或承运底盘路线。 |

| 表现 | 安全区恢复后的脊索自检反馈和维护提示。 |

字段草案：


## 6. 跨配置引用

| 引用方向 | 要求 |
|---|---|
| `Prosthetics -> Chassis` | 每个义体的 `SlotType` 或 `SlotCompatibilityAliases` 必须被至少一个正式底盘允许。 |
| `Prosthetics -> Effects` | `EffectRefs.EffectID` 必须来自 `41` 或实际 `Effects` JSON。 |
| `Prosthetics -> CraftingRecipes` | 每个 `CraftRecipeRef` 必须由后续 `GROWTH-CRAFT-MAINT` 落到配方 JSON。 |
| `Prosthetics -> Feedback` | `FeedbackRefs` 若暂未配置，Validator 先 warning；核心可见效果必须有 UI / 文案 fallback。 |
| `Prosthetics -> Rewards / Dungeons` | 解锁材料必须能追到前三层 Boss、精英、节点奖励、订单或事件来源。 |
| `Prosthetics -> Dolls` | 安装状态属于人偶运行时实例，不写入 `Dolls` 静态档案。 |

## 7. Validator

| ValidatorID | 检查内容 | 失败级别 |
|---|---|---|
| `CFG-PROSTHETIC-001` | `ProstheticID`、`DisplayName`、`DescriptionKey`、`VisualID`、`Tier`、`SlotType`、`Tags` 必填。 | error |
| `CFG-PROSTHETIC-002` | `SlotType` 必须被至少一个正式底盘允许；若通过 `SlotCompatibilityAliases` 命中则 warning；完全未命中则 error。 | warning / error |
| `CFG-PROSTHETIC-003` | `EffectRefs` 非空，且每个 `EffectID` 存在，参数与效果字典 schema 一致。 | error |
| `CFG-PROSTHETIC-004` | `TriggerRules` 必须声明触发点、次数或冷却；影响核心决策的触发必须可见。 | error |
| `CFG-PROSTHETIC-005` | `CraftRecipeRef` 必须存在或明确列为后续 `GROWTH-CRAFT-MAINT` warning。 | warning / error |
| `CFG-PROSTHETIC-006` | `ConflictGroup` 不得导致同一义体自冲突；同槽同组义体不能同时生效。 | error |
| `CFG-PROSTHETIC-007` | 高收益义体必须至少有一种长期代价：维护倍率、磨损、侵蚀、冷却、材料成本或槽位冲突。 | error |
| `CFG-PROSTHETIC-008` | 旧 `pros_*` ID 不应作为正式内容输出；若保留必须出现在 `LegacyAliases` 或测试兼容清单。 | warning |

## 8. 固定验收样例

| 验收 ID | 前置 | 操作 | 期望 |
|---|---|---|---|
| `V-GROWTH-PROSTHETIC-01` | 标准底盘安装 `prosthetic_focus_lens`。 | 进入第二层地图并打开节点预览。 | 相邻节点只显示倾向，不完全透视；缺 UI 支持时报告 warning，不删除字段。 |
| `V-GROWTH-PROSTHETIC-02` | 标准或重载底盘安装 `prosthetic_anchor_left_arm`。 | 遭遇第二层塞包 / 封格怪。 | 首次干涉被降低，并显示义体来源；后续干涉仍产生压力。 |
| `V-GROWTH-PROSTHETIC-03` | 安装 `prosthetic_charge_coil_arm`。 | 使用 `Charge` / `Electric` 物品叠满层数后攻击。 | 下一次匹配攻击获得额外效果，层数消耗并产生磨损。 |
| `V-GROWTH-PROSTHETIC-04` | 安装 `prosthetic_san_regulator_core`。 | 遭遇一次超过阈值的 SAN 损失。 | 损失被部分削减，附加调节疲劳；不能免疫 Broken。 |
| `V-GROWTH-PROSTHETIC-05` | 安装 `prosthetic_salvage_fingertips`。 | 撤离结算低阶机械 / 源石材料。 | 触发一次材料识别 / 拆解收益；战斗中无直接收益。 |
| `V-GROWTH-PROSTHETIC-06` | 重载底盘安装 `prosthetic_mender_spine`。 | 到达安全区并免费恢复 HP / SAN。 | 安全区全恢复后额外缓解少量磨损或侵蚀，但不清除订单、污染物、背包满载或特质历史。 |
| `V-GROWTH-PROSTHETIC-07` | 轻装底盘尝试安装 `prosthetic_anchor_left_arm`。 | 执行安装检查。 | 因槽位不支持而失败，义体不销毁，并给出可读原因。 |
| `V-GROWTH-PROSTHETIC-08` | `prosthetic_salvage_fingertips` 使用 `RightHand` 槽位。 | 执行槽位 Validator。 | 通过 `RightArm` 兼容别名给 warning；若底盘无 `RightArm` 则 error。 |

## 9. 迁移规则

| 旧 ID | 推荐处理 | 原因 |
|---|---|---|
| `pros_power_arm` | 不作为正式主 ID；可进入 `prosthetic_charge_coil_arm.LegacyAliases`。 | 旧配置只表达伤害增幅，缺少充能、触发、磨损和反馈。 |
| `pros_cooling_system` | 不作为正式主 ID；可进入 `prosthetic_san_regulator_core.LegacyAliases`。 | 旧配置只表达战后 SAN 恢复，缺少阈值削减、疲劳和维护代价。 |

后续实现时应避免以下做法：

1. 直接把旧 `SlotType=Arm` 当作 `LeftArm` 或 `RightArm`，必须人工映射。
2. 直接复用 `DamageMultiplier` 作为完整充能义体效果，必须增加积层、消耗和磨损边界。
3. 直接复用 `RestoreSANOnCombatEnd` 作为完整 SAN 调节，必须增加阈值、疲劳和 Broken 边界。
4. 把义体安装状态写进 `Dolls` 静态档案。

## 10. 完成判定

`GROWTH-PROSTHETICS` 只有在以下条件满足后，才能视为义体配置域局部完成：

1. `配置表(JSON)/Prosthetics` 中存在 6 个正式义体主 ID，或存在明确迁移后的等价结构。
2. 每个义体具备身份、槽位、效果引用、触发规则、配方引用、安装成本、冲突组、维护 / 磨损代价和反馈字段。
3. `prosthetic_salvage_fingertips` 的 `RightHand` 槽位兼容策略已被配置或 Validator 明确处理。
4. 旧 `pros_power_arm`、`pros_cooling_system` 有迁移 / 兼容说明，不被误判为正式完成。
5. 每个 `EffectID` 可追到 `41` 或实际 JSON；每个 `CraftRecipeRef` 可追到后续配方配置或 warning。
6. `CFG-PROSTHETIC-*` 或人工等价检查通过，至少覆盖 `V-GROWTH-PROSTHETIC-01` 到 `V-GROWTH-PROSTHETIC-06`。
7. `agent_status/design.md` 的 `DES-V3-002` 追加本文证据；如影响长期节点门禁，PM 同步 `09`，但整个局外成长配置仍不能因此标记为 `配置完成`。

## 11. 下一步

完成本文后，局外成长配置链路的下一步建议：

1. 若继续策划侧设计，推进 `GROWTH-CRAFT-MAINT`，把 6 个义体制造配方、2 个底盘解锁配方、5 个维护方案和材料来源拆到字段级清单。
2. 若进入配置实现，先按 `40` / `41` / 本文补底盘、效果 / 标签 / 特质和义体 JSON，再补配方与维护。
3. 配置实现后运行配置同步和 Validator；如程序暂不支持新字段，应记录 warning，不删除正式字段。
