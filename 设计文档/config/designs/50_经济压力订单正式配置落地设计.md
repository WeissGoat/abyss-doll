# 经济压力订单正式配置落地设计

> 本文承接 `46_经济压力正式配置承接审计.md` 的 `ECON-ORDERS`。它把 `24_势力订单声望内容包.md` 的 5 个订单池和 19 条订单模板转成 JSON 修改前字段级清单。最终 `OrderPoolID` / `OrderID` 以 `55_经济压力订单ID最终锁定表.md` 为准。本文不直接修改 `配置表(JSON)`，不代表订单配置已经完成。

---

## 1. 当前事实

当前 `配置表(JSON)/Orders/` 只有一个可运行样例：

| 当前 OrderID | 当前作用 | 正式判断 |
|---|---|---|
| `order_mechanic_scrap_drive` | 机械工坊低阶采购单，要求 2 个 `Mechanical` 标签物，7 天期限，奖励金币和声望 / 信任变化。 | 可迁移为工坊低阶采购原型，但不能代表正式订单池；缺 5 个订单池、19 条模板、探索报告、大型委托物、活体捕获、Boss 核心互斥和黑市背叛。 |

当前缺口：

1. 无订单池配置，势力只能依赖单条订单样例或程序默认刷新。
2. 缺 `ExplorationReport`、`TargetItem`、`LargeCargo`、`LiveCapture`、`BlackMarketBetrayal` 的字段级样例。
3. 缺 `AvailabilityCondition`、`OrderPoolID`、`LayerRange`、`RewardValueBand`、`ValidationRefs` 等正式字段。
4. 黑市背叛没有明确原订单裁决、二次确认、正规势力惩罚和黑市信任奖励。
5. 订单目标无法稳定追到 Items / Dungeons / Rewards / Factions。

## 3. OrderPoolConfig 正式字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `OrderPoolID` | string | 是 | 订单池全局唯一 ID。 |
| `FactionID` | string | 是 | 发布势力，必须引用 `Factions`。 |
| `PoolRole` | enum | 是 | `Exploration`、`Engineering`、`Research`、`AlchemySupply`、`BlackMarket`。 |
| `VisibleSlots` | int 或 object | 是 | 默认可见槽位，可被声望 / 信任覆盖。 |
| `CandidateOrderIDs` | string[] | 是 | 池内订单模板。 |
| `UnlockCondition` | object | 是 | 可见条件：层级、声望、信任、事件或首次获得物。 |
| `RefreshPolicy` | object | 是 | 周刷新、保留已接订单、重复限制和 fallback。 |
| `DiversityRules` | object | 是 | 去重、同池大型订单上限、保底可完成订单。 |
| `WeightModifiers` | object[] | 否 | 传闻、声望、失败、黑市怀疑对权重的修正。 |
| `ValidationRefs` | object | 是 | 指向 Factions / Orders / Rewards / Items / Dungeons 的校验引用。 |

## 4. OrderConfig 正式字段

当前 README 已有字段保留，正式订单模板需要补齐以下字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `OrderPoolID` | string | 是 | 所属订单池。 |
| `DisplayNameKey` / `DescriptionKey` | string | 是 | UI 文案 key。 |
| `OrderRole` | enum | 是 | `SafeIncome`、`RouteTarget`、`BagPressure`、`BuildUnlock`、`RiskReward`、`Betrayal`。 |
| `LayerRange` | int[] | 是 | 订单可完成层级范围。 |
| `Requirement` | object | 是 | 需求表达，必须可机器裁决。 |
| `DeadlineDays` | int | 是 | 接取后的期限，最小 1。 |
| `RewardID` / `FixedGold` | string / int | 是 | 奖励引用和金币补充。 |
| `ReputationDelta` / `TrustDelta` | int | 是 | 正规势力声望或黑市信任变化。 |
| `FailurePenalty` | object | 是 | `Expired`、`Abandoned`、`Betrayed`、绑定物丢失的裁决。 |
| `AvailabilityCondition` | object | 是 | 声望、信任、层级、事件、已完成订单或传闻条件。 |
| `RepeatPolicy` | enum | 是 | `Once`、`Repeatable`、`WeeklyOnce`、`UntilCompleted`。 |
| `Weight` | int | 是 | 刷新权重。 |
| `Tags` | string[] | 是 | 刷新、传闻、Validator 和 UI 筛选标签。 |
| `RiskSummaryKey` | string | 否 | 背叛、污染、活体捕获、限时腐坏等风险提示。 |
| `ValidationRefs` | object | 是 | 目标物、节点、奖励、势力和冲突规则引用。 |

| `pool_alchemy_purification` | `faction_alchemy_guild` | 2 | `order_alchemy_purification_batch`、`order_alchemy_spore_sample_fast`、`order_alchemy_antitoxin_contract`、`order_alchemy_market_forecast` | `order_alchemy_purification_batch` |
| `pool_black_market_betrayal` | `faction_black_market` | 0-1 | `order_black_forbidden_relic_buyout`、`order_black_bound_core_betrayal`、`order_black_live_sample_no_questions`、`order_black_smuggled_route_key` | `order_black_forbidden_relic_buyout` |

池级规则：

1. 同一池同周不生成重复 `OrderID`。
2. 同一势力同周最多 1 个 `LargeCargo`，除非声望 Rank >= 3 且玩家主动刷新。
3. 黑市池默认 0 槽，必须由信任、事件或黑市窗口开启。
4. 如果池内候选全不可用，必须使用 fallback；fallback 仍不可越层。
5. 订单池引用的所有 FactionID、OrderID、RewardID、目标标签和层级来源都必须可追踪。

## 7. 关键裁决

| 裁决 | 正式口径 |
|---|---|
| 订单物绑定 | 接取或拾取后添加动态标签 `OrderBound:{OrderInstanceID}`；可移动和旋转，不能普通出售或制造消耗。 |
| 大型委托物 | `LargeCargo` 必须声明形状、面积、是否可旋转、战败流向和交付后去向。 |
| 活体捕获 | 空容器和活体样本是同一实例生命周期的不同状态，撤离后才能交付。 |
| Boss 核心互斥 | 同一核心只能完成一个正规订单或黑市背叛订单。 |
| 黑市背叛 | 必须二次确认，原订单转 `Betrayed`，正规势力惩罚和黑市奖励同时写日志。 |
| 超期腐坏 | `Perishable` 订单物超期后转无效样本或普通低价值污染物，不直接吞物。 |

## 8. Validator

| ValidatorID | 检查内容 | 失败级别 |
|---|---|---|
| `CFG-ORDER-001` | `OrderID` 唯一，`FactionID`、`OrderPoolID`、`OrderType` 合法。 | error |
| `CFG-ORDER-002` | 订单池引用的候选订单全部存在，fallback 存在且可刷新。 | error |
| `CFG-ORDER-003` | `Requirement` 至少包含 ItemID、ItemQuery、ExploreCondition、TargetItem 或 CaptureRule 之一。 | error |
| `CFG-ORDER-004` | `RewardID`、`UnlockRefs`、目标物、目标节点、目标怪物引用存在；迁移期缺引用给 warning。 | warning / error |
| `CFG-ORDER-005` | `DeadlineDays >= 1`，`Weight > 0`，声望 / 信任变化在安全范围。 | error |
| `CFG-ORDER-006` | `LargeCargo` 必须有形状、面积、可旋转性和战败 / 放弃流向。 | error |
| `CFG-ORDER-007` | `LiveCapture` 必须有捕获容器、捕获后实例状态和 SAN / 风险提示。 | error |
| `CFG-ORDER-008` | `BlackMarketBetrayal` 必须声明原订单裁决、正规势力惩罚、二次确认和黑市奖励。 | error |

## 10. 完成判定

`ECON-ORDERS` 只有在以下条件满足后，才能视为订单配置设计局部完成：

1. 5 个订单池都有 OrderPoolID、FactionID、候选订单、刷新策略、fallback 和多样性规则。
2. 19 条订单模板都有需求表达、期限、奖励、声望 / 信任、失败惩罚、可见条件、重复策略、权重和标签。
3. 探索报告、大型委托物、活体捕获、Boss 核心互斥、黑市背叛和限时腐坏都有字段级裁决。
4. 订单目标能追到 Factions / Rewards / Items / Dungeons / Economy / Rumors 的后续承接点。
5. `CFG-ORDER-*` 检查项和 `V-ECON-ORDER-*` 固定验收样例已定义。
6. `agent_status/design.md` 的 `DES-V4-001` 追加本文证据；如影响长期节点门禁，PM 同步 `09`，但整个经济压力配置仍不能因此标记为 `配置完成`。

## 11. 下一步

完成本文后，经济压力配置链路的下一步建议：

1. `ECON-VALIDATION` 已由 `51_经济压力正式配置Validator与固定验收样例.md` 承接；配置实现派发顺序和证据模板见 `52_经济压力正式配置实现任务拆分.md`。
2. 若进入配置实现，先确保 `ECON-FACTIONS-JSON` 已有订单池引用，再按 `52` 的 `ECON-ORDERS-JSON` 补 `Orders` 配置源或等价配置结构，并进入 `ECON-CROSS-REFS`。
3. 不要把当前单条 `order_mechanic_scrap_drive` 样例视为正式订单池完成。
