# 经济压力核心正式配置落地设计

> 本文承接 `46_经济压力正式配置承接审计.md` 的 `ECON-CORE`。它把 `22_小镇经济月租内容包.md` 中的月租、账单、顾客、违禁、NightTax 和死锁保护转成 JSON 修改前字段级清单。本文不直接修改 `配置表(JSON)`，不代表经济压力配置已经完成。

---

## 1. 当前事实

当前 `配置表(JSON)/Economy/economy_town_v1.json` 已有首版可运行经济骨架：

| 字段 | 当前值 | 正式判断 |
|---|---|---|
| `WeekLength` | 7 | 符合正式周口径。 |
| `MonthLength` | 28 | 符合正式月租口径。 |
| `RentCurveID` | `rent_curve_workshop_v1` | 与 `22` 的首批月租曲线一致。 |
| `RentCurve` | 1200 / 2400 / 4200 / 5200 | 可作为首版曲线，但需要补月租预告、周报缺口和账单来源。 |
| `WorkshopMaintenanceBase` | 0 | 不能作为正式经济压力完成；需要接维护 / 设施支出。 |
| `LicenseFeeBase` | 0 | 可暂为 0，但正式字段需要说明何时由剧情或势力压力接入。 |
| `DebtInterestRate` | 0.1 | 可承接轻债长期压力。 |
| `LightDebtThresholdRatio` | 0.1 | 与经济规则卡一致。 |
| `PawnValueMultiplier` | 0.25 | 符合典当刺痛但可补救的方向。 |
| `PawnProtectedTags` | `Bond`、`OrderBound`、`StoryLocked`、`Memento`、`MainQuest`、`KeyItem` | 符合硬保护边界。 |

当前问题：

1. 日结报告目前更偏程序报告结构，缺正式配置化的账单栏目、账单展示规则和异常来源标签。
2. 月租曲线已存在，但缺周报 / 月租预告 / 缺口提示 / 典当推荐 / 重度违约事件引用。
3. 顾客、橱窗、黑市和违禁品目前没有 Economy 核心配置承接，只能靠后续系统硬编码或缺省逻辑。
4. NightTax 没有字段承接，污染 / 违禁隔夜代价无法被配置、验收和复盘。
5. DeadlockGuard 没有字段承接，难以机械检查前三层阶段是否存在不可恢复经济死锁。

---

## 2. 本轮范围

`ECON-CORE` 本轮只处理经济核心配置，不处理传闻池、势力池和订单模板。

| 范围内 | 范围外 |
|---|---|
| `economy_town_v1` 的正式字段补齐设计。 | 8 条传闻的完整 JSON 字段设计，后续 `ECON-RUMORS` 处理。 |
| 4 套账单字段设计。 | 5 个势力和声望 / 信任阶梯，已由 `49_经济压力势力正式配置落地设计.md` 承接。 |
| 6 类顾客字段设计。 | 18 条订单模板和订单池，已由 `50_经济压力订单正式配置落地设计.md` 承接。 |
| 4 类违禁品规则、NightTax、典当保护和死锁保护。 | 程序实现、UI 版式、美术资源和真实 JSON 修改。 |

设计原则：

1. 经济压力必须可预告、可复盘、可补救，不用突袭扣款制造压力。
2. 普通出售不做额外保护；硬保护只给订单绑定、剧情锁定、人偶情感锚点和不可替代主线物。
3. 月租、维护、成长、订单准备和黑市风险要共同吃掉收益，不能只靠提高月租。
4. DeadlockGuard 是正式配置的底线：前三层阶段允许失误，但不应因为一次坏账直接不可恢复。
5. 如果程序暂不支持某字段，配置仍保留正式字段，Validator 可先给 warning，不删正式口径。

## 3. EconomyConfig 正式字段

### 3.1 保留字段

| 字段 | 处理 |
|---|---|
| `EconomyConfigID` | 保留 `economy_town_v1`。 |
| `Name` | 保留，可改为玩家不可见的策划名。 |
| `WeekLength` / `MonthLength` | 保留 7 / 28。 |
| `RentCurveID` / `RentCurve` | 保留首版曲线，后续数值可调。 |
| `DebtInterestRate` / `LightDebtThresholdRatio` | 保留。 |
| `PawnValueMultiplier` / `PawnProtectedTags` | 保留，并加入 Validator 硬保护检查。 |

### 3.2 新增 / 补齐字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `DailyReportPolicy` | object | 是 | 每日营业日报栏目、展示顺序和大额变化标记。 |
| `WeeklyReportPolicy` | object | 是 | 周结时传闻刷新、订单刷新、月租缺口和下周建议信息。 |
| `MonthlyBillPolicy` | object | 是 | 月租触发、预告、扣款、欠债、典当和违约裁决。 |
| `SellChannelRules` | object[] | 是 | `DumpBox`、`ShowcaseGrid`、`OrderSlot`、`BlackMarketSlot`、`PawnPool` 的结算规则。 |
| `CustomerPool` | object[] | 是 | 6 类顾客定义；若后续拆独立 Customers 配置，可由 `CustomerPoolRefs` 替代。 |
| `ContrabandRules` | object[] | 是 | 4 类违禁品规则、普通渠道限制、黑市渠道、隔夜代价和清理方式。 |
| `NightTaxPolicy` | object | 是 | 违禁 / 污染隔夜代价公式、状态影响、日志和 warning 规则。 |
| `DeadlockGuard` | object | 是 | 前三层经济死锁保护：欠债、典当、低层回刷、保底订单和最小下潜许可。 |
| `MaintenanceExpensePolicy` | object | 否 | 将局外维护成本接入账单 / 日报，不替代维护配置。 |
| `ScenarioEventRefs` | object | 否 | 债务、违约、黑市诱惑和月租危机事件引用。 |

## 4. 账单设计

### 4.1 账单总表

| BillID | 触发 | 配置职责 | 必须展示 |
|---|---|---|---|
| `bill_daily_settlement_v1` | 每日营业后 | 复盘当天收入 / 支出。 | 倾倒箱、橱窗、订单、黑市、维护支出、未售物、NightTax、租金倒计时。 |

## 5. 出售渠道

| ChannelID | 用途 | 结算口径 | 边界 |
|---|---|---|---|
| `DumpBox` | 快速普通出售。 | 基础价、传闻倍率、状态修正。 | 低操作、低上限；普通渠道拒收违禁。 |
| `ShowcaseGrid` | 高价值展示出售。 | 顾客预算、偏好、相邻标签和传闻。 | 小空间、高上限；未售物退回。 |
| `OrderSlot` | 订单提交。 | 订单固定奖励。 | 优先级高于出售，物品进入 `Delivered`。 |
| `BlackMarketSlot` | 违禁 / 背叛渠道。 | 高价、信任、声望风险。 | 仅在黑市窗口、黑市势力或事件开启时可用。 |
| `PawnPool` | 月租不足时典当。 | 估值 * `PawnValueMultiplier`。 | 只由月租裁决或玩家主动进入，不自动处理硬保护物。 |

字段草案：

```json
{
  "SellChannelRules": [
    {
      "ChannelID": "DumpBox",
      "Priority": 30,
      "AllowedTags": ["CommonLoot", "Material", "Weapon", "Armor"],
      "RejectedTags": ["Contraband", "OrderBound", "StoryLocked", "Memento", "MainQuest"],
      "UsesRumorMultiplier": true,
      "UnsoldPolicy": "ReturnToSafeBox"
    },
    {
      "ChannelID": "ShowcaseGrid",
      "Priority": 20,
      "UsesCustomerPool": true,

    {
      "ChannelID": "BlackMarketSlot",
      "Priority": 10,
      "RequiresRuleOrEvent": true,
      "AllowedTags": ["Contraband", "ForbiddenRelic", "Cursed", "Suspicious"],

    },
    {
      "ChannelID": "PawnPool",
      "Priority": 40,
      "OnlyWhen": "MonthlyRentShortfall",
      "ValueMultiplierRef": "PawnValueMultiplier",
      "ProtectedTagsRef": "PawnProtectedTags"
    }
  ]
```

| CustomerID | 预算 | 偏好 | 拒收 | 用途 |

| `cust_set_collector` | 500-1800 | `SetPiece`、`ThemeMatched` | `Polluted` | 强化橱窗拼图价值。 |

### 6.2 字段草案

```json
{
  "CustomerPool": [
    {
      "CustomerID": "cust_relic_collector",
      "DisplayName": "遗物藏家",
      "BudgetMin": 600,
      "BudgetMax": 2200,
      "PreferredTags": ["OriginStone", "Relic", "BossDrop"],
      "RejectedTags": ["BrokenJunk"],
```

实现注意：

1. 顾客不是逐个议价小游戏，只参与营业结算。
2. 倾倒箱可以使用抽象散客；橱窗优先匹配高预算顾客。
3. `cust_black_market_broker` 只在黑市窗口或事件中出现，不能常驻普通售卖。

## 7. 违禁品规则

### 7.1 首批规则

| ContrabandRuleID | 标签 | 普通渠道 | 黑市渠道 | 隔夜代价 | 清理方式 |
|---|---|---|---|---|---|
| `contra_polluted_sample_v1` | `CorruptionSample` | 拒收或极低价 | 医疗 / 黑市可收 | SAN 小损、侵蚀上升或仓库污染 | 净化冲洗、丢弃、医疗订单。 |
| `contra_forbidden_relic_v1` | `ForbiddenRelic` | 禁止倾倒箱 | 黑市高价 | 债主注意、窗外风险、声望风险 | 黑市出售、剧情交付、封存。 |
| `contra_order_leak_v1` | `OrderBound`、`Suspicious` | 不可普通出售 | 可背叛出售 | 委托势力怀疑 | 正规交付、黑市背叛、放弃订单。 |
| `contra_cursed_keepsake_v1` | `Cursed`、`MementoCandidate` | 普通拒收 | 黑市可售但触发人偶抗拒 | 低 SAN 额外情绪压力 | 房间封存、剧情净化、特殊赠礼。 |

### 7.2 字段草案

```json
{
  "ContrabandRules": [
    {
      "ContrabandRuleID": "contra_polluted_sample_v1",
      "TargetTags": ["CorruptionSample"],
      "Severity": 1,
      "AllowedChannels": ["BlackMarketSlot", "OrderSlot"],
      "RejectedChannels": ["DumpBox"],
      "NightTaxRef": "nighttax_corruption_sample_v1",
      "ClearMethods": ["maint_purification_flush", "ManualDiscard", "MedicalOrder"],
      "WarningLevel": "Medium",
      "FeedbackKey": "contraband.polluted_sample.warning"
    }
  ]
}
```

硬边界：

1. 违禁品不能只是高价标签，必须有渠道限制或隔夜代价。
2. `OrderBound` 物普通出售必须拒绝；黑市背叛是独立订单行为，必须二次确认。
3. 情感锚点和主线物不可被典当算法选中。

## 8. NightTax

### 8.1 公式

```text
NightTax =
  ContrabandSeverity
  + CorruptionLevel
  + StorageLeakFactor
  - ContainmentBonus
```

### 8.2 字段草案

```json
{
  "NightTaxPolicy": {
    "PolicyID": "nighttax_default_v1",
    "EvaluateContainers": ["SafeBox"],
    "IgnoreContainers": ["BackpackInDive", "OrderSlot", "Sold", "Delivered"],
    "SeverityBands": [
      {"Min": 1, "Max": 1, "Effects": [{"Target": "SAN", "Delta": -2}], "WarningLevel": "Low"},
      {"Min": 2, "Max": 3, "Effects": [{"Target": "SAN", "Delta": -5}, {"Target": "Corruption", "Delta": 5}], "WarningLevel": "Medium"},
      {"Min": 4, "Max": 99, "Effects": [{"Target": "SAN", "Delta": -8}, {"Target": "Corruption", "Delta": 10}, {"TriggerEvent": "event_contraband_attention"}], "WarningLevel": "High"}
    ],
    "ContainmentBonusTags": ["Sealed", "Purified", "ContainmentBox"],
    "ReportSection": "NightTaxResult"
  }
}
```

### 8.3 验收边界

| 场景 | 期望 |
|---|---|
| 污染样本留在 SafeBox 一晚。 | 日报显示 NightTax 来源，SAN 或侵蚀变化可复盘。 |
| 密封容器保存污染物。 | `ContainmentBonus` 降低或免除 NightTax。 |
| 违禁品在黑市当天售出。 | 不再触发隔夜税，但记录黑市风险。 |

## 9. DeadlockGuard

DeadlockGuard 不是减压系统，而是防止前三层阶段因为一次经济失败导致不可恢复。

### 9.1 字段草案

```json
{
  "DeadlockGuard": {
    "EnabledUntilHighestLayer": 3,
    "MinimumDivePermitPolicy": {
      "AllowDebtDiveIfHPAndSANSafe": true,
      "MinimumHP": 1,
      "MinimumSAN": 1,
      "BlockIfBroken": true
    },
    "RecoveryRoutes": [
      {"RouteID": "low_layer_bulk_buy", "RequiresRumorOrFallback": true, "LayerMax": 1},
      {"RouteID": "basic_scrap_order", "RequiresFaction": "faction_mechanic_workshop", "LayerMax": 2},
      {"RouteID": "pawn_nonprotected_items", "RequiresPawnCandidates": true}
    ],
    "HeavyDefaultLimitBeforeEnding": 2,
    "ForceWarningDaysBeforeRent": [7, 3, 1],
    "MinimumVisibleSolutions": 1
  }
}
```

### 9.2 检查口径

| 检查 | 失败信号 |
|---|---|
| 月租缺口较小时是否允许欠债。 | 轻债阈值无效，直接重度违约。 |
| 缺口较大时是否至少有典当、低层回刷或订单补救。 | 无可见解决路径。 |
| 典当是否跳过硬保护标签。 | 自动处理订单物、剧情物、情感锚点。 |
| 重度违约是否先进入事件 / 风险，而非立即失败。 | 连续违约前直接终局。 |

## 10. 与其它配置域关系

| 配置域 | 依赖 / 输出 |
|---|---|
| `Items` | 需要 `Contraband`、`CorruptionSample`、`OrderBound`、`StoryLocked`、`Memento`、`MainQuest` 等标签与生命周期去向。 |
| `Rumors` | 传闻倍率和渠道要被 `SellChannelRules` 接住；完整传闻池由 `ECON-RUMORS` 处理。 |
| `Orders` | 订单提交优先于普通售卖；订单物和背叛物由 `OrderSlot` / `BlackMarketSlot` 处理。 |
| `Factions` | 黑市势力和正规势力怀疑由 `ContrabandRules`、黑市渠道和 `49_经济压力势力正式配置落地设计.md` 承接。 |
| `Rewards` | 订单奖励、黑市材料、服务解锁和传闻提前量需要正式 RewardID。 |
| `ScenarioEvents` | 债务通知、债主事件、黑市诱惑和违禁注意事件需要事件引用。 |
| UI / 美术 | 日账单、周报、月租、黑市和典当确认必须有玩家可见表达。 |

## 13. 完成判定

`ECON-CORE` 只有在以下条件满足后，才能视为经济核心配置设计局部完成：

1. `economy_town_v1` 的正式字段清单覆盖日账单、周报、月租、出售渠道、顾客、违禁、NightTax 和 DeadlockGuard。
2. 4 套账单、6 类顾客、4 类违禁品规则、1 套 NightTax 和 1 套 DeadlockGuard 已有 JSON 修改前字段级设计。
3. 每个硬保护标签、违禁标签和渠道规则都能追到 Items / Orders / Factions / Rumors 的后续承接点。
4. `CFG-ECON-*`、`CFG-CONTRA-*`、`CFG-NIGHT-*`、`CFG-DEADLOCK-*` 检查项已定义。
5. 至少覆盖 `V-ECON-CORE-DAILY-01`、`V-ECON-CORE-RENT-01`、`V-ECON-CORE-PAWN-01`、`V-ECON-CORE-CONTRA-01`。
6. `agent_status/design.md` 的 `DES-V4-001` 追加本文证据；如影响长期节点门禁，PM 同步 `09`，但整个经济压力配置仍不能因此标记为 `配置完成`。

完成本文后，经济压力配置链路的下一步建议：

1. `ECON-VALIDATION` 已由 `51_经济压力正式配置Validator与固定验收样例.md` 承接；配置实现派发顺序和证据模板见 `52_经济压力正式配置实现任务拆分.md`。
