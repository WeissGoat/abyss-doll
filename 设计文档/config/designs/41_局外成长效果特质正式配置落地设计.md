# 局外成长效果特质正式配置落地设计

> 本文承接 `38_局外成长正式配置实现任务拆分.md` 的 `GROWTH-EFFECTS-TRAITS`。它把义体、维护、动态标签和 8 个特质所需的效果 / 标签 / 特质字典转成 JSON 修改前字段级清单，供后续配置实现使用。本文不直接修改 `配置表(JSON)`，不代表效果、标签或特质 JSON 已完成。

---

## 1. 当前事实

当前 `配置表(JSON)/Effects/EffectEnums.json` 已有 8 个旧原型效果：

| EffectID | 当前用途 | 正式判断 |
|---|---|---|
| `DamageMultiplier` | 伤害乘区增幅。 | 可作为战斗数值效果兼容保留，不承接局外成长全量需求。 |
| `RestoreSANOnCombatEnd` | 战后恢复 SAN。 | 可作为 SAN 稳定方向参考，但缺少疲劳、维护和触发反馈。 |
| `AddRuntimeShield` | 使用时加护盾。 | 战斗效果，保留。 |
| `AddRuntimeShieldOnTurnStart` | 回合开始加护盾。 | 战斗效果，保留。 |
| `Heal` | 恢复 HP。 | 可作为维护恢复 HP 的底层动作参考。 |
| `RestoreSAN` | 恢复 SAN。 | 可作为维护恢复 SAN 的底层动作参考。 |
| `ReduceDamage` | 怪物技能削弱伤害。 | 怪物干涉效果，保留。 |
| `AddCursedItem` | 怪物强塞诅咒物。 | 背包干涉效果，保留。 |

现有问题：

1. 只有 `effects` 列表，没有正式 `tags`、`traits`、`feedbackEffects` 或等价分区。
2. 旧效果缺少 `AttachableScope`、`VisibleToPlayer`、`StackPolicy`、`ClearRule` 等正式字段。
3. 义体、维护、特质和房间反馈会引用效果，但当前字典不能解释这些引用的参数和值域。
4. 负面特质还没有可配置的获得、阻碍、转化和消除路径。

---

## 2. 本轮目标

`GROWTH-EFFECTS-TRAITS` 本轮处理 4 类配置字典：

| 类别 | 目标 |
|---|---|
| 义体效果 | 支撑路线预览、撤离提示、背包干涉抵抗、充能积层、SAN 损失调节、材料识别和安全区磨损缓解。 |
| 维护效果 | 支撑 HP、SAN、磨损、侵蚀、Broken、义体稳定、特质转化推进。 |
| 动态标签 | 支撑适应期、污染、调节疲劳、义体稳定、边缘压力、房间记忆待处理等临时状态。 |
| 特质 | 支撑 8 个正式特质的获得、生效、反馈、互斥、压制、转化和历史保留。 |

设计原则：

1. 效果字典只定义行为词汇和参数格式，不直接给玩家发放效果。
2. 标签只表达身份和状态，不主动执行效果。
3. 特质是人偶经历的规则包，必须有来源、影响、反馈和转化 / 消除路径。
4. 负面特质不能永久死锁；正面特质也不能无代价叠加成无限收益。
5. 如果程序暂不支持某字段，配置仍保留正式字段，Validator 先给 warning，不删除正式口径。

---

## 3. 字段标准

### 3.1 Effect 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `EffectID` | string | 是 | 全局唯一 ID。新正式效果建议使用 `effect_*`。旧程序内置效果可保留旧 ID。 |
| `DisplayName` | string | 是 | 策划 / UI 可读名。 |
| `Type` | string | 是 | `Modifier`、`Action`、`StateTag`、`TraitRule`、`Feedback`、`Meta`。 |
| `TriggerTiming` | string | 是 | `Passive`、`OnDungeonEnter`、`OnNodePreview`、`OnPackInterference`、`OnMaintenanceComplete` 等。 |
| `AttachableScope` | string[] | 是 | `Prosthetic`、`Maintenance`、`DollRuntime`、`Trait`、`Room`、`DungeonRoute`。 |
| `VisibleToPlayer` | bool | 是 | 是否需要 UI 解释。影响核心决策的效果必须可见。 |
| `ConfigSchema` | object | 是 | 参数名、类型、默认值、合法范围和失败处理。 |
| `StackPolicy` | string | 否 | `NoStack`、`StackBySource`、`RefreshDuration`、`AddValueWithCap`。 |
| `ClearRule` | object/string | 否 | 战斗结束、撤离、维护、日程推进、特质转化或手动事件清除。 |
| `FallbackRule` | object/string | 否 | 程序暂不支持时的 warning / no-op / 兼容映射。 |

### 3.2 Tag 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `TagID` | string | 是 | 标签唯一 ID。动态标签建议使用 `tag_*`。 |
| `TagGroup` | string | 是 | `DollState`、`RouteRisk`、`MaintenanceState`、`ProstheticState`、`RoomMemory`。 |
| `AttachableScope` | string[] | 是 | 可附着对象。 |
| `VisibleToPlayer` | bool | 是 | 是否展示给玩家。 |
| `DurationType` | string | 是 | `RunOnly`、`CombatOnly`、`UntilMaintenance`、`UntilDayEnd`、`PermanentHistory`。 |
| `StackPolicy` | string | 是 | `NoStack`、`RefreshDuration`、`StackCountWithCap`。 |
| `ClearRule` | object/string | 是 | 清除或转化规则。 |

### 3.3 Trait 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `TraitID` | string | 是 | 全局唯一 ID。 |
| `DisplayName` | string | 是 | 玩家可见名。 |
| `Polarity` | string | 是 | `Positive`、`Negative`、`Mixed`。 |
| `Category` | string | 是 | `Trauma`、`Growth`、`Bond`、`Exploration`、`Workshop`。 |
| `SourceCondition` | object | 是 | 获得条件和经历计数器。 |
| `Trigger` | string[] | 是 | 监听事件白名单。 |
| `Conditions` | object | 否 | 生效条件。 |
| `Effects` | object[] | 是 | 引用 `EffectID` 或动态标签。 |
| `ConflictGroup` | string[] | 否 | 互斥组。 |
| `TransformRule` | object | 是 | 转化、消除、压制或长期保留规则。 |
| `FeedbackRefs` | string[] | 否 | UI / 文案 / 房间反馈引用。 |
| `HistoryPolicy` | string | 是 | 消除后历史是否保留。默认 `KeepHistory`。 |

## 4. 义体效果清单

| EffectID | 用途 | 触发 | 参数草案 | 引用方 |
|---|---|---|---|---|
| `effect_route_preview_hint` | 揭示相邻未探索节点的类型倾向。 | `OnNodePreview` | `RevealCount:int`、`Confidence:float`、`AllowedNodeTags:string[]` | `prosthetic_focus_lens`、`chassis_compact_raider` |
| `effect_extract_node_hint` | 标记撤离 / 安全回流倾向。 | `OnDungeonMapOpen` | `HintCount:int`、`OnlyAdjacent:bool` | `chassis_compact_raider` |
| `effect_pack_interference_resist` | 降低首次塞包 / 封格 / 位移强度。 | `OnPackInterference` | `ReduceLevel:int`、`TimesPerCombat:int`、`ValidInterferenceTags:string[]` | `prosthetic_anchor_left_arm`、`chassis_bulwark_carrier` |
| `effect_charge_coil_stack` | 使用指定物品后积层，达到阈值后强化下一次攻击。 | `OnItemUsed` | `AcceptedItemTags:string[]`、`StackMax:int`、`ConsumeAt:int`、`BonusEffectRef:string` | `prosthetic_charge_coil_arm` |
| `effect_san_loss_regulate` | 单次 SAN 损失超过阈值时削减部分损失并附加疲劳。 | `OnSanLoss` | `Threshold:int`、`ReduceFlat:int`、`AddTagID:string`、`Cooldown:string` | `prosthetic_san_regulator_core` |
| `effect_salvage_material_identify` | 撤离结算时识别 / 拆解低阶机械或源石材料。 | `OnExtractSettlement` | `TargetTags:string[]`、`ExtraRoll:int`、`NoCombatBenefit:bool` | `prosthetic_salvage_fingertips` |
| `effect_safezone_wear_ease` | 安全区免费恢复 HP / SAN 后额外缓解少量磨损或侵蚀。 | `OnSafeZoneRecover` | `TargetState:string`、`ReduceValue:int`、`OncePerRun:bool` | `prosthetic_mender_spine` |

边界：

1. 路线预览不能完全透视整张地图，只能给倾向或相邻提示。
2. 背包干涉抵抗只降低一次或少量强度，不能免疫怪物机制。
3. SAN 调节不能阻止剧情强制 Broken。
4. 材料识别不提供战斗收益。

## 5. 维护效果与动态标签

### 5.1 维护效果

| EffectID | 用途 | 参数草案 | 引用方 |
|---|---|---|---|
| `effect_maint_restore_hp` | 恢复 HP。 | `RestoreValue:int`、`ClampToMax:bool` | `maint_basic_patch`、`maint_standard_overhaul` |
| `effect_maint_restore_san` | 恢复 SAN。 | `RestoreValue:int`、`ClampToMax:bool`、`BrokenAllowed:bool` | `maint_standard_overhaul`、`maint_deep_therapy` |
| `effect_maint_reduce_wear` | 降低磨损。 | `ReduceValue:int`、`MinValue:int` | `maint_basic_patch`、`maint_standard_overhaul` |
| `effect_maint_reduce_corruption` | 降低侵蚀 / 污染。 | `ReduceValue:int`、`ClearTagGroups:string[]` | `maint_purification_flush` |
| `effect_clear_broken_state` | 解除 Broken 或推进解除。 | `RequireCondition:string`、`AdvanceDay:bool`、`FeedbackRef:string` | `maint_deep_therapy` |
| `effect_trait_transform_progress` | 推进特质转化条件。 | `TargetTraitID:string`、`Progress:int`、`RequiredProgress:int` | `maint_deep_therapy`、特质转化事件 |
| `effect_prosthetic_stability_next_run` | 下一次下潜义体稳定。 | `TargetSlot:string`、`DurationRunCount:int`、`NoStack:bool` | `maint_field_tuning` |

### 5.2 动态标签

| TagID | 分组 | 生命周期 | 作用 |
|---|---|---|---|
| `tag_corrosion_taint` | `DollState` | `UntilMaintenance` | 第二层腐蚀 / 污染路线遗留压力，可被净化冲洗处理。 |
| `tag_chassis_adaptation` | `MaintenanceState` | `UntilDayEnd` / `RunCount` | 更换底盘后的适应期，影响反馈和下潜提示。 |
| `tag_san_regulation_fatigue` | `DollState` | `UntilMaintenance` | SAN 调节核心副作用，提高维护成本或降低调节效率。 |
| `tag_prosthetic_stable_next_run` | `ProstheticState` | `RunOnly` | 下潜前微调后的临时稳定。 |
| `tag_pack_edge_stress` | `DollState` | `UntilMaintenance` | 多次边缘封格 / 关键物失效带来的焦虑来源。 |
| `tag_room_memory_pending` | `RoomMemory` | `UntilEventResolved` | 关键经历待生成房间纪念物 / 日记。 |

## 6. 特质正式配置清单

| TraitID | 极性 | SourceCondition | Trigger | Effects | TransformRule |
|---|---|---|---|---|---|
| `trait_fear_of_spores` | `Negative` | 第二层孢雾 / 腐蚀类敌人导致 Broken 或战败。 | `OnDungeonNodeEnter`、`OnNodePreview` | 相关节点额外 SAN 压力或预警抗拒；附加 `tag_corrosion_taint` 可见提示。 | `maint_purification_flush` + 击败对应精英后转化为克服记录，历史保留。 |
| `trait_grid_edge_anxiety` | `Negative` | 多次因边缘封格导致关键物品失效。 | `OnItemPlaced`、`OnPackInterference` | 边缘格放关键装备时警告或小幅 SAN 压力；附加 `tag_pack_edge_stress`。 | 装备 `prosthetic_anchor_left_arm` 并完成成功战斗后缓解。 |
| `trait_scrap_hoarder` | `Mixed` | 连续撤离保留大量低价废料。 | `OnExtractSettlement`、`OnBusinessSettlement` | 废料识别 / 拆解收益；出售低价材料时触发抗拒反馈。 | 订单交付或赠礼事件转化为稳定拾荒习惯。 |
| `trait_steady_hands` | `Positive` | 低 HP / 低 SAN 下多次撤离成功。 | `OnItemPlaced`、`OnItemRotated` | 本轮首次关键操作提供一次宽限或提示。 | 长期保留，可被重大创伤压制但历史不删除。 |
| `trait_miracle_afterglow` | `Mixed` | 高 Bond 触发奇迹后获得。 | `OnInteraction`、`OnMaintenanceApplied`、`OnDayEnd` | Bond 反馈增强；SAN 恢复效率或上限承受余波。 | 深层安抚或 Bond 里程碑后转为纪念历史。 |
| `trait_resolute_return` | `Positive` | 从第二层高压路线撤离并完成修复。 | `OnExtract`、`OnMaintenanceApplied` | 撤离节点识别或撤离后维护反馈增强。 | 长期保留，可被更高优先级剧情特质覆盖。 |
| `trait_fragile_trust` | `Negative` | 连续忽视低 SAN 警告并强行下潜。 | `OnInteraction`、`OnDungeonStart` | 交互收益降低，低 SAN 触摸更容易抗拒。 | 多日照料 + 不强行下潜后恢复信任。 |
| `trait_workshop_comfort` | `Positive` | 多次及时维护、赠礼和房间回访。 | `OnInteraction`、`OnMaintenanceApplied`、`OnRoomVisit` | 工坊中 SAN 反馈更稳定，温和台词更易触发。 | 长期保留，不直接提供战斗数值。 |

特质互斥建议：

| ConflictGroup | 成员 | 裁决 |
|---|---|---|
| `SporeTrauma` | `trait_fear_of_spores` 及其后续转化特质 | 同组唯一，转化优先。 |
| `TrustState` | `trait_fragile_trust`、`trait_workshop_comfort` | 可共存历史，但有效状态互斥；当前交互以高优先级状态为准。 |
| `PackAnxiety` | `trait_grid_edge_anxiety`、后续稳定类特质 | 转化或压制，不叠加惩罚。 |
| `MiracleAftermath` | `trait_miracle_afterglow` 及奇迹后续状态 | 不与普通 SAN 恢复增益无限叠加。 |

## 7. Validator

| ValidatorID | 检查内容 | 失败级别 |
|---|---|---|
| `CFG-EFFECT-001` | `EffectID`、`Type`、`TriggerTiming`、`AttachableScope`、`ConfigSchema` 必填。 | error |
| `CFG-EFFECT-002` | 引用效果的配置项参数数量、类型和值域与 `ConfigSchema` 一致。 | error |
| `CFG-EFFECT-003` | 影响核心决策的效果必须 `VisibleToPlayer=true` 或有明确反馈引用。 | warning / error |
| `CFG-TAG-001` | `TagID`、`TagGroup`、`DurationType`、`StackPolicy`、`ClearRule` 必填且值域合法。 | error |
| `CFG-TAG-002` | `UntilMaintenance` 类动态标签必须至少被一个维护方案或事件清除 / 转化。 | error |
| `CFG-TRAIT-001` | 特质必须有获得条件、生效规则、反馈和 `TransformRule`。 | error |
| `CFG-TRAIT-002` | 负面特质不能缺少转化、消除或压制路径。 | error |
| `CFG-TRAIT-003` | 同一 `ConflictGroup` 内不能同时存在多个默认有效特质，除非明确 `HistoryOnly`。 | error |
| `CFG-TRAIT-004` | 特质引用的 `EffectID`、`TagID`、`FeedbackID` 必须存在或有占位 warning。 | warning / error |
| `CFG-TRAIT-005` | 正面特质不能产生无限叠加收益；`StackPolicy` 必须有上限或唯一策略。 | error |

## 8. 固定验收样例

| 验收 ID | 前置 | 操作 | 期望 |
|---|---|---|---|
| `V-GROWTH-EFFECT-01` | `prosthetic_focus_lens` 引用 `effect_route_preview_hint`。 | 进入深渊地图并打开节点预览。 | 相邻节点只显示倾向，不完全透视；缺 UI 支持时 Validator 给 warning，不删除字段。 |
| `V-GROWTH-EFFECT-02` | `prosthetic_san_regulator_core` 引用 `effect_san_loss_regulate`。 | 遭遇一次超过阈值的 SAN 损失。 | 损失被部分削减，附加 `tag_san_regulation_fatigue`，维护面板能解释疲劳来源。 |
| `V-GROWTH-TAG-01` | 人偶带有 `tag_corrosion_taint`。 | 执行 `maint_purification_flush`。 | 污染标签降低或清除，磨损仍保留，玩家理解净化不是全恢复。 |
| `V-GROWTH-TRAIT-01` | 获得 `trait_fear_of_spores`。 | 净化冲洗后击败对应精英。 | 负面特质被转化或压制，历史保留，节点预警不再作为惩罚生效。 |
| `V-GROWTH-TRAIT-02` | 获得 `trait_fragile_trust`。 | 连续多日照料并不强行低 SAN 下潜。 | 交互收益逐步恢复，特质进入历史或转化为信任修复记录。 |
| `V-GROWTH-TRAIT-03` | 拥有 `trait_steady_hands`。 | 本轮第一次关键背包拖拽 / 旋转失误。 | 获得一次提示或宽限；同一轮不无限触发。 |

## 9. 完成判定

`GROWTH-EFFECTS-TRAITS` 只有在以下条件满足后，才能视为效果 / 特质配置域局部完成：

1. `EffectEnums` 或等价配置结构能表达本文件列出的义体效果、维护效果、动态标签和 8 个特质。
2. 旧效果 ID 的兼容边界清楚，不把旧原型效果误判为正式局外成长效果完成。
3. `Prosthetics`、`CraftingRecipes`、`Dolls` 后续引用的 `EffectID`、`TagID`、`TraitID` 都可追到本文或实际 JSON。
4. 所有负面特质都有转化、消除或压制路径。
5. `CFG-EFFECT-*`、`CFG-TAG-*`、`CFG-TRAIT-*` 或人工等价检查通过。
6. 至少覆盖 `V-GROWTH-EFFECT-01`、`V-GROWTH-TAG-01`、`V-GROWTH-TRAIT-01` 三条样例。
7. `agent_status/design.md` 的 `DES-V3-002` 追加效果 / 特质证据；如影响长期节点门禁，PM 同步 `09`，但整个局外成长配置仍不能因此标记为 `配置完成`。
