# 局外成长底盘正式配置落地设计

> 本文承接 `38_局外成长正式配置实现任务拆分.md` 的 `GROWTH-CHASSIS`。它把 3 个正式底盘转成 JSON 修改前字段级清单，供后续配置实现使用。本文不直接修改 `配置表(JSON)`，不代表底盘 JSON 已完成。

---

## 1. 当前事实

当前 `配置表(JSON)/Chassis` 已有两个旧原型底盘：

| 文件 | 当前 ID | 当前用途 | 正式判断 |
|---|---|---|---|
| `chassis_lv1_basic.json` | `chassis_lv1_basic` | 4x4 基础网格，带 `UpgradeCost.NextChassisID=chassis_lv2_expanded`。 | 旧 MVP / 原型 ID，可迁移为 `chassis_standard_frame` 或保留为兼容别名。 |
| `chassis_lv2_expanded.json` | `chassis_lv2_expanded` | 5x5 扩展网格，无进一步升级。 | 旧 MVP / 原型 ID，不等同于正式重载底盘。 |

旧配置的问题：

1. 只表达 `Level` 和网格尺寸，缺少构筑职责。
2. 没有 `DisplayName`、`DescriptionKey`、`ChassisRole`、`VisualID`。
3. 没有义体槽、维护倍率、适应期、风险标签和规则修正。
4. `UpgradeCost` 只能表达线性升级，不适合正式版横向底盘选择。
5. 没有下潜许可、换装适应期和旧底盘回装边界。

---

## 2. 本轮目标

`GROWTH-CHASSIS` 本轮只处理首批 3 个正式底盘：

| ChassisID | 定位 | 玩家决策 |
|---|---|---|
| `chassis_standard_frame` | 标准 / 教学 / 基准对照 | 稳定、无适应期、作为其它底盘的比较基准。 |
| `chassis_compact_raider` | 轻装 / 路线预览 / 撤离 | 背包面积较小，换取路线信息和低风险深入。 |
| `chassis_bulwark_carrier` | 重载 / 订单承载 / 抗干涉 | 背包面积更大，换取更高维护成本和适应期压力。 |

设计原则：

1. 底盘不是线性升级树，而是构筑方向。
2. 强底盘必须有代价：适应期、维护倍率、风险标签或槽位限制。
3. 旧底盘不销毁；迁移时要保留兼容 / 回装口径。
4. 如果程序暂不支持某字段，配置仍保留正式字段，Validator 先给 warning，不降级为旧字段。

---

## 3. 字段标准

### 3.1 必填字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `ChassisID` | string | 全局唯一 ID。 |
| `DisplayName` | string | 玩家可见名。 |
| `DescriptionKey` | string | 本地化描述 Key。 |
| `ChassisRole` | string[] | 构筑职责标签。 |
| `VisualID` | string | UI / 工坊展示资源 ID，可先用 fallback。 |
| `GridWidth` | int | 背包宽度。 |
| `GridHeight` | int | 背包高度。 |
| `GridMask` | bool[][] | 可用格掩码，必须与宽高一致。 |
| `AllowedProstheticSlots` | string[] | 可安装义体槽。 |
| `MaintenanceModifier` | float | 维护费用或磨损倍率，默认 1.0。 |

### 3.2 推荐字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `BaseSlotTags` | string[] | 底盘自带槽位语义，例如 `StableCore`、`WideCargo`。 |
| `UnlockCondition` | object | 图纸、层级、Boss / 精英材料、剧情或订单条件。 |
| `BuildCost` | object | 首次制造 / 解锁成本。 |
| `InstallCost` | object | 更换 / 安装成本。 |
| `AdaptationDays` | int | 更换后适应期。 |
| `RuleModifiers` | object[] | 路线预览、封格抗性、负重修正等。 |
| `RiskTags` | string[] | 风险标签。 |
| `EndingTags` | string[] | 长线倾向标签。 |
| `LegacyAliases` | string[] | 迁移兼容旧 ID。 |

## 4. 正式底盘清单

### 4.1 `chassis_standard_frame`

| 字段组 | 口径 |
|---|---|
| 迁移来源 | 可由 `chassis_lv1_basic` 迁移。旧 ID 可进入 `LegacyAliases`。 |
| 职责 | `Baseline`、`Tutorial`、`Stable`。 |
| 背包 | 建议 6x4 标准矩形；若程序当前只支持旧 4x4，可先保留 4x4 并在 Validator 标 warning。 |
| 槽位 | `CorePump`、`LeftArm`、`RightArm`、`HeadSensor`。 |
| 解锁 | 初始拥有，无图纸要求。 |
| 成本 | `BuildCost=0`，`InstallCost=0`。 |
| 代价 | `AdaptationDays=0`，`MaintenanceModifier=1.0`，无风险标签。 |
| 规则 | 不提供特殊加成，作为基准对照。 |
| 表现 | `VisualID=chassis_standard_frame_icon`，允许 fallback。 |

### 4.2 `chassis_compact_raider`

| 字段组 | 口径 |
|---|---|
| 迁移来源 | 新增正式 ID，不复用旧 `chassis_lv2_expanded`。 |
| 职责 | `Scout`、`Extract`、`RoutePreview`。 |
| 背包 | 面积小于标准，建议 5x4 或 6x4 带缺口；边角更规整，利于小件 / 撤离物。 |
| 槽位 | 优先 `HeadSensor`、`RightArm`、`CorePump`；可不开放 `LeftArm` 或限制重型手臂。 |
| 解锁 | 第一层 Boss 核心 + 掠行图纸。 |
| 成本 | 中低金币 + 第一层核心材料。 |
| 代价 | `AdaptationDays=1`；低承载、HP / 负重或重型物风险。 |
| 规则 | 轻度路线预览、撤离节点识别或低风险路线提示。 |
| 表现 | 更轻的轮廓、警觉待机、地图扫描反馈。 |

| 字段组 | 口径 |
|---|---|
| 迁移来源 | 不能直接把 `chassis_lv2_expanded` 当作完成；可把旧 ID 作为兼容 / 测试 ID，或迁移后加入 `LegacyAliases`。 |
| 职责 | `HeavyCarry`、`Order`、`GridResist`。 |
| 背包 | 面积高于标准，建议 7x4 或 6x5，适合长条、大件、订单物。 |

## 5. 迁移规则

### 5.1 旧 ID 处理

| 旧 ID | 推荐处理 | 原因 |
|---|---|---|
| `chassis_lv1_basic` | 迁移为 `chassis_standard_frame`，旧 ID 写入 `LegacyAliases`。 | 旧 ID 是初始底盘语义，适合成为标准底盘兼容别名。 |
| `chassis_lv2_expanded` | 不直接等同正式完成；可作为 `chassis_bulwark_carrier` 的兼容别名，或保留为测试 ID。 | 旧 ID 只有 5x5 扩容，没有正式重载职责和代价。 |

### 5.2 存档 / 引用兼容

后续程序或配置实现需要决定：

1. 读取旧 `DefaultChassisID=chassis_lv1_basic` 时，是否自动映射到 `chassis_standard_frame`。
2. 如果旧存档持有 `chassis_lv2_expanded`，是否映射到 `chassis_bulwark_carrier`，还是保留为兼容底盘。
3. `CraftingRecipes` 的底盘解锁配方输出必须使用正式 ID，不再输出旧 `chassis_lv*` ID。
4. `Dolls` 静态档案的 `DefaultChassisID` 正式配置应改为 `chassis_standard_frame`。

---

## 6. 与其它配置域关系

| 配置域 | 依赖 / 输出 |
|---|---|
| `Dolls` | `DefaultChassisID` 应指向 `chassis_standard_frame`；当前运行时底盘属于人偶实例，不写入静态当前状态。 |
| `Prosthetics` | 每个义体的 `SlotType` 必须被至少一个正式底盘允许。 |
| `CraftingRecipes` | `craft_chassis_compact_raider`、`craft_chassis_bulwark_carrier` 输出正式底盘解锁。 |
| `Effects` | `RuleModifiers` 若引用效果或规则 ID，必须进入效果 / 规则字典或程序映射。 |
| `Dungeons / Rewards` | 第一层 Boss、第二层精英、订单或节点奖励需要提供底盘解锁材料来源。 |

## 7. Validator

| ValidatorID | 检查内容 | 失败级别 |
|---|---|---|
| `CFG-CHASSIS-001` | `ChassisID`、`DisplayName`、`DescriptionKey`、`ChassisRole`、`GridWidth`、`GridHeight`、`GridMask` 必填。 | error |
| `CFG-CHASSIS-002` | `GridMask` 行数等于 `GridHeight`，每行长度等于 `GridWidth`，至少 1 个可用格。 | error |
| `CFG-CHASSIS-003` | `ChassisRole` 非空，且不能只写 `Level`。 | error |
| `CFG-CHASSIS-004` | `AllowedProstheticSlots` 来自正式槽位枚举，且每个正式义体至少被一个底盘允许。 | error |
| `CFG-CHASSIS-005` | `VisualID` 存在或明确 fallback。 | warning |
| `CFG-CHASSIS-006` | `UnlockCondition`、`BuildCost.RequiredItems`、`BlueprintRef` 引用存在；暂未配置来源时给 warning。 | warning / error |
| `CFG-CHASSIS-007` | `AdaptationDays >= 0`，`MaintenanceModifier > 0`；强底盘不能无代价。 | error |
| `CFG-CHASSIS-008` | 旧 ID 不应出现在正式内容包输出中；如出现必须有 `LegacyAliases` 或兼容说明。 | warning |

## 8. 固定验收样例

| 验收 ID | 前置 | 操作 | 期望 |
|---|---|---|---|
| `V-GROWTH-CHASSIS-01` | 初始人偶读取默认底盘。 | 解析 `chassis_standard_frame`。 | 背包网格、基础义体槽、维护倍率和下潜许可均正常；旧 `chassis_lv1_basic` 不再作为正式主 ID。 |
| `V-GROWTH-CHASSIS-02` | 玩家拥有第一层 Boss 核心、掠行图纸和金币。 | 解锁 / 安装 `chassis_compact_raider`。 | 扣除成本，背包面积变小或形状改变，路线预览规则可见，适应期 1 天生效。 |
| `V-GROWTH-CHASSIS-03` | 玩家拥有第二层精英材料、承运图纸和金币。 | 解锁 / 安装 `chassis_bulwark_carrier`。 | 背包承载增强，槽位偏重载，维护倍率提高，适应期 2 天生效。 |
| `V-GROWTH-CHASSIS-04` | 当前装备义体槽在新底盘中非法。 | 切换到底盘后重建槽位。 | 非法义体卸回工坊库存，不销毁，并给出提示。 |
| `V-GROWTH-CHASSIS-05` | 更换底盘后立即下潜。 | 进入下潜许可检查。 | 允许下潜，但适应期惩罚或 warning 生效；极端磨损 / 侵蚀仍可阻止下潜。 |

## 9. 完成判定

`GROWTH-CHASSIS` 只有在以下条件满足后，才能视为底盘配置域局部完成：

1. `配置表(JSON)/Chassis` 中存在 3 个正式底盘主 ID，或存在明确迁移后的等价结构。
2. `chassis_standard_frame`、`chassis_compact_raider`、`chassis_bulwark_carrier` 均具备职责、网格、槽位、成本、解锁、代价和表现字段。
3. 旧 `chassis_lv1_basic`、`chassis_lv2_expanded` 有迁移 / 兼容说明，不被误判为正式完成。
4. `Dolls` 默认底盘、`CraftingRecipes` 底盘解锁输出和义体槽位引用与正式 ID 对齐。
5. `CFG-CHASSIS-*` 或人工等价检查通过，至少覆盖 `V-GROWTH-CHASSIS-01` 到 `V-GROWTH-CHASSIS-03`。
6. `agent_status/design.md` 的 `DES-V3-002` 追加底盘证据；如影响长期节点门禁，PM 同步 `09`，但整个局外成长配置仍不能因此标记为 `配置完成`。

---

## 10. 下一步

完成本文后，局外成长配置链路的下一步建议：

1. 若继续策划侧设计，推进 `GROWTH-EFFECTS-TRAITS`，先把义体和特质需要的效果 / 标签字典拆清。
2. 若进入配置实现，先按本文补 `Chassis` JSON，再同步 `Dolls.DefaultChassisID` 和底盘解锁配方。
3. 配置实现后运行配置同步和 Validator；如程序暂不支持新字段，应记录 warning，不删除正式字段。
