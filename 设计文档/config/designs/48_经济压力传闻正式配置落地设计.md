# 经济压力传闻正式配置落地设计

> 本文承接 `46_经济压力正式配置承接审计.md` 的 `ECON-RUMORS`。它把 `22_小镇经济月租内容包.md` 的 8 条经济传闻转成 JSON 修改前字段级清单。本文不直接修改 `配置表(JSON)`，不代表传闻配置已经完成。

---

## 1. 当前事实

当前 `配置表(JSON)/Rumors/` 只有一个可运行样例：

| 当前 RumorID | 当前作用 | 正式判断 |
|---|---|---|
| `rumor_mechanical_price_up` | `Mechanical` 标签在 `DumpBox` 渠道 1.5x，持续 7 天，并提高机械订单权重。 | 可迁移为 `rumor_scrap_workshop_shortage` 的原型，但字段、倍率、来源层级和玩家可见意图需要按正式传闻池重做。 |

当前缺口：

1. 只有涨价传闻，缺跌价、黑市窗口、订单预告、橱窗顾客和维护需求导向。
2. 只有 `TargetTags` 和 `BoostedOrderTags`，缺正式的来源追踪、风险提示、兑现渠道和玩家可见建议。
3. 无法机械检查传闻是否能在当前开放层级兑现。
4. 无法区分“价格倍率传闻”“渠道开启传闻”“订单刷新权重传闻”“路线目标传闻”。
5. 无法把周报中的传闻刷新转成下一次下潜目标。

---

## 2. 本轮范围

`ECON-RUMORS` 只处理传闻池，不处理顾客池、账单、订单模板和势力阶梯。

| 范围内 | 范围外 |
|---|---|
| 8 条正式传闻的字段级设计。 | 真实 JSON 修改。 |
| 传闻类型、倍率、安全区间、渠道、持续时间和刷新权重。 | 订单系统运行时刷新实现。 |
| 传闻来源追踪：物品标签、层级、节点、怪物、订单和事件。 | 5 个势力完整字段已由 `49_经济压力势力正式配置落地设计.md` 承接。 |
| 黑市窗口传闻和违禁品传闻的边界。 | 18 条订单模板已由 `50_经济压力订单正式配置落地设计.md` 承接。 |
| Validator 和固定验收样例。 | UI 版式、美术资源和程序服务。 |

## 3. RumorConfig 正式字段

### 3.1 保留字段

| 字段 | 处理 |
|---|---|
| `RumorID` | 保留全局唯一 ID。 |
| `DisplayName` / `Description` | 保留，但正式配置应改为本地化 key 或明确由 UI 文案层承接。 |
| `RumorType` | 保留枚举，需扩展类型语义。 |
| `TargetTags` | 保留，改为目标查询的一部分。 |
| `TargetLayer` | 保留，可改为 `LayerRange` 支撑多层。 |
| `Channel` | 保留，但要支持 `DumpBox`、`ShowcaseGrid`、`OrderSlot`、`BlackMarketSlot` 和 `AnySellChannel`。 |
| `PriceMultiplier` | 保留，必须受安全区间和持续时间约束。 |
| `DurationDays` / `Weight` | 保留，用于周刷新池。 |
| `BoostedOrderTags` | 保留，用于订单池权重。 |

### 3.2 新增 / 补齐字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `TargetQuery` | object | 是 | 比 `TargetTags` 更完整的查询表达，支持 `AllOf`、`AnyOf`、`NoneOf`、`LayerRange`、`ItemRole`。 |
| `SourceTrace` | object | 是 | 玩家能从哪里兑现传闻：层级、节点、怪物、物品、订单或事件。 |
| `PlayerHintKey` | string | 是 | 周报和传闻板给玩家的路线建议。 |
| `RiskHintKey` | string | 否 | 跌价、违禁、黑市、NightTax 或订单冲突风险提示。 |
| `ChannelModifiers` | object[] | 是 | 不同出售渠道的倍率、预算、是否开启、是否拒收。 |
| `OrderWeightModifiers` | object[] | 否 | 对订单标签、势力或订单池的权重影响。 |
| `CustomerWeightModifiers` | object[] | 否 | 对橱窗顾客类型出现率或预算的影响。 |
| `BlackMarketWindow` | object | 否 | 黑市窗口开启条件、持续天数和风险输出。 |
| `NightTaxModifier` | object | 否 | 传闻是否提高或降低违禁 / 污染隔夜代价。 |
| `RefreshGroup` | string | 是 | 周刷新分组，防止同类传闻连续重复。 |
| `MutualExclusionTags` | array | 否 | 与其它传闻互斥，避免同周出现冲突口径。 |
| `ValidationRefs` | object | 是 | 指向 Items / Orders / Dungeons / Economy 需要校验的引用。 |

### 3.3 RumorType 正式语义

| RumorType | 含义 | 示例 |
|---|---|---|
| `DemandUp` | 某类物品涨价或买方预算提高。 | `rumor_origin_stone_demand` |
| `DemandDown` | 某类物品跌价，鼓励囤货、放弃或转用途。 | `rumor_slime_crash` |
| `MaterialShortage` | 材料需求提高，并影响制造 / 订单权重。 | `rumor_scrap_workshop_shortage` |
| `RiskPremium` | 高风险物品高价，但附带 NightTax 或渠道限制。 | `rumor_corrosion_sample_premium` |
| `BlackMarketWindow` | 临时开放黑市渠道。 | `rumor_contraband_night_channel` |
| `FactionRequest` | 某势力需求提高，影响订单和顾客。 | `rumor_faction_medical_request` |
| `CustomerVisit` | 特殊顾客到访，主要影响橱窗预算。 | `rumor_weapon_collector_visit` |
| `BulkPurchase` | 常见低层物短期收购，提高回刷价值。 | `rumor_low_layer_bulk_buy` |

## 4. 8 条正式传闻

### 4.1 总表

| RumorID | 类型 | 目标 | 渠道 | 持续 | 职责 |
|---|---|---|---|---:|---|
| `rumor_origin_stone_demand` | `DemandUp` | `OriginStone` / `Relic` | `ShowcaseGrid`、`DumpBox` | 7 | 第一层高价值占格物目标。 |
| `rumor_slime_crash` | `DemandDown` | `Slime` / `CommonLoot` | `DumpBox` | 7 | 教玩家跌价、囤货或转用途。 |
| `rumor_scrap_workshop_shortage` | `MaterialShortage` | `Scrap` + `Mechanical` | `DumpBox`、`OrderSlot` | 7 | 制造材料与卖钱取舍。 |
| `rumor_corrosion_sample_premium` | `RiskPremium` | `CorrosionSample` | `BlackMarketSlot`、`OrderSlot` | 3 | 高价与 NightTax 风险绑定。 |
| `rumor_contraband_night_channel` | `BlackMarketWindow` | `Contraband` / `ForbiddenRelic` | `BlackMarketSlot` | 1 | 临时处理违禁品，诱导高风险收益。 |
| `rumor_faction_medical_request` | `FactionRequest` | `Purification` / `Medical` | `OrderSlot`、`ShowcaseGrid` | 7 | 把维护需求接到经济目标。 |
| `rumor_weapon_collector_visit` | `CustomerVisit` | `Weapon` | `ShowcaseGrid` | 1 | 教高价值装备走橱窗。 |
| `rumor_low_layer_bulk_buy` | `BulkPurchase` | `Tier1Material` / `CommonLoot` | `DumpBox` | 7 | 给低层回刷短期理由。 |

### 4.2 `rumor_origin_stone_demand`

```json
{
  "RumorID": "rumor_origin_stone_demand",
  "RumorType": "DemandUp",
  "TargetQuery": {
    "AnyOf": ["OriginStone", "Relic"],
    "LayerRange": [1, 2],
    "NoneOf": ["StoryLocked", "OrderBound"]
  },
  "ChannelModifiers": [
    {"Channel": "ShowcaseGrid", "PriceMultiplier": 1.5, "CustomerBudgetMultiplier": 1.15},
    {"Channel": "DumpBox", "PriceMultiplier": 1.25}
  ],
  "DurationDays": 7,
  "Weight": 80,
  "SourceTrace": {
    "Layers": [1, 2],
    "ItemTags": ["OriginStone", "Relic"],
    "NodeTags": ["Mine", "RelicCache"]
  },
  "PlayerHintKey": "rumor.origin_stone.hint",
  "RefreshGroup": "value_spike"
}
```

用途：让玩家在低层就理解“传闻 -> 捡取目标 -> 出货渠道”的完整链路。若当前 JSON 尚无 `OriginStone` 标签，配置实现时必须先补 Items 标签或把该传闻降为 warning。

### 4.3 `rumor_slime_crash`

```json
{
  "RumorID": "rumor_slime_crash",
  "RumorType": "DemandDown",
  "TargetQuery": {
    "AnyOf": ["Slime", "CommonLoot"],
    "LayerRange": [1, 1]
  },
  "ChannelModifiers": [
    {"Channel": "DumpBox", "PriceMultiplier": 0.35}
  ],
  "DurationDays": 7,
  "Weight": 60,
  "PlayerHintKey": "rumor.slime_crash.hint",
  "RiskHintKey": "rumor.slime_crash.risk",
  "RefreshGroup": "value_crash"
}
```

用途：不是惩罚玩家，而是让玩家理解跌价信息也会改变背包选择。跌价物可以选择囤货、制造消耗、订单提交或低价清理。

## 5. 刷新与组合规则

### 5.1 周刷新规则

| 字段 | 正式口径 |
|---|---|
| `RefreshIntervalDays` | 7 天，跟周报同步。 |
| `ActiveRumorCount` | 前三层阶段建议 2 条：1 条收益导向，1 条风险 / 订单 / 渠道导向。 |
| `NoRepeatWindow` | 同一 `RefreshGroup` 2 周内不重复。 |
| `LayerEligibility` | 不生成当前已开放层级无法兑现的传闻。 |
| `FallbackRumor` | 如果所有高阶传闻不可用，回退到 `rumor_low_layer_bulk_buy` 或同类低层保底传闻。 |

### 5.2 组合限制

| 限制 | 原因 |
|---|---|
| 同周最多 1 条 `BlackMarketWindow`。 | 避免黑市成为常驻普通渠道。 |
| 同周最多 1 条 `DemandDown`。 | 避免玩家觉得周报只是在降收益。 |
| `RiskPremium` 必须和可见清理方式共存。 | 高收益必须可补救。 |
| `FactionRequest` 必须能追到至少一个订单池或顾客。 | 避免假目标。 |
| `CustomerVisit` 必须影响橱窗，不影响倾倒箱。 | 保持渠道差异。 |

## 6. 与其它配置域关系

| 配置域 | 依赖 / 输出 |
|---|---|
| `Items` | 传闻目标标签必须能在物品 `Tags`、`ValueTags`、`RiskTags` 或动态标签中追到。 |
| `Dungeons` | `SourceTrace.Layers`、`NodeTags` 和 `MonsterTags` 必须能在已开放层级兑现。 |
| `Orders` | `BoostedOrderTags`、`OrderWeightModifiers` 和 `FactionID` 必须能追到订单池或势力。 |
| `Economy` | `WeeklyReportPolicy.RefreshRumors=true` 时，周报必须展示传闻和目标建议。 |
| `Factions` | `FactionRequest` 和黑市窗口需要势力 / 信任阶梯承接，已由 `49_经济压力势力正式配置落地设计.md` 处理。 |
| `ScenarioEvents` | 黑市、债主注意、违禁警告等风险输出需要事件承接。 |
| UI / 美术 | 传闻板、周报、出货收益来源和风险提示必须可见。 |

## 7. Validator

| ValidatorID | 检查内容 | 失败级别 |
|---|---|---|
| `CFG-RUMOR-001` | `RumorID` 唯一，`RumorType`、`DurationDays`、`Weight` 合法。 | error |
| `CFG-RUMOR-002` | `TargetQuery` 至少包含 `AnyOf` 或 `AllOf`，且目标标签能追到 Items 或 Orders。 | error |
| `CFG-RUMOR-003` | `PriceMultiplier` 在安全区间内：常规涨价 1.05-1.5，风险涨价可到 1.8，跌价不低于 0.3。 | warning / error |
| `CFG-RUMOR-004` | `SourceTrace` 必须至少声明层级、节点、怪物、物品或订单之一。 | error |
| `CFG-RUMOR-005` | 每个当前开放层级至少有 1 条可兑现传闻。 | error |
| `CFG-RUMOR-006` | 黑市传闻必须开启 `BlackMarketSlot`，声明风险输出，并要求二次确认。 | error |
| `CFG-RUMOR-007` | `RiskPremium` 必须有 `RiskHintKey`，并引用 NightTax、违禁规则或订单风险之一。 | error |
| `CFG-RUMOR-008` | `OrderWeightModifiers` 引用的 FactionID、OrderTag 或订单池必须存在或处于明确预留 warning。 | warning / error |
| `CFG-RUMOR-009` | 同一刷新池中不能出现互斥传闻，例如同一标签同时大涨和大跌。 | error |

## 8. 固定验收样例

| 验收 ID | 前置 | 操作 | 期望 |
|---|---|---|---|
| `V-ECON-RUMOR-ORIGIN-01` | 周报刷新 `rumor_origin_stone_demand`，第一层有源石类物品。 | 玩家带回源石并走橱窗或倾倒箱。 | 售价倍率可见，日报能列出传闻贡献。 |
| `V-ECON-RUMOR-SLIME-01` | 周报刷新 `rumor_slime_crash`，玩家带回史莱姆掉落。 | 出售前查看收益。 | 跌价清楚展示，玩家可选择囤货、低价处理或转订单 / 制造。 |
| `V-ECON-RUMOR-SCRAP-01` | 刷新工坊废料短缺，存在机械废料和工坊订单池。 | 玩家带回机械废料。 | 普通出售收益提高，同时工坊订单权重提高。 |

## 9. 完成判定

`ECON-RUMORS` 只有在以下条件满足后，才能视为传闻配置设计局部完成：

1. 8 条传闻都有 RumorID、类型、目标查询、渠道修正、持续、权重、来源追踪和玩家提示。
2. 涨价、跌价、材料短缺、风险溢价、黑市窗口、势力请求、特殊顾客和低层保底都被覆盖。
3. 每条传闻都能追到 Items / Dungeons / Orders / Economy / Factions 的后续承接点。
4. 黑市、违禁和风险溢价传闻都声明风险输出和二次确认边界。
5. `CFG-RUMOR-*` 检查项和 `V-ECON-RUMOR-*` 固定验收样例已定义。
6. `agent_status/design.md` 的 `DES-V4-001` 追加本文证据；如影响长期节点门禁，PM 同步 `09`，但整个经济压力配置仍不能因此标记为 `配置完成`。
