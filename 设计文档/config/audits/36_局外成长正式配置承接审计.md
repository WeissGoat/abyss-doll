# 局外成长正式配置承接审计

> **定位：** 本文是 `26_正式配置设计与填充推进计划.md` 中 W3「局外成长与经济目标补齐」的第一份配置承接审计。它只审计 `Chassis`、`Prosthetics`、`CraftingRecipes`、`Dolls`、`Effects` 现有配置 README 和 JSON 是否能承接正式规则与内容包；它不直接改配置值，也不代表局外成长配置已经完成。审计后的 JSON 修改前落地设计见 `37_局外成长正式配置落地设计.md`。

---

## 1. 审计结论

当前局外成长配置域已经具备最小原型：

| 配置域 | 当前源数据 | 当前作用 |
|---|---|---|
| `Chassis` | `chassis_lv1_basic.json`、`chassis_lv2_expanded.json` | 提供 4x4 / 5x5 背包尺寸升级。 |
| `Prosthetics` | `pros_power_arm.json`、`pros_cooling_system.json` | 提供 2 个义体被动效果样例。 |
| `CraftingRecipes` | `craft_pros_power_arm.json`、`craft_pros_cooling_system.json` | 提供 2 个制造义体配方样例。 |
| `Dolls` | `doll_proto_0.json`、`doll_proto_0_test.json` | 提供人偶基础属性、当前状态、初始物品和默认底盘。 |
| `Effects` | `EffectEnums.json` | 提供物品和义体共用的效果字典。 |

但这些配置仍主要是 MVP / 原型口径，距离正式局外成长循环还有明显缺口：

1. `Chassis` 仍是线性尺寸升级，没有 `ChassisRole`、视觉 ID、解锁条件、适应期、维护倍率、义体槽和构筑方向。
2. `Prosthetics` 只有 2 个样例，槽位、互斥、维护代价、触发条件和视觉反馈不足。
3. `CraftingRecipes` 只能制造义体，不能表达底盘、维护方案、消耗品、取消返还、污染继承或图纸门槛。
4. `Dolls` 把运行时状态写入静态档案，且缺少 Bond、情绪、特质、房间、交互反馈和下潜许可字段。
5. `Effects` 是效果字典，不足以承接正式特质、动态标签、维护方案、适应期、侵蚀和房间记忆规则。

结论：W3 不能直接进入“配置完成”判断，下一步应先补局外成长配置落地设计，再进入 JSON 实现。

## 3. `Chassis` 审计

### 3.1 当前字段

| 字段 | 当前情况 | 判断 |
|---|---|---|
| `ChassisID` | 已有。 | 可保留。 |
| `Level` | 已有。 | 过于线性，正式版不能只靠等级表达构筑。 |
| `GridWidth` / `GridHeight` | 已有。 | 可保留。 |
| `GridMask` | 已有。 | 可承接异形背包。 |
| `UpgradeCost` | 已有。 | 只能表达线性升级，不能表达图纸、Boss 核心、适应期和横向底盘选择。 |

### 3.2 正式字段缺口

| 缺口字段 | 设计目的 | 来源 |
|---|---|---|
| `DisplayName` / `DescriptionKey` | UI 与日志可读。 | `16` |
| `ChassisRole` | 标记空间、战斗、续航、侦察、订单承载等构筑方向。 | `05` / `21` |
| `VisualID` | 对接底盘外观或工坊展示。 | `16` / 美术交接 |
| `RuleModifiers` | 表达路线预览、封格抗性、维护效率等规则变化。 | `05` |
| `AllowedProstheticSlots` | 表达底盘改变义体槽位。 | `05` |
| `UnlockCondition` / `BlueprintRef` | 图纸、Boss 核心、势力声望或剧情门槛。 | `05` / `21` |
| `BuildCost` / `InstallCost` | 区分制造成本和更换成本。 | `05` |
| `AdaptationDays` | 更换底盘后的短期代价。 | `05` |
| `MaintenanceModifier` | 强底盘提高维护费用或磨损压力。 | `05` / `21` |
| `RiskTags` / `EndingTags` | 服务风险提示、结局倾向或长期统计。 | `05` |

### 3.3 内容缺口

`21` 要求首批至少 3 个方向：

| 目标 ID | 职责 | 当前状态 |
|---|---|---|
| `chassis_standard_frame` | 默认基准，服务低压入门。 | 当前 `chassis_lv1_basic` 可迁移，但缺正式字段。 |
| `chassis_compact_raider` | 轻装、路线预览、撤离和低风险路线。 | 缺配置。 |
| `chassis_bulwark_carrier` | 重载、订单、大件战利品和封格抗性。 | 当前 `chassis_lv2_expanded` 只像尺寸升级，需重设职责。 |

### 3.4 Validator 建议

| ValidatorID | 检查内容 |
|---|---|
| `CFG-CHASSIS-001` | `ChassisID`、`DisplayName`、`GridWidth`、`GridHeight`、`GridMask`、`ChassisRole` 必填。 |
| `CFG-CHASSIS-002` | `GridMask` 尺寸必须与宽高一致，且至少存在 1 个可用格。 |
| `CFG-CHASSIS-003` | `UnlockCondition`、`BuildCost` 引用的物品、奖励或图纸存在。 |
| `CFG-CHASSIS-004` | `AllowedProstheticSlots` 的槽位必须能被义体配置引用。 |
| `CFG-CHASSIS-005` | `AdaptationDays`、`MaintenanceModifier`、`RiskTags` 的值域合法。 |

## 4. `Prosthetics` 审计

### 4.1 当前字段

| 字段 | 当前情况 | 判断 |
|---|---|---|
| `ProstheticID` | 已有。 | 可保留。 |
| `Name` | 已有。 | 应补 `DisplayName` / `DescriptionKey` 或统一命名。 |
| `Level` | 已有，当前为 `Primary`。 | 需要正式 `Tier` 口径。 |
| `SlotType` | 已有，当前 `Arm` / `Core`。 | 槽位太少，与规则卡五槽位不一致。 |
| `Effects` | 已有。 | 只表达效果，不表达触发条件、互斥、维护代价和表现反馈。 |

### 4.2 正式字段缺口

| 缺口字段 | 设计目的 |
|---|---|
| `DisplayName` / `DescriptionKey` / `VisualID` | UI、日志和图标表现。 |
| `Tier` | 基础、强化、极致或特殊。 |
| `Tags` | 构筑标签，如 `MeleeSupport`、`Scout`、`SanStabilizer`。 |
| `TriggerRules` | 描述义体何时生效。 |
| `UnlockCondition` / `CraftCost` / `InstallCost` | 解锁、制造和更换成本。 |
| `ConflictGroup` | 同类互斥和跨槽冲突。 |
| `MaintenanceModifier` / `WearImpact` / `CorruptionImpact` | 强力义体带来的长期维护代价。 |
| `FeedbackRefs` | 生效时的 UI / 文案 / 动效反馈。 |

### 4.3 内容缺口

`21` 首批需要 6 个义体：

| 目标 ID | 职责 | 当前状态 |
|---|---|---|
| `prosthetic_focus_lens` | 地图阅读和路线规划。 | 缺配置。 |
| `prosthetic_anchor_left_arm` | 抵抗背包干涉。 | 缺配置。 |
| `prosthetic_charge_coil_arm` | 支撑充能武器爆发。 | 可参考 `pros_power_arm`，但当前效果太泛。 |
| `prosthetic_san_regulator_core` | 降低短线崩溃风险。 | 可参考 `pros_cooling_system`，但需疲劳和维护代价。 |
| `prosthetic_salvage_fingertips` | 提高材料转化和制造方向。 | 缺配置。 |
| `prosthetic_mender_spine` | 长线恢复和安全区后续修复。 | 缺配置。 |

### 4.4 Validator 建议

| ValidatorID | 检查内容 |
|---|---|
| `CFG-PROSTHETIC-001` | `ProstheticID`、`DisplayName`、`SlotType`、`Tier`、`Effects` 或 `TriggerRules` 必填。 |
| `CFG-PROSTHETIC-002` | `SlotType` 必须来自正式槽位枚举。 |
| `CFG-PROSTHETIC-003` | `Effects.EffectID` 必须存在于 `Effects` 字典或程序效果注册表。 |
| `CFG-PROSTHETIC-004` | `ConflictGroup` 互斥关系不能形成不可装备死锁。 |
| `CFG-PROSTHETIC-005` | `CraftCost` / `InstallCost` 引用材料存在，且不会引用未开放层级的必需材料。 |

## 5. `CraftingRecipes` 审计

### 5.1 当前字段

| 字段 | 当前情况 | 判断 |
|---|---|---|
| `RecipeID` | 已有。 | 可保留。 |
| `TargetProstheticID` | 已有。 | 只能制造义体，不足以承接正式工坊。 |
| `Cost` | 已有。 | 结构较窄，缺图纸、取消、输出类型、污染继承和失败规则。 |

### 5.2 正式字段缺口

| 缺口字段 | 设计目的 |
|---|---|
| `RecipeType` | 区分义体、底盘部件、维护品、消耗品、订单加工。 |
| `DisplayName` / `DescriptionKey` | UI 与日志。 |
| `RequiredTags` | 允许按标签消耗材料，而不只按具体 ID。 |
| `BlueprintCondition` | 图纸、势力声望、剧情和 Boss 材料门槛。 |
| `GoldCost` | 与材料分离，便于经济压力调参。 |
| `OutputItemID` / `OutputProstheticID` / `OutputChassisUnlock` | 支持多种输出。 |
| `OutputCount` | 支持批量制造或拆解。 |
| `ConsumePolicy` | 消耗、保留、转化和委托物禁止消耗。 |
| `InheritTagsPolicy` | 污染物、违禁品或来源标签继承。 |
| `CancelPolicy` | 取消制造时返还规则，避免复制或吞材料。 |

### 5.3 内容缺口

| 内容类型 | 当前状态 | 近期目标 |
|---|---|---|
| 义体制造 | 有 2 个样例。 | 扩到 `21` 的 6 个义体。 |
| 底盘制造 / 更换 | 缺配置。 | 支持轻装、重载和标准底盘改造。 |
| 维护方案 | 缺配置。 | 支持 `maint_basic_patch`、`maint_standard_overhaul`、`maint_purification_flush` 等。 |
| 材料转化 | 缺配置。 | 把前三层战利品接到义体 / 维护 / 订单。 |
| 污染处理 | 缺配置。 | 承接第三层污染物和局外处理。 |

### 5.4 Validator 建议

| ValidatorID | 检查内容 |
|---|---|
| `CFG-CRAFT-001` | `RecipeID`、`RecipeType`、输入、输出和成本必填。 |
| `CFG-CRAFT-002` | 输入 ItemID / Tag / Blueprint 引用存在。 |
| `CFG-CRAFT-003` | 输出 ItemID / ProstheticID / ChassisID 引用存在或明确为解锁。 |
| `CFG-CRAFT-004` | `ConsumePolicy` 不能消耗订单绑定、剧情锁定或情感锚点物。 |
| `CFG-CRAFT-005` | `CancelPolicy` 不产生复制、丢失或金币负数。 |

## 6. `Dolls` 审计

| 字段 | 当前情况 | 判断 |

|---|---|

| ValidatorID | 检查内容 |
|---|---|

| `CFG-DOLL-002` | 静态配置不得保存当前 HP / SAN / Bond / 磨损 / 侵蚀等运行时状态，除非字段明确为初始值。 |
| `CFG-DOLL-003` | `DefaultChassisID`、交互池、房间、反馈、表情和动作引用存在。 |
| `CFG-DOLL-004` | SAN / Bond 阈值递增且不会形成无恢复死锁。 |

## 7. `Effects` 审计

### 7.1 当前情况

`Effects/EffectEnums.json` 当前主要服务物品和义体效果，包括伤害增幅、叠盾、恢复、战后 SAN、怪物干涉等。它适合作为效果字典，但不能单独承接正式特质 / 维护 / 动态标签系统。

### 7.2 正式缺口

| 缺口 | 说明 |
|---|---|
| 标签定义 | `TagID`、`TagGroup`、适用范围、可见性需要独立表达。 |
| 动态标签生命周期 | 持续时间、叠加、来源、清除规则缺失。 |
| 特质定义 | `TraitID`、极性、触发器、条件、效果、互斥、转化和历史保留缺失。 |
| 维护效果 | 磨损、侵蚀、SAN、Bond、副作用和适应期缩短需要正式效果或维护配置表达。 |
| 房间 / 交互反馈效果 | 不能只靠数值效果，需要反馈池和事件结果承接。 |

### 7.3 Validator 建议

| ValidatorID | 检查内容 |
|---|---|
| `CFG-EFFECT-001` | `EffectID` 唯一，`ConfigSchema` 与使用方参数数量匹配。 |
| `CFG-EFFECT-002` | `TriggerTiming` 必须来自合法枚举，且能被使用场景支持。 |
| `CFG-TRAIT-001` | 正式特质必须有获得条件、生效规则、可见反馈和转化 / 消除路径。 |
| `CFG-TAG-001` | 标签查询引用的 `TagID` 必须存在且作用域匹配。 |

## 8. 推荐后续任务拆分

### 8.1 `GROWTH-README`

目标：先同步 `Chassis`、`Prosthetics`、`CraftingRecipes`、`Dolls`、`Effects` README 的正式字段口径。

输出：

1. 每个配置域的正式字段、运行时边界、合法值和引用关系。
2. Validator 建议写入 README。
3. 明确哪些字段只是预留，哪些进入当前实现批次。

禁止误判：README 字段口径完成不等于 JSON 完成。

### 8.2 `GROWTH-CHASSIS`

目标：把 `21` 的 3 个底盘转成 JSON 修改前清单。

输出：

1. `chassis_standard_frame`、`chassis_compact_raider`、`chassis_bulwark_carrier` 的字段清单。
2. 与前三层 Boss 核心、材料、图纸和维护代价的引用关系。
3. `V-PACK-DOLL-CHASSIS-01/02` 验收路径。

### 8.3 `GROWTH-PROSTHETICS`

目标：把 `21` 的 6 个义体转成 JSON 修改前清单。

输出：

1. 槽位、效果、互斥、制造成本和维护代价。
2. 与 `Effects` 字典和 `CraftingRecipes` 的引用关系。
3. `V-PACK-DOLL-PROSTHETIC-*` 验收路径。

### 8.4 `GROWTH-CRAFT-MAINT`

目标：补制造、维护方案和材料回流。

输出：

1. 义体制造、底盘制造 / 更换、维护方案、污染处理和材料转化的配方清单。
2. `ConsumePolicy`、`CancelPolicy` 和污染继承规则。
3. `V-PACK-DOLL-MAINT-*` 验收路径。

### 8.5 `GROWTH-DOLL-TRAIT-ROOM`

目标：补人偶静态档案、运行时边界、特质、交互反馈和房间记忆的配置落点。

输出：
