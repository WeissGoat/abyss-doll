# 经济压力订单ID最终锁定表

> 本文是 `ECON-ORDERS-JSON` 前置证据。它只锁定经济压力首批订单池 ID 和订单模板 ID，统一 `50_经济压力订单正式配置落地设计.md`、`52_经济压力正式配置实现任务拆分.md`、`53_经济压力正式配置ID锁定与冲突检查.md`、`54_经济压力正式配置README字段口径检查.md` 与 `配置表(JSON)/Orders/README.md` 的 ID 口径；不直接修改 JSON，也不代表订单配置完成。

---

## 1. 锁定结论

当前 `50` 正文实际列出 5 个订单池和 19 条订单模板。后续经济压力首批订单配置以本文锁定的 5 个 `OrderPoolID` 和 19 个 `OrderID` 为准。

此前文档中出现的 `18 条订单模板` 是计数错误，应统一改为 `19 条订单模板`。此前 `50` 和 `24` 中出现的 `order_pool_*` 前缀是内容包草案期 ID，应迁移为本文锁定的 `pool_*` ID。

## 5. 后续 JSON 实现约束

进入 `ECON-ORDERS-JSON` 前必须满足：

1. `ECON-FACTIONS-JSON` 已落地 5 个 `FactionID`，并能引用本文 5 个 `OrderPoolID`。
2. `Orders` 配置源使用本文锁定的 5 个 `OrderPoolID` 和 19 个 `OrderID`。
3. 所有订单的 `OrderPoolID`、`FactionID`、`RewardID`、目标物、目标标签、层级来源和互斥组都能进入 `ECON-CROSS-REFS` 检查。
4. 旧样例 `order_mechanic_scrap_drive` 不作为正式订单池候选项，除非明确迁移为本文锁定 ID。
5. `50`、`52`、`53`、`54`、`Orders/README.md` 和 `agent_status/design.md` 都引用本文作为最终 ID 证据；如影响长期节点门禁，再通知 PM 更新 `09`。

## 6. 完成判定

本文完成后，`ECON-ORDERS-JSON` 的 ID 前置缺口可视为策划证据完成。`DES-V4-001` 仍保持 `进行中`，不能标记为 `配置完成`，原因如下：

1. 本文没有修改 `配置表(JSON)`。
2. 5 个订单池和 19 条订单模板尚未落到配置源。
3. `ECON-CROSS-REFS`、配置同步、Validator 和固定验收样例尚未形成通过证据。
4. 旧样例迁移或废弃口径尚未在 JSON 实现证据中落地。
