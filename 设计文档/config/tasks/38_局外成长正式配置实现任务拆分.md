# 局外成长正式配置实现任务拆分

> 本文是 `26_正式配置设计与填充推进计划.md` 中 W3「局外成长与经济目标补齐」的配置实现派发层。它承接 `36_局外成长正式配置承接审计.md`、`37_局外成长正式配置落地设计.md` 和五个局外成长配置 README。本文不直接修改 JSON，不代表局外成长配置完成；它定义后续真正改 JSON 时应该拆成哪些任务、按什么顺序执行、交付什么证据，以及如何回写 `agent_status/design.md`；如影响长期节点门禁，再通知 PM 更新 `09`。

---

## 1. 任务边界

### 1.1 本文处理

| 范围 | 说明 |
|---|---|
| 配置实现任务拆分 | 把 `GROWTH-CHASSIS`、`GROWTH-PROSTHETICS`、`GROWTH-CRAFT-MAINT`、`GROWTH-DOLL-TRAIT-ROOM` 拆成可派发任务。 |
| 依赖顺序 | 明确哪些 ID、字段或引用必须先落地，避免 JSON 互相引用失败。 |
| 交付证据 | 规定每个任务完成时必须留下 ID 清单、引用检查、同步结果、Validator 结果和状态回写。 |
| 验收样例 | 定义模块级固定样例和失败信号，后续可交给程序补 Validator。 |
| 防误判口径 | 明确 README、策划清单、JSON、程序支持和验收通过分别是什么状态。 |

### 1.2 本文不处理

| 范围外 | 原因 |
|---|---|
| 直接改 `配置表(JSON)` | 本文只拆任务，不执行 JSON 修改。 |
| 程序字段实现 | 程序能力以开发文档、代码和程序台账为准。 |
| UI / 美术资源入库 | 美术与 UI 规格另行进入美术文档和美术台账。 |
| 经济压力完整配置 | 本文只处理局外成长核心链；月租、订单、声望和价格波仍由后续经济配置任务承接。 |
| 完整义体池和长期房间系统 | 当前只处理首批正式骨架，后续扩展不抢本轮任务。 |

## 2. 总依赖顺序

局外成长配置实现必须按以下顺序执行：

```text
GROWTH-README
  -> GROWTH-ID-LOCK
  -> GROWTH-CHASSIS
  -> GROWTH-EFFECTS-TRAITS
  -> GROWTH-PROSTHETICS
  -> GROWTH-CRAFT-MAINT
  -> GROWTH-DOLL-TRAIT-ROOM
  -> GROWTH-VALIDATION
```

| 顺序 | 任务 | 依赖 | 产出 |
|---:|---|---|---|
| 0 | `GROWTH-README` | `37` 字段清单 | 五个配置 README 已同步正式字段口径。当前已完成。 |
| 1 | `GROWTH-ID-LOCK` | `37` 全部 ID | 已由 `39_局外成长正式配置ID锁定与冲突检查.md` 完成当前工作区冲突核对，不改 JSON。 |
| 2 | `GROWTH-CHASSIS` | `GROWTH-ID-LOCK`、Chassis README | 字段级设计已由 `40_局外成长底盘正式配置落地设计.md` 完成；后续仍需改 3 个底盘 JSON 和底盘引用检查。 |
| 3 | `GROWTH-EFFECTS-TRAITS` | Effects README、特质清单 | 字段级设计已由 `41_局外成长效果特质正式配置落地设计.md` 完成；后续仍需改效果、动态标签和特质 JSON。 |
| 4 | `GROWTH-PROSTHETICS` | `GROWTH-CHASSIS`、`GROWTH-EFFECTS-TRAITS` | 字段级设计已由 `42_局外成长义体正式配置落地设计.md` 完成；后续仍需改 6 个义体 JSON、槽位引用和效果引用。 |
| 5 | `GROWTH-CRAFT-MAINT` | `GROWTH-PROSTHETICS`、CraftingRecipes README | 字段级设计已由 `43_局外成长制造维护正式配置落地设计.md` 完成；后续仍需改配方、维护和材料引用 JSON。 |
| 6 | `GROWTH-DOLL-TRAIT-ROOM` | `GROWTH-EFFECTS-TRAITS`、Dolls README | 字段级设计已由 `44_局外成长人偶特质房间正式配置落地设计.md` 完成；后续仍需改人偶静态档案、特质、反馈和房间纪念物 JSON。 |
| 7 | `GROWTH-VALIDATION` | 以上全部 | 策划验收规格已由 `45_局外成长正式配置Validator与固定验收样例.md` 完成；后续仍需程序 Validator / 配置同步 / 固定样例执行证据。 |

禁止跳过 `GROWTH-ID-LOCK` 直接改 JSON。局外成长配置涉及多表互引，ID 一旦散乱，后续 Validator 只能报错，不能判断设计意图。

4. 当前证据文档：`39_局外成长正式配置ID锁定与冲突检查.md`。

## 4. `GROWTH-CHASSIS`

目标：补齐 3 个正式底盘 JSON。

当前策划证据：`40_局外成长底盘正式配置落地设计.md` 已把 3 个正式底盘拆到 JSON 修改前字段级清单、Validator 和固定验收样例；该证据不代表底盘 JSON 已完成。

| 子任务 | 内容 | 依赖 | 交付证据 |
|---|---|---|---|
| `GROWTH-CHASSIS-01` | 新增或迁移 `chassis_standard_frame`。 | Chassis README | JSON 中有标准背包网格、基础义体槽、`Baseline` / `Tutorial` 职责和初始拥有口径。 |
| `GROWTH-CHASSIS-02` | 新增 `chassis_compact_raider`。 | 第一层 Boss 核心、轻装路线设计 | JSON 中有轻装路线职责、较低容量或风险标签、路线预览规则、适应期和成本。 |
| `GROWTH-CHASSIS-03` | 新增 `chassis_bulwark_carrier`。 | 第二层精英材料、重载路线设计 | JSON 中有重载 / 订单承载职责、更高维护代价、槽位优势和适应期。 |
| `GROWTH-CHASSIS-04` | 检查底盘与下潜许可。 | 程序 `DiveReadinessService` 当前事实 | 配置能被下潜许可读取；不支持字段标为 warning，不降级字段目标。 |

字段最低要求：

| 字段组 | 必须落地 |
|---|---|
| 身份 | `ChassisID`、`DisplayName`、`DescriptionKey`、`ChassisRole`、`VisualID` |
| 背包 | `GridWidth`、`GridHeight`、`GridMask` |
| 槽位 | `AllowedProstheticSlots` |
| 解锁 / 成本 | `UnlockCondition` 或初始拥有口径、`BuildCost`、`InstallCost` |
| 代价 | `AdaptationDays`、`MaintenanceModifier`、`RiskTags` |

验收样例：

| 验收 ID | 路径 | 期望 |
|---|---|---|
| `V-GROWTH-CHASSIS-01` | 初始人偶读取 `chassis_standard_frame`。 | 背包网格、基础槽位和下潜许可正常。 |
| `V-GROWTH-CHASSIS-02` | 第一层 Boss 后满足轻装底盘解锁条件。 | 材料和金币足够时可解锁 / 安装，适应期生效。 |
| `V-GROWTH-CHASSIS-03` | 第二层精英材料满足重载底盘解锁条件。 | 重载底盘增加承载能力，同时维护代价上升。 |

失败信号：

- 底盘 JSON 只有 `Level` 和 `UpgradeCost`，没有构筑职责。
- `GridMask` 与宽高不一致。
- `AllowedProstheticSlots` 与义体槽位枚举不一致。
- 强底盘没有维护、适应期或风险代价。

## 5. `GROWTH-EFFECTS-TRAITS`

目标：先补义体、维护、特质、动态标签需要引用的效果 / 标签字典，避免义体和人偶配置先引用不存在的效果。

当前策划证据：`41_局外成长效果特质正式配置落地设计.md` 已把义体效果、维护效果、动态标签、8 个特质、Validator 和固定验收样例拆到 JSON 修改前字段级清单；该证据不代表效果、标签或特质 JSON 已完成。

| 子任务 | 内容 | 交付证据 |
|---|---|---|
| `GROWTH-EFFECTS-01` | 补义体效果字典：路线预览、背包干涉抵抗、充能积层、SAN 调节、材料拆解、长线恢复。 | 每个义体效果有 `EffectID`、`TriggerTiming`、`ConfigSchema` 和 `AttachableScope`。 |
| `GROWTH-EFFECTS-02` | 补维护效果字典：HP、SAN、磨损、侵蚀、Broken、义体稳定。 | 每个维护效果声明目标状态、恢复 / 降低量和清除边界。 |
| `GROWTH-EFFECTS-03` | 补动态标签：污染、适应期、调节疲劳、义体稳定、房间记忆。 | 每个标签有 `TagGroup`、`DurationType`、`StackPolicy`、`ClearRule`。 |
| `GROWTH-EFFECTS-04` | 补 8 个特质的效果 / 转化规则。 | 每个特质有获得条件、生效规则、反馈和转化 / 消除路径。 |

验收样例：

| 验收 ID | 路径 | 期望 |
|---|---|---|
| `V-GROWTH-EFFECT-01` | 义体引用新增效果。 | 引用存在，参数数量和类型可解释。 |
| `V-GROWTH-TRAIT-01` | 获得负面特质后执行转化条件。 | 负面特质可被修复或转化，不形成永久死锁。 |

失败信号：

- `Prosthetics` 或 `Dolls` 引用不存在的 `EffectID` / `TraitID`。
- 负面特质没有转化或消除路径。
- 动态标签没有清除规则。

## 6. `GROWTH-PROSTHETICS`

目标：补齐 6 个正式义体 JSON。

当前策划证据：`42_局外成长义体正式配置落地设计.md` 已把 6 个正式义体拆到 JSON 修改前字段级清单、槽位兼容、Validator 和固定验收样例；该证据不代表义体 JSON 已完成。

| 子任务 | 内容 | 依赖 | 交付证据 |
|---|---|---|---|
| `GROWTH-PROSTHETIC-01` | `prosthetic_focus_lens`。 | `GROWTH-EFFECTS-01` | 地图阅读职责、`HeadSensor` 槽位、路线预览触发、配方引用。 |

| `GROWTH-PROSTHETIC-03` | `prosthetic_charge_coil_arm`。 | `GROWTH-EFFECTS-01` | 充能积层、战斗爆发、磨损代价和反馈引用。 |
| `GROWTH-PROSTHETIC-04` | `prosthetic_san_regulator_core`。 | `GROWTH-EFFECTS-02` | SAN 调节、Broken 边界、调节疲劳标签。 |
| `GROWTH-PROSTHETIC-05` | `prosthetic_salvage_fingertips`。 | `GROWTH-EFFECTS-01` | 撤离结算材料拆解，明确不提供战斗收益。 |
| `GROWTH-PROSTHETIC-06` | `prosthetic_mender_spine`。 | `GROWTH-EFFECTS-02` | 安全区后续修复，明确不清除订单 / 污染物。 |

字段最低要求：

| 字段组 | 必须落地 |
|---|---|
| 身份 | `ProstheticID`、`DisplayName`、`DescriptionKey`、`VisualID`、`Tier` |
| 装配 | `SlotType`、`ConflictGroup`、`InstallCost` |
| 效果 | `EffectRefs`、`TriggerRules`、`Tags` |
| 制造 | `CraftRecipeRef`、`UnlockCondition` |
| 代价 / 反馈 | `MaintenanceModifier`、`WearImpact` 或 `CorruptionImpact`、`FeedbackRefs` |

验收样例：

| 验收 ID | 路径 | 期望 |
|---|---|---|
| `V-GROWTH-PROSTHETIC-01` | 安装 `prosthetic_focus_lens` 后进入地图。 | 路线预览或相邻节点提示生效；无 UI 支持时 Validator 报 warning。 |
| `V-GROWTH-PROSTHETIC-02` | 安装锚定左臂后遭遇塞包 / 封格怪。 | 首次背包干涉降低，并产生磨损或维护压力。 |
| `V-GROWTH-PROSTHETIC-03` | 安装 SAN 调节核心后遭遇高 SAN 损失。 | 可削减部分损失，但不能免疫 Broken。 |

失败信号：

- 义体没有 `SlotType` 或不被任何底盘允许。
- 义体只写数值加成，没有触发规则和反馈。
- 义体引用不存在的配方或效果。
- 高收益义体没有磨损、维护、冲突或其他长期代价。

## 7. `GROWTH-CRAFT-MAINT`

目标：补制造配方、底盘解锁、维护方案和材料转化，让前三层材料能进入局外成长链。

当前策划证据：`43_局外成长制造维护正式配置落地设计.md` 已把 6 个义体制造配方、2 个底盘解锁配方、5 个维护方案、材料来源、消耗 / 取消策略、Validator 和固定验收样例拆到 JSON 修改前字段级清单；该证据不代表配方或维护 JSON 已完成。

| 子任务 | 内容 | 依赖 | 交付证据 |
|---|---|---|---|
| `GROWTH-CRAFT-01` | 6 个义体制造配方。 | `GROWTH-PROSTHETICS` | 每个义体有 `RecipeType=Prosthetic` 配方，输入材料、金币和图纸条件清晰。 |
| `GROWTH-CRAFT-02` | 2 个底盘解锁配方。 | `GROWTH-CHASSIS` | `chassis_compact_raider`、`chassis_bulwark_carrier` 有解锁配方。 |
| `GROWTH-MAINT-01` | 5 个维护方案。 | `GROWTH-EFFECTS-02` | HP、SAN、磨损、侵蚀、Broken、义体稳定至少各有处理入口。 |
| `GROWTH-CRAFT-03` | 消耗与取消策略。 | CraftingRecipes README | `ConsumePolicy`、`InheritTagsPolicy`、`CancelPolicy` 落到配置。 |
| `GROWTH-CRAFT-04` | 材料来源检查。 | 前三层内容包和配置 | 配方输入可追到前三层材料、Boss 核心、精英材料或订单来源。 |

验收样例：

| 验收 ID | 路径 | 期望 |
|---|---|---|
| `V-GROWTH-CRAFT-01` | 第二层撤离带回材料 -> 制造锚定左臂。 | 扣材料和金币，生成义体或解锁义体，引用不丢失。 |
| `V-GROWTH-MAINT-01` | 战败后执行标准整备。 | 消耗金币 / 材料，恢复下潜许可，但不免费清除所有状态。 |
| `V-GROWTH-MAINT-02` | 孢雾恐惧后执行净化冲洗。 | 降低污染 / 恐惧相关状态，但不处理磨损。 |

失败信号：

- 配方输出引用不存在。
- 配方输入引用前三层没有来源的材料。
- 维护方案免费清除 HP、SAN、磨损、侵蚀、污染和特质历史。
- 取消策略可复制材料或导致金币负数。

## 8. `GROWTH-DOLL-TRAIT-ROOM`

目标：补人偶静态档案边界、特质、反馈和房间纪念物配置落点，让成长结果能被人偶状态和长期记忆承接。

当前策划证据：`44_局外成长人偶特质房间正式配置落地设计.md` 已把 Doll 静态档案、运行时状态拆分、8 个特质、8 条反馈、8 个房间纪念物、Validator 和固定验收样例拆到 JSON 修改前字段级清单；该证据不代表人偶、特质、反馈或房间纪念物 JSON 已完成。

| 子任务 | 内容 | 依赖 | 交付证据 |
|---|---|---|---|
