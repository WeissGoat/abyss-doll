# 正式版内容生产规格

> **定位：** 本文档规定正式版纵切中，策划新增物品、怪物、地图画像、传闻、订单、事件、房间记忆等内容时，必须交到什么粒度。它不替代 GDD、规则卡、配置 README 或美术规格；它用于防止内容生产变成“只填 ID 和数值”，确保每条内容都有玩法职责、玩家可读性、跨系统去向和验收口径。

---

## 1. 适用范围

本文适用于以下内容类型：

| 内容类型 | 对应承接清单 | 主要落点 |
|---|---|---|
| 物品、掉落、材料、风险物 | `15_P0主干配置表现验收承接清单` | `Items`、掉落池、经济和制造。 |
| 怪物、意图组合、遭遇模板 | `15_P0主干配置表现验收承接清单` | `Monsters`、`Dungeons`、战斗表现。 |
| 深渊层级、地图画像、节点池 | `15_P0主干配置表现验收承接清单` | `Dungeons`、事件池、奖励池。 |
| 人偶状态、底盘、义体、特质、交互反馈 | `16_P1人偶成长情感承接清单` | `Dolls`、`Chassis`、`Prosthetics`、`Effects`、交互配置。 |
| 经济传闻、顾客、账单、违禁品 | `17_P2长期循环叙事承接清单` | 经济配置、营业结算、黑市渠道。 |
| 势力、订单、奖励、黑市背叛 | `17_P2长期循环叙事承接清单` | Factions、Orders、Rewards。 |
| 剧情事件、对话、系统指令 | `17_P2长期循环叙事承接清单` | ScenarioEvents、DialogueTrees、Flags。 |
| 房间纪念物、日记、展示、窗外、待机 | `16`、`17` | RoomMemory、Mementos、Diary、房间资源。 |

原则：规则文档决定“系统怎么裁决”，本文决定“内容怎么写才有设计质量”。

## 2. 内容条目通用模板

每一条正式内容都应能回答下列问题。

| 字段组 | 必填问题 | 不合格表现 |
|---|---|---|
| 身份 | 它叫什么，ID 是什么，属于哪个系统和版本内容包？ | 只有内部 ID，没有展示名或归属。 |
| 玩家承诺 | 玩家看到它时，应期待什么收益、风险或情绪？ | 描述很酷，但玩家不知道用途。 |
| 玩法职责 | 它在循环中教会、考验或改变什么决策？ | 只是数值更高或更低。 |
| 系统连接 | 它进入哪些配置池，被哪些系统读取，产出流向哪里？ | 只存在于一张表，无法获得或无法消耗。 |
| 可读信息 | 玩家必须看到哪些提示、图标、文案或失败原因？ | 效果生效了，但玩家不知道来源。 |
| 风险与代价 | 它是否带来占格、SAN、金币、声望、违禁、时间或机会成本？ | 只有收益没有代价，或代价暗扣。 |
| 验收样例 | 至少一条玩家路径能证明它成立。 | 只能靠策划口头解释。 |
| 内容边界 | 它不应该做什么，不应替代哪个系统？ | 内容项偷偷写死跨系统规则。 |

### 2.1 标准条目模板

```text
ContentID:
DisplayName:
ContentType:
OwnerSystem:
VersionPack:

PlayerPromise:
GameplayRole:
PrimaryLoopHook:
SecondaryLoopHook:

ConfigLanding:
RuntimeState:
CrossReferences:

PlayerVisibleInfo:
FailureReasons:
RiskAndCost:

AcceptancePath:
InvalidCases:
BalanceNotes:
ArtAndAudioNeeds:
```

### 2.2 禁止用法

| 禁止项 | 原因 |
|---|---|
| 只写“高伤害 / 高价值 / 稀有” | 不能说明玩法职责。 |
| 用剧情描述代替机器可判断条件 | 配置和 Validator 无法承接。 |
| 新增私有标签或私有状态机 | 会绕开统一标签、事件和结算规则。 |
| 把运行时状态写进静态内容定义 | 会导致存档、复现和配置热更新混乱。 |
| 让内容绕过玩家可见反馈 | 玩家无法理解收益、失败或代价。 |
| 用“后续再补表现”交付核心内容 | 正式纵切中内容必须同时考虑可读性。 |

## 3. P0 内容生产标准

### 3.1 物品内容

物品内容不能只按稀有度堆数值。每件正式物品至少承担一种职责：

| 职责 | 说明 | 示例方向 |
|---|---|---|
| 构筑核心 | 改变玩家战斗节奏或背包布局。 | 方向相邻武器、占大格高爆发武器。 |
| 空间取舍 | 形状、旋转或相邻需求制造背包压力。 | L 形高价值物、长条武器、异形污染样本。 |
| 经济诱因 | 在出售、橱窗、订单或黑市中有明显价值。 | 受传闻影响的源石、违禁遗物。 |
| 风险载体 | 带来污染、SAN、违禁、耐久或怪物干涉。 | 高价但隔夜有 NightTax 的样本。 |
| 系统钥匙 | 解锁制造、订单、剧情或房间记忆。 | Boss 核心、图纸残片、关键赠礼。 |

物品条目补充字段：

| 字段 | 设计要求 |
|---|---|
| `SpatialPromise` | 说明形状、旋转和相邻关系给玩家带来的取舍。 |
| `CombatPromise` | 说明主动、被动、消耗或常驻效果的使用场景。 |
| `EconomyPromise` | 说明普通出售、橱窗、订单或黑市中的价值差异。 |
| `LifecyclePromise` | 说明战败、撤离、出售、制造、赠礼、展示后的去向。 |
| `RiskPromise` | 说明污染、违禁、绑定、耐久或 SAN 风险。 |

验收底线：

* 玩家能在拾取前判断“它值得占这个格子吗”。
* 玩家能在使用前判断“它本回合能解决什么问题”。
* 玩家能在出售 / 制造 / 赠礼前判断“消耗它会失去什么可能性”。

### 3.2 怪物内容

怪物不是血量和攻击力容器。每个怪物必须有一个清晰教学或检验目标。

| 怪物职责 | 设计要求 |
|---|---|
| 基础攻击教学 | 行为简单，意图稳定，用于教 AP、护盾和击杀节奏。 |
| 背包压力 | 预告塞包、封格、污染或移动物品，让背包成为战场。 |
| SAN 压力 | 低直接伤害，高情绪 / 特质 / 崩溃风险。 |
| 构筑检查 | 针对单一打法短板，但应有可读反制窗口。 |
| 路线诱导 | 作为精英或节点主题，让玩家决定绕开还是贪奖励。 |

怪物条目补充字段：

| 字段 | 设计要求 |
|---|---|
| `TeachOrTest` | 这只怪教什么，或检验什么。 |
| `IntentReadablePattern` | 玩家几回合内能看懂的意图规律。 |
| `Counterplay` | 玩家可以通过击杀、叠盾、清格、路线或消耗品应对什么。 |
| `FailureLesson` | 玩家输给它时，应该学到什么。 |
| `DropLogic` | 掉落是否服务该怪物职责或路线主题。 |

验收底线：

* 怪物意图和实际行为一致。
* 玩家至少有一个合理反制窗口。
* 掉落或奖励能解释为什么值得打它。

### 3.3 地图画像与节点内容

地图内容应服务路线选择，而不是随机铺节点。

| 内容 | 设计要求 |
|---|---|
| `LayerConfig` | 明确层级主题、解锁、直达、Boss、安全区和主要压力。 |
| `MapProfile` | 明确路线倾向、节点权重、精英可绕、奖励密度和约束。 |
| `NodeTemplate` | 明确节点类型、风险预告、内容池和可见信息。 |
| `RouteTheme` | 明确高风险高收益、低风险低收益、事件密集或订单追踪路线。 |

验收底线：

* 同 seed 可复现。
* 至少两条路线的风险和收益差异能被玩家看懂。
* 精英、Boss、安全区和已通层直达规则不被内容破坏。

## 4. P1 内容生产标准

### 4.1 人偶成长内容

底盘、义体、维护方案和天赋必须改变玩家下一次下潜的感知，而不是只改面板数字。

| 内容 | 必须说明 |
|---|---|
| 底盘 | 背包形状、义体槽、构筑方向、适应代价和解锁来源。 |
| 义体 | 槽位、触发条件、互斥、维护压力和可见反馈。 |
| 维护方案 | 恢复什么、消耗什么、副作用是什么、是否影响下潜许可。 |
| 制造配方 | 输入、输出、取消 / 失败规则、污染或标签继承。 |

验收底线：

* 玩家能比较新旧方案差异。
* 成长项能改变背包、战斗、维护、下潜许可或情感反馈中的至少一项。
* 强力成长项必须有材料、金币、维护、适应期或风险成本。

### 4.2 标签与特质内容

标签用于查询，特质用于改写规则。二者不能混用。

| 内容 | 必须说明 |
|---|---|
| 标签 | 归属、可附着对象、是否可见、生命周期和查询用途。 |
| 动态标签 | 来源事件、持续时间、叠加、清除和玩家提示。 |
| 特质 | 触发器、条件、效果、优先级、互斥和转化 / 消除路径。 |
| 负面特质 | 具体阻碍什么、玩家如何理解、如何面对或转化。 |

验收底线：

* 玩家能知道特质何时获得、何时生效、为什么生效。
* 负面特质带来真实决策，但不能造成不可恢复死锁。
* 特质历史应保留，不因消除而抹掉叙事痕迹。

### 4.3 交互与房间内容

交互内容要服务状态反馈，房间内容要服务经历沉淀。

| 内容 | 必须说明 |
|---|---|
| 触摸 / 对话 | 触发条件、反馈池、收益上限、低 SAN 变体。 |
| 赠礼 | 偏好标签、拒收条件、反馈、消耗结果和边际递减。 |
| 保养 | 材料成本、恢复量、副作用、情绪反馈。 |
| 房间纪念物 | 来源事件、显示槽、日记关联和替换规则。 |

验收底线：

* 交互反馈必须读当前人偶状态，不能所有状态播放同一套温馨反馈。
* 房间不推进 Day，不承担仓库功能。
* 关键经历至少能通过纪念物、日记、窗外或待机中的一种留下痕迹。

## 5. P2 内容生产标准

### 5.1 经济内容

经济内容要改变玩家下一次下潜目标或局外支出决策。

| 内容 | 必须说明 |
|---|---|
| 传闻 | 目标标签、倍率、持续天数、来源池、玩家如何追踪目标。 |
| 顾客 | 偏好、预算、拒收标签、出现权重和特殊规则。 |
| 账单 | 费用来源、预告时机、缺口提示、欠债 / 典当裁决。 |
| 违禁品 | 普通渠道、黑市渠道、隔夜代价、风险提示和清理方式。 |

验收底线：

* 传闻必须能改变捡取或路线目标。
* 账单必须能复盘，不允许只显示金币最终变化。
* 违禁品高收益和长期风险都要可见。

### 5.2 订单与势力内容

订单要制造路线、背包和长期关系的取舍。

| 内容 | 必须说明 |
|---|---|
| 势力 | 价值观、奖励类型、冲突关系、声望解锁。 |
| 订单 | 需求表达、截止日、目标来源、奖励、失败和放弃规则。 |
| 委托物 | 占格、绑定、战败处理、是否允许背叛。 |
| 黑市背叛 | 原势力损失、黑市收益、长期怀疑和二次确认。 |

验收底线：

* 订单目标必须机器可判断。
* 订单至少影响路线、背包、出售或成长规划中的一项。
* 背叛是玩家主动选择，不自动发生。

### 5.3 剧情事件内容

剧情事件要安全地改写系统状态，不能靠播放文本替代规则。

| 内容 | 必须说明 |
|---|---|
| 事件 | 触发器、优先级、表现层、重复规则和阻塞策略。 |
| 对话节点 | 说话人、条件、选项、fallback 和跳过摘要。 |
| 系统指令 | 指令类型、目标、payload、幂等键和失败 fallback。 |
| 旗标 | 开始旗标、完成旗标、历史保留和压制条件。 |

验收底线：

* 跳过文本不丢奖励、惩罚、旗标或状态变化。
* 读档重入不重复执行已完成指令。
* 缺少表现资源不阻断系统状态结算。

| 内容包 | 目标 | 最低内容 |
|---|---|---|
| `pack_layer1_formal_core` | 第一层搜打撤正式体验。 | 12 件物品、5 只怪物、2 个地图画像、1 个 Boss、3 条传闻、2 个事件、2 个房间记忆。 |
| `pack_layer2_bag_pressure` | 第二层背包压力与直达体验。 | 10 件物品、5 只怪物、2 个地图画像、2 个精英、3 个订单、3 个事件。 |
| `pack_layer3_route_corrosion` | 第三层路线侵蚀、污染物品和订单冲突体验。 | 12 件物品、5 只普通怪、2 个精英、2 个地图画像、4 个订单、3 个事件、3 条传闻、4 个房间记忆。 |

内容包可以按纵切顺序分批进入开发，但一旦进入批次，包内内容应按正式标准交付，不按临时 MVP 标准交付。

## 7. 内容评审清单

策划提交一批内容前，应逐项检查：

1. 每条内容都有玩家承诺和玩法职责。
2. 每条内容都有配置落点和运行时边界。
3. 每条内容至少连接一个核心循环，不是孤立装饰。
4. 关键收益、代价、失败原因都能被玩家看见。
5. 内容引用的物品、标签、奖励、事件、视觉资源和配置池都有明确来源。
6. 内容不会绕过既有规则卡新增私有裁决。
7. 内容包至少覆盖一条跨系统验收路径。
8. 如果内容引入新标签、新节点类型、新意图、新事件指令，必须同步规则卡或配置 README。

## 8. 与其他文档的关系

| 文档 | 分工 |
|---|---|
| GDD | 决定系统存在的理由、体验目标和跨系统关系。 |
| 规则卡 | 决定字段、状态机、算法、边界和基础验收。 |
| `14_策划配置表现验收承接规格` | 决定交给配置、表现和验收的通用粒度。 |
| `15` / `16` / `17` 承接清单 | 决定 P0 / P1 / P2 主干系统各自需要交付什么。 |
| 本文档 | 决定具体内容条目和内容包如何生产才算正式版质量。 |
| 配置 README | 接收本文档的字段和内容包，落成可校验的数据结构。 |

如果后续某个内容包无法按本文模板填写，通常不是“模板太麻烦”，而是该内容还没有想清楚它在正式循环中的职责。
