# P1人偶成长情感承接清单

> **定位：** 本文档把人偶状态、局外成长、交互反馈、标签特质和房间视觉叙事从“规则可开发”推进到“正式纵切可交付清单”。它不写代码，也不替代配置 README；它规定策划交给配置、UI / 美术和验收时，必须交到什么粒度。

---

## 1. P1 总览

| 主干 | 对应配置域 | 对应设计 | 当前判断 | 本文目标 |
|---|---|---|---|---|
| 人偶核心状态 | `Dolls` | `GDD_03`、`08_人偶核心状态与好感双轨规则卡` | 规则可开发 | 补齐 SAN / Bond / 情绪 / 奇迹 / 创伤的配置承接、表现和验收。 |
| 局外成长维护 | `Chassis`、`Prosthetics`、`CraftingRecipes`、`Dolls` | `GDD_08`、`05_局外成长与维护规则卡` | 规则可开发 | 补齐底盘、义体、天赋、维护、换装和下潜许可承接。 |
| 标签与特质 | `Effects`、`Dolls`、`Items` | `GDD_09`、`06_标签与特质规则卡` | 规则可开发 | 补齐统一标签语言、特质触发器、互斥优先级和玩家可读反馈。 |
| 人偶交互 | `Dolls`、对话池、交互配置 | `GDD_12`、`09_人偶交互事件与反馈规则卡` | 规则可开发 | 补齐触摸、对话、赠礼、保养、特殊交互和防刷承接。 |
| 人偶房间 | `Dolls` 或房间配置 | `GDD_11`、`11_人偶房间布局与视觉叙事规则卡` | 规则可开发 | 补齐房间布局、家具、纪念物、展示品、窗外状态和视觉日记验收。 |

P1 的设计目标不是“多加养成按钮”，而是让深渊经历能在局外留下长期状态、成长方向和情感反馈。

## 2. Dolls 承接清单

### 2.1 必读事实来源

| 文档 | 读取重点 |
|---|---|
| `GDD_03_人偶实体对象与好感双轨机制.md` | 人偶作为状态实体、SAN / Bond、奇迹和异常边界。 |
| `08_人偶核心状态与好感双轨规则卡.md` | 实例字段、SAN 阈值、Bond 阶梯、情绪状态机、奇迹和崩溃处置。 |
| `09_人偶交互事件与反馈规则卡.md` | 交互事件结构、偏好、反馈选择和每日上限。 |
| `11_人偶房间布局与视觉叙事规则卡.md` | 默认房间、待机、房间反馈和视觉资源。 |
| `13_策划跨系统验收场景矩阵.md` | `A-04`、`A-07`、`A-08`、`A-09`、`A-12`。 |

### 2.2 配置承接字段

| 字段组 | 必填字段 | 设计规则 |
|---|---|---|
| 身份 | `DollID`、`DisplayName`、`BaseProfileID`、`DefaultRoomID` | 人偶配置是基础档案，不保存当前 HP / SAN / Bond。 |
| 基础属性 | `BaseMaxHP`、`BaseMaxSAN`、`BaseBondCurveID`、`InitialEmotion` | Bond 阈值可引用曲线；SAN / HP 上限可被底盘、义体和效果修正。 |
| 情绪 | `EmotionStateSet`、`DefaultEmotionFallback`、`EmotionFeedbackRefs` | 每个情绪必须有表现 fallback，避免状态无反馈。 |
| Bond | `BondThresholds`、`BondMilestoneRefs`、`MiraclePolicyID` | Bond 升级可要求里程碑；奇迹必须有触发条件和代价。 |
| SAN | `SanThresholds`、`SanBreakPolicyID`、`SanRecoveryPolicyRefs` | `SAN=0` 必须有恢复路径，不能死锁。 |
| 偏好 | `LikeTags`、`DislikeTags`、`HiddenPreferenceRules` | 偏好影响赠礼、对话和房间反馈，不直接变成无限刷数值。 |
| 交互 | `AllowedInteractionRefs`、`DialoguePoolRefs`、`FeedbackSetRefs` | 交互入口和反馈资源可配置。 |
| 房间 | `RoomPreferenceTags`、`DefaultIdlePoseRules`、`RoomFeedbackPools` | 房间表现从人偶状态读取，不私自改写核心状态。 |
| 资源 | `ExpressionVisualIDs`、`MotionIDs`、`VoiceSetRefs`、`FallbackVisualID` | 所有可见状态必须有 fallback。 |

运行时字段不得写入静态 `Dolls` 配置：

| 运行时字段 | 归属 |
|---|---|
| `CurrentHP`、`CurrentSAN`、`BondValue`、`BondLevel` | 人偶实例状态。 |
| `EmotionState`、`DynamicStateTags`、`TraitInstanceIDs` | 人偶实例状态。 |
| `RecentEventMemory`、`NeglectDays`、`LastInteractionDay` | 经历日志 / 存档。 |
| `HasMiracleRevivedThisRun` | 本轮下潜状态。 |

### 2.3 玩家可见信息

| 场景 | 必须可见 |
|---|---|
| 工坊主界面 | HP、SAN、磨损、侵蚀、主情绪、下潜风险提示。 |
| 备战入口 | 下潜许可、锁定原因、状态警告、已通层推荐风险。 |
| 战败后 | 创伤、维修需求、SAN 变化、丢失物与保留物、情感反馈。 |
| 交互界面 | 当前可交互类型、上限、低 SAN 抗拒、礼物偏好反馈。 |
| 房间 | 当前待机状态、纪念物、窗外状态、情绪投射。 |

### 2.4 验收样例

| ID | 前置状态 | 玩家行为 | 期望结果 | 失败信号 |
|---|---|---|---|---|
| `V-DOLL-SAN-01` | `CurrentSAN=35/100`，进入高风险节点，SAN -10。 | 节点结算。 | SAN=25，情绪进入压抑，发布状态变化并显示反馈。 | SAN 变化无日志、情绪不变、玩家不知道状态恶化。 |
| `V-DOLL-BOND-01` | BondValue 达到 Lv.2 阈值但里程碑未完成。 | 完成一次普通交互。 | BondValue 增加，但 BondLevel 等待里程碑；提示可触发里程碑对话。 | Bond 无条件升级或卡住无提示。 |
| `V-DOLL-MIRACLE-01` | HP=8，致死伤害=12，BondLevel>=5，本轮未触发奇迹。 | 受到致死伤害。 | 奇迹触发，HP 保底，SAN 付出代价，本轮不可再次触发。 | 无限复活、无代价、没有高优先级反馈。 |
| `V-DOLL-BREAK-01` | SAN=4，恐惧特质触发 SAN -5。 | 结算特质。 | SAN=0，进入 Broken，普通交互锁定，出现崩溃处置入口。 | SAN 负数、普通触摸直接治好、存档死锁。 |

### 2.5 完成判定

`Dolls` 达到正式纵切可交付，需要同时满足：

1.  配置能表达基础属性、SAN、Bond、情绪、偏好、交互和房间资源。
2.  运行时实例字段与静态配置边界清楚。
3.  玩家能在工坊、备战、战败、交互、房间读懂人偶状态。
4.  至少通过 `V-DOLL-SAN-01`、`V-DOLL-MIRACLE-01`、`V-DOLL-BREAK-01` 三条验收。

## 3. Chassis / Prosthetics / CraftingRecipes 承接清单

### 3.1 必读事实来源

| 文档 | 读取重点 |
|---|---|
| `GDD_08_人偶养成子模块全案.md` | 底盘、义体、心智天赋、维护、换装五大模块定位。 |
| `05_局外成长与维护规则卡.md` | 成长状态机、底盘字段、义体字段、维护方案、下潜许可。 |
| `GDD_07_时间日程系统与天数轮转机制.md` | 零时耗成长操作与核心抉择边界。 |
| `13_策划跨系统验收场景矩阵.md` | `A-07`、`A-08`。 |

### 3.2 Chassis 配置字段

| 字段组 | 必填字段 | 设计规则 |
|---|---|---|
| 身份 | `ChassisID`、`DisplayName`、`ChassisRole`、`VisualID` | 底盘是构筑方向，不是线性更强。 |
| 背包 | `GridWidth`、`GridHeight`、`GridMask`、`BaseSlotTags` | 改变真实背包空间和布局压力。 |
| 规则 | `RuleModifiers`、`AllowedProstheticSlots`、`ResonanceModifiers` | 规则修正必须可解释，不能隐藏加成。 |
| 解锁 | `UnlockCondition`、`BlueprintRef`、`BuildCost` | 图纸、Boss 核心、势力声望或剧情解锁。 |
| 代价 | `AdaptationDays`、`MaintenanceModifier`、`RiskTags` | 换底盘有短期代价，但不能让底盘完全不可用。 |

### 3.3 Prosthetics 配置字段

| 字段组 | 必填字段 | 设计规则 |
|---|---|---|
| 身份 | `ProstheticID`、`DisplayName`、`SlotType`、`Tier`、`VisualID` | 同槽位只能装备一件。 |
| 效果 | `EffectRefs`、`Tags`、`TriggerRules` | 优先改规则、效率、视野和容错，不做无脑裸加。 |
| 装配 | `UnlockCondition`、`CraftCost`、`InstallCost`、`ConflictGroup` | 互斥用配置表达。 |
| 维护 | `MaintenanceModifier`、`WearImpact`、`CorruptionImpact` | 强力义体可提高维护压力。 |

### 3.4 CraftingRecipes 配置字段

| 字段组 | 必填字段 | 设计规则 |
|---|---|---|
| 身份 | `RecipeID`、`RecipeType`、`DisplayName` | 配方可制造义体、底盘部件、维护品、消耗品。 |
| 输入 | `RequiredItems`、`RequiredTags`、`GoldCost`、`BlueprintCondition` | 材料消耗必须指向真实库存实例或标签需求。 |
| 输出 | `OutputItemID`、`OutputProstheticID`、`OutputChassisUnlock`、`OutputCount` | 输出生成新实例或解锁项，不能复制原实例。 |
| 规则 | `ConsumePolicy`、`InheritTagsPolicy`、`CancelPolicy` | 污染继承、取消返还、失败产物必须明确。 |

### 3.5 玩家可见信息

| 场景 | 必须可见 |
|---|---|
| 底盘更换 | 新旧背包形状、规则变化、材料缺口、适应期、义体槽变化。 |
| 义体装配 | 槽位、互斥、效果触发条件、维护代价、卸下旧义体结果。 |
| 制造 | 输入材料、金币、输出、消耗后果、图纸条件。 |
| 维护 | 当前磨损 / 侵蚀、恢复量、成本、副作用、下潜许可变化。 |
| 下潜许可 | 不允许下潜的明确原因和解决路径。 |

### 3.6 验收样例

| ID | 前置状态 | 玩家行为 | 期望结果 | 失败信号 |
|---|---|---|---|---|
| `V-GROWTH-CHASSIS-01` | 拥有新底盘图纸、Boss 核心和金币。 | 更换底盘。 | 扣成本，切换底盘，重建背包网格，设置适应期。 | 背包形状不变、义体冲突无处理、成本未扣。 |
| `V-GROWTH-PROSTHETIC-01` | 同槽位已有旧义体。 | 装备新义体。 | 旧义体卸回库存，新义体生效，冲突组刷新。 | 旧义体消失、两个同槽义体同时生效。 |
| `V-GROWTH-CRAFT-01` | 有材料和金币。 | 制造义体。 | 材料实例消耗，生成义体或解锁义体，日志可复盘。 | 材料复制、输出无实例、取消导致物品重复。 |
| `V-GROWTH-DIVELOCK-01` | 磨损 92 或侵蚀 92。 | 尝试下潜。 | 禁止或强警告，显示维护 / 净化 / 休息路径。 | 允许无提示下潜、锁定原因不明。 |

### 3.7 完成判定

成长维护主干达到正式纵切可交付，需要同时满足：

1.  `Chassis`、`Prosthetics`、`CraftingRecipes` 三类配置能表达构筑方向、成本、冲突和代价。
2.  成长界面能让玩家看懂材料缺口、前后变化、适应期和下潜许可。
3.  至少通过 `V-GROWTH-CHASSIS-01`、`V-GROWTH-PROSTHETIC-01`、`V-GROWTH-DIVELOCK-01` 三条验收。

## 4. Effects / 标签特质承接清单

### 4.1 必读事实来源

| 文档 | 读取重点 |
|---|---|
| `GDD_09_标签与特质系统.md` | 标签与特质概念边界、特质分类和叙事功能。 |
| `06_标签与特质规则卡.md` | 标签命名、查询表达、特质字段、监听白名单、互斥、优先级、消除转化。 |
| `08_人偶核心状态与好感双轨规则卡.md` | 人偶状态给特质提供输入事件。 |
| `13_策划跨系统验收场景矩阵.md` | `A-09`。 |

### 4.2 配置承接字段

| 字段组 | 必填字段 | 设计规则 |
|---|---|---|
| 标签定义 | `TagID`、`TagGroup`、`DisplayName`、`AttachableScope` | 标签只表达身份，不执行效果。 |
| 动态标签 | `DurationType`、`StackPolicy`、`VisibleToPlayer` | 影响核心决策的动态标签必须可见。 |
| 查询表达 | `AllOf`、`AnyOf`、`NoneOf`、`CountAtLeast` | 订单、传闻、物品、特质使用统一语言。 |
| 特质定义 | `TraitID`、`Polarity`、`Category`、`Trigger`、`Conditions`、`Effects` | 特质主动改写规则，必须有获得和生效原因。 |
| 冲突 | `ConflictGroup`、`Priority`、`StackPolicy`、`TransformRule` | 互斥、覆盖、转化必须稳定可复盘。 |
| 消除 | `RemoveRule`、`TherapyRequirement`、`NarrativeHistoryPolicy` | 消除不抹掉历史。 |

### 4.3 玩家可见信息

| 场景 | 必须可见 |
|---|---|
| 获得特质 | 特质名、极性、来源事件、主要效果。 |
| 特质生效 | 本次规则被谁改写，影响了什么数值或操作。 |
| 特质阻止操作 | 阻止原因、解除或转化途径。 |
| 标签不满足 | 缺少或排除了哪个标签。 |
| 特质转化 | 旧特质、新特质、触发条件和历史保留。 |

### 4.4 验收样例

| ID | 前置状态 | 玩家行为 | 期望结果 | 失败信号 |
|---|---|---|---|---|
| `V-TRAIT-TAG-01` | 订单要求 `AllOf(Material, OriginStone)`。 | 放入只有 `OriginStone` 的物品。 | 不满足，提示缺少 `Material`。 | 标签条件失败但无原因。 |
| `V-TRAIT-ACQUIRE-01` | 被虫型 Boss 击败，满足恐惧特质条件。 | 战败结算。 | 获得或推进 `FearOfInsects`，记录来源。 | 特质凭空出现或没有历史。 |
| `V-TRAIT-EFFECT-01` | 拥有 `MeleeFear`。 | 尝试放入近战武器。 | 触发 SAN 代价或拒绝，并提示特质来源。 | 操作被改写但无提示。 |
| `V-TRAIT-TRANSFORM-01` | 拥有 `FearOfInsects`。 | 击杀虫型 Boss。 | 转化为正向或双刃特质，旧特质进入历史。 | 新旧特质同时无规则叠加。 |

### 4.5 完成判定

标签特质主干达到正式纵切可交付，需要同时满足：

1.  标签定义、动态标签、查询表达、特质定义和互斥优先级能落到配置。
2.  玩家能理解标签不满足、特质获得、特质生效和特质转化。
3.  至少通过 `V-TRAIT-TAG-01`、`V-TRAIT-ACQUIRE-01`、`V-TRAIT-EFFECT-01` 三条验收。

## 5. 交互与房间承接清单

### 5.1 交互配置字段

| 字段组 | 必填字段 | 设计规则 |
|---|---|---|
| 交互身份 | `InteractionID`、`InteractionType`、`AllowedScenes` | 触摸、对话、赠礼、保养、特殊交互区分清楚。 |
| 限制 | `LimitPolicyID`、`DailyEffectiveCount`、`Cooldown`、`DiminishCurve` | 产出 SAN / Bond 的交互必须防刷。 |
| 输入 | `TargetRegion`、`InputItemFilter`、`DialoguePoolID`、`ContextTags` | 赠礼和对话要能读取偏好与上下文。 |
| 结果 | `ResultPolicyID`、`BaseOutcome`、`FeedbackSetID` | 最终 SAN / Bond 裁决交给人偶核心状态。 |
| 反馈 | `DialogueLineID`、`ExpressionID`、`MotionID`、`ResultHint` | 无反馈的数值增长不合格。 |

### 5.2 房间配置字段

| 字段组 | 必填字段 | 设计规则 |
|---|---|---|
| 房间 | `RoomID`、`BackgroundVisualID`、`ZoneList`、`SlotList`、`FallbackVisualSetID` | 房间布局固定槽位，不做自由像素摆放。 |
| 家具 | `FurnitureID`、`FurnitureCategory`、`AllowedSlotTypes`、`AcquireSource`、`RoomEffectPolicyID` | 家具以表现和轻微效率为主，不直接加战斗力。 |
| 纪念物 | `MementoID`、`Trigger`、`TargetSlotID`、`DiaryEntryID` | 纪念物由经历触发，不当仓库。 |
| 展示品 | `DisplaySlot`、`SourceItemInstanceID`、`SnapshotVisualID` | 展示不锁定来源物；来源物出售后展示清空。 |
| 窗外 | `WindowProfileID`、`WindowStateRules`、`Priority` | 结局预兆和重大事件优先于普通天气。 |
| 待机 | `PoseRuleID`、`Conditions`、`IdlePointSlotID`、`MotionID`、`ExpressionID` | 低 SAN 和重大创伤优先于日常温馨状态。 |

### 5.3 玩家可见信息

| 场景 | 必须可见 |
|---|---|
| 触摸 / 对话 | 当前反馈、上限、低 SAN 抗拒、是否有收益。 |
| 赠礼 | 是否喜欢、是否拒收、是否消耗、边际递减。 |
| 保养 | 材料成本、恢复量、副作用、情绪反馈。 |
| 房间 | 纪念物来源、展示品状态、窗外预兆、待机情绪。 |
| 日记本 | 战败、Boss 胜利、关键赠礼、Bond 里程碑。 |

### 5.4 验收样例

| ID | 前置状态 | 玩家行为 | 期望结果 | 失败信号 |
|---|---|---|---|---|
| `V-INTERACT-TOUCH-01` | 当日有效触摸次数已满。 | 第 6 次触摸。 | 播放反馈，不再增加 Bond，日志记录上限。 | 继续刷收益或完全无反馈。 |
| `V-INTERACT-GIFT-01` | 礼物标签命中人偶偏好。 | 赠送礼物。 | 接受并消耗，偏好倍率生效，反馈可读。 | 只按金币价值结算，无偏好反馈。 |
| `V-INTERACT-LOWSAN-01` | SAN=7，情绪 Panic。 | 触摸脸部。 | 触发应激反馈，不增加 Bond，不直接治好。 | 低 SAN 无影响或触摸强行恢复。 |
| `V-ROOM-MEMENTO-01` | 首次深渊战败。 | 进入房间。 | 战败纪念物出现，日记本新增回顾。 | 房间不记录经历。 |
| `V-ROOM-DISPLAY-01` | 展柜展示来源物品。 | 卖出来源物品。 | 展示槽清空，日记本保留曾展示记录。 | 展示阻止出售或产生复制物。 |
| `V-ROOM-ZEROTIME-01` | Day=23。 | 进入房间查看展柜和日记。 | Day 不变，不触发结算。 | 进入房间推进日期。 |

### 5.5 完成判定

交互与房间达到正式纵切可交付，需要同时满足：

1.  交互配置能表达入口、限制、输入、结果和反馈。
2.  房间配置能表达布局、家具、纪念物、展示品、窗外和待机。
3.  玩家能理解低 SAN 抗拒、赠礼偏好、房间纪念和展示品来源。
4.  至少通过 `V-INTERACT-GIFT-01`、`V-INTERACT-LOWSAN-01`、`V-ROOM-MEMENTO-01`、`V-ROOM-ZEROTIME-01` 四条验收。
