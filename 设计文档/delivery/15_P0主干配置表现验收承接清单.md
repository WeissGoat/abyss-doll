# P0主干配置表现验收承接清单

> **定位：** 本文档把 `Items`、`Monsters`、`Dungeons` 三个 P0 主干从“规则可开发”推进到“正式纵切可交付清单”。它不写程序实现，也不替代配置 README；它规定策划交给配置、UI / 美术和验收时，必须交到什么粒度。

> **程序工具需求：** P0 Validator、统一验收命令、报告格式和门禁标准见 `开发文档/15_P0配置Validator与自动验收底座需求.md`。

---

## 1. 使用方式

本清单用于三类场景：

| 场景 | 用法 |
|---|---|
| 策划继续补设计 | 逐项补齐配置字段、表现信息和验收样例，避免只扩写体验描述。 |
| 程序 / 配置 agent 接单 | 对照“必读事实来源”和“完成判定”，确认任务输入是否够清楚。 |
| 体验验收 | 用验收样例检查玩家路径是否真的成立，而不是只检查按钮能不能点。 |

完成口径：

*   `规则可开发`：GDD 和规则卡已能支撑领域规则开工。
*   `配置可承接`：字段、枚举、引用、内容池、运行时边界已能落到配置 README 或样例 JSON。
*   `表现可承接`：玩家必须看懂的信息和失败原因已明确。
*   `验收可复现`：至少有一条可复现玩家路径和最低证据形式。
*   `正式纵切可交付`：以上四项全部成立。

## 2. P0 总览

| 主干 | 对应设计 | 当前判断 | 本文目标 |
|---|---|---|---|
| `Items` 物品 / 背包生命周期 | `GDD_01`、`GDD_06`、`02_物品背包旋转与生命周期规则卡` | 规则可开发 | 补齐物品定义字段、实例边界、背包表现、生命周期验收和首批内容要求。 |
| `Monsters` 怪物 / 战斗意图 | `GDD_01`、`03_战斗回合与怪物意图规则卡` | 规则可开发 | 补齐怪物字段、意图枚举、行为组合、UI 可读性、战斗验收和首批怪物职能。 |
| `Dungeons` 深渊 / 地图节点 | `GDD_02` | 规则可开发 | 补齐层级配置、地图画像、节点池、seed 样例、地图表现和搜打撤验收。 |

三条主干必须一起看：物品决定玩家取舍，怪物决定压力类型，深渊地图决定压力出现的节奏和路线选择。

## 3. Items 承接清单

### 3.1 必读事实来源

| 文档 | 读取重点 |
|---|---|
| `GDD_01_背包战斗与局内网格机制.md` | 背包作为战斗空间、旋转放置、构筑流派、怪物对包干涉。 |
| `GDD_06_物品系统与物品生命周期.md` | 物品定义、实例状态、组件模型、价值与生命周期。 |
| `02_物品背包旋转与生命周期规则卡.md` | 容器、旋转、放置合法性、状态迁移、绑定、出售、制造、战败 / 撤离裁决。 |
| `13_策划跨系统验收场景矩阵.md` | `A-01`、`A-02`、`A-03`、`A-04`、`A-06`、`A-07`。 |

### 3.2 配置承接字段

| 字段组 | 必填字段 | 设计规则 |
|---|---|---|
| 身份 | `ItemID`、`DisplayName`、`Rarity`、`IconVisualID`、`DescriptionKey` | `ItemID` 唯一；名称和描述要能解释物品用途或风险。 |
| 空间 | `ShapeCells`、`DefaultRotation`、`CanRotate`、`AllowedRotations`、`PlacementTags` | 形状必须可机械校验；允许旋转的物品至少说明 90 度步长或具体角度集合。 |
| 分类 | `ItemType`、`ItemRole`、`Tags`、`RiskTags` | `ItemType` 用于系统分类，`Tags` 用于查询，`RiskTags` 用于经济 / 侵蚀 / 事件后果。 |
| 战斗 | `TriggerComponents`、`ApCost`、`TargetRule`、`EffectRefs`、`UseTiming` | 主动 / 被动 / 消耗 / 常驻必须区分；战斗效果引用 `Effects` 或本地组件。 |
| 空间干涉 | `AuraShape`、`DirectionLinks`、`LockResistance`、`PollutionProfile` | 方向性和相邻关系必须跟旋转后形状一起刷新。 |
| 经济 | `BasePrice`、`SellChannel`、`CanSell`、`DismantleProfile`、`ContrabandRule` | 普通出售不做保护；不可出售只用于委托物、剧情锁定或强情感物。 |
| 来源 | `DropPools`、`RewardRefs`、`CraftingRefs`、`ShopRefs`、`OrderRefs` | 来源必须能追溯，避免出现无法获得或无法消耗的物品。 |
| 绑定 | `DefaultBinding`、`BattleLossRule`、`AnchorRule` | 绑定表示战败不直接丢失，不表示不损坏。 |

运行时实例字段不得写进静态物品定义，包括：

| 运行时字段 | 归属 |
|---|---|
| `InstanceID`、`CurrentContainer`、`GridPosition`、`CurrentRotation` | 物品实例 / 背包状态。 |
| `Durability`、`CorruptionLevel`、`DynamicTags`、`IsBinding` | 物品实例状态。 |
| `OwnerScope`、`SourceRunID`、`CreatedDay`、`LastMovedAt` | 存档 / 日志状态。 |

### 3.3 玩家可见信息

| 场景 | 必须可见 |
|---|---|
| 背包整理 | 物品形状、当前朝向、可旋转状态、非法格、封锁格、放置预览。 |
| 战斗中使用 | AP 成本、目标、效果预期、次数限制、不可用原因。 |
| 搜刮窗口 | 掉落来源、是否本轮新获、是否绑定、放弃后果、未拾取会丢失。 |
| 撤离 / 战败 | 哪些物品带回、哪些丢失、哪些损坏、为什么保留。 |
| 出售 / 制造 | 售价来源、传闻倍率、是否不可出售、材料消耗和产出。 |

### 3.4 首批内容要求

| 类型 | 最低数量 | 必须覆盖的体验 |
|---|---:|---|
| 武器 | 3 | 低 AP 快攻、重型高伤、方向 / 相邻依赖。 |
| 防具 / 护盾 | 2 | 基础叠盾、条件防御或占格取舍。 |
| 消耗品 | 3 | 恢复 HP、恢复 / 稳定 SAN、清理污染或封锁。 |
| 贸易品 | 3 | 高价小件、低价大件、受传闻影响物。 |
| 材料 | 3 | 基础材料、进阶材料、Boss / 精英材料。 |
| 两栖物品 | 2 | 既能战斗又能高价出售，制造真实取舍。 |
| 风险物 | 2 | 高侵蚀、高污染、违禁或情感代价。 |

### 3.5 验收样例

| ID | 前置状态 | 玩家行为 | 期望结果 | 失败信号 |
|---|---|---|---|---|
| `V-ITEM-ROTATE-01` | 背包中有 1x3 长刀，只有竖向 1x3 空位。 | 旋转长刀并放入空位。 | 放置成功，实例保存当前角度，方向效果按新朝向刷新。 | 旋转后占格错误、重进界面角度丢失、方向效果仍按旧角度。 |
| `V-ITEM-PLACE-02` | 背包有一个封锁格和一个 L 形战利品。 | 尝试把 L 形战利品压到封锁格。 | 放置失败，原背包不变，显示非法原因。 | 自动挤开其他物品、吞掉战利品、没有失败反馈。 |
| `V-ITEM-LIFE-01` | 本轮新获 2 件战利品，另有 1 件局前绑定武器。 | 战斗失败。 | 新获战利品丢失；绑定武器保留但损坏或标记。 | 全部保留、全部丢失、无法解释丢失原因。 |
| `V-ITEM-EXTRACT-01` | 背包和安全盒各有物品。 | 在安全区选择撤离。 | 背包和安全盒物品进入地面库存，实例状态保留。 | 安全区清空账本、物品重复、实例状态重置。 |
| `V-ITEM-SELL-01` | 地面库存有普通战利品、委托物和情感锚点物。 | 尝试出售三类物品。 | 普通物品可售；委托物硬阻止；情感锚点按配置阻止或给强反馈。 | 普通物品被过度保护、委托物可静默卖掉、情感物无反馈。 |

### 3.6 完成判定

`Items` 达到正式纵切可交付，需要同时满足：

1.  配置 README 能列出上述静态字段和运行时排除字段。
2.  至少有首批内容覆盖武器、防具、消耗品、贸易品、材料、两栖物品和风险物。
3.  背包表现能让玩家看懂旋转、非法放置、绑定、丢失和出售后果。
4.  至少通过 `V-ITEM-ROTATE-01`、`V-ITEM-LIFE-01`、`V-ITEM-EXTRACT-01` 三条验收。

## 4. Monsters 承接清单

### 4.1 必读事实来源

| 文档 | 读取重点 |
|---|---|
| `GDD_01_背包战斗与局内网格机制.md` | 怪物类型、对包干涉、构筑破坏、胜负结算。 |
| `03_战斗回合与怪物意图规则卡.md` | 战斗状态机、AP、护盾、意图字段、目标选择、多怪行动顺序。 |
| `02_物品背包旋转与生命周期规则卡.md` | 怪物对包干涉的统一裁决和冲突优先级。 |
| `13_策划跨系统验收场景矩阵.md` | `A-02`、`A-04`、`A-05`。 |

### 4.2 配置承接字段

| 字段组 | 必填字段 | 设计规则 |
|---|---|---|
| 身份 | `MonsterID`、`DisplayName`、`MonsterRole`、`CombatVisualID`、`LoreTags` | `MonsterRole` 应说明它在战斗中教玩家什么。 |
| 层级 | `LayerRange`、`EncounterTags`、`DifficultyBudget` | 浅层不投放高复杂组合；第 2 层开始出现机制压力。 |
| 属性 | `MaxHP`、`BaseShield`、`SpeedOrder`、`SanPressureBase` | 数值是表现意图的载体，不是唯一难度来源。 |
| 意图 | `IntentList`、`IntentWeights`、`IntentSequence`、`Reliability` | 意图必须能预告；未知意图只用于少量特殊怪。 |
| 目标 | `TargetRule`、`ItemTargetFilter`、`GridTargetRule` | 对包干涉必须说明目标选择和备用目标。 |
| 对包干涉 | `GridLockProfile`、`AddJunkProfile`、`MoveItemProfile`、`PollutionProfile` | 与 `02` 规则卡的干涉类型一致，不新增私有裁决。 |
| 奖励 | `DropPoolRefs`、`RewardProfile`、`MemoryReward` | 精英 / Boss 应有与风险匹配的奖励钩子。 |
| 表现 | `IntentIconSet`、`ActionVfxRef`、`HitFeedbackRef`、`DefeatFeedbackRef` | 意图图标必须覆盖攻击、防御、塞包、封格、SAN 压力。 |

运行时字段不得写进怪物静态定义：

| 运行时字段 | 归属 |
|---|---|
| 当前 HP、当前护盾、本回合意图、蓄力层数 | 战斗实例。 |
| 已行动、眩晕 / 冻结、召唤来源、临时效果 | 战斗状态。 |
| 本次掉落结果、击杀日志、玩家伤害来源 | 战斗结算日志。 |

### 4.3 怪物职能分层

| 层级 | 怪物职能 | 设计要求 |
|---|---|---|
| 浅层普通怪 | 教意图、伤害、护盾。 | 行为单纯，数值温和，不能突然封死核心构筑。 |
| 浅层压力怪 | 教轻度塞包 / SAN 压力。 | 行为可绕开或容易反制。 |
| 第 2 层普通怪 | 引入腐蚀、封边缘格、垃圾占格。 | 让玩家感到背包空间开始变成战场。 |
| 精英怪 | 检验构筑缺口。 | 至少有一个强机制，但地图上应可绕开。 |
| Boss | 检验层级主题。 | 应有阶段或节奏变化，不只是高 HP。 |

### 4.4 首批怪物建议

| 怪物 | 职能 | 意图组合 | 投放 |
|---|---|---|---|
| 深渊狂犬 | 基础攻击教学 | `Attack` | 第 1 层普通战斗。 |
| 酸液软体 | 轻度空间压力 | `Attack`、`AddJunk`、轻污染 | 第 1-2 层普通战斗。 |
| 结晶守卫 | 防御与封格 | `Defend`、`GridLock`、`Attack` | 第 2 层普通 / 精英。 |
| 窃魂虫群 | SAN 压力 | `SanPressure`、低 HP 多体 | 第 2 层压力路线。 |
| 畸变融合体 | 第一批精英 | `Charge`、`AddJunk`、`Attack`、阶段强化 | 第 2 层精英。 |
| 层末守门者 | Boss | 阶段攻击、封格、奖励钩子 | 第 1 或第 2 层 Boss。 |

### 4.5 玩家可见信息

| 信息 | 表现要求 |
|---|---|
| 怪物意图 | 每个怪物头顶或脚下必须显示本回合主要意图和关键数值。 |
| 多怪顺序 | UI 排列或行动序号要让玩家理解谁先行动。 |
| 对包干涉 | 封格、塞包、推移、污染必须有形状 / 数量 / 目标倾向提示。 |
| 反制窗口 | 蓄力、可绕开的精英、可抢杀小怪要有清晰视觉暗示。 |
| 战败原因 | 战败结算应能复盘主要伤害、SAN 压力或背包干涉来源。 |

### 4.6 验收样例

| ID | 前置状态 | 玩家行为 | 期望结果 | 失败信号 |
|---|---|---|---|---|
| `V-COMBAT-INTENT-01` | 怪物意图为攻击 12，玩家有 3 AP。 | 玩家叠 14 护盾并结束回合。 | 怪物攻击被护盾抵消，护盾剩余 2 后回合末清空。 | 意图伤害和实际伤害不一致且无解释。 |
| `V-COMBAT-BAG-01` | 酸液软体预告塞入 1x1 毒液，背包有空格。 | 玩家不处理空格并结束回合。 | 毒液进入合法空格，背包状态刷新。 | 毒液覆盖已有物品或没有任何可见反馈。 |
| `V-COMBAT-BAG-02` | 结晶守卫预告封格，目标格已有物品。 | 玩家结束回合。 | 物品按规则弹出或目标改选，封格结果可读。 | 物品静默消失或同格状态无法解释。 |
| `V-COMBAT-ORDER-01` | 左怪攻击，右怪塞包。玩家击杀左怪。 | 结束回合。 | 左怪不行动，右怪继续按顺序塞包。 | 死亡怪仍行动，或右怪无故跳过。 |
| `V-COMBAT-DEFEAT-01` | 玩家 HP 低，怪物意图足以击倒。 | 玩家不防御并结束回合。 | 进入战败结算，显示主要伤害来源和物品裁决。 | 战败后玩家无法知道为什么输。 |

### 4.7 完成判定

`Monsters` 达到正式纵切可交付，需要同时满足：

1.  配置 README 能表达怪物身份、层级、属性、意图、目标、对包干涉、奖励和表现字段。
2.  首批怪物至少覆盖攻击、防御、塞包、封格、SAN 压力和蓄力。
3.  UI 表现能让玩家看懂本回合主要威胁和下一步反制空间。
4.  至少通过 `V-COMBAT-INTENT-01`、`V-COMBAT-BAG-01`、`V-COMBAT-ORDER-01` 三条验收。

## 5. Dungeons 承接清单

### 5.1 必读事实来源

| 文档 | 读取重点 |
|---|---|
| `GDD_02_深渊地图遍历与搜打撤抉择.md` | 节点网络、路线主题、层级节奏、战争迷雾、安全区和 seed 验收。 |
| `02_物品背包旋转与生命周期规则卡.md` | 战利品拾取、撤离 / 战败物品裁决、安全盒。 |
| `03_战斗回合与怪物意图规则卡.md` | 节点战斗压力和怪物机制投放。 |
| `13_策划跨系统验收场景矩阵.md` | `A-01`、`A-03`、`A-04`、`A-05`、`A-10`。 |

### 5.2 配置承接字段

| 字段组 | 必填字段 | 设计规则 |
|---|---|---|
| 层级 | `LayerID`、`LayerName`、`ThemeTags`、`UnlockRule`、`DirectStartRule` | 已通层直达直接生成目标层，不重复打一遍前置层。 |
| 地图形状 | `RowCount`、`MinWidth`、`MaxWidth`、`BossRowRule`、`SafeZoneRule` | Boss 和 SafeZone 固定；路线行按配置生成。 |
| 地图画像 | `MapProfileID`、`NodeTypeWeights`、`RouteThemes`、`Constraints` | 权重是满足约束后的候选权重，不是无条件概率。 |
| 内容池 | `EncounterPool`、`ElitePool`、`BossEncounterID`、`RewardPool`、`EventPool`、`HazardPool` | 所有节点绑定必须能找到有效内容。 |
| 节奏约束 | `MinCombatPerRoute`、`EliteBypassRule`、`BossBufferRule`、`MaxSameTypeChain` | 第 1 层精英可绕；第 2 层开始有机制压力。 |
| 信息可见 | `FogRules`、`BossPreviewRule`、`NodeRevealRange` | 当前节点和下一行可读；更远保持迷雾。 |
| 安全区 | `SafeZoneRecoveryRule`、`ExtractionRule`、`DescendRule`、`SafeBoxRule` | 安全区免费全恢复；继续深入不清探索账本。 |
| 调试 | `SeedPolicy`、`DebugSummaryFormat`、`ValidationChecks` | 同 `LayerID + RunSeed + MapProfileID` 必须复现。 |

运行时字段不得写进静态层级配置：

| 运行时字段 | 归属 |
|---|---|
| `RunSeed`、当前节点、已访问节点、已解锁层 | 探索存档。 |
| 地图实例节点 ID、连线 ID、可见状态、绑定内容结果 | 本轮地图实例。 |
| 本轮探索账本、已带回 / 已丢失物、当前安全盒内容 | 本轮探索账本。 |

### 5.3 地图画像建议

| `MapProfileID` | 用途 | 节点倾向 | 约束 |
|---|---|---|---|
| `layer1_tutorial_branching` | 第 1 层教学分支。 | 普通战斗、少量宝箱、低复杂事件。 | 至少 2 条路线；精英可绕；无高压连续事件。 |
| `layer2_bag_pressure` | 第 2 层背包机制压力。 | 普通战斗、精英、宝箱、轻危害。 | 至少 1 个对包干涉遭遇；精英至少 1 个可绕。 |
| `risk_reward_elite` | 高风险高收益路线画像。 | 精英、宝箱、高价值事件。 | 高收益路线不应同时也是最低风险路线。 |
| `explore_event_dense` | 探索 / 事件路线画像。 | Event、Treasure、ShopOrTrade。 | 事件不能连续 3 个；至少保留战斗压力。 |

### 5.4 玩家可见信息

### 5.6 验收样例

| ID | 前置状态 | 玩家行为 | 期望结果 | 失败信号 |
|---|---|---|---|---|
| `V-MAP-SEED-01` | 同一 `LayerID + RunSeed + MapProfileID`。 | 连续生成两次地图。 | 节点、连线、绑定内容和检查摘要一致。 | 同 seed 结果变化且无配置变更。 |
| `V-MAP-ROUTE-01` | 第 1 层地图生成完成。 | 检查所有节点与 Boss 路线。 | 所有节点可达并可通 Boss，精英可绕。 | 孤岛、死路、Boss 不可达、精英强制必打。 |
| `V-MAP-DIRECT-01` | 玩家已解锁第 2 层。 | 从小镇选择第 2 层出发。 | 直接生成第 2 层地图，不重复打一遍第 1 层。 | 必须重打前置层或解锁状态丢失。 |
| `V-SAFEZONE-01` | 击败 Boss 后进入安全区。 | 选择继续深入。 | HP / SAN 免费全恢复；探索账本、背包和安全盒不清空；生成下一层地图。 | 安全区收费、账本清空、物品丢失、下一层生成失败。 |
| `V-EXTRACT-01` | 安全区中背包有战利品。 | 选择撤离。 | 战利品转入地面库存，本次收益和人偶状态可复盘。 | 撤离后收益来源不明、物品重复或丢失。 |

### 5.7 完成判定

`Dungeons` 达到正式纵切可交付，需要同时满足：

1.  配置 README 能表达层级、地图画像、节点类型、内容池、迷雾、安全区和调试摘要。
2.  至少有第 1 层和第 2 层两个可复现 seed 样例。
3.  地图表现能让玩家看懂当前节点、可选路线、精英可绕、Boss 方向和安全区决策。
4.  至少通过 `V-MAP-SEED-01`、`V-MAP-ROUTE-01`、`V-SAFEZONE-01` 三条验收。

## 6. 跨主干联合验收

P0 三条主干不能只分别通过，还要能组合成玩家路径。

| ID | 路径 | 期望 |
|---|---|---|
| `V-P0-RUN-01` | 备战携带武器和消耗品 -> 进入第 1 层地图 -> 普通战斗 -> 搜刮 -> Boss -> 安全区撤离。 | 玩家能理解每一步收益和代价，物品实例、HP / SAN、地图账本和库存回流一致。 |
| `V-P0-RUN-02` | 直接从已解锁第 2 层出发 -> 选择精英可绕路线 -> 遇到对包干涉怪 -> 安全区继续深入。 | 已通层直达、路线选择、怪物意图、背包干涉、安全区免费恢复和账本保留全部成立。 |
| `V-P0-FAIL-01` | 玩家贪路线 -> 背包满载 -> 战斗失败。 | 新获未绑定物丢失，绑定物损坏保留，安全盒保留，人偶创伤和失败原因可复盘。 |

联合验收通过后，才能认为 P0 主干不只是“单系统可开发”，而是形成了正式版核心搜打撤体验。
