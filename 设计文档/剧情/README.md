# 剧情设计阅读入口

> 本目录承接剧情大纲、世界观叙事、主角 / 零号魔偶关系、记忆拼图、主线事件方向和结局线。它不替代 `GDD_05` 的剧本调度规则，不替代 `23_长期记忆剧情内容包` 的事件 / 房间记忆内容粒度，也不代表任何剧情配置或剧本表已经落地。

`剧情` 是独立专业 Role，不归入策划。Owner 处理完整模块时可以切换到剧情 Role，但剧情事实仍以本目录为入口。

## 1. 目录定位

`设计文档/剧情/` 用来存放“写什么故事”和“故事为什么能驱动主循环”的文档。

适合放在这里：

- 主剧情大纲、世界观基准、主角和零号魔偶设定。
- 剧情阶段、情绪曲线、记忆拼图、关键遗物和结局方向。
- 后续文案、剧本表、内容包和房间记忆需要遵守的叙事母题。

不放在这里：

- 剧本事件字段、触发器、优先级、跳过 / 重入和系统指令规则；这些归 `设计文档/GDD/GDD_05_剧本调度引擎与世界观封装逻辑.md` 和 `设计文档/规则卡/10_剧本调度与事件队列规则卡.md`。
- 已进入配置或验收粒度的事件、纪念物、日记、窗外状态和待机规则；这些归 `设计文档/content_packs/23_长期记忆剧情内容包.md`。
- JSON、剧本表、对话树、运行时 UI 或美术素材。
- Yarn 脚本源、对白节点清单、触发 JSON、说话人表、命令白名单和 Validator 口径；这些按 `开发文档/18_全局叙事播放系统开发方案.md` 的全局叙事播放系统承接。

## 3. 推荐阅读顺序

1. `00_剧情大纲.md`：先确认故事主轴和后续填充边界。
2. `01_序章演出与对话节奏.md`：确认序章和第一轮循环如何先像游戏开场，再像系统入口。
3. `设计文档/参考/01_This_Is_the_Police_演出参考.md`：确认可借鉴的演出组织方式。
4. `版本规划/13_正式版全局体验总线与开放节奏.md`：确认叙事在完整游戏体验中的位置。
5. `版本规划/14_0-12小时候选主循环细案设计.md`：确认 0-12 小时按时长推进的剧情 / 系统融合口径。
6. `GDD_05` 与 `规则卡/10`：进入剧本调度、事件队列和字段规则。
7. `content_packs/23`：进入长期记忆剧情、房间纪念物和验收样例。

## 4. 后续填充规则

- 先补叙事母题和角色真相，再补对白正文；不要让对白绕过系统状态。
- 剧情事件必须由深渊、债务、Bond、房间记忆、日程或势力状态触发，避免变成独立章节播放器。
- 机械、工坊、旧工具和魔偶是局部语义；全局风格仍以“日系二次元地底奇幻冒险 + 低信息密度”为准。
- 序章和关键主线节点优先按“短剧情段 -> 可玩操作段 -> 结果回声段”编排，不先做长剧情播放器。
- 新增剧情文档前先判断能否补进 `00_剧情大纲.md`；只有主题稳定且会持续维护时再拆新文档。
