# P2长期循环叙事承接清单

> **定位：** 本文档把经济压力、势力订单、剧本事件队列和房间长期记忆从“规则可开发”推进到“正式纵切可交付清单”。它不写程序实现，也不替代配置 README；它规定这些长期系统交给配置、UI / 美术和验收时，必须交到什么粒度。

---

## 1. P2 总览

| 主干 | 对应配置域 | 对应设计 | 当前判断 | 本文目标 |
|---|---|---|---|---|
| 长期经济压力 | 经济配置、传闻、顾客、账单、黑市渠道 | `GDD_04`、`04_小镇经济结算与压力链规则卡` | 规则可开发 | 补齐日营业、传闻、违禁品、月租、欠债和账单复盘的承接粒度。 |
| 势力订单 | Factions、Orders、Rewards、Shops、商店 / 解锁 | `GDD_10`、`07_势力声望与订单规则卡`、`24_势力订单声望内容包` | 规则可开发，内容包可拆分 | 按 `24` 补齐势力、订单刷新、委托物绑定、背叛、声望、奖励、商店解锁和验收承接。 |
| 剧本事件队列 | ScenarioEvents、DialogueTrees、Flags、Commands | `GDD_05`、`10_剧本调度与事件队列规则卡` | 规则可开发 | 补齐事件触发、队列优先级、跳过重入、系统指令和内容安全承接。 |
| 房间长期记忆 | RoomMemory、Mementos、Diary、DisplaySlots | `GDD_11`、`11_人偶房间布局与视觉叙事规则卡` | 规则可开发 | 补齐房间作为长期经历记录器的内容、表现、资源和验收承接。 |

P2 的目标不是横向堆玩法，而是让玩家每次下潜、撤离、出售、接单、失败、修复和互动都能沉淀为长期压力、长期目标或长期记忆。

## 2. 长期经济承接清单

### 2.1 必读事实来源

| 文档 | 读取重点 |
|---|---|
| `GDD_04_小镇循环与经济物价波浪模型.md` | 小镇经营、物价波浪、账单压力和经济循环定位。 |
| `04_小镇经济结算与压力链规则卡.md` | 经济状态机、容器流向、售价公式、传闻、顾客、违禁品、月租和欠债裁决。 |
| `GDD_07_时间日程系统与天数轮转机制.md` | Day / Week / Month 口径、周结、月租和零时耗局外行为。 |
| `13_策划跨系统验收场景矩阵.md` | `A-03`、`A-06`、`A-10`。 |

### 2.2 配置承接字段

| 字段组 | 必填字段 | 设计规则 |
|---|---|---|
| 经济周期 | `EconomyProfileID`、`WeekLength`、`MonthLength`、`BaseRentCurveID`、`GlobalPriceCurveID` | 当前口径默认每 7 天周结、每 28 天月租；曲线可配置但不能与 Day / Week / Month 冲突。 |
| 售价规则 | `CellValueByStage`、`RarityMultiplier`、`ShapeMultiplier`、`RiskCompensation`、`ConditionMultiplier` | 售价来源必须可复盘；形状补偿、稀有度和风险补偿不能只写在描述里。 |
| 容器出口 | `DumpBoxRule`、`ShowcaseRule`、`OrderSlotRule`、`BlackMarketRule`、`PawnPoolRule` | 同一物品同一天只能进入一个结算出口；优先级沿用经济规则卡。 |
| 传闻 | `RumorID`、`TargetQuery`、`Multiplier`、`DurationDays`、`SourcePool`、`AvailabilityCondition` | 传闻必须指向可获得标签或来源；不能生成当前版本完全不可兑现的目标。 |
| 顾客 | `CustomerID`、`BudgetRange`、`PreferredTags`、`RejectedTags`、`AppearanceWeight`、`SpecialRule` | 顾客只抽象成交，不变成逐个讨价还价小游戏。 |
| 违禁品 | `ContrabandTag`、`Severity`、`AllowedChannels`、`NightTaxRule`、`WarningLevel` | 高收益必须伴随可读风险；隔夜代价不能暗扣关键状态。 |
| 月租账单 | `BillID`、`BaseRent`、`MaintenanceFee`、`LicenseFee`、`InterestRule`、`DebtPolicy` | 月租是长期压力核心，必须提前提示缺口和裁决路径。 |
| 典当 | `PawnDiscountRange`、`ProtectedItemQuery`、`RecommendationRule`、`RedeemPolicy` | 普通物品可由玩家手动处理；保护只用于剧情、委托、人偶情感锚点或不可替代物。 |

运行时字段不得写进静态经济配置：

| 运行时字段 | 归属 |
|---|---|
| 当前金币、当日售出物、未售物、账单明细 | 经济存档 / 日报。 |
| 当前周传闻、剩余天数、当日顾客抽取结果 | 经济运行时状态。 |
| 本月欠款、已典当物、债主事件冷却 | 长期经济状态。 |
| 某物品实际成交价、售出渠道、买方摘要 | 结算日志。 |

### 2.3 玩家可见信息

| 场景 | 必须可见 |
|---|---|
| 备战期 | 当前传闻、涨跌标签、剩余天数、月租倒计时、预计缺口。 |
| 出售前 | 售价来源、传闻倍率、损坏 / 污染折价、违禁渠道限制。 |
| 日终账单 | 倾倒箱收入、橱窗收入、订单收入、黑市收入、支出、未售品、隔夜代价。 |
| 月租前 | 应付金额、可用金币、缺口、欠债后果、典当入口。 |
| 欠债后 | 欠款、利息、债主事件、下一次风险节点。 |

### 2.4 首批内容要求

| 内容 | 最低数量 | 必须覆盖的体验 |
|---|---:|---|
| 传闻模板 | 6 | 标签涨价、标签崩盘、违禁窗口、势力需求、高污染溢价、低层材料需求。 |
| 顾客模板 | 5 | 普通散客、高预算藏家、拒收违禁者、黑市买家、偏好套装者。 |
| 账单模板 | 3 | 正常日结、月租结算、欠债 / 典当结算。 |
| 违禁品规则 | 3 | 普通拒收、黑市可售、隔夜代价。 |
| 月租曲线 | 1 | 至少覆盖前 3 个月压力增长。 |

### 2.5 验收样例

| ID | 前置状态 | 玩家行为 | 期望结果 | 失败信号 |
|---|---|---|---|---|
| `V-ECON-RUMOR-01` | 本周传闻 `OriginStone * 1.5`，库存有源石物品。 | 放入倾倒箱并日结。 | 售价吃到传闻倍率，账单显示涨价来源。 | 金币变化无来源，或传闻只显示不生效。 |
| `V-ECON-CONTRABAND-01` | 库存有高污染违禁品，黑市未开启。 | 尝试普通出售后留到次日。 | 普通出售被拒并说明；过夜触发 NightTax 或强提示。 | 违禁品静默卖出，或暗扣 SAN 无提示。 |
| `V-ECON-BILL-01` | 月末账单 1500G，玩家金币 1200G，有可典当物。 | 进入月租结算。 | 显示缺口，打开典当或欠债裁决，结果进入日志。 | 月租突然失败，玩家不知道如何补救。 |
| `V-ECON-REPORT-01` | 同日有倾倒箱、橱窗、订单和维护支出。 | 查看日终账单。 | 四类收入和支出分列，未售品回流清楚。 | 只显示最终金币变化。 |

### 2.6 完成判定

长期经济达到正式纵切可交付，需要同时满足：

1. 配置能表达售价、传闻、顾客、违禁品、账单、欠债和典当。
2. 玩家能在备战、出售、日结、月租和欠债时理解收益与代价。
3. 至少有首批传闻、顾客、账单和违禁品内容样例。
4. 至少通过 `V-ECON-RUMOR-01`、`V-ECON-CONTRABAND-01`、`V-ECON-BILL-01` 三条验收。

## 3. 势力订单承接清单

### 3.1 必读事实来源

| 文档 | 读取重点 |
|---|---|
| `GDD_10_势力声望与订单系统.md` | 势力关系、订单目标、声望解锁和长期社会压力。 |
| `07_势力声望与订单规则卡.md` | 势力字段、订单定义 / 实例、刷新算法、状态机、黑市背叛和奖励引用。 |
| `04_小镇经济结算与压力链规则卡.md` | 订单作为经济出口和黑市背叛的收益入口。 |
| `13_策划跨系统验收场景矩阵.md` | `A-05`、`A-10`、`A-11`。 |

### 3.2 配置承接字段

| 字段组 | 必填字段 | 设计规则 |
|---|---|---|
| 势力 | `FactionID`、`DisplayName`、`FactionTags`、`OrderPoolIDs`、`ReputationRankTableID`、`ConflictRules` | 声望必须解锁服务、商品、图纸、情报或结局倾向，不能只是文本好感。 |
| 订单池 | `OrderPoolID`、`FactionID`、`CandidateOrderIDs`、`RefreshPolicy`、`SlotCount` | 周刷新可复现，已接订单不被刷新覆盖。 |
| 订单定义 | `OrderID`、`OrderType`、`Requirement`、`DeadlineDays`、`RewardID`、`FailurePenalty`、`AvailabilityCondition` | 需求必须机器可判断，不能只有描述文本。 |
| 委托物 | `BoundItemRule`、`OrderBoundTag`、`BattleLossRule`、`BetrayalAllowed` | 委托物可移动、旋转、占格，但不能普通出售或被其他正规订单消耗。 |
| 奖励 | `RewardID`、`FixedGold`、`ReputationDelta`、`TrustDelta`、`UnlockRefs` | 奖励引用必须能被 Validator 找到。 |
| 背叛 | `BetrayalReward`、`OriginFactionPenalty`、`BlackMarketTrustDelta`、`ConfirmTextKey` | 背叛必须玩家主动确认，不自动触发。 |
| 声望 | `RankThresholds`、`UnlockTable`、`CooldownPolicy`、`SuspicionPolicy` | 声望最低为 0；惩罚通过冷却、涨价和低优先订单表现。 |

运行时字段不得写进订单静态定义：

| 运行时字段 | 归属 |
|---|---|
| 订单实例 ID、当前状态、接取日、截止日 | 订单实例。 |
| 已交付物品实例、绑定委托物实例、当前进度 | 订单实例。 |
| 当前声望值、黑市信任、势力冷却 | 势力运行时状态。 |
| 本周刷新结果、刷新 seed、可见槽位 | 周期订单状态。 |

### 3.3 玩家可见信息

| 场景 | 必须可见 |
|---|---|
| 订单列表 | 发布势力、目标、截止日、奖励、失败惩罚、当前进度。 |
| 接取前 | 是否占背包、是否绑定物、目标来源层、可完成性提示。 |
| 深渊地图 | 订单目标可能出现的层级、节点类型或路线倾向。 |
| 交付时 | 满足 / 不满足的具体条件，物品是否会被消耗。 |
| 背叛时 | 原订单失败、声望惩罚、黑市收益和长期风险。 |

### 3.4 首批内容要求

| 内容 | 最低数量 | 必须覆盖的体验 |
|---|---:|---|
| 势力 | 3 | 正规委托方、工坊 / 技术势力、黑市。 |
| 订单模板 | 9 | 采购、目标物、大型委托物、探索报告、黑市背叛、限期高价。 |
| 声望阶梯 | 3 套 | 低阶服务、中阶图纸、高阶情报或独占商品。 |
| 奖励引用 | 9 | 金币、材料、图纸、商店解锁、剧情旗标。 |
| 失败惩罚 | 4 | 超期、放弃、背叛、绑定物丢失。 |

### 3.5 验收样例

| ID | 前置状态 | 玩家行为 | 期望结果 | 失败信号 |
|---|---|---|---|---|
| `V-ORDER-REFRESH-01` | `RunSeed=1001`，第 3 周，玩家到达第 2 层。 | 刷新机械工坊订单。 | 同输入结果一致；不出现第 4 层目标；至少一个可完成订单。 | 同 seed 漂移，或刷新不可能订单。 |
| `V-ORDER-BOUND-01` | 接取大型委托物订单，生成 2x3 绑定容器。 | 带入深渊并整理背包。 | 委托物占格、可旋转、不可普通出售，订单面板显示绑定。 | 委托物不占格或被普通出售。 |
| `V-ORDER-COMPLETE-01` | 订单要求 3 个第 2 层矿石，玩家持有合法实例。 | 提交订单。 | 物品被消耗，发奖励，声望增加，日志可复盘。 | 交付吞物但无奖励，或条件不满足仍完成。 |
| `V-ORDER-BETRAY-01` | 正规势力委托物可被黑市收购。 | 二次确认后交给黑市。 | 原订单 `Betrayed`，正规声望受罚，黑市信任增加。 | 背叛自动发生或原订单仍可完成。 |

### 3.6 完成判定

势力订单达到正式纵切可交付，需要同时满足：

1. 配置能表达势力、订单池、订单需求、委托物绑定、奖励、失败和背叛。
2. 玩家能在订单列表、地图、背包、交付和背叛确认中理解目标与代价。
3. 首批内容至少覆盖三个势力和九类订单模板。
4. 至少通过 `V-ORDER-REFRESH-01`、`V-ORDER-BOUND-01`、`V-ORDER-COMPLETE-01`、`V-ORDER-BETRAY-01` 四条验收。

## 4. 剧本事件队列承接清单

### 4.1 必读事实来源

| 文档 | 读取重点 |
|---|---|
| `GDD_05_剧本调度引擎与世界观封装逻辑.md` | 世界观事件、剧情触发和系统包装定位。 |
| `10_剧本调度与事件队列规则卡.md` | 事件字段、触发表达、队列优先级、对话树、系统指令、跳过和重入。 |

### 4.2 配置承接字段

| 字段组 | 必填字段 | 设计规则 |
|---|---|---|
| 事件定义 | `EventID`、`EventType`、`Trigger`、`Priority`、`Presentation`、`RepeatPolicy`、`BlockPolicy` | 事件是系统状态触发，不是独立章节播放器。 |
| 触发器 | `TriggerType`、`ConditionExpression`、`CooldownDays`、`FlagRequirements`、`SuppressConditions` | 条件表达必须可校验，不能只写自然语言。 |
| 队列 | `Priority`、`QueueGroup`、`ExpirePolicy`、`ConflictPolicy`、`IdleWindow` | 高优先级先播；低优先级保留；不能无限堆积。 |
| 对话树 | `DialogueTreeID`、`NodeList`、`ChoiceList`、`FallbackNodeID` | 对话可以跳过，但系统指令不能丢。 |
| 系统指令 | `CommandID`、`CommandType`、`TargetRef`、`Payload`、`IdempotentKey`、`FailureFallback` | 所有改变状态的剧情效果必须显式指令化。 |
| 旗标 | `SetFlagsOnStart`、`SetFlagsOnComplete`、`ClearFlags`、`HistoryPolicy` | 历史旗标用于去重、重入和房间记忆。 |
| 表现映射 | `Presentation`、`SpeakerSet`、`ExpressionRefs`、`VoiceRefs`、`RoomMemoryRef` | 没有资源时必须 fallback，不阻断系统指令执行。 |

运行时字段不得写进事件静态配置：

| 运行时字段 | 归属 |
|---|---|
| 事件实例 ID、触发日、当前状态、当前对话节点 | 事件实例。 |
| 已执行指令、跳过状态、重入点 | 事件实例。 |
| 当前队列、播放中事件、被压制事件 | 剧本队列状态。 |
| 已触发历史、完成历史、剧情旗标 | 存档剧情状态。 |

### 4.3 玩家可见信息

| 场景 | 必须可见 |
|---|---|
| 强制事件 | 为什么触发、是否阻塞当前流程、完成后状态变化。 |
| 非阻塞气泡 | 不打断玩家操作，但能回看或进入日志。 |
| 跳过 | 跳过只跳文本，不跳系统结算；关键结果必须摘要显示。 |
| 选择分支 | 选项后果类型要可读，不能隐藏重大惩罚。 |
| 读档重入 | 事件回到稳定节点，不重复发奖励或重复扣状态。 |

### 4.4 首批内容要求

| 内容 | 最低数量 | 必须覆盖的体验 |
|---|---:|---|
| 主线事件 | 6 | 开局、首次下潜、首次战败、首次 Boss 胜利、月租危机、第二层解锁。 |
| Bond 事件 | 6 | Bond 阈值、低 SAN 安抚、奇迹后对话、赠礼里程碑。 |
| 债务 / 经济事件 | 4 | 欠债警告、典当后果、黑市诱惑、债主登门。 |
| 深渊 lore | 6 | 节点发现、Boss 线索、物品图鉴、层级异常。 |
| RoomMemory 事件 | 6 | 战败、Boss 胜利、关键礼物、委托背叛、月租危机、低 SAN 夜晚。 |

### 4.5 验收样例

| ID | 前置状态 | 玩家行为 | 期望结果 | 失败信号 |
|---|---|---|---|---|
| `V-SCENARIO-QUEUE-01` | 同日触发债务事件、Bond 事件和房间记忆事件。 | 进入日终结算。 | 债务高优先级先播；Bond 排队；房间记忆写入但可稍后看。 | 事件互相覆盖或低优先事件丢失。 |
| `V-SCENARIO-SKIP-01` | 事件含奖励、旗标和对话。 | 玩家跳过文本。 | 奖励、旗标和日志照常执行，显示结果摘要。 | 跳过导致奖励丢失或旗标未写。 |
| `V-SCENARIO-RELOAD-01` | 事件播放到中间节点后存档。 | 读档并继续。 | 回到稳定节点，已执行指令不重复。 | 重复发奖励、重复扣 SAN 或事件卡死。 |
| `V-SCENARIO-FALLBACK-01` | 某事件缺少表情资源。 | 播放事件。 | 使用 fallback 表现，系统指令仍执行。 | 因资源缺失阻断剧情或状态结算。 |

### 4.6 完成判定

剧本事件队列达到正式纵切可交付，需要同时满足：

1. 配置能表达事件、触发器、队列、对话树、系统指令、旗标和表现映射。
2. 玩家能理解强制事件、跳过、选择后果和关键状态变化。
3. 首批事件能覆盖主线、Bond、经济、深渊 lore 和房间记忆。
4. 至少通过 `V-SCENARIO-QUEUE-01`、`V-SCENARIO-SKIP-01`、`V-SCENARIO-RELOAD-01` 三条验收。

### 5.1 必读事实来源

| 文档 | 读取重点 |

### 5.2 配置承接字段

| 字段组 | 必填字段 | 设计规则 |
|---|---|---|
| 房间记忆 | `RoomMemoryID`、`TriggerEventID`、`Priority`、`TargetSlotID`、`DiaryEntryID` | 记忆由经历触发，不是仓库列表。 |
| 纪念物 | `MementoID`、`VisualID`、`AcquireCondition`、`ReplacePolicy`、`InspectDialogueID` | 纪念物可以替换但不能静默消失；来源可回看。 |
| 日记 | `DiaryEntryID`、`SourceEventID`、`SummaryTextKey`、`UnlockCondition`、`SortKey` | 日记保留历史，不因物品出售而删除。 |
| 展示品 | `DisplaySlotID`、`SourceItemScope`、`SnapshotVisualID`、`ClearPolicy` | 展示不锁定来源物；来源物卖出后展示清空或变为历史记录。 |
| 窗外 | `WindowStateID`、`Condition`、`Priority`、`VisualID`、`AmbientAudioID` | 重大事件和结局预兆优先于普通天气。 |
| 待机 | `IdleRuleID`、`Conditions`、`PoseID`、`ExpressionID`、`MotionID`、`DialogueBubblePool` | 低 SAN、创伤和重大事件优先于日常温馨。 |

运行时字段不得写进房间静态配置：

| 运行时字段 | 归属 |
|---|---|
| 已解锁纪念物、当前展示来源、当前待机状态 | 房间存档。 |
| 最近触发事件、日记阅读状态、窗外当前状态 | 房间 / 剧情运行时状态。 |
| 展示品来源实例是否仍存在 | 存档查询结果。 |

### 5.3 玩家可见信息

| 场景 | 必须可见 |
|---|---|
| 进入房间 | 房间不推进 Day，不触发经济倒计时。 |
| 查看纪念物 | 来源事件、简短回忆、是否有相关日记。 |
| 展示品 | 当前展示来源、来源物是否仍存在、清空原因。 |
| 窗外 | 世界状态、重大危机或结局预兆的视觉暗示。 |
| 待机 | 人偶当前情绪、低 SAN 抗拒、创伤或亲密状态。 |

### 5.4 首批内容要求

| 内容 | 最低数量 | 必须覆盖的体验 |
|---|---:|---|
| 纪念物 | 8 | 首次战败、首次 Boss 胜利、关键赠礼、订单背叛、月租危机、低 SAN 修复、第二层解锁、奇迹触发。 |
| 日记条目 | 12 | 关键事件摘要、情绪反馈、深渊 lore、经济压力和 Bond 里程碑。 |
| 窗外状态 | 5 | 日常、雨夜、月租危机、黑市风险、结局前夜。 |
| 待机规则 | 6 | 日常、低 SAN、Broken、Bond 高、战败后、Boss 胜利后。 |
| 展示槽 | 3 | 礼物展示、Boss 战利品展示、玩家手选展示。 |

### 5.5 验收样例

| ID | 前置状态 | 玩家行为 | 期望结果 | 失败信号 |
|---|---|---|---|---|
| `V-ROOM-MEMORY-01` | 首次 Boss 胜利并生成 RoomMemory。 | 进入房间。 | Boss 纪念物出现，日记新增，Day 不变。 | 房间不记录事件或进入房间推进日期。 |
| `V-ROOM-DIARY-01` | 玩家曾触发黑市背叛事件。 | 查看日记。 | 保留背叛摘要和后果，不依赖物品是否还在。 | 日记因物品出售而丢失。 |
| `V-ROOM-DISPLAY-01` | 展示槽绑定某物品快照。 | 卖出来源物品后回房间。 | 展示槽清空或显示历史快照，来源状态可读。 | 展示品复制物品或阻止普通出售。 |
| `V-ROOM-IDLE-01` | SAN=0 且 Broken。 | 进入房间。 | 待机、表情、气泡优先表现崩溃状态。 | 仍播放日常温馨待机。 |

### 5.6 完成判定

房间长期记忆达到正式纵切可交付，需要同时满足：

1. 配置能表达 RoomMemory、纪念物、日记、展示品、窗外和待机规则。
2. 玩家能在房间读懂经历来源、状态变化和长期记忆。
3. 房间保持零压力定位，不推进 Day，不承担仓库功能。
4. 至少通过 `V-ROOM-MEMORY-01`、`V-ROOM-DIARY-01`、`V-ROOM-DISPLAY-01`、`V-ROOM-IDLE-01` 四条验收。

## 6. P2 联合验收

| ID | 路径 | 期望 |
|---|---|---|
| `V-P2-ECON-01` | 撤离带回货物 -> 传闻涨价 -> 倾倒箱 / 橱窗出售 -> 月租倒计时变化。 | 战利品、传闻、售价、日账单和长期压力形成可复盘经济闭环。 |
| `V-P2-ORDER-01` | 接取订单 -> 为目标选择层级 / 路线 -> 背包携带委托物 -> 完成交付。 | 订单改变路线和背包取舍，奖励、声望和日志可读。 |
| `V-P2-BETRAY-01` | 接正规委托 -> 黑市提出更高收购 -> 玩家确认背叛。 | 原势力惩罚、黑市信任、短期收益和长期风险全部成立。 |
| `V-P2-SCENARIO-01` | 债务事件、Bond 事件、RoomMemory 同日触发。 | 事件按优先级排队，跳过不丢指令，房间记忆可稍后查看。 |
| `V-P2-ROOM-01` | 首次战败 / Boss 胜利 / 月租危机后进入房间。 | 房间以纪念物、日记、窗外和待机反映经历，不推进 Day。 |

P2 联合验收通过后，才能认为长期循环不是单纯“多几个按钮”，而是形成“深渊收益 -> 经济压力 -> 订单目标 -> 剧情反馈 -> 房间记忆 -> 下一次下潜动机”的正式长线结构。
