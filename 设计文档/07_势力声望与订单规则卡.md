# 势力声望与订单规则卡

> **定位：** 本规则卡把 `GDD_10` 的势力 / 声望 / 订单系统落实为正式设计规格。势力系统负责给玩家提供长期目标、独占资源和社会压力；订单系统负责把这些目标转化为可接取、可失败、可背叛、可验证的运行时实例。首批正式内容见 `设计文档/24_势力订单声望内容包.md`。

---

## 1. 设计目标

| 目标 | 说明 |
|---|---|
| 让下潜带目标 | 订单把“随便搜刮”变成“为了某个势力找特定东西”。 |
| 用背包制造压力 | 委托物占用格子、可能绑定、可能有负面标签，迫使玩家在战斗空间和订单收益之间取舍。 |
| 让声望有资源意义 | 声望不是好感文本，而是商店、图纸、情报、特殊服务和结局倾向的解锁条件。 |
| 允许有代价的背叛 | 黑市可以收购委托物，但会触发正规势力失败惩罚和长期信任风险。 |
| 可配置可复盘 | 订单池、需求表达、奖励、截止日、失败惩罚和刷新结果都必须能被配置和日志复现。 |

---

## 2. 势力状态

### 2.1 势力定义字段

势力定义是配置数据，代表一局中稳定存在的社会组织。

| 字段 | 类型 | 规则 |
|---|---|---|
| `FactionID` | string | 全局唯一。示例：`guild_adventurer`、`workshop_mechanic`、`black_market`。 |
| `DisplayName` | string | UI 显示名。 |
| `FactionTags` | string[] | 势力标签，接 `06_标签与特质规则卡`。 |
| `OrderPoolIDs` | string[] | 该势力可抽取的订单池。 |
| `ShopUnlockTableID` | string | 声望商店解锁表引用，可为空。 |
| `ReputationRankTableID` | string | 声望等级阈值表引用；黑市可改用 `TrustRankTableID`。 |
| `ConflictRules` | array | 与其他势力或黑市的排斥规则。 |
| `RefreshPolicy` | object | 每周刷新槽位、保留规则、冷却规则。 |

### 2.2 势力运行时字段

| 字段 | 类型 | 规则 |
|---|---|---|
| `FactionID` | string | 指向势力定义。 |
| `ReputationValue` | int | 正规势力累计声望，最低 0。 |
| `ReputationRank` | int | 由 `ReputationValue` 映射，不手写保存为事实来源；可缓存。 |
| `TrustValue` | int | 黑市使用，最低 0。正规势力可为空。 |
| `CompletedOrderIDs` | string[] | 已完成订单定义 ID，用于一次性订单和里程碑判断。 |
| `FailedOrderCount` | int | 近期失败次数，用于冷却和态度惩罚。 |
| `CooldownUntilDay` | int | 冷却结束日；冷却期间不刷新新订单。 |
| `UnlockedShopItemIDs` | string[] | 已解锁商店商品。可由声望和特定订单共同驱动。 |
| `KnownFlags` | string[] | 叙事或系统标记，例如 `black_market_suspicion_high`。 |

---

## 3. 订单定义

### 3.1 订单定义字段

订单定义是配置模板，不记录玩家当前进度。

| 字段 | 类型 | 规则 |
|---|---|---|
| `OrderID` | string | 全局唯一。 |
| `FactionID` | string | 发布势力。 |
| `OrderType` | enum | `Procurement`、`LiveCapture`、`TargetItem`、`ExplorationReport`、`BlackMarketBetrayal`。 |
| `DisplayName` | string | UI 显示名。 |
| `Description` | string | 订单说明，不参与逻辑。 |
| `Requirement` | object | 需求表达，见 3.3。 |
| `DeadlineDays` | int | 接取后剩余天数，默认 7；不得小于 1。 |
| `RewardID` | string | 指向 `Rewards`。订单不直接内联复杂奖励。 |
| `FixedGold` | int | 可选的固定金币补充；如存在，应计入总奖励价值。 |
| `ReputationDelta` | int | 完成后的正规势力声望变化。 |
| `TrustDelta` | int | 黑市信任变化，仅黑市或背叛分支使用。 |
| `FailurePenalty` | object | 失败、超期、放弃、背叛各自的惩罚。 |
| `AvailabilityCondition` | string | 可见条件表达式，引用标签、层数、声望、已完成订单、天数等。 |
| `UnlockRefs` | string[] | 完成后解锁的图纸、商店项、旗标或服务。 |
| `RepeatPolicy` | enum | `Once`、`Repeatable`、`WeeklyOnce`、`UntilCompleted`。 |
| `Weight` | int | 刷新抽取权重，必须大于 0。 |
| `Tags` | string[] | 订单标签，例如 `LargeCargo`、`Contraband`、`Layer2`。 |

### 3.2 订单实例字段

订单实例是运行时状态，由刷新或接取生成。

| 字段 | 类型 | 规则 |
|---|---|---|
| `InstanceID` | string | 单局唯一。建议由 `OrderID + Week + Index` 派生，便于日志复盘。 |
| `OrderID` | string | 指向订单定义。 |
| `FactionID` | string | 冗余缓存，便于查询。 |
| `Status` | enum | 见 4.1。 |
| `GeneratedDay` | int | 出现在可接列表的天数。 |
| `AcceptedDay` | int | 接取日；未接取为空。 |
| `DeadlineDay` | int | `AcceptedDay + DeadlineDays`。未接取为空。 |
| `DeliveredItems` | string[] | 已交付物品实例 ID。 |
| `BoundItemIDs` | string[] | 接取或采集后绑定的委托物实例 ID。 |
| `Progress` | object | 当前进度，例如已收集数量、已到达层数、已击败目标。 |
| `FailureReason` | enum | `Expired`、`Abandoned`、`Betrayed`、`InvalidItem`、`FactionCooldown`。 |
| `LogSeed` | int | 订单刷新或需求抽取使用的 seed。 |

### 3.3 需求表达

订单需求必须用统一结构表达，不允许写成仅供人读的文本。

| 需求类型 | 字段 | 说明 |
|---|---|---|
| 按物品 ID | `RequiredItemIDs` | 指定一个或多个物品 ID。 |
| 按标签查询 | `ItemQuery` | 使用 `06_标签与特质规则卡` 的查询表达，例如 `ItemTag:Ore AND Layer:2`。 |
| 按数量 | `RequiredCount` | 需要交付的数量。 |
| 按形状 / 尺寸 | `ShapeConstraint` | 可要求大型委托物，例如面积不小于 6 或包含 2x2。 |
| 按实例状态 | `InstanceStateQuery` | 要求未损坏、已净化、带污染、活体捕获等。 |
| 按探索结果 | `ExploreCondition` | 要求到达指定层、发现节点类型、击败目标或带回报告。 |

需求裁决顺序：

1. 校验订单状态是否允许交付。
2. 校验物品是否存在且位于玩家可交付容器。
3. 校验物品未被其他已接订单绑定。
4. 校验 `RequiredItemIDs` 或 `ItemQuery`。
5. 校验数量、形状、状态和特殊条件。
6. 成功后将物品加入 `DeliveredItems`，并按订单规则移除、消耗或转移归属。

## 4. 订单状态机

### 4.1 状态定义

| 状态 | 含义 | 可转入状态 |
|---|---|---|
| `Available` | 已刷新，玩家可接取。 | `Accepted`、`Expired` |
| `Accepted` | 玩家已接取，但尚未产生进度。 | `InProgress`、`Completed`、`Expired`、`Abandoned`、`Betrayed` |
| `InProgress` | 已有进度或绑定委托物。 | `Completed`、`Expired`、`Abandoned`、`Betrayed` |
| `Completed` | 已按规则交付并发奖。 | 终态 |
| `Expired` | 超过截止日未完成。 | 终态 |
| `Abandoned` | 玩家主动放弃。 | 终态 |
| `Betrayed` | 委托物交给黑市或敌对势力。 | 终态 |

### 4.2 接取规则

*   同一订单实例只能接取一次。
*   玩家可同时拥有多个已接订单，但 `MaxActiveOrders` 可由全局或难度配置限制。
*   接取时设置 `AcceptedDay` 和 `DeadlineDay`。
*   若订单要求预发委托容器、捕获器或任务道具，接取时生成绑定物品并写入 `BoundItemIDs`。
*   接取不推进天数，符合 `GDD_07` 的零时耗拜访口径。

### 4.3 完成规则

完成订单时按以下顺序结算：

1. 锁定订单实例，避免重复提交。
2. 校验状态为 `Accepted` 或 `InProgress`。
3. 校验 `CurrentDay <= DeadlineDay`。
4. 校验需求全部满足。
5. 消耗或转移交付物。
6. 发放 `RewardID`、`FixedGold` 和解锁项。
7. 应用 `ReputationDelta` 或 `TrustDelta`。
8. 写入 `CompletedOrderIDs` 和日志。
9. 刷新势力商店解锁和里程碑对话旗标。

### 4.4 失败、放弃和超期

| 情况 | 触发 | 结果 |
|---|---|---|
| 超期 | 日结或周结时 `CurrentDay > DeadlineDay` | `Status=Expired`，按 `FailurePenalty.Expired` 扣声望、进入冷却或移除绑定物。 |
| 主动放弃 | 玩家在订单面板取消 | `Status=Abandoned`。默认不扣声望，但该势力本周可用槽位不立即补新。 |
| 物品无效 | 提交物不满足需求 | 不改状态，只返回失败原因；不得吞物品。 |
| 势力冷却 | 近期失败过多 | 冷却期间不刷新新订单，可保留已接订单。 |
| 背叛 | 委托物交给黑市或敌对订单 | 原订单 `Status=Betrayed`，正规势力扣声望，黑市增加信任。 |

### 4.5 委托物绑定

*   被订单绑定的物品必须带动态标签 `OrderBound:{OrderInstanceID}`。
*   绑定物可以移动、旋转、参与背包管理，但不能普通出售、制造消耗或交给其他正规订单。
*   若订单定义允许背叛，黑市交付可绕过普通出售限制，转入 `Betrayed`。
*   战败时绑定物按订单配置处理：`Drop`、`Keep`、`Damage` 或 `ConvertToFailure`。
*   放弃或超期后，绑定物按 `FailurePenalty` 决定返还、销毁、解绑或转为普通战利品。

## 5. 订单刷新算法

### 5.1 刷新时机

订单默认在每周开始时刷新，对齐 `GDD_07` 的 Week 节奏。

刷新触发：

*   新周开始。
*   新势力首次解锁。
*   关键声望等级提升后，如果 `RefreshPolicy.RefreshOnRankUp=true`。
*   冷却结束后的下一个刷新点。

### 5.2 刷新输入

刷新器输入：

| 输入 | 说明 |
|---|---|
| `CurrentDay` / `CurrentWeek` | 时间状态。 |
| `RunSeed` | 单局 seed。 |
| `FactionState` | 声望、冷却、完成记录、失败记录。 |
| `ReachedLayer` | 玩家已到达的最高深渊层。 |
| `EconomyState` | 当前物价、传闻、黑市风险。 |
| `OrderPool` | 订单定义池。 |

### 5.3 刷新步骤

```text
For each unlocked faction:
  1. If CurrentDay < CooldownUntilDay: skip new orders.
  2. Read visible slot count from RefreshPolicy.
  3. Keep accepted/in-progress orders; do not replace them.
  4. Remove expired unaccepted Available orders from previous refresh.
  5. Build candidate list:
     - faction matches
     - AvailabilityCondition passes
     - RepeatPolicy allows appearance
     - requirement can be satisfied within reached or near-future layers
     - reward references are valid
  6. Apply weight modifiers:
     - low rank favors low-risk orders
     - high rank unlocks large cargo / live capture / target item
     - current rumor can boost matching tags
     - recent failure reduces high-risk order weight
  7. Roll weighted candidates using RunSeed + FactionID + CurrentWeek.
  8. Enforce diversity:
     - no duplicate OrderID in visible slots
     - no more than one LargeCargo order per faction unless configured
     - at least one order must be realistically completable if slots >= 2
  9. Create Available instances and write LogSeed.
 10. If no candidate exists, generate a configured fallback low-risk procurement order.
```

### 5.4 不可能订单禁止

刷新器不得生成以下订单：

*   要求玩家尚未解锁且无法在截止日前到达的层级素材。
*   要求不存在的物品、标签、奖励或图纸。
*   要求同一局已永久失效的唯一物品，除非订单是剧情失败分支。
*   在新手保护期内要求大型活体捕获或高污染委托物。
*   奖励价值低于委托物基准价值和背包风险成本太多的订单，除非明确标记为陷阱或黑市诱饵。

## 6. 声望、信任与冲突

### 6.1 声望阈值

正规势力使用统一阈值表，具体数值可按势力调整。

| 等级 | 建议阈值 | 设计含义 |
|---|---:|---|
| Lv.0 陌生 | 0 | 只显示基础低风险订单。 |
| Lv.1 认识 | 10 | 解锁基础商店或折扣。 |
| Lv.2 熟人 | 30 | 解锁稳定服务、低阶图纸。 |
| Lv.3 伙伴 | 70 | 解锁中阶图纸、专属订单。 |
| Lv.4 英雄 | 140 | 解锁高阶服务、关键情报。 |
| Lv.5 传奇 | 250 | 解锁终局倾向或终极蓝图。 |

声望只由订单完成、失败、特殊事件和少数剧情裁决修改；普通买卖不应刷声望。

### 6.2 黑市信任

黑市不使用普通声望，而使用 `TrustValue`。

| 行为 | 信任变化 | 备注 |
|---|---:|---|
| 成功黑市交易 | +1 | 普通出售违禁品。 |
| 完成黑市委托 | +2 ~ +5 | 由订单定义。 |
| 出售正规势力委托物 | +2 | 同时触发原势力背叛。 |
| 爽约黑市委托 | -3 | 最低为 0。 |
| 举报或剧情背刺黑市 | -5 以上 | 可触发长期封禁。 |

当 `TrustValue >= 10` 时，正规势力可进入怀疑状态：

*   订单高价值权重下降。
*   商店价格上浮。
*   对违禁品相关标签更敏感。
*   完成正规高难度订单可逐步清除怀疑。

### 6.3 冲突裁决

冲突裁决顺序：

1. 完成订单优先于普通交易。
2. 已绑定委托物优先归属绑定订单。
3. 黑市背叛必须由玩家明确确认，不自动触发。
4. 背叛成功后，原订单立即终态，不允许再补交同一物品挽回。
5. 声望最低为 0，不出现负数；但可通过冷却、涨价和低优先级订单表现惩罚。

## 7. 奖励与经济价值

订单奖励由三部分组成：

| 奖励 | 来源 | 规则 |
|---|---|---|
| 金币 | `FixedGold` 或 `RewardID` | 需要计入经济模型，不能无限高于同层卖店收益。 |
| 物品 / 材料 | `RewardID` | 指向 `配置表(JSON)/Rewards`。 |
| 解锁 | `UnlockRefs` | 可解锁图纸、商品、服务、旗标或剧情入口。 |

价值约束：

*   普通采购订单总价值建议为委托物直接出售价值的 1.2 到 1.8 倍。
*   大型委托物、活体捕获、污染风险订单可提高到 2.0 到 3.0 倍。
*   图纸和商店解锁应视为长期奖励，金币部分可低于同层期望。
*   黑市背叛收益应短期更高，但附带正规势力惩罚和长期怀疑成本。

---

## 8. UI 与玩家可读性

订单面板至少展示：

*   发布势力、声望等级或黑市信任。
*   订单需求的物品 / 标签 / 数量 / 形状 / 状态。
*   截止日和剩余天数。
*   奖励摘要：金币、物品、图纸、商店解锁、声望变化。
*   失败惩罚摘要。
*   当前进度和可提交状态。
*   绑定物品标记，避免玩家误以为普通出售可用。

背叛确认必须二次确认，并明确显示：

*   原势力订单会失败。
*   原势力声望或冷却惩罚。
*   黑市信任和奖励。
*   委托物会被消耗或转移。

---

## 9. Validator 规则

配置校验至少覆盖：

| 校验项 | 规则 |
|---|---|
| ID 唯一 | `FactionID`、`OrderID`、订单池 ID 全局唯一。 |
| 引用合法 | `RewardID`、`UnlockRefs`、物品 ID、标签、图纸和商店项必须存在。 |
| 截止日合法 | `DeadlineDays >= 1`。 |
| 权重合法 | 可刷新订单 `Weight > 0`。 |
| 需求可解 | 订单至少有一种可判断的需求，不能只有描述文本。 |
| 状态惩罚完整 | `Expired`、`Abandoned`、`Betrayed` 的处理必须有默认值或显式配置。 |
| 黑市规则闭环 | 背叛订单必须声明原势力惩罚和黑市收益。 |
| 奖励价值范围 | 高风险订单可超出常规倍率，但必须带高风险标签或特殊标记。 |
| 重复策略 | `Once` 订单完成后不能再次进入刷新候选。 |

## 10. 验收样例

### 样例 A：每周刷新可复现

输入：

```text
RunSeed=1001
CurrentWeek=3
FactionID=workshop_mechanic
ReputationRank=1
ReachedLayer=2
VisibleSlots=2
```

期望：

*   同样输入连续生成结果完全一致。
*   不出现要求第 4 层素材的订单。
*   两个可见订单不重复。
*   至少一个订单可在第 1 到第 2 层完成。

### 样例 B：按时完成订单

输入：

```text
CurrentDay=15
AcceptedDay=10
DeadlineDay=17
Requirement=ItemTag:Ore AND Layer:2, RequiredCount=3
DeliveredItems=3 个合法矿石实例
RewardID=reward_order_workshop_ore_week3
ReputationDelta=10
```

期望：

*   订单转为 `Completed`。
*   三个矿石实例被消耗或转移归属。
*   发放奖励。
*   机械工坊声望 +10。
*   若跨过声望阈值，刷新商店解锁。

### 样例 C：超期失败

输入：

```text
CurrentDay=18
DeadlineDay=17
Status=InProgress
FailurePenalty.Expired.ReputationDelta=-5
```

期望：

*   订单转为 `Expired`。
*   原势力声望扣 5，但不低于 0。
*   若近期失败达到阈值，设置 `CooldownUntilDay`。
*   绑定物按配置解绑、销毁或转为普通战利品。

### 样例 D：黑市背叛

输入：

```text
原订单：FactionID=mage_tower, Status=InProgress, BoundItem=abyss_core_01
黑市交易：接受 OrderType=BlackMarketBetrayal，提交 abyss_core_01
```

期望：

*   原订单转为 `Betrayed`。
*   法师塔声望按背叛惩罚下降。
*   黑市信任增加。
*   委托物被黑市消耗。
*   UI 日志显示这是玩家主动选择的背叛行为。

## 11. 与其他系统的边界

| 系统 | 边界 |
|---|---|
| `GDD_04` 经济 | 订单奖励和黑市交易属于经济回流，但订单状态机由本规则卡负责。 |
| `GDD_07` 时间 | 订单截止、周刷新、冷却用 Day / Week；接取和提交不推进天数。 |
| `GDD_08` 成长 | 声望可解锁底盘、义体、图纸和服务，但成长消耗与装配规则仍归成长规则卡。 |
| `GDD_09` 标签 | 订单需求、势力条件、委托物绑定全部使用标签 / 查询表达。 |
| `Rewards` 配置 | 奖励内容由奖励表发放，本规则卡只声明订单如何引用奖励。 |
| 黑市 | 黑市是特殊势力，不绕过状态机；只是使用信任、背叛和违禁品规则。 |
