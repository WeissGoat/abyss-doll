# 设计文档纵切批次矩阵

> **更新时间：** 2026-05-24  
> **定位：** 本文档回答“`版本规划/09_正式版核心纵切开发路线.md` 如何覆盖 `设计文档/`”。结论是：`09` 以正式版标准纵向处理系统，不把所有 GDD 同时并行开发。本文用于把每份 GDD 的纵切批次、当前依赖和正式完成口径讲清楚。

---

## 1. 批次原则

正式版核心纵切的目标不是先用临时版本占位再返工，而是：

```text
按正式版去处理，只不过纵向处理，依次完整处理每个系统。
```

因此，本文只控制“哪个系统先做、哪个系统后做”，不降低被选中系统的完成标准。

每份 GDD 被分为四类：

| 批次类型 | 含义 |
|---|---|
| **当前主干** | A1-A4 必须进入可玩或可验收状态，否则正式版核心纵切不成立。 |
| **当前依赖** | 支撑当前主干的规则、数据或表现入口；若进入开发，同样按正式版口径处理。 |
| **后续批次** | 不在当前 A1-A4 主线中抢跑，但保留为正式版后续完整系统。 |
| **接口意识** | 当前只要求不堵死后续接入；不把占位内容当作系统完成。 |

旧 MVP 文档只作为历史验证材料。若旧 MVP 文档、`09` 路线和当前 GDD 出现冲突，按以下顺序判定：

```text
当前 GDD 具体规则 > 09 / 11 阶段路线 > 旧 MVP 归档文档
```

## 2.1 功能开发优先级映射

本表用于回答“下一步程序 / 配置 / UI 应先开发什么功能”，不用于安排内容量生产。

| 功能优先级 | 覆盖 GDD | 近期开发重点 | 暂不纳入 |
|---|---|---|---|
| P0 配置 / Validator / 验收底座 | `GDD_00`、`GDD_01`、`GDD_02`、`GDD_06` | Items、Monsters、Dungeons、Rewards、VisualID、地图 seed、怪物意图、内容包引用和自动化验收门禁。 | 新层内容铺量。 |
| P1 背包战斗主干 | `GDD_01`、`GDD_06`、`GDD_09` | 旋转放置、拾取、战利品 Inbox、物品生命周期、怪物意图、对包干涉、战败 / 撤离 / 出售。 | 大量装备流派、复杂 Boss 行为库。 |
| P2 深渊地图与搜打撤 | `GDD_02` | 节点网络、路线主题、层级入口、已通层直达、安全区、撤离 / 继续深入、失败结算。 | 第四层以后内容包和特殊层规则。 |
| P3 局外成长 | `GDD_08`、`GDD_03`、`GDD_12` | 底盘、义体、配方、材料缺口、维护、下潜许可和基础交互反馈。 | 大量情感文本、完整好感剧情。 |
| P4 经济与目标导向 | `GDD_04`、`GDD_07`、`GDD_10` | 售卖、维护支出、账单、材料目标、轻量订单或等价压力链。 | 完整势力线、完整商店生态。 |
| P5 表现支撑 | 当前 P1-P4 涉及 GDD | Formal V1 UI、关键 VisualID、截图验收和玩家可读反馈。 | 与当前功能无关的横向界面铺量。 |

功能优先级高于内容包层数优先级。也就是说，先把前三层主干和系统能力做可配置、可验证、可表达，再扩第四层及以后。

## 3. 按纵切节点拆分

### A1：核心边界收口

本阶段主要不是新增 GDD 功能，而是为后续 GDD 功能接入收边界。

| 必读 GDD | 用途 |
|---|---|
| `GDD_00` | 确认系统关系，不让程序重构改变设计归属。 |
| `GDD_01` / `GDD_06` | 确认背包、物品和 UI 交互真实状态归属。 |
| `GDD_04` / `GDD_08` | 确认出售、制造和成长资源流向不被 UI 临时逻辑截断。 |

出口要求：

*   背包、物品、战斗、流程、UI 的责任边界清晰。
*   不为了 UI 或美术接入改写玩法事实来源。
*   A2 所需的规则入口已经能对应到 GDD 和配置。

### A2：背包与战斗正式纵切

主覆盖：

*   `GDD_01`
*   `GDD_06`
*   `GDD_09` 的标签接口

策划验收重点：

*   旋转放入、拾取、丢弃、撤离、战败、出售、制造消耗的生命周期一致。
*   玩家能读懂每次战斗收益、损失、异常状态和失败原因。
*   典型怪物行为能体现“对人攻击 + 对包干涉”的核心差异。

### A3：深渊与局外成长纵切

主覆盖：

*   `GDD_02`
*   `GDD_08`
*   `GDD_03` 的人偶核心状态反馈与 `GDD_12` 的交互入口

策划验收重点：

*   玩家知道当前从哪一层出发、为什么继续深入、何时撤离。
*   回到局外后能看懂自己可以升级什么、缺什么、升级后下次会怎样变强。
*   安全区、撤离、战败、层级入口和局外成长形成稳定节奏。

### A4：经济压力与候选版本

主覆盖：

*   `GDD_04`
*   `GDD_07`
*   `GDD_10` 的势力订单目标入口
*   `GDD_05` 的事件接口意识

策划验收重点：

*   玩家开始面对“今天做什么”的局外决策。
*   至少一条经济压力链能驱动玩家继续下深渊。
*   经济压力不压垮早期体验，但能推动中期取舍。

## 4. 明确后续批次

以下内容不应在 A1 / A2 中抢跑。它们不是降标准处理，而是尚未进入对应纵切批次：

*   完整好感双轨与大量人偶互动内容。
*   完整剧情章节、剧本调度和世界事件。
*   大量势力剧情、订单池内容量和势力商店内容量。
*   人偶房间的内容量、家具池、美术资源和长期视觉叙事系统。
*   大量怪物、大量装备、大量义体、大量层级。

这些内容不是被废弃，而是等进入对应系统批次后按正式版口径完整处理。当前如果提前铺开，会稀释背包战斗、物品生命周期、深渊节奏和局外成长这四条主线。

---

## 5. 后续维护规则

当某个 GDD 的功能被拉入当前纵切节点时，必须同步补齐：

1.  所属纵切节点。
2.  当前批次职责。
3.  后续批次说明。
4.  配置影响。
5.  程序边界。
6.  UI / 美术表达需求。
7.  验收方式。

如果只是“有一天会做”，不要写入当前批次职责；但一旦进入批次，就按正式版标准补齐规则、配置、实现边界、表现需求和验收方式。

同时同步 `版本规划/12_版本规划需求文档承接审计.md`，确认该批次职责能追到详细需求文档；如果只能写成一句功能项，先补 GDD、规则卡、承接清单、配置 README、开发文档或美术规格，再进入当前批次。
