# T0-01A 开局人偶状态到首次下潜许可开发方案

本文是三层文档关系中的第三层 `开发方案`。上游设计只看 [T0-01A 开局人偶状态到首次下潜许可实现设计](T0-01A_开局人偶状态到首次下潜许可实现设计.md)，完整 T0 的开发拆分和边界看 [T0-01 序章首次循环开发总方案](T0-01_序章首次循环开发总方案.md)。本文不改体验方向，只把 A 段拆成可执行工作。

2026-07-11 文档重构后，本文只代表完整 T0 的 `A 段开发方案`。第一层浅缘短遭遇、首件带回物、回城照看、抵债 / 维护 / 记忆反馈和下一轮目标，不再追加进本文；这些内容应进入后续 `T0-01B / T0-01C` 的 Owner 具体设计和开发方案。

2026-07-11 封板候选轮不再重做已完成的 `NARR-00..04` 和 `T0-FLOW-01..05`。现有证据已说明全局叙事底座、T0-01A 内容源、手动推进、半开放工坊、首潜许可和进入第一层的主链存在。本轮只处理“从条件通过纵切到正式 A 段封板候选”的差距，对齐 Owner 设计中的 `T0-PRE-01..11`。

本轮开发只做到：

```text
黑屏醒来
  -> 工坊过程 CG
  -> 发现零号
  -> 启动人偶
  -> 零号苏醒
  -> 状态小卡
  -> 擦去核心仓灰尘
  -> 浅层入口
  -> 第一层确认
  -> 出发进入第一层
```

不做第一层内战斗、首次战利品、背包取舍、回城出售、维护闭环和下一轮目标。

本方案必须把 [全局叙事播放系统开发方案](../../开发文档/18_全局叙事播放系统开发方案.md) 作为正式开发项承接。T0-01A 是全局叙事播放系统的第一批纵切验证，不再写一个只服务序章的一次性对白 / 过场控制器。序章中的黑屏对白、过程 CG、启动人偶、苏醒对白、状态小卡、擦灰反馈、浅层入口解锁和首潜确认前对白，都应通过全局叙事播放系统的节点、触发、对白层和命令桥接完成。

## 1. 开发落地总线

开发按玩家看到的顺序推进，不按职能先后横切。每一段都要同时确认策划文案、美术 / UI 表现、程序接入和验证方式。

```text
P0 事实审计（设计阶段已完成）
  -> NARR 全局叙事播放最小底座
  -> P1 黑屏醒来
  -> P2 工坊过程 CG
  -> P3 发现零号
  -> P4 启动人偶
  -> P5 零号苏醒
  -> P6 状态小卡与擦灰
  -> P7 浅层入口
  -> P8 第一层确认
  -> P9 出发进入第一层
  -> P10 联调与证据回写
```

程序侧优先复用现有链路：

- `WorkshopUIController`：承载工坊入口、半开放工坊和浅层入口。
- `DungeonStartLayerUIController`：承载第一层出发确认。
- `DiveReadinessService.Evaluate(player, 1, false)`：只读下潜许可和阻断原因。
- `DungeonManager.StartRunAtLayer(1)`：点击 `出发` 后进入第一层的唯一领域入口。

新增代码如果需要，优先是全局叙事播放系统下的薄适配器，而不是独立序章大控制器。`PrologueFirstDiveController` 只能作为 T0-01A 的流程上下文适配层：发布叙事事件、切换半开放工坊、调用已有 UI 入口和领域服务；对白、过场播放、选项 / 点击继续、表现命令、输入锁和叙事旗标写入由 `NarrativeTriggerService`、`NarrativeScheduler`、`NarrativePlaybackService`、`P3DialogueOverlayController`、`NarrativeCommandBridge` 和 `NarrativeStateStore` 承接。它不写下潜规则、不直接改 HP / SAN / 金币 / 背包。

### 1.1 全局叙事播放系统在本切片中的范围

T0-01A 只承接 `18` 文档中对序章必需的最小范围：

| 项 | 本切片需要做到 | 本切片不做 |
|---|---|---|
| Yarn Spinner spike | 明确候选版本、导入方式、许可证记录和最小节点播放证据；如果 spike 受限，记录 `validation_limited:*`。 | 不把完整 VN 引擎接管 UI、输入、存档或主流程。 |
| 叙事触发服务 | 支持 T0-01A 所需事件：新档开始、发现零号、启动人偶、苏醒完成、擦灰完成、浅层入口点击、首潜确认。 | 不覆盖日程循环、人偶日常闲聊、战斗 bark、休息区和 Boss 全量触发。 |
| 播放调度 | 支持 `modal` 主线过场、`modal_light` 轻状态反馈、输入锁、点击继续和播放完成回调。 | 不做复杂队列压力测试，不做多段并发对白。 |
| UGUI 对白层 | 以纯 UGUI 展示对白框、姓名、短选项 / 单按钮、CG / 立绘 / VFX 命令结果。 | 不使用第三方默认 UI，不引入 UI Toolkit 运行时路径。 |
| 命令桥接 | 只允许展示 / 隐藏序章 UI、启动人偶表现、打开状态小卡、开放擦灰动作、开放浅层入口、写入叙事旗标、打开首潜确认。 | 不允许 Yarn 命令直接扣金币、改背包、改 HP / SAN、生成掉落或开始战斗结算。 |
| 内容配置 | 落地 T0-01A 的 Yarn 节点、节点清单、触发清单、说话人和必要 VisualID / fallback 引用。 | 不填日程、人偶日常、副本 Boss 等后续内容池。 |

本切片完成后，后续日程、人偶互动、副本进层、休息区和 Boss 对白继续扩展同一套系统；不能再为这些场景分别追加孤立对白播放器。

### 2.2 可复用主链路

设计阶段确认后续实现应沿用以下真实链路：

```text
WorkshopUIController
  -> DungeonStartLayerUIController
  -> DiveReadinessService.Evaluate(player, 1, false)
```

这条链路能承接“玩家从半开放工坊点击浅层入口、看到第一层确认、许可通过后进入第一层”的真实领域路径。T0-01A 后续开发重点不再是证明这条链路存在，而是把序章叙事播放、输入锁、半开放 UI 状态、首潜确认上下文和玩家可读阻断文案接到这条链路上。

## 3. P1 黑屏醒来

玩家看到黑屏、环境音、第一句字幕，然后自动淡入工坊。

### 策划 / 文案

- 文案 key 建议：
  - `prologue.t0_01a.black_wake.line_01 = 主角：又到早上了。`
- 不配置点击继续，不配置跳过按钮。

### 美术 / UI

- 黑屏层、字幕层、轻环境音。
- 不出现 HUD、金币、背包、工坊按钮或教程框。

### 程序

- 序章控制器进入 `BlackWake` 状态。
- 播放字幕后自动切到工坊 CG，不等待玩家输入。
- 写入轻量旗标：`PrologueStarted=true`。

### 验证

- 新档进入后，第一个可点击对象为空。
- 画面自动进入下一段，不停在黑屏。

## 4. P2 工坊过程 CG

玩家只看镜头带过债务纸、工匠手记、工具匣。这里仍然没有交互。

### 策划 / 文案

- 固定三段信息：
  - 债务压力：工坊封存预告。
  - 浅层修复线索：浅层晶核可暂时稳定魔偶核心。
  - 最后一枚核心碎片：卖掉够一天，用掉也许够她醒一次。
- 每段对白只按上游设计播放，不扩成长背景解释。

### 美术 / UI

- 优先用 UGUI 分层实现轻 CG：
  - 工坊背景。
  - 纸张特写面板。
  - 手记特写面板。
  - 工具匣特写面板。
  - 轻暗角 / 聚焦遮罩。
- 不要求首版制作完整视频。

### 程序

- 序章控制器按顺序播放 `DebtNotice -> RepairNote -> CoreShard`。
- 只开放自动推进，不注册点击调查物。
- 完成后写入：
  - `DebtNoticeSeen=true`
  - `RepairNoteSeen=true`
  - `LastCoreShardSeen=true`

### 验证

- 播放期间不出现可点击调查物高亮。
- 跳到下一段时三段旗标已写入。

## 5. P3 发现零号

镜头回到工作台，主角掀开防尘布，零号完整露出。

### 策划 / 文案

- 播放两句：
  - `主角：没有第二台了。`
  - `主角：也没有第二个早上。`
- 不出现人偶选择列表，不出现二次确认。

### 美术 / UI

- 画面重点落在零号脸部和核心仓之间。
- 可用 `doll_proto_0_stand` 叠加遮布 / 暗角 / 核心微光。
- 如果没有遮布 overlay，首版可用淡入和遮罩模拟掀布。

### 程序

- 序章控制器进入 `No0Found` 状态。
- 完成后写入 `No0Found=true`。
- 停在零号画面，准备显示唯一按钮。

### 验证

- 发现零号前仍无玩家输入。
- 发现零号后只出现 `启动人偶`。

## 6. P4 启动人偶

这是开场第一个玩家输入。按钮只有一个：`启动人偶`。

### 策划 / 文案

- 按钮文案：`启动人偶`。
- 按钮含义同时覆盖救起零号、使用最后一枚核心碎片、完成核心接入。
- 不做“确认使用核心碎片”二次弹窗。

### 美术 / UI

- 单按钮使用主按钮样式。
- 画面不显示背包、属性面板、人偶池、角色选择。
- 点击反馈为核心灯从暗红转微弱冷白，工坊灯短亮后压暗。

### 程序

- 点击后写入：
  - `No0Started=true`
- 切换到核心启动演出。
- 禁用按钮重复点击。
- 不在 UI Controller 中直接改长期人偶养成数据；如需记录序章进度，放入序章状态或存档旗标。

### 验证

- smoke 断言：新档第一个可交互按钮文本为 `启动人偶`。
- 连点不会重复触发状态写入或重复播放苏醒段。

## 7. P5 零号苏醒

启动后播放零号苏醒对白，不弹教程。

### 策划 / 文案

- 使用上游设计的苏醒对白。
- 节奏要求：
  - 零号句子之间有短停顿。
  - “你也会。等你没钱的时候。”后保留停顿。
  - 不插入地下城说明或属性教程。

### 美术 / UI

- 仍以零号为画面主体。
- 可用轻微核心光、待机变化或字幕节奏表达苏醒。
- 不打开完整角色面板。

### 程序

- 序章控制器播放 `No0WakeDialogue`。
- 完成后写入 `No0WakeDialogueSeen=true`。
- 自动进入状态小卡段。

### 验证

- 苏醒对白期间没有教程弹窗。
- 结束后进入状态小卡，不进入完整工坊按钮网格。

## 8. P6 状态小卡与擦灰

零号苏醒后出现小型状态卡，并开放一次整理动作 `擦去核心仓灰尘`。

### 策划 / 文案

- 初始状态：
  - `核心：不稳定`
  - `身体：多处裂纹`
  - `意识：断续`
  - `判断：无法长时间行动`
- 整理按钮：`擦去核心仓灰尘`
- 整理后状态：
  - `核心：短时稳定`
  - `判断：可进行一次浅层下潜，返回后需要照看`
- 短对白：
  - `零号：你手在抖。`
  - `主角：灰太多。`
  - `零号：你说谎的声音……很明显。`

### 美术 / UI

- 状态小卡是轻面板，不是完整维护界面。
- `擦去核心仓灰尘` 是状态卡下方唯一动作。
- 不显示义体、底盘、完整维护树、背包深操作。

### 程序

- 显示状态小卡。
- 点击擦灰后写入：
  - `FirstStatusShown=true`
  - `FirstCoreWiped=true`
- 刷新小卡文案。
- 不调用完整维护服务来伪造一次维护；这是序章整理动作，只改变序章许可叙事和轻状态。

### 验证

- 点击 `启动人偶` 后出现状态小卡。
- 点击擦灰前浅层入口不可点。
- 点击擦灰后状态卡刷新。

## 9. P7 浅层入口

擦灰后，债务钟声和下潜理由对白把深渊暗门变成主行动。

### 策划 / 文案

- 播放下潜理由：
  - `主角：浅层有稳定材料。`
  - `主角：带回来，能让你撑过今晚，也能让他们暂时闭嘴。`
  - `零号：如果带不回来？`
  - `主角：那就先带你回来。`
- 主行动：
  - 标题：`浅层入口`
  - 副文案：`她还能撑一次。`
- 灰态反馈：`现在先让她撑过这一次。`

### 美术 / UI

- 工坊进入半开放状态：
  - 零号仍是主体。
  - 状态摘要收起。
  - 右后方暗门或入口成为主行动。
  - 角落显示 `今晚前` 压力提示。
- 出售、完整维护、义体、底盘、订单、传闻、势力都不开放或灰态。

### 程序

- 写入 `FirstDiveUnlocked=true`。
- 工坊 UI 进入 `PrologueHalfOpen` 或等效状态。
- 点击 `浅层入口` 后打开第一层确认，不直接调用 `StartRunAtLayer(1)`。

### 验证

- 半开放工坊没有回退成 FormalV2 完整按钮网格。
- `浅层入口` 点击后进入第一层确认。

## 10. P8 第一层确认

第一次出发必须有确认感，不直接进战斗。

### 策划 / 文案

- 标题：`第一层：旧矿井浅缘`
- 状态：`状态：可抵达`
- 可能带回：
  - `稳定核心碎屑`
  - `可售废料`
  - `记忆噪声`
- 同行状态：`零号可行动一次，返回后需要照看。`
- 按钮：
  - `出发`
  - `再看她一眼`

### 美术 / UI

- 复用 `layer_select` / 第一层确认面板，但进入首潜确认态。
- 只展示第一层，不展示多层列表、扫荡、自动编队。
- `再看她一眼` 返回半开放工坊。

### 程序

- `DungeonStartLayerUIController` 支持首潜确认上下文。
- 默认 layerID 固定为 `1`。
- 摘要来自 `DiveReadinessService.Evaluate(player, 1, false)`。
- 通过态显示 `出发` 可点击；阻断态禁用并显示玩家可读原因。

### 验证

- 点击 `浅层入口` 后默认层为 1。
- `再看她一眼` 返回工坊，并播放 `零号：我还在。`
- 阻断原因不显示内部 issue code。

## 11. P9 出发进入第一层

玩家点击 `出发` 后，播放三句短对白，然后进入第一层。

### 策划 / 文案

- 出发对白：
  - `零号：下面比这里安静。`
  - `主角：那不是好事。`
  - `零号：我知道。`

### 美术 / UI

- 切黑 1 秒。
- 工坊滴水声消失，切换深渊风声。
- 不在这一刻弹结算、教学或战斗说明。

### 程序

- 点击 `出发` 调用 `DungeonManager.StartRunAtLayer(1)`。
- 成功后进入第一层。
- 失败时停留确认界面，显示 `DiveReadinessService` 的玩家文案。
- 不允许 UI fallback 到 debug 战斗或假成功。

### 验证

- smoke 断言 `StartRunAtLayer(1)` 被真实调用并成功进入第一层。
- 失败路径显示玩家文案，不显示内部 code。

完成后只能标记为 `T0-01A 开发方案落地完成` 或 `实现完成`，不能标记整个 T0 序章完成。若 `18` 的全局叙事播放最小底座、T0-01A Yarn / trigger / node 配置、UGUI 对白层或命令桥没有完成并有验证证据，即使序章画面能临时跑通，也只能标记为 `临时演示` 或 `validation_limited:narrative_system_missing`。第一层遭遇、战利品、背包和回城照看由后续切片承接。
