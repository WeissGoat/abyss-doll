### 1.1 不再使用的口径

- 不再把 `T0-VAL-01` 当作完整 T0 验收文档。
- 不再把 `进入第一层地图` 当作 T0 完成。
- 不再把 `T0-01A` 扩展成完整序章后半段。
- 不再用 `semantic_failed=False` 单独证明商业化序章成立。
- 不再新建孤立的“截图优化”“UI 小修”“临时演出”文档；这些内容必须归入 A/B/C 开发方案或对应验收记录。

## 2. 完整玩家结果

T0-01 完成后，玩家从新档进入游戏应经历：

```text
黑屏醒来
  -> 破败工坊与债务压力
  -> 手记 / 核心碎片 / 防尘布下的零号
  -> 唯一仪式交互：启动零号
  -> 零号苏醒与第一次照看
  -> 首潜许可
  -> 第一层浅缘短遭遇
  -> 带回第一件东西
  -> 回城照看 / 抵债 / 记忆反馈
  -> 获得下一轮下潜理由
```

完整 T0 的完成句是：

```text
玩家亲手启动零号，陪她完成第一次浅层行动，看见深渊带回结果也造成消耗，回到工坊后通过照看、抵债或记忆反馈获得下一轮目标。
```

任何只做到 `出发进入第一层` 的版本，只能标记为 `T0-01A` 范围完成或条件通过。

## 3. 开发批次

### 3.1 T0-PRE：商业化基线

T0-PRE 不是一个可玩切片，也不是继续给 `T0-VAL-01` 找补丁。它是在 A/B/C 正式继续开发前先锁定完整 T0 的“目标样片”：后续每个 Owner 具体设计、开发方案、美术任务、程序接入和验收截图都按这里的画面序列对齐。

T0-PRE 的完成句是：

```text
团队已经知道完整 T0 应该被玩家看成哪 16 张关键画面，知道每张画面为什么存在、画面主体是什么、玩家能点什么、不能出现什么临时 UI，以及它归属 A/B/C 哪个开发切片。
```

#### 3.1.1 T0-PRE 交付物

| 交付物 | 内容 | 用途 |
|---|---|---|
| 16 张目标截图序列 | 覆盖开场、启动零号、半开放工坊、首潜许可、浅缘短遭遇、带回物、回城照看和下一轮目标。 | 后续 T0-VAL-02 完整验收的画面基线。 |
| 每张截图的画面规格 | 主视觉、读图顺序、允许 UI、禁止 UI、首要失败信号。 | 给美术 / UI / 程序判断“是不是正式画面”。 |
| 文案节奏锁定 | 每张图最多承担 1 个情绪点或 1 个行动点；每屏 1-2 句对白。 | 防止把序章做成说明书或系统教程。 |
| A/B/C 归属表 | 每张图归入 `T0-01A`、`T0-01B` 或 `T0-01C`。 | 防止继续把完整 T0 塞回 A 段。 |
| 验收模板 | Owner 自验 + subagent 复验，均包含 `问题 / 建议 / 结论`。 | 后续每段验收沿用同一口径。 |

T0-PRE 不交付：

- Unity 代码。
- Narrative 配置源。
- 新 Approved 素材。
- 运行时截图。
- T0-VAL-02 正式验收结论。

#### 3.1.2 完整 T0 目标截图序列

| `T0-PRE-07` | A | 零号苏醒 | 零号半身或近全身，脸和核心仓不被遮挡。 | 正式对白框，手动推进。 | 旧测试感 LOG/AUTO 皮肤、滚动长文本。 | 玩家感到她是角色，不是教程助手。 |
| `T0-PRE-08` | A | 状态小卡与擦灰前 | 零号旁出现轻状态卡，按钮为 `擦去核心仓灰尘`。 | 状态小卡、单一整理按钮。 | 完整维护树、义体、底盘、属性大表。 | 玩家理解她现在只能撑一次。 |
| `T0-PRE-09` | A | 擦灰后短时稳定 | 核心仓灰尘淡出，状态从不稳定变为短时稳定。 | 刷新后状态小卡、1 句短反馈。 | 大结算、奖励、系统解锁弹窗。 | 玩家看到照看动作改变了她。 |

| `T0-PRE-12` | B | 浅层入口转场 | 工坊暗门冷光、黑场、深渊风声接入。 | 可无 UI。 | 直接硬切地图、加载 debug 文本。 | 玩家感知从工坊进入深渊。 |
| `T0-PRE-13` | B | 旧矿井浅缘第一镜 | 菌光、湿石阶、旧轨道、低矮晶簇和远处浅层门。 | 极简行动提示。 | 完整地图节点网、Boss、密集 HUD。 | 第一层有地底奇幻气质，不是灰色测试场。 |
| `T0-PRE-14` | B | 第一次短遭遇结果 | 零号完成一次低风险行动，画面同时读到轻消耗和可拾取结果。 | 1-2 个行动按钮或结果提示。 | 完整战斗教学长面板、复杂背包教程。 | 玩家知道“下去会带回东西，也会消耗她”。 |
| `T0-PRE-15` | B/C | 第一件带回物 | 稳定核心碎屑 / 可售废料 / 记忆噪声片作为视觉焦点。 | 轻取舍或带回槽。 | 金币 +1 式纯结算、掉落列表刷屏。 | 物品能指向维护、抵债或记忆。 |
| `T0-PRE-16` | C | 回城照看与下一轮目标 | 零号回到工坊，状态变化、带回物和催缴压力同屏。 | 三行复盘、`先照看她` / `先看催缴纸`、下一轮短目标。 | 通用结算页、任务列表、完整经济系统。 | T0 闭合为“回来照看 -> 还要再下去”。 |

#### 3.1.3 读图顺序

完整 T0 的 16 张图应按以下节奏阅读：

```text
处境压迫
  -> 最后资源
  -> 她出现
  -> 玩家启动她
  -> 她醒来并需要照看
  -> 只开放一次浅层行动
  -> 下去带回东西并付出代价
  -> 回来把结果转成照看 / 抵债 / 记忆
  -> 下一轮理由成立
```

如果某张图需要用 UI 说明玩家才知道发生了什么，这张图不合格。UI 可以辅助确认状态，但不能替代镜头、构图和角色状态。

#### 3.1.4 对白与 UI 统一口径

| 项 | T0-PRE 口径 |
|---|---|
| 对白推进 | 默认手动点击推进；自动播放不作为默认态。 |
| 对白框 | 正式皮肤，低信息密度；不能保留旧测试感 `AUTO / LOG` 皮肤。 |
| 字幕 | 黑屏和过程 CG 可使用轻字幕，不必每屏都开完整对白框。 |
| 句长 | 单句不超过 22 个中文字，超过时拆句。 |
| 每屏对白量 | 1-2 句为主，情绪停顿优先于解释世界观。 |
| 行动按钮 | T0 前半段只允许 `启动人偶`、`擦去核心仓灰尘`、`浅层入口`、`出发` 这类当下动作。 |
| 禁止文案 | “恭喜解锁”“当前任务 0/3”“点击此处打开系统”等教程腔。 |

#### 3.1.5 美术 / UI 门禁

T0-PRE 采用当前全局方向：日系二次元地底奇幻冒险 + 低信息密度。以下画面一律不能作为商业化基线通过：

- 背景 + 通用对白框 + 长滚动文本。
- 小道具卡片替代债务纸、手记、核心碎片特写。
- 黄铜 / 棕金 / 暖灯 / 蒸汽朋克成为主视觉。
- 黑边大底板、青色矩形调试牌、厚金边旧 RPG 框。
- 零号被裁脸、核心仓被遮挡、角色和 UI 抢视觉中心。
- 半开放工坊出现完整功能按钮墙。
- 首潜许可回退成多层列表或通用面板。
- 回城直接跳通用结算页，不回到零号身边。

T0-PRE 允许的第一版制作策略：

- A 段可继续使用运行时漫画页 / 过程 CG。
- B 段浅缘可先用正式背景 + 轻事件 / 短战斗承接，但必须是真实可玩的深渊行动。
- C 段回城可先用 FormalV2 工坊骨架 + 零号状态变化 + 结果三行结构承接。

#### 3.1.6 A/B/C 归属与后续承接

| 切片 | 承接截图 | 必须补出的具体设计 |
|---|---|---|
| `T0-01A` | `T0-PRE-01` 到 `T0-PRE-11` | 将现有条件通过纵切提升到 A 段封板候选：漫画页排版、对白皮肤、启动仪式、半开放工坊、首潜许可卡。 |
| `T0-01B` | `T0-PRE-12` 到 `T0-PRE-15` | 新增浅层入口转场、旧矿井浅缘、第一次短遭遇、首件带回物与轻消耗。 |
| `T0-01C` | `T0-PRE-16` | 新增回城照看、抵债 / 照看轻选择、零号反馈和 T1 下一轮目标。 |
| `T0-VAL-02` | 全部 16 张 | A/B/C 都可跑后，按完整截图序列做 Owner 自验、subagent 复验和用户人工复验。 |

#### 3.1.7 T0-PRE 验收

T0-PRE 只验文档与设计完整性，不验运行时。

文档验收：

- `Generate-DocsIndex` 通过。
- `Validate-Docs` 通过。
- 本文的 T0-PRE 已能独立说明 16 张目标画面，不依赖聊天记录。

设计验收：

- 16 张图覆盖 `启动她 -> 下去一次 -> 带回 / 消耗 -> 回来照看 -> 下一轮理由`。
- 每张图都有主视觉、允许 UI、禁止 UI和首要通过标准。
- A/B/C 归属清楚，不再把 B/C 内容塞回 `T0-01A`。
- 验收口径明确区分 `运行时纵切条件通过`、`A 段封板候选` 和 `完整 T0 商业化通过`。

T0-PRE 通过后，下一步不再继续争论“现在截图是不是像正式版”，而是按本节逐段补：

```text
T0-01A 封板候选
  -> T0-01B Owner 具体设计
  -> T0-01B 开发方案
  -> T0-01C Owner 具体设计
  -> T0-01C 开发方案
  -> T0-VAL-02 完整 T0 验收
```

### 3.2 T0-01A：开场到首次下潜许可封板

范围：

- 黑屏醒来。
- 工坊过程 CG / 漫画页。
- 债务、手记、核心碎片。
- 发现零号。
- `启动零号` 独立仪式交互。
- 零号苏醒。
- 状态小卡。
- 擦灰整理。
- 半开放工坊。
- 第一层首潜许可。
- 出发进入第一层。

必须补强：

| 方向 | 要求 |
|---|---|
| 美术 / UI | 运行时漫画页达到 `美术文档/19_T0-01序章CG细案.md` 的 6 张截图验收；半开放工坊使用 FormalV2 设计语言；许可卡有独立仪式感。 |
| 策划 / 文案 | 每屏 1-2 句，保留留白；动作文案锁定 `启动零号`、`擦去核心仓灰尘`、`浅层入口`、`出发`。 |
| 程序 | 继续走全局叙事播放系统、UGUI、真实 `DiveReadinessService` 和 `DungeonManager.StartRunAtLayer(1)`。 |
| 验证 | `T0-VAL-01` 升级为 A 段封板候选验收记录，但不能声明完整 T0。 |

完成口径：

```text
T0-01A 封板候选通过：玩家能看到正式序章前半段，并真实进入第一层。
```

不可声明：

```text
完整 T0 序章完成。
```

### 3.3 T0-01B：第一层浅缘短遭遇到带回第一件东西

目标：补上第一次真实深渊行动，让玩家理解“下去会带回东西，也会消耗她”。

范围：

- 固定浅缘场景。
- 一次低风险短遭遇，可以是 `战斗 + 事件` 混合。
- 零号状态轻消耗。
- 首件带回物：稳定核心碎屑 / 可售废料 / 记忆噪声片。
- 轻背包或临时带回槽。
- 返回前的短提示。

设计要求：

| 项 | 要求 |
|---|---|
| 场景 | 旧矿井浅缘，菌光、湿石阶、晶簇、旧轨道和远处呼吸般亮灭的浅层门。 |
| 遭遇 | 2-4 分钟完成，不展开完整第一层节点网络和 Boss。 |
| 操作 | 只开放必要行动，不把完整战斗、背包、撤离教学一次性塞满。 |
| 状态 | 至少有一处零号状态变化，如核心稳定下降、轻磨损或记忆噪声。 |
| 带回 | 第一件东西必须暗示用途：维护、抵债或记忆。 |

需要新增：

- `T0-01B_第一层浅缘短遭遇到带回第一件东西实现设计.md`
- `T0-01B_第一层浅缘短遭遇到带回第一件东西开发方案.md`

完成口径：

```text
玩家完成第一次短遭遇，带回一个有明确用途暗示的结果，并看见零号付出轻代价。
```

### 3.4 T0-01C：回城照看到下一轮目标

目标：补上 T0 最关键的闭环，让玩家回到工坊后愿意继续下一轮。

范围：

- 回到工坊，不直接进入通用结算表。
- 展示带回物、零号消耗、债务压力。
- 轻选择：`先照看她` / `先看催缴纸`。
- 根据带回物触发维护、抵债或记忆反馈。
- 给出 T1 动机：第一层更深处有更稳定、更值钱或更接近零号记忆的东西。

设计要求：

| 项 | 要求 |
|---|---|
| 回城画面 | 零号回到工作台或床边，核心状态与下潜前不同。 |
| 结果表达 | 三行结构：`带回`、`消耗`、`可处理`。 |
| 轻选择 | 选择影响短反馈和下一轮目标措辞，不提前开放完整经济和维护系统。 |
| 情绪回声 | 零号不做教程助手，要像刚从下面回来的人。 |
| 下一轮目标 | 必须自然指向 T1 的第一层搜打撤，而不是弹出任务列表。 |

需要新增：

- `T0-01C_回城照看到下一轮目标实现设计.md`
- `T0-01C_回城照看到下一轮目标开发方案.md`

完成口径：

```text
玩家看见第一次下潜结果被转化为照看、抵债或记忆反馈，并获得再次进入第一层的理由。
```

### 3.5 T0-VAL：完整 T0 验收

目标：A/B/C 都可跑后，再验完整序章首次循环。

建议新增：

- `T0-VAL-02_完整序章首次循环验收文档.md`

验收路径：

```text
Owner 自验
  -> 问题 / 建议 / 结论
subagent 复验
  -> 问题 / 建议 / 结论
用户人工复验
  -> 商业化序章是否成立
```

完成口径：

| 结论 | 使用条件 |
|---|---|
| `通过` | A/B/C 全部主路径跑通，截图、自动断言和人工体验无 P0 / P1。 |
| `受限通过` | 主路径成立，但存在明确 `validation_limited:*`，且不影响当前玩家路径判断。 |
| `不通过` | 任一关键段缺失、画面仍像 staging、无回城闭环、或用户人工否决。 |

### 4.3 程序 / Unity

- 继续使用纯 UGUI。
- 叙事播放走全局叙事播放系统，不为 B/C 新增孤立播放器。
