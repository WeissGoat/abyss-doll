# T0-01 序章首次循环

## 1. 时长定位

本文是 `0-30 分钟` 的游戏设计细案，承接 `13` 第 12 节“捡回坏掉的人偶，完成第一次完整循环”。

T0-01 在三层文档关系中属于第一层 `细案`：它只负责描述 0-30 分钟序章首次循环的玩家体验、剧情推进、系统自然开放和段末钩子。它不承担 Owner 具体设计，也不拆开发方案。后续承接顺序固定为：

```text
T0-01_序章首次循环.md
  -> T0-01A_开局人偶状态到首次下潜许可实现设计.md
  -> T0-01A_开局人偶状态到首次下潜许可开发方案.md
```

其中 `T0-01A_开局人偶状态到首次下潜许可实现设计.md` 是 Owner 具体设计；`T0-01A_开局人偶状态到首次下潜许可开发方案.md` 用来拆策划、美术 / UI、程序、配置 / 文案、联调和验证工作。

它不是旧 `T0-01 / T0-02 / T0-03` 的功能步骤合并清单，也不是实现 Owner 的验收表。本文只先回答这一段游戏应该怎么玩：

```text
玩家第一次理解：
我为什么要照看她。
我为什么要把她送进深渊。
深渊会带回东西，也会带走东西。
回到小镇以后，下一次下潜的理由反而更明确。
```

序章的任务不是把所有系统讲清楚，而是让玩家在第一次循环后产生继续的意愿。

本段演出组织参考 `设计文档/参考/01_This_Is_the_Police_演出参考.md`：先用短剧情段和环境压力把玩家拉进处境，再让工坊交互、下潜许可和第一次短循环自然打开。

## 2. 核心设计命题

0-30 分钟要建立三层关系。

第一层是玩家和人偶的关系：她不是普通出战单位，而是坏掉但仍想行动的对象。玩家不是抽象指挥官，而是照看者、冒险合伙人和压力承担者。

第二层是玩家和深渊的关系：深渊不是奖励按钮，也不是线性教程关。它一开始可以很短、很浅、很安全，但必须让玩家知道每一次进入都会留下结果。

第三层是玩家和小镇的关系：小镇不是菜单大厅，而是把深渊结果翻译成钱、修复、状态、日程和下一轮目标的地方。

本段设计的核心句是：

```text
她还能下去一次，但这一次回来以后，你会更清楚自己欠了什么、缺了什么、还想带她去哪里。
```

## 3. 玩家旅程

推荐的 0-30 分钟旅程分为六个连续片段。实现 Owner 可以调整顺序、镜头、文本和交互形式，但不应改变这些片段承担的体验功能。

### 3.1 看见人偶

开场应尽快让玩家看到“她”的状态，而不是先解释世界设定。

她可以被放在房间、工坊角落、小镇临时床铺或深渊入口附近。重点不是展示完整角色面板，而是通过立绘 / 表情 / 状态短句 / 缺损部位 / 呼吸或待机动作，让玩家知道：

- 她醒着，但不完整。
- 她能行动，但很勉强。
- 她的状态会影响接下来能不能下去。
- 玩家需要对她负责，而不是只使用她。

这一段可以带一句非常短的世界钩子，例如小镇账单、修复材料、深渊传闻或她自己的请求。不要在开场塞长篇背景说明。

更具体的开场演出顺序见 `设计文档/剧情/01_序章演出与对话节奏.md`。T0 这里锁定的是体验目标：玩家先进入处境，再进入系统。

### 3.2 给出第一次下潜理由

第一次下潜理由应简单、具体、带一点情绪。

可选方向：

- 需要一笔最低限度的修复钱。
- 需要浅层材料来稳定她的核心。
- 小镇只给了一个很差的临时住处，今天必须带回点东西。
- 她记得深渊浅层有某个能证明自己还“有用”的东西。

这一理由不需要展开完整订单、月租、势力或长期剧情。它只需要把“下潜”从按钮变成当下问题的解决路径。

### 3.3 第一次准备

准备阶段只开放最少选择。

玩家应能看到：

- 当前人偶状态。
- 当前可携带或可使用的极少量资源。
- 下潜入口。
- 一个能理解的风险提示。

这里的设计重点不是教完背包、日程、状态、出售、维护，而是让玩家第一次做出“让她下去”的决定。提示可以用人偶反馈、小镇旁白、入口状态或 UI 轻提示表达。

### 3.4 第一次浅层遭遇

第一次深渊不需要完整地图，但要像深渊。

推荐包装是第一层浅层的短入口：菌光裂隙、旧井下的潮湿石阶、坍塌矿道前厅、被根须包住的门廊，或其他符合日系二次元地底奇幻冒险的空间。避免把它做成纯按钮战斗或纯结算弹窗。

首次遭遇可以是：

- 一场极短战斗。
- 一个低风险事件。
- 战斗加拾取的混合节点。

这一段要让玩家第一次理解“行动会带来消耗”。消耗可以是 HP、SAN、磨损、临时状态、道具损耗或背包取舍，不需要全部出现。

### 3.5 带回第一件东西

第一件战利品最好有用途暗示，而不只是“卖钱物”。

它可以是浅层矿片、发光菌核、破损护符、旧金币、可修复材料或带有一点世界信息的小物。它的设计作用是连接深渊和小镇：

- 可以卖钱。
- 可以作为维护材料。
- 可以引出小镇对深渊物的态度。
- 可以让人偶产生一句反馈。

如果第一次没有带回物品，也必须是有设计意义的结果，例如背包放弃、战斗撤退、物品污染或人偶状态不稳，而不是空结算。

### 3.6 回城照看与下一轮理由

回城不是结算终点，而是第一次循环真正成立的地方。

回城后应出现一个短复盘：

- 她带回了什么。
- 她消耗了什么。
- 小镇愿意如何处理这些东西。
- 玩家下一步为什么不是停在这里。

出售、维护、休整可以用完整界面，也可以用更轻的复盘交互表达。关键是让玩家看到“深渊结果 -> 小镇转化 -> 人偶状态 -> 下一轮目标”的关系。

本段结束时，玩家应自然得到下一轮理由，例如：

- 钱还不够，但现在知道浅层可以带回东西。
- 她状态恢复了一点，可以尝试更远的节点。
- 她状态变差了，需要先找维护材料。
- 小镇有人提到第一层更深处有更值钱或更危险的东西。

## 4. 系统开放设计

| 系统 | 0-30 分钟出现方式 | 设计意图 |
|---|---|---|
| 小镇 | 作为临时落脚点、出售 / 维护发生地和压力来源。 | 让玩家知道回城会产生下一轮理由，而不是只开菜单。 |
| 人偶状态 | 用少量可读状态展示脆弱、可行动和需要照看。 | 建立情感责任与再次下潜判断。 |
| 日程 | 只露出“今天 / 初始日 / 刚回城”的轻状态。 | 让时间存在，但不提前压周月规则。 |
| 深渊 | 只开放第一层浅入口或等价序章遭遇。 | 让玩家第一次进入风险空间。 |
| 战斗 / 事件 | 一次短、低风险、真实结算的遭遇。 | 让玩家理解行动会改变状态。 |
| 背包 / 战利品 | 只展示携带、放弃或带回转化的最小关系。 | 把深渊物和小镇用途连起来。 |
| 出售 / 维护 | 只做第一次转化和照看压力。 | 让玩家知道钱和材料会回到人偶身上。 |
| 叙事反馈 | 用短句、状态变化、物品描述或人偶反应表达。 | 让世界和她都对第一次循环有反应。 |
| UI / 美术 | 低信息密度，优先呈现人偶、入口、结果和下一步行动。 | 避免序章变成系统教学面板。 |

## 5. 叙事与情绪节奏

序章情绪应是“安静的压力 + 小小的行动希望”，而不是热血出征或复杂经营开局。

建议节奏：

1. 先让玩家看到她的脆弱。
2. 再给一个很近、很具体的下潜理由。
3. 让第一次下潜短而可完成。
4. 用第一次战利品或消耗证明深渊不是空按钮。
5. 回城后让玩家照看她，而不是只结算收益。
6. 在玩家刚理解第一轮循环时，露出下一轮更清晰的目标。

文案不需要解释所有规则。序章更适合使用短反馈：

- “她还撑得住。”
- “这个能换一点钱，也可能先拿来修她。”
- “再往里走一点，会有更好的东西，也会更危险。”
- “今天还没结束。”

实际文案由后续剧情 / 文案 Owner 细化，本文只约束语气和功能。

## 6. UI / 美术方向

0-30 分钟的画面重点应放在人偶、小镇落脚点、第一层浅入口和回城结果。

视觉关键词：

- 日系二次元地底奇幻冒险。
- 明亮但不轻飘的浅层深渊。
- 可爱的危险感，而不是厚重蒸汽机械感。
- 人偶状态清楚、界面信息克制。

避免：

- 用大段 UI 文本解释系统。
- 把小镇做成黄铜 / 暖灯 / 蒸汽朋克主轴。
- 用复杂按钮堆叠压过人偶和第一次下潜的情绪。
- 让首次回城像普通战利品结算页，缺少照看与下一轮理由。

## 7. 留给 T1 的状态与钩子

`T0` 结束时，`T1 30 分钟-2 小时：第一层搜打撤成形` 应能承接以下设计状态：

- 玩家知道第一层不是一次性关卡，而是可以再次进入的风险空间。
- 玩家至少理解一种人偶状态会影响继续下潜。
- 玩家见过一种深渊物如何转化为钱、维护或下一轮目标。
- 玩家知道小镇会处理深渊结果，但还没有理解完整经济。
- 玩家对“更深一点的第一层”产生好奇或压力。

T1 不需要重新解释“为什么下去”，而应把重点转向“进去以后我该怎么走、怎么打、什么时候撤”。

## 8. Owner 可创作空间

后续实现 Owner 可以根据现有工程、剧情素材和 UI 状态决定：

- 序章从人偶房间、小镇、深渊入口还是回忆片段开始。
- 第一次下潜是战斗、事件，还是战斗与事件混合。
- 第一件带回物是可售物、维护材料、剧情小物或无收益结果。
- 回城转化是放在出售界面、维护界面、回城摘要，还是一个轻量剧情复盘中。
- 第一次维护是实际操作、剧情式照看、资源不足提示，还是下一轮目标。
- 教学提示由 UI、旁白、人偶反馈还是场景反馈承担。

不应改变：

- 玩家必须在 0-30 分钟内理解“下潜 -> 带回 / 消耗 -> 回城转化 -> 下一轮理由”。
- 人偶不是普通战斗单位，而是需要照看的核心对象。
- 第一次深渊结果必须影响后续状态，不能只是假结算或只读演出。
- 小镇必须承担压力转换器身份，不能只是按钮集合。
- 全局视觉不回到黄铜 / 暖灯 / 蒸汽朋克默认主轴。

## 9. 实现承接提示

以下内容只作为后续实现 Owner 拆方案时的提示，不是本文主体：

- 已有功能能支撑的部分应先做证据审计，不重复开发。
- 关键状态不能只由 UI 文案伪造，至少要有真实状态来源或明确的受限说明。
- 配置源仍以 `配置表(JSON)` 为准，运行时副本只通过同步生成。
- 如果实现中发现当前工程无法按本文节奏落地，应回提细案修订，而不是把序章拆回旧的功能步骤清单。
