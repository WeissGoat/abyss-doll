# T0-VAL-01 T0-01A 运行时效果验收记录

> 2026-07-11 文档重构说明：本文只保留为 `T0-01A 开场到首次下潜许可并进入第一层` 的运行时效果验收记录和历史问题追溯。完整 T0-01 开发入口已迁移到 [T0-01 序章首次循环开发总方案](T0-01_序章首次循环开发总方案.md)；完整 T0 后续验收应新建 `T0-VAL-02_完整序章首次循环验收文档.md`。本文不再作为“完整 T0 序章最终实际效果”完成依据。

本文只处理 T0-01A 的运行时实际效果收口。它不替代 [T0-01A Owner 具体设计](T0-01A_开局人偶状态到首次下潜许可实现设计.md)，也不重新拆全局叙事播放系统架构；本文的目标是把当前 Unity 里“能跑通但体验像技术演示”的序章前半段，优化到可以作为 T0-01A 纵切验收的玩家可见版本。

T0-VAL-01 的完成口径不是“点击路径能跑通”，而是玩家新档进入后能看到一段完整、节奏清楚、有画面调度、有第一次仪式性交互、有半开放工坊承接、有真实首潜确认的序章。

运行时主要承接代码入口为 `UnityClient/Assets/Scripts/UI/Narrative/PrologueFirstDiveController.cs`，截图证据目录为 `UnityClient/Logs/T0Validation/`。

## 2. 最终玩家路径

T0-VAL-01 最终版本按以下路径验收：

```text
新档 / Play 启动
  -> 黑屏醒来
  -> 工坊全景建立
  -> 债务纸特写
  -> 手记特写
  -> 核心碎片特写
  -> 发现零号
  -> 唯一交互：启动人偶
  -> 零号苏醒对白
  -> 状态小卡出现
  -> 唯一整理动作：擦去核心仓灰尘
  -> 半开放工坊
  -> 点击浅层入口
  -> 第一层首潜确认
  -> 点击出发
  -> 浅层转场
  -> 第一层地图
```

总时长目标：

| 段落 | 首次体验时长 | 输入 |
|---|---:|---|
| 黑屏醒来 | 4-6 秒 | 无 |
| 工坊过程 CG | 35-55 秒 | 无 |
| 发现零号停顿 | 3-5 秒 | 无 |
| 启动人偶 | 玩家决定 | 只有 `启动人偶` |
| 苏醒对白 | 45-70 秒 | 点击继续或自动推进均可，但不能出现系统功能按钮 |
| 状态小卡与擦灰 | 玩家决定 | 只有 `擦去核心仓灰尘` |
| 半开放工坊 | 玩家决定 | 主行动为 `浅层入口` |
| 首潜确认 | 玩家决定 | `再看她一眼` / `出发` |

## 3. 画面与交互最终标准

### 3.1 黑屏醒来

玩家看到：

- 全屏黑色，无 HUD、无工坊按钮、无鼠标高亮。
- 字幕位于屏幕下 20%-25% 的安全区，不使用大对白框。
- 只出现一句：`主角：又到早上了。`
- 结束时用 0.8-1.2 秒淡入工坊全景。

验收失败条件：

- 开场直接显示工坊面板。
- 左上角日程 / 金币 / 债务 HUD 提前出现。
- 底部出现完整对白框或滚动文本框。

### 3.2 工坊过程 CG

工坊过程 CG 必须像一段被导演过的序章，而不是功能界面。首版可以用 UGUI 合成，不要求视频文件。

播放顺序：

| 镜头 | 画面 | 文案 | 表现要求 |
|---|---|---|---|
| 工坊全景 | 暗旧工坊，工作台是视觉中心，防尘布下隐约有人偶轮廓。 | 无或极短环境字幕。 | 停 2 秒；背景稍暗，中央工作台有弱光。 |
| 债务纸 | 催缴纸占画面 45%-60%，背景虚化或压暗。 | `他们连坏掉的东西也收。` | 纸张不是小卡片，应像镜头推近；纸面文字可读。 |
| 手记 | 手记页占画面 45%-60%，圈出“浅层晶核”。 | `所以浅层至少还有一点办法。` | 画面冷光短闪，提示浅层入口但不可点。 |
| 核心碎片 | 工具匣打开，核心碎片是焦点。 | `卖掉它，够一天。用掉它，也许够她醒一次。` | 核心微光照向工作台。 |
| 发现零号 | 防尘布被掀开，零号脸部和核心仓进入构图。 | `没有第二台了。也没有第二个早上。` | 结束后才显示 `启动人偶`。 |

表现约束：

- 这一段不出现任何玩家可点击调查点。
- 不出现功能卡片、市场、账单、背包、层选择。
- 文案一行不超过 22 个中文字，超过时换行。
- 道具特写不能是小型漂浮卡，必须占据主要视线。

### 3.3 第一次交互：启动人偶

`启动人偶` 是序章第一次玩家输入，必须有仪式感。

画面状态：

- 零号位于画面中心偏右或中心，完整脸部、胸口核心仓和上半身可见。
- 背景压暗，非关键 UI 全部隐藏。
- 只有一个主按钮 `启动人偶`，按钮位于核心仓下方或画面下中，不能与对白框重叠。
- 点击前不显示状态卡、浅层入口、工坊功能、HUD。

点击反馈：

```text
点击启动人偶
  -> 按钮消失
  -> 核心仓 0.4 秒微光
  -> 工坊灯 0.2 秒短亮
  -> 画面短暂压暗
  -> 零号苏醒第一句对白出现
```

验收失败条件：

- `启动人偶` 和其他功能按钮同时出现。
- 点击后无视觉反馈直接进入下一句文本。
- 零号被裁掉脸、裁掉核心仓或被 UI 遮挡。

### 3.4 零号苏醒对白

苏醒对白是玩家第一次与零号建立关系的段落，不能像日志播放。

画面：

- 零号立绘使用半身或 70%-85% 高度，不裁脸，不压住底部对白。
- 对白框宽度 62%-72%，底部居中；姓名栏清楚但不抢画面。
- 主角说话时可以不显示主角立绘；零号说话时零号轻微亮起。
- HUD 仍隐藏。

节奏：

- 零号短句之间保留 0.3-0.6 秒停顿。
- `你也会。等你没钱的时候。` 后停 0.8 秒。
- 对白结束前不弹状态卡，不打断情绪。

### 3.5 状态小卡与擦灰

状态小卡是第一次轻系统说明，不是完整属性面板。

画面布局：

| 元素 | 位置 | 要求 |
|---|---|---|
| 零号 | 中央偏左或中央，半身 / 近全身，脸和核心仓可见。 | 不超过屏幕高 85%，底部不压按钮。 |
| 状态小卡 | 右侧或下右，宽度 28%-34%。 | 只显示 3 条：核心不稳、行动余量一次、浅层晶核可暂稳。 |
| 整理按钮 | 状态小卡下方或核心仓附近。 | 文案固定 `擦去核心仓灰尘`。 |
| 对白 / 提示 | 状态卡外的一行短提示。 | 不使用长滚动文本。 |

点击 `擦去核心仓灰尘` 后：

- 核心仓灰尘遮罩淡出。
- 状态小卡从红线 / 不稳切到黄线 / 短时可行动。
- 写入 `FirstCoreDustCleaned=true` 和 `FirstDiveUnlocked=true`。
- 1 秒后进入半开放工坊。

验收失败条件：

- 状态卡和对白框重叠。
- 零号尺寸过大导致脸部或按钮被裁。
- 擦灰后没有可见变化。

### 3.6 半开放工坊

半开放工坊必须表达“系统还没全开，当前唯一目标是带零号下潜一次”。

画面结构：

```text
左上：极简日期 / 债务 / 资金 HUD
中央：零号站在工作台前，尺寸稳定
右侧：浅层入口主行动
左侧：工坊互锁灰态
右下：账单 / 市场暂缓灰态
底部：当前目标条
```

主行动卡：

- 标题：`浅层入口`
- 副文案：`压力稳定，零号还能撑一次`
- 主按钮：`浅层入口`
- 视觉强度最高，但不能做成通用蓝绿调试框。

灰态功能：

- `工坊交互暂锁：先确认零号能否行动`
- `账单 / 市场暂缓：当前目标：带零号下潜一次`

当前目标条：

```text
零号：核心仓已清理，行动余量一次
下潜许可：浅层一次
```

验收失败条件：

- 屏幕上出现完整商业街 / 市场 / 养成系统入口。
- 主行动不明确，玩家不知道下一步点哪里。
- 混用英文标题，例如 `Studio`、`Descend`、`Ledger`。

### 3.7 第一层首潜确认

首潜确认应是“第一次下潜许可确认”，不是通用多层列表。

画面结构：

- 背景切到浅层入口或井口门，不再使用工坊全景。
- 标题：`第一层：旧矿井浅缝`
- 状态：`可抵达`
- 许可：`入口稳定，零号还能撑一次`
- 可能带回：`稳定核心碎屑 / 可售废料 / 记忆噪声`
- 按钮：左侧 `再看她一眼`，右侧 `出发`。

按钮要求：

- `出发` 是主按钮，亮度最高。
- `再看她一眼` 返回半开放工坊，不丢状态。
- 阻断态必须显示玩家文案，不显示内部 issue code。

验收失败条件：

- 显示多层列表或可切换其他层。
- `出发` 以外还有多余战斗 / 调试按钮。
- 文本过小、重叠或混用英文。

### 3.8 出发转场与第一层地图

点击 `出发` 后需要短转场，避免像 UI 硬切。

转场：

```text
出发点击
  -> 按钮锁定
  -> 画面压暗
  -> 浅层入口冷光从门缝亮起
  -> 黑场 0.4 秒
  -> 第一层地图淡入
```

第一层地图进入后：

- 保留一句短引导：`点击右下角打开背包，整理局内物资。`
- 不能重新弹序章对白。
- 不能回到蓝屏或空场景。

## 8. 验收流程

T0-VAL-01 后续验收固定为两轮：

```text

```

实现 Owner 必须先自验一次，证明自己提交的版本已经按本文跑通过玩家路径、自动断言和截图清单；自验不通过时不得提交 subagent 验收。subagent 在第二轮独立执行验收，可以复用 Owner 提供的运行入口、截图路径、测试命令和已知限制，但必须自行判断结论，不能用 Owner 自评替代最终验收。

完整验收流程：

```text
实现 Owner 完成实现
  -> 实现 Owner 读取 T0-01A 设计、开发方案和本文
  -> 实现 Owner 运行 T0-VAL-01 玩家路径

  -> 实现 Owner 输出自验报告

  -> subagent 读取 T0-01A 设计、开发方案和本文
  -> subagent 运行或复核 T0-VAL-01 玩家路径
  -> subagent 检查自动断言、截图证据和人工体验
  -> subagent 输出验收报告
  -> 实现 Owner 按问题修复
  -> subagent 复验
```

两轮报告都至少包含以下两部分：

### 8.1 问题

`问题` 部分记录阻断完成或影响玩家体验的事实缺陷。每条问题必须写清：

| 字段 | 要求 |
|---|---|
| 严重级别 | `P0 阻断`、`P1 重要`、`P2 可后续优化`。 |
| 现象 | 玩家实际看到或自动断言实际失败的内容。 |
| 证据 | 截图路径、日志路径、测试报告或可复现步骤。 |
| 对应标准 | 对应本文第 3、7、8、9 节中的验收要求。 |
| 影响 | 为什么会影响 T0-VAL-01 完成判定。 |

如果没有发现问题，必须明确写：

```text
问题：未发现阻断 T0-VAL-01 进入下一轮 / 完成的问题。
```

### 8.2 建议

`建议` 部分记录不阻断完成、但能提升体验或降低后续风险的改进项。每条建议必须写清：

| 字段 | 要求 |
|---|---|
| 建议内容 | 具体要改什么，不能只写“继续优化”。 |

```text
建议：暂无额外建议。
```

### 8.3 结论

Owner 自验报告结论只能使用：

| 结论 | 使用条件 |
|---|---|
| `自验通过，提交 subagent 验收` | Owner 自验无 P0 / P1 问题，截图、自动断言和人工体验均满足本文标准。 |

subagent 最终验收报告只能给出以下三种结论之一：

| 结论 | 使用条件 |
|---|---|
| `通过` | Owner 自验已提交，subagent 未发现 P0 / P1 问题，截图、自动断言和人工体验均满足本文标准。 |

人工验收按 4 个问题判断：

1. 开场是否像一段可观看的序章，而不是直接扔到功能界面。

本轮按正式版 Owner 交付处理，不再做“最小实现 / staging 截图修补”。T0-VAL-01 的目标改为：玩家新档进入后，能看到一段正式序章演出，亲手完成唯一的零号启动交互，在零号苏醒后进入 FormalV2 半开放工坊，并通过正式的首次下潜许可卡进入第一层。

本方案直接接入 `workshop_main` FormalV2 active 规格中 T0 需要的部分，不再另做一套临时工坊 UI。T0 半开放工坊必须落到以下 active zone：

| FormalV2 ZoneID | T0 使用方式 | 本轮要求 |
|---|---|---|
| `home_room_scene` | 工坊 / 房间背景基底。 | 使用 cover 背景、暗角和光源调度承接序章，不显示临时调试面板。 |
| `light_status_strip` | 日期、资金、债务 / 压力、零号短状态。 | 擦灰完成前隐藏；半开放工坊后只显示轻量摘要。 |
| `doll_center` | 零号视觉中心。 | 零号是画面主对象，脸、上半身和核心仓不可被裁切或遮挡。 |
| `abyss_door` | 浅层入口主行动。 | 半开放工坊中唯一最高权重行动，按钮文案为 `浅层入口`。 |
| `workshop_entry` | 工作室 / 整备入口灰态。 | T0 阶段低权重锁定，只显示“先确认零号能否行动”。 |
| `ledger_corner` | 账本 / 市场 / 订单灰态。 | T0 阶段低权重锁定，只显示债务压力，不展开经营系统。 |

### 13.1 正式版路径

正式版 T0-VAL-01 按以下玩家路径重做：

```text
Play / 新档启动
  -> 黑屏醒来，玩家点击推进第一句
  -> 过程 CG：工坊全景
  -> 过程 CG：债务纸特写
  -> 过程 CG：维修手记特写
  -> 过程 CG：核心碎片特写
  -> 过程 CG：发现零号
  -> 唯一交互：启动零号
  -> 零号苏醒对白，默认点击推进
  -> 状态小卡：核心不稳 / 行动一次 / 浅层暂稳
  -> 唯一整理动作：擦去核心仓灰尘
  -> FormalV2 半开放工坊
  -> 点击浅层入口
  -> 第一层首次下潜许可卡
  -> 点击出发
  -> 浅层入口短转场
  -> 第一层地图
```

开场前半段仍是过程 CG 和对白为主，不增加多处调查交互。玩家第一次真正输入只出现在 `启动零号`。

### 13.2 对话框与播放方式

对话框参考用户提供的参考图一，只借鉴交互结构和阅读节奏，不照搬美术皮肤。

| 项 | 正式设计 |
|---|---|
| 默认播放 | 不自动播放。每句对白默认等待玩家点击继续。 |
| 点击推进 | 点击对白框、继续按钮或屏幕安全区域均可推进，但不能误触发场景热点。 |
| `AUTO` | 可见但默认关闭。玩家主动开启后才自动推进；切换场景、进入关键交互、出现选择 / 行动按钮时自动关闭。 |
| `LOG` | 可见，打开后显示本段已播放对白；不阻断剧情状态，不触发命令。 |
| 对白框位置 | 底部居中，宽度约屏幕 62%-72%，高度约 20%-24%。 |
| 角色显示 | 零号处于 `doll_center` 或近景构图；说话时轻微提亮，非说话时降低亮度。 |
| 开场字幕 | 黑屏醒来和部分过程 CG 可使用无框字幕，不强行套完整对白框。 |
| 行动按钮 | `启动零号`、`擦去核心仓灰尘` 不放进对白框内部，必须作为独立仪式按钮。 |

默认不自动播放的原因：T0 前 5 分钟承担玩家与零号建立关系的任务，必须让玩家亲手确认关键句和关键动作。`AUTO` 只能作为二周目或长对白便利功能，不能成为首次体验默认值。

### 13.3 开场过程 CG 分镜

过程 CG 首版可以继续使用 UGUI 合成，不要求立刻导入视频文件，但每张画面必须有独立主视觉、暗角、焦点和短停顿。

| 镜头 | 主视觉 | 屏幕文本 | 禁止出现 |
|---|---|---|---|
| 黑屏醒来 | 全黑，极轻环境声 / 字幕。 | `主角：又到早上了。` | HUD、对白框、工坊按钮。 |
| 工坊全景 | FormalV2 工坊背景，工作台 / 遮布轮廓居中。 | `窗缝里透进来的光，照不亮整间工坊。` | 可点击热点、系统入口。 |
| 债务纸特写 | 催缴纸占画面 45%-60%，纸面有可读债务 / 抵押信息。 | `他们连坏掉的东西也收。` | 小浮窗、图标卡、通用金边面板。 |
| 维修手记特写 | 手记页、浅层晶核圈注、旧维修图。 | `浅层晶核，也许还能让她醒一次。` | 完整工坊 UI、层选择按钮。 |
| 核心碎片特写 | 工具匣与最后一枚核心碎片。 | `卖掉它，够一天。用掉它，也许够她醒一次。` | 背包格、出售按钮。 |
| 发现零号 | 掀开的遮布、零号脸部和核心仓。 | `没有第二台了。也没有第二个早上。` | 其他交互点、状态卡。 |

`发现零号` 镜头结束后，画面停 0.5-0.8 秒，再出现独立按钮 `启动零号`。

### 13.4 启动零号仪式交互

`启动零号` 是序章第一次玩家输入，必须从普通对白按钮中剥离出来。

画面设计：

- 零号使用近景或半身构图，占屏高 70%-85%，脸、肩、核心仓完整可见。
- 背景压暗，只保留核心仓微光、工作台轮廓和少量尘光。
- 底部对白框收起或降到无输入状态。
- 主按钮 `启动零号` 位于核心仓下方或画面下中，尺寸明显大于普通继续按钮。
- 按钮旁不出现其他功能、市场、账本、工坊、浅层入口。

点击反馈：

```text
点击启动零号
  -> 按钮锁定并淡出
  -> 核心仓微光 0.4 秒
  -> 工坊灯短亮 0.2 秒
  -> 零号呼吸 / 眼部或核心弱亮
  -> 进入零号苏醒第一句
```

如果本轮暂无 Live2D / Spine，允许用立绘缩放、alpha、glow、粒子或遮罩完成反馈，但不能无反馈直接跳下一句。

### 13.5 零号苏醒对白

苏醒对白采用正式对话播放层：

| 项 | 要求 |
|---|---|
| 推进 | 默认点击推进，不自动滚完。 |
| 节奏 | 短句之间保留 0.3-0.6 秒输入保护；关键句后停 0.8 秒。 |
| UI | 使用正式对白框，`AUTO` / `LOG` 位于右上角或框内右侧辅助区。 |
| 角色 | 零号为中心，主角无立绘或只以姓名栏表达。 |
| 状态 | 不在对白中途弹状态卡，不提前显示工坊热点。 |

本段核心目的不是解释系统，而是让玩家记住三件事：

```text
她醒了。
她不完整。
她只能撑一次。
```

### 13.6 状态小卡与擦灰

状态小卡只承担第一次轻系统说明，不做完整属性页。

状态卡文本固定为 3 条以内：

```text
核心：不稳
行动余量：一次
暂稳方式：浅层晶核
```

画面结构：

| 元素 | 位置 | 要求 |
|---|---|---|
| 零号 | `doll_center`，中央偏左或中央。 | 不裁脸、不遮核心仓。 |
| 状态小卡 | 右侧轻卡，宽度约 28%-34%。 | 只显示 3 条状态，不堆字段。 |
| 擦灰按钮 | 核心仓附近或状态小卡下方。 | 文案固定 `擦去核心仓灰尘`。 |
| 文案 | 一行短提示。 | 不使用滚动文本解释整套系统。 |

点击 `擦去核心仓灰尘` 后必须有可见变化：

- 核心仓灰尘遮罩淡出。
- 状态小卡从红 / 不稳切换为黄 / 可行动一次。
- 写入 `FirstCoreDustCleaned=true` 与 `FirstDiveUnlocked=true`。
- 1 秒后进入 FormalV2 半开放工坊。

### 13.7 FormalV2 半开放工坊

半开放工坊直接使用 `workshop_main` FormalV2 骨架，但进入 T0 专用模式 `PrologueHalfOpenWorkshop`。

```text
home_room_scene：工坊房间背景
light_status_strip：日期 / 债务 / 资金 / 零号短状态
doll_center：零号站在房间中心
abyss_door：浅层入口主行动
workshop_entry：工作室入口灰态
ledger_corner：账本 / 市场灰态
bottom_goal_hint：当前目标条
```

屏幕文案：

| 区域 | 文案 |
|---|---|
| `light_status_strip` | `第 1 日 / 债务催缴中 / 资金不足 / 零号：短时可行动` |
| `doll_center` | `零号：核心仓已清理，行动余量一次` |
| `abyss_door` | 标题 `浅层入口`；副文案 `入口稳定，零号还能撑一次`；按钮 `浅层入口` |
| `workshop_entry` | `工作室暂锁：先确认零号能否行动` |
| `ledger_corner` | `账本暂缓：当前目标是带零号下潜一次` |
| `bottom_goal_hint` | `当前目标：带零号去浅层，找一枚能稳定核心的晶核。` |

验收重点：

- 3 秒内能看出这是工坊，不是首潜确认面板。
- 3 秒内能看出下一步是 `浅层入口`。
- 主行动只有一个。
- 工作室和账本是灰态空间热点，不是同权重按钮。
- 不显示完整市场、背包、订单、维护、义体、底盘系统。

### 13.8 首次下潜许可卡

点击 `浅层入口` 后进入首次下潜许可卡，不进入通用层列表。

画面结构：

```text
背景：浅层入口 / 井口门 / 深渊门近景
中央：许可卡
右下：出发主按钮
左下：再看她一眼
```

许可卡文案：

```text
第一层：旧矿井浅缝
状态：可抵达
许可：入口稳定，零号还能撑一次
可能带回：稳定核心碎屑 / 可售废料 / 记忆噪声
风险：核心波动会随路线推进增加
```

按钮：

- `出发` 是唯一主按钮。
- `再看她一眼` 返回 FormalV2 半开放工坊，不丢状态。
- 阻断态使用玩家可读文案，例如 `零号核心过载，无法离开工坊`，不显示内部 issue code。

### 13.9 出发转场与第一层地图

点击 `出发` 后增加短转场：

### 13.14 验收流程修正

T0-VAL-01 重新验收必须执行两轮：

```text
Owner 自验
  -> 记录 问题 / 建议 / 结论
  -> 无 P0/P1 后提交 subagent
subagent 验收
  -> 独立记录 问题 / 建议 / 结论
  -> 不通过则 Owner 继续修复
```

两轮验收都必须从商业化体验判断，不允许只复核文件存在、截图尺寸、非蓝屏和 smoke。

人工问题必须回答：

1. 开场是否像正式序章，而不是功能界面或滚动文本。
