# 正式版长期版本节点规划

> **定位：** 本文是正式版长期里程碑和子节点规划。`09` 决定宏观优先级，`11` 决定批次和需求文档承接，本文决定每个版本节点要交付什么、各职能分别完成什么、用什么门禁进入下一节点。

---

## 1. 节点设计原则

正式版开发按纵向系统推进，但版本节点需要同时管理四类产出：

- 策划：规则、配置意图、内容包、数值假设和验收样例。
- 程序：领域服务、配置读取、Validator、自动化验收和 UI 接入边界。
- 美术 / UI：Formal V1 结构、VisualID、Approved 资源、运行时截图验收。
- PM：范围边界、交接状态、门禁、风险和下一节点切换条件。

每个节点都按正式版质量处理进入范围的系统。节点可以控制内容量，但不能用“先半成品以后重做”的口径定义系统。

---

## 2. 长期目标

### 当前纵切候选目标

当前优先支撑前三层和局外循环：

```text
第 1 层低压入门
  -> 第 2 层背包压力
  -> 第 3 层路线侵蚀 / 订单冲突
  -> 回城出售 / 制造 / 维护 / 成长
  -> 经济目标推动再次下潜
```

目标时长：

| 目标 | 时长口径 | 说明 |
|---|---:|---|
| 首次有效体验 | 30-60 分钟 | 玩家完成第 1 层基础闭环，并理解背包、战斗、撤离和出售。 |
| 三层纵切体验 | 3-5 小时 | 玩家体验第 1-3 层递进、局外成长、经济压力和至少一种路线目标。 |
| 反复构筑体验 | 6-10 小时 | 不同物品、怪物、订单和成长选择形成多轮下潜差异。 |

### 完整正式版目标

长期正式版按以下容量规划：

| 目标 | 时长口径 | 内容支撑 |
|---|---:|---|
| 主线首次通关 | 8-12 小时 | 5 个正式层级、局外成长、经济压力、订单目标和关键剧情事件。 |
| 深度构筑 / 多路线 | 15-25 小时 | 多义体构筑、势力订单、黑市背叛、房间记忆、事件分支和高层内容。 |
| 长尾收集 / 完成度 | 25 小时以上 | 遗物、义体、订单链、房间纪念物、剧情回收和挑战路线。 |

这些目标来自 `设计文档/26_正式配置设计与填充推进计划.md`，用于反推节点内容量和验收，不是市场承诺。

## 3. 版本节点总表

| 节点 | 核心目标 | 主优先级 | 进入条件 | 退出门禁 |
|---|---|---|---|---|
| V0 规划治理基线 | 文档层级、需求承接、状态页和旧 MVP 归档稳定。 | 文档 / PM | 当前文档体系混乱或重复。 | `09/11/12` 分工清晰，需求不能只是一句话的门禁可执行。 |
| V1 验收与配置底座 | 让配置、Validator、自动化验收和报告成为正式开发门禁。 | P0 | P0 需求文档和主干配置承接清单已存在。 | 一键 P0 验收、统一报告、固定 seed 摘要和 Strict 门禁可用。 |
| V2 背包战斗正式纵切 | 核心手感正式化。 | P1 | P0 静态校验能覆盖 Items / Monsters / Rewards 基础引用。 | 背包生命周期和战斗可读性通过核心验收。 |
| V3 深渊与局外成长纵切 | 打通下潜、回城、变强、再下潜。 | P2 / P3 | P1 主干稳定，地图和成长需求文档已承接。 | 前三层地图节奏、局外成长和下潜许可形成 3-5 小时体验。 |

| V6 候选版收口 | 进入可发布候选质量门禁。 | 全局 | V5 内容容量达到主线目标。 | 主线首通、回归测试、运行时美术验收和配置门禁稳定。 |

## 4. 节点拆分

### V0：规划治理基线

目标：让版本规划不再互相抢事实来源。

策划 / PM：

- `09` 收敛为正式版宏观总线。
- `11` 合并 GDD 批次和需求文档承接矩阵。
- `12` 维护长期版本节点和各职能节点工作。
- 旧 MVP 文档只作为历史归档。

程序：

- 只从 `09` 判断当前优先级，从 `11` 查需求承接，从 `12` 查节点门禁。

美术 / UI：

- 只围绕当前节点主线补 UI / 资源，不横向铺所有界面。

退出门禁：

- 文档导航清楚。
- 新需求有详细文档承接。
- 各职能知道从哪个文档判断阶段、需求和执行节点。

### V1：验收与配置底座

目标：把 P0 做成所有后续正式配置和内容填充的门禁。

策划：

- 执行 `设计文档/26` 的 D0：配置承接审计。
- 优先审计 `Items`、`Monsters`、`Dungeons`、`Rewards`。
- 输出字段缺口、合法值、引用关系、默认值建议和验收样例。

程序：

- 完成 P0 一键验收入口。
- 汇总 ConfigValidator、Unity smoke test、UI 校验和 ArtAcceptance latest。
- 输出统一 `report.json` / `report.md`。
- 支持固定 seed 摘要和 Strict 门禁。

美术 / UI：

- 明确 VisualID、Approved 资源、active UI 规格与截图验收的门禁关系。
- 当前只补 P0 验收所需的关键表现引用。

PM：

- 将 P0 作为后续节点进入条件。
- 避免重复派发已完成的静态 Validator 基础检查。

退出门禁：

- 主干配置修改可以被机械检查。
- P0 报告能说明失败原因和归属。
- 固定 seed 样例可重复验收。

### V2：背包战斗正式纵切

目标：让核心手感可玩、可读、可回归。

策划：

- 以 `GDD_01`、`GDD_06`、`02`、`03`、`15`、`19/20/25` 为完整交付包。
- 补齐背包生命周期、怪物意图、对包干涉、战利品拾取和失败 / 撤离分流的配置落点。

程序：

- 收口拾取、丢弃、使用、出售、制造消耗、撤离和战败的同一套领域规则。
- 战斗反馈、怪物意图、异常和失败原因不写入 UI 临时逻辑。
- 2026-05-25 程序侧已补 `MonsterIntentPreviewService` 只读意图预览数据层，并用 `MonsterIntentPreviewServiceSmokeTest.Run` 验证攻击、腐蚀武器、塞污染物的可读数据；后续仍需补回合意图锁定、UI 消费和战斗整体验收。
- 补核心 smoke test 和 P0 规则回归。

美术 / UI：

- 补背包、战利品、战斗 HUD、怪物意图和失败 / 撤离反馈的 Formal V1 表达。
- 对关键界面跑运行时截图验收。

PM：

- 控制范围在核心手感，不提前铺大量新怪物和装备流派。

退出门禁：

- 玩家能理解物品为什么进入、移动、消耗、卖出或丢失。
- 玩家能读懂战斗收益、损失、异常和失败原因。
- P1 核心路径有自动化或固定验收样例。

### V3：深渊与局外成长纵切

目标：打通“下潜 -> 回来变强 -> 继续深入”。

策划：

- 执行 `设计文档/26` 的 D1：前三层正式配置填充。
- 每层至少具备低风险路线、高收益路线和 Boss 终点。
- 每层至少提供两类背包取舍，以及一个局外回流点。
- 执行 D2 的成长部分：底盘、义体、配方、维护和下潜许可。

程序：

- 实现或完善节点网络、路线 seed、层级入口、已通层直达、安全区、撤离 / 继续深入和失败结算。
- 路线风险表达和战争迷雾基础已落地，验证：`DungeonMapVisibilitySmokeTest.Run`、`DungeonStairsProgressionTest.Run`、`ConfigValidationSmokeTest.Run`。
- 成长服务、维护、材料缺口和下潜许可进入统一规则入口。

美术 / UI：

- 地图节点、路线、层级入口、安全区、结算、工坊 / 成长界面跟随主线接入。
- 只补玩家读懂路线和成长所需的关键资源。

PM：

- 以 3-5 小时三层纵切体验作为节点目标。
- 第四层以后内容包暂不抢跑。

退出门禁：

- 玩家知道从哪层出发、当前目标、何时撤离和为什么继续深入。
- 回城后至少能看到两条成长方向。
- 前三层配置能支撑 3-5 小时纵切体验。

### V4：经济压力与候选循环

目标：让玩家有“今天做什么”的中期局外决策。

策划：

- 执行 `设计文档/26` 的 D2 经济部分。
- 补月租、维护费用、传闻价格波、订单或等价目标链。
- 经济压力能驱动下潜目标，但不能在前三层形成不可恢复死锁。

程序：

- 支持账单、订单 / 目标、声望或等价压力链状态。
- 补经济结算、价格波、目标完成和失败反馈。

美术 / UI：

- 补出售、账单、传闻、订单 / 目标和压力反馈界面。
- 当前以可读性为优先，不追求完整商业化美术量。

PM：

- 判断是否进入候选循环：P1-P4 是否能形成稳定 6-10 小时反复构筑体验。

退出门禁：

- 玩家完成第 3 层后至少形成一条中期目标链。
- 经济压力推动下潜选择，而不是只增加惩罚。
- 候选循环能稳定回归。

### V5：正式内容扩展

目标：从前三层纵切扩展到 8-12 小时主线容量。

策划：

- 执行 `设计文档/26` 的 D3：长期内容池规划。
- 第 4-5 层先定义主题、核心压力和内容量目标，再拆内容包。
- 扩展订单链、剧情事件、房间记忆、义体、配方和经济传闻。

程序：

- 只在系统能力稳定后支持新增内容池和复杂规则。
- 优先补内容生产效率、配置校验覆盖和回归样例。

美术 / UI：

- 扩展正式资源覆盖，优先补进入主线首通的关键节点。
- 增加房间记忆、剧情事件、订单和高层节点的可读表现。

PM：

- 控制内容生产节奏，避免用低职责配置堆时长。

退出门禁：

- 5 个正式层级具备主线首通内容。
- 主线首通目标接近 8-12 小时。
- 内容扩展不破坏 P0-P4 已有门禁。

### V6：候选版收口

目标：进入可发布候选质量。

策划：

- 收口数值曲线、内容职责、经济压力和主线目标。
- 标记长尾、后续 DLC 或非候选范围内容。

程序：

- 固化回归测试、性能风险、存档兼容、错误报告和构建流程。

美术 / UI：

- 关键界面、关键角色 / 怪物 / 物品 / 地图节点达到候选版表现标准。
- 运行时美术验收覆盖主要流程。

PM：

- 建立候选版验收清单、风险列表和冻结策略。

退出门禁：

- 主线首通可完成。
- 关键回归稳定。
- 配置、程序、UI / 美术验收报告可重复生成。

## 5. 配置填充嵌入节点

`设计文档/26_正式配置设计与填充推进计划.md` 不再独立作为孤立计划，而是嵌入版本节点：

| `26` 阶段 | 对应版本节点 | 节点内产出 |
|---|---|---|
| D0 配置承接审计 | V1 | `Items`、`Monsters`、`Dungeons`、`Rewards` 字段缺口、Validator 项和验收样例。 |
| D1 前三层正式配置填充 | V3 | 第 1-3 层物品、怪物、地图、奖励和固定 seed 路径。 |
| D2 局外成长与经济压力填充 | V3 / V4 | 底盘、义体、配方、维护、下潜许可、账单、传闻和订单目标链。 |
| D3 长期内容池规划 | V5 | 第 4-5 层、订单链、剧情事件、房间记忆和长期内容池模板。 |

这样处理后，`26` 负责策划配置方法论，本文负责版本节点安排，二者不重复。

---

## 6. 节点切换规则

进入下一节点前必须满足：

1. 当前节点核心路径可运行或可验收。
2. 当前节点新增需求已在 `11` 找到详细文档承接。
3. 策划、程序、美术 / UI 状态页已回写。
4. 自动化、Validator 或人工验收样例至少覆盖核心路径。
5. 未完成项被明确归类为阻塞、观察或后续内容生产。

如果某节点只完成文档，没有配置、程序、表现或验收落点，不视为节点完成。
