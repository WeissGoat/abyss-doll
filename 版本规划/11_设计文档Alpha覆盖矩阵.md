# 设计文档 Alpha 覆盖矩阵

> **更新时间：** 2026-05-24  
> **定位：** 本文档回答“`版本规划/09_正式版核心纵切开发路线.md` 是否覆盖 `设计文档/` 的所有功能”。结论是：`09` 覆盖正式版 Alpha 的主干系统，不覆盖所有 GDD 细项。本文用于把每份 GDD 在 Alpha 阶段的进入范围、阶段归属和暂缓理由讲清楚。

---

## 1. 覆盖原则

正式版核心纵切 Alpha 的目标不是把所有 GDD 功能做完，而是完成一条足够成熟、可扩展、可验收的正式版主干纵切。

因此每份 GDD 被分为四类：

| 覆盖类型 | 含义 |
|---|---|
| **主干必做** | Alpha 必须进入可玩或可验收状态，否则纵切不成立。 |
| **局部进入** | 只取支撑主干的部分规则，不做完整内容量。 |
| **接口预留** | 当前不做可玩内容，但数据、规则或 UI 上不能堵死未来接入。 |
| **完整版暂缓** | 不进入 Alpha，保留为正式版后续系统。 |

旧 MVP 文档只作为历史验证材料。若旧 MVP 文档、`09` 路线和当前 GDD 出现冲突，按以下顺序判定：

```text
当前 GDD 具体规则 > 09 / 10 阶段路线 > 旧 MVP 文档
```

## 2. GDD 覆盖总表

| `GDD_00` | 系统关联总图 | 主干必做 | A0-A4 全程 | 作为系统关系、资源流向、优先级和循环健康度入口。 | 不展开每个系统细则。 |

## 3. 按 Alpha 节点拆分

### A1：核心边界收口

本阶段主要不是新增 GDD 功能，而是为后续 GDD 功能接入收边界。

| 必读 GDD | 用途 |
|---|---|
| `GDD_00` | 确认系统关系，不让程序重构改变设计归属。 |
| `GDD_01` / `GDD_06` | 确认背包、物品和 UI 交互真实状态归属。 |
| `GDD_04` / `GDD_08` | 确认出售、制造和成长资源流向不被 UI 临时逻辑截断。 |

出口要求：

*   背包、物品、战斗、流程、UI 的责任边界清晰。
*   不为了 UI 或美术接入改写玩法事实来源。
*   A2 所需的规则入口已经能对应到 GDD 和配置。

### A2：背包与战斗正式纵切

主覆盖：

*   `GDD_01`
*   `GDD_06`
*   `GDD_09` 的标签接口

策划验收重点：

*   旋转放入、拾取、丢弃、撤离、战败、出售、制造消耗的生命周期一致。
*   玩家能读懂每次战斗收益、损失、异常状态和失败原因。
*   典型怪物行为能体现“对人攻击 + 对包干涉”的核心差异。

### A3：深渊与局外成长纵切

主覆盖：

*   `GDD_02`
*   `GDD_08`
*   `GDD_03` / `GDD_12` 的轻量状态反馈

策划验收重点：

*   玩家知道当前从哪一层出发、为什么继续深入、何时撤离。
*   回到局外后能看懂自己可以升级什么、缺什么、升级后下次会怎样变强。
*   安全区、撤离、战败、层级入口和局外成长形成稳定节奏。

### A4：经济压力与 Alpha 候选

主覆盖：

*   `GDD_04`
*   `GDD_07`
*   `GDD_10` 的轻量目标入口
*   `GDD_05` 的事件接口意识

策划验收重点：

*   玩家开始面对“今天做什么”的局外决策。
*   至少一条经济压力链能驱动玩家继续下深渊。
*   经济压力不压垮早期体验，但能推动中期取舍。

---

## 4. 明确暂缓项

以下内容不应在 Alpha 1 / Alpha 2 中抢跑：

*   完整好感双轨与大量人偶互动内容。
*   完整剧情章节、剧本调度和世界事件。
*   完整势力声望、订单池和势力商店。
*   人偶房间、家具和长期视觉叙事系统。
*   网状深渊地图完整版。
*   大量怪物、大量装备、大量义体、大量层级。

这些内容不是被废弃，而是要等主干纵切稳定后再逐步接入。当前如果提前铺开，会稀释背包战斗、物品生命周期、深渊节奏和局外成长这四条主线。

---

## 5. 后续维护规则

当某个 GDD 的功能被拉入当前 Alpha 节点时，必须同步补齐：

1.  所属 Alpha 节点。
2.  进入范围。
3.  暂缓范围。
4.  配置影响。
5.  程序边界。
6.  UI / 美术表达需求。
7.  验收方式。

如果只是“有一天会做”，不要写入当前 Alpha 必做范围。
