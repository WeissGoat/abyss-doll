# MVP 自动化试玩验收方案

> **更新时间：** 2026-05-10  
> **定位：** 本文档定义 MVP 阶段的“自动化试玩员”方案。它用于替代第一轮白盒中重复、机械、可量化的验收劳动，帮助策划快速发现闭环断点和数值离谱点；它不替代真人对节奏、爽感、理解成本的最终判断。

## 1. 目标

自动化试玩员要回答 5 个问题：

*   正式 `doll_proto_0` 开局是否能跑通 1 层。
*   1 层 Boss 的一阶核心是否稳定出现，并形成背包取舍。
*   卖出多余物品后，玩家多久能触发底盘升级或义体制造。
*   通关 1 层并解锁入口后，是否能从小镇直接选择 2 层出发。
*   进入 2 层后，毒性、腐蚀、诅咒是否被实际感知。
*   当前配置的金币、掉落、背包空间、怪物压力是否明显偏离 MVP 目标。

## 2. 不做什么

本阶段自动化试玩不模拟以下内容：

*   复杂真人策略，例如预判路线、长期投资、审美偏好。
*   网状地图路线选择。
*   出售保护、仓库转存、误售纠错。
*   UI 点击链路和表现流畅度。
*   剧情、好感、订单、房租等完整版压力。

## 3. 玩家模型

自动化试玩员采用“谨慎普通玩家”规则：

*   战斗时优先使用单位 AP 伤害最高的武器。
*   HP 低于 45% 时尝试使用修复剂。
*   SAN 低于 35% 时尝试使用镇静剂。
*   背包拾取优先级：核心材料 > 可制造材料 > 高价战利品 > 装备 > 普通消耗品 > 低价战利品。
*   如果背包放不下高优先级物品，会尝试丢弃低优先级物品。
*   回工坊后卖出纯卖钱战利品，保留核心材料、制造材料、装备和消耗品。
*   可升级底盘时优先升级底盘；否则尝试制造义体。
*   首次通关 1 层后，后续下潜优先使用已解锁的 2 层入口，不再重复打一遍 1 层。

## 4. 指标输出

每轮自动试玩输出以下统计：

| 指标 | 用途 |
| :--- | :--- |
| 1 层完成率 | 判断正式开局是否过难 |
| 2 层进入率 | 判断局外成长和 1 层收益是否接上 |
| 2 层直接出发次数 | 判断分层入口解锁是否生效 |
| 平均剩余 HP / SAN | 判断战斗与深渊续航压力 |
| 一阶核心获得率 | 判断关键成长奖励是否稳定 |
| 二阶核心获得率 | 判断后续成长钩子是否稳定 |
| 平均金币收入 | 判断经济回流速度 |
| 底盘升级次数 | 判断局外成长是否可触发 |
| 义体制造次数 | 判断材料和金币配方是否可达 |
| 背包拾取失败次数 | 判断空间取舍是否出现 |
| 被丢弃物品列表 | 判断哪些物品没有吸引力 |
| Toxic / 腐蚀 / 诅咒触发次数 | 判断 2 层特色压力是否可感知 |

## 5. 验收阈值

首轮建议阈值不是硬性上线标准，而是调参警戒线：

*   1 层完成率低于 60%：1 层过难或开局资源不足。
*   1 层完成率高于 95%，且平均 HP/SAN 很高：1 层过松。
*   一阶核心获得率低于 100%：关键奖励配置或拾取策略有问题。
*   3 次下潜后仍无法升级底盘或制造任意义体：经济/材料回流偏慢。
*   解锁 2 层后仍从 1 层重复出发：入口选择流程或自动试玩策略有问题。
*   2 层压力触发为 0：毒性、腐蚀、诅咒没有进入实际体验。
*   背包拾取失败始终为 0：空间取舍可能不足。

## 6. 实现入口

新增测试入口：

```text
MVPAutoplaytestTest.Run()
```

稳定性批量验收入口：

```text
MVPAutoplaytestTest.RunStability()
```

运行方式：

```powershell
Set-Content -Path "UnityClient/Logs/.test_trigger" -Value "MVPAutoplaytestTest.Run"
```

批量稳定性验收运行方式：

```powershell
Set-Content -Path "UnityClient/Logs/.test_trigger" -Value "MVPAutoplaytestTest.RunStability"
```

测试会同时向 Unity 日志输出摘要，并写入：

```text
UnityClient/Logs/MVPAutoplaytestReport.json
```

稳定性批量验收会额外写入：

```text
UnityClient/Logs/MVPAutoplaytestStabilityReport.json
```

## 7. 使用方式

推荐流程：

1.  每次调配置后运行 `MVPAutoplaytestTest.Run()`。
2.  查看报告摘要，先判断是否有闭环断点。
3.  若闭环可跑，再根据指标微调掉落、售价、成本、怪物权重。
4.  进入白盒候选前运行 `MVPAutoplaytestTest.RunStability()`，用多批不同种子确认结果不是单轮偶然。
5.  自动试玩稳定后，再安排真人白盒，重点观察理解成本和手感。

自动化试玩的原则是：**先把“能不能跑、数值是否离谱”交给机器，把“好不好玩、是否有欲望继续玩”留给真人。**
