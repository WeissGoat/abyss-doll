# T0-02 首次下潜到第一笔战利品

> 归档说明：本文是 2026-06-14 的早期拆分稿，已被 `版本规划/0-12小时细案/T0-01_序章首次循环.md` 合并替代，不再作为实现 Owner 开工依据。

## 1. 细案状态

`T0-02` 细案完成，下一步由实现 Owner 读取本文后做证据审计和本切片具体落地方案。

## 2. 玩家结果

玩家从 `T0-01` 的第一层入口进入深渊后，在 0-30 分钟内完成一次低风险但真实的“搜打撤”前半段：

1. 进入第一层浅层入口，看到环境、当前人偶状态和一个可理解的低风险选择。
2. 经历第一场基础战斗或基础事件，理解 HP / SAN / AP 等核心消耗至少有一种会真实变化。
3. 获得第一笔真实战利品，并通过背包 / 携带状态完成拾取、放弃或取舍。

本切片完成后，玩家应该能回答：“下去以后会遇到什么、我怎么做出第一步行动、这件东西为什么能被带回去卖或用于维护。”

## 3. 前后关系

输入状态：

- `T0-01` 已允许下潜，并创建或进入第一层入口上下文。
- 当前存在被选中的可行动人偶，且人偶状态可被战斗 / 事件消耗读取和写回。
- 第一层存在一个新手安全范围内的起点节点、基础战斗或基础事件池。
- 背包 / 携带状态至少支持查看剩余空间、拾取战利品和放弃战利品。

输出状态：

- 至少一件第一层基础战利品已被生成，并进入“已拾取 / 已放弃 / 因背包取舍被替换”的明确状态。
- 当前人偶至少有一种可见状态变化被记录，例如 HP、SAN、AP、磨损或等价消耗。
- 当前下潜上下文保留可供 `T0-03` 使用的结果：携带战利品、未携带原因、人偶消耗和是否准备回城。

## 4. 玩家路径

1. 玩家从第一层入口进入浅层起点。
2. 界面显示第一层浅层环境、当前人偶 HP / SAN / AP 摘要和一个低风险前进选择。
3. 玩家选择第一个节点或第一个行动。
4. 系统进入基础战斗或基础事件。
5. 界面显示敌人意图 / 事件风险、玩家可用行动和本次行动可能消耗。
6. 玩家执行一次基础行动，例如攻击、防御、调查、回避或使用一个默认可用动作。
7. 系统通过真实战斗 / 事件规则结算结果，并写回人偶状态变化。
8. 成功路径展示第一笔战利品，至少显示名称、类型、占用 / 重量或价值倾向。
9. 玩家选择拾取、放弃，或在背包空间不足时进行一次取舍。
10. 系统写回背包 / 携带状态，并保留可供回城结算读取的下潜结果。

## 5. 系统开放深度

| 系统 | 本切片开放深度 | 不开放内容 |
|---|---|---|
| 深渊第一层 | 只开放入口后的第一个浅层节点或极短路径，重点是首次遭遇和第一笔战利品。 | 完整节点网络、楼梯、安全区、Boss、第二层入口。 |
| 战斗 / 事件 | 只要求一个基础敌人或一个基础风险事件；需要真实结算、清晰意图和至少一种状态变化。 | 完整怪物生态、复杂连携、长战斗、精英 / Boss 机制。 |
| 人偶状态 | 展示并写回 HP / SAN / AP / 磨损中的至少一种消耗。 | 完整养成、复杂情绪事件、长期伤病链。 |
| 背包 / 战利品 | 支持战利品生成、展示、拾取、放弃和基础空间取舍。 | 高阶旋转谜题、套装构筑、复杂归属、完整仓库管理。 |
| 小镇经济 | 只在战利品提示上露出“可出售 / 可维护转化”的方向。 | 实际出售、金币结算、维护消费、账单推进。 |
| UI / 美术 | 需要浅层环境、状态 HUD、敌人 / 事件风险、战利品和背包空间可读。 | 完整深渊地图皮肤、全部怪物立绘、完整结算大屏。 |
| 验证 | 要求正常 UI 可达、真实战斗 / 事件结算、真实拾取 / 放弃状态和固定样例。 | 不要求 3-5 轮主循环回归。 |

## 6. 首次遭遇规则

首次遭遇必须低风险、短回合、可读，但不能是假演示。

基本规则：

- 默认优先使用第一层浅层的基础敌人；如果当前工程事件系统更完整，也可以使用基础事件承接，但必须产生真实状态变化和真实战利品。
- 首次遭遇不应要求玩家理解完整构筑，只开放 1-2 个基础行动。
- 敌人意图或事件风险必须在行动前可见，避免玩家第一次受损时不知道原因。
- 成功路径应稳定给出一件基础战利品，保证 `T0-03` 有可消费输出。
- 失败或受损可以存在，但不能在开局形成不可恢复的硬死亡循环；如有失败路径，必须显示原因并保留回城 / 重试空间。

推荐首场战斗口径：

| 要素 | 细案要求 |
|---|---|
| 敌人数量 | 1 个基础敌人。 |
| 战斗长度 | 1-3 次玩家行动内可结束。 |
| 行动选择 | 基础攻击 + 防御 / 稳定 / 回避中的一个即可。 |
| 意图表达 | 显示下一次敌人行动类型，例如攻击、蓄力、干扰或逃散。 |
| 消耗表达 | 至少写回 HP / SAN / AP / 磨损中的一种。 |
| 奖励表达 | 战斗胜利后展示一件基础战利品，并进入背包取舍。 |

推荐基础事件口径：

| 要素 | 细案要求 |
|---|---|
| 事件类型 | 浅层资源点、遗迹残片、发光菌丛、旧矿道缝隙等低风险主题。 |
| 选择数量 | 1 个主要选择 + 1 个放弃 / 离开选择即可。 |
| 风险表达 | 行动前显示可能消耗，例如少量 SAN、AP 或磨损。 |
| 结果表达 | 成功后给出基础战利品；放弃后记录无战利品原因。 |

## 7. 第一笔战利品规则

第一笔战利品是整个小镇经济和维护闭环的种子，必须是真实数据，不是结算文案。

战利品状态机：

```text
生成 -> 展示给玩家 -> 拾取 / 放弃 / 背包取舍 -> 写入携带状态 -> 交给 T0-03 结算
```

设计要求：

- 成功路径至少保证一件基础战利品出现。
- 战利品必须有可读名称、类型、基础价值倾向和背包 / 携带占用信息。
- 战利品进入背包后，`T0-03` 能读取它用于出售、维护材料提示或回城结果展示。
- 放弃战利品时，系统应记录或清理当前战利品 offer，不能让 UI 显示“已拿到”但背包没有状态。
- 背包空间不足时，只需要教一次基础取舍：拿新的、保留旧的、或放弃本次战利品。

示例方向只用于设计语义，不作为固定配置 ID：

| 类型 | 体验含义 | 后续用途提示 |
|---|---|---|
| 浅层矿石 | 地底资源的第一眼价值。 | 可卖出，或作为维护材料语义。 |
| 破损旧件 | 深渊里有可回收物。 | 可卖出，或引向修复 / 制造。 |
| 发光菌丝 | 第一层奇幻生态，不走机械主轴。 | 可卖出，或作为轻素材。 |

## 8. UI / UX 表达

本切片 UI 要让玩家在短时间内理解三件事：当前风险、自己能做什么、这件战利品会被带到哪里。

必须表达：

- 当前人偶 HP / SAN / AP 或等价行动资源。
- 敌人意图或事件风险。
- 玩家当前可执行的基础行动。
- 行动结算后的状态变化。
- 战利品名称、类型、占用 / 重量或价值倾向。
- 背包 / 携带空间，以及拾取 / 放弃 / 取舍结果。

表达约束：

- 不用长教程解释“战斗系统是什么”，用按钮可用性、意图图标、短反馈和结果变化说明规则。
- 战利品反馈要明确指向“可带回去转化”，但不在本切片实际完成出售或维护。
- 背包空间不足时，选择必须清楚，不要让玩家误以为点击关闭等于自动拾取。

## 9. 美术与氛围

本切片是玩家第一次真正进入深渊，视觉重点是“浅层奇幻、可理解、低压但真实”。

- 第一层浅层可使用入口废墟、失落矿道、浅层遗迹、发光洞穴植物、少量旧工具和浅层腐蚀。
- 整体仍服从日系二次元地底奇幻冒险主轴，不把黄铜、铜件、暖灯、蒸汽朋克或棕金机械 UI 当作默认风格。
- 首个敌人或事件剪影要简单可读，避免第一次遭遇就出现过多复杂细节。
- 第一笔战利品图标要清楚表达“可带走的小物”，优先可读性，不靠复杂装饰。
- 战斗 / 事件反馈可以有轻微受击、闪烁、获得物提示或背包入格反馈，但不要求完整动效包。

## 10. 配置与数据意图

实现 Owner 需要审计现有配置源，确认是否已有以下意图。如果没有，应先补配置设计再落源：

- 第一层浅层起点：节点 ID、显示名、环境标签、首个遭遇入口。
- 首次遭遇池：基础敌人或基础事件的可选列表、权重、保底项。
- 新手基础敌人 / 事件：HP、意图、行动、风险、胜利 / 成功条件、失败 / 放弃结果。
- 第一笔战利品表：保底基础战利品、类型、占用 / 重量、价值倾向、用途提示。
- 背包 / 携带规则：拾取、放弃、空间不足时的取舍结果。
- 结果文案：进入浅层、遭遇开始、行动结算、获得战利品、放弃战利品、背包空间不足。
- UI VisualID：浅层环境、敌人 / 事件、意图、基础行动、战利品、背包格 / 携带空间。

配置源必须是 `配置表(JSON)`；运行时副本只通过同步生成。

## 11. 程序接入意图

实现 Owner 需要把首次下潜接到真实领域服务或等价运行时规则，不允许只做 UI 假流程。

关键接入点：

- 从 `T0-01` 的第一层入口上下文进入浅层起点。
- 根据配置创建首次遭遇或读取新手保底遭遇。
- 通过真实战斗 / 事件服务结算玩家行动、敌人 / 事件结果和人偶状态变化。
- 根据配置生成第一笔战利品。
- 通过真实背包 / 携带服务处理拾取、放弃和空间不足取舍。
- 把下潜结果写入可供 `T0-03` 读取的回城 / 结算上下文。

如果当前工程已有战斗、背包、掉落或事件服务，只补正常 UI 路径、配置绑定和缺口；如果当前只有测试入口或 debug 面板，本切片按正常玩家 UI 可达补强处理。

## 12. 实现切片边界

实现 Owner 可在本切片内处理：

- 第一层入口到浅层第一个节点的正常 UI 路径。
- 一个基础敌人或基础事件的真实结算。
- 首次行动的资源 / 状态消耗反馈。
- 第一笔基础战利品生成、展示、拾取、放弃和背包取舍。
- 为 `T0-03` 留下可读取的战利品和人偶消耗状态。
- 对应配置、文案、VisualID、smoke / 固定样例和状态回写。

实现 Owner 不在本切片内处理：

- 回城出售、金币入账、维护消费、休整恢复和日程推进；这些属于 `T0-03`。
- 完整第一层节点网络、撤离选择、楼梯、安全区和 Boss；这些从 `T1-01` / `T1-03` 开始展开。
- 完整背包旋转深度、仓库、商店、订单、账单、势力和长线成长。
- 完整战斗构筑、复杂怪物意图组合、长线失败惩罚。

## 13. 验收样例

固定样例 A：基础战斗获得战利品并拾取。

```text
给定：T0-01 已允许下潜，当前人偶可行动，第一层浅层保底基础敌人可用，背包至少有 1 个空位
当：玩家进入第一层浅层，完成第一场基础战斗并选择拾取战利品
则：系统通过真实战斗服务写回人偶状态变化，通过掉落 / 战利品配置生成一件基础战利品，并把该物品写入背包 / 携带状态
```

固定样例 B：放弃第一笔战利品。

```text
给定：首次遭遇已生成一件基础战利品
当：玩家选择放弃
则：背包 / 携带状态不增加该物品，当前战利品 offer 被记录为放弃或被清理，UI 不再显示已获得状态
```

固定样例 C：背包空间不足时进行取舍。

```text
给定：当前背包 / 携带空间不足以直接拾取新战利品
当：玩家尝试拾取
则：UI 显示清晰取舍，玩家可以保留旧物、放弃新物或按已有规则替换；最终背包状态与选择一致
```

固定样例 D：状态消耗可见。

```text
给定：玩家完成首次战斗或事件行动
当：系统结算本次行动
则：HP / SAN / AP / 磨损中的至少一种变化可见，并被写入后续下潜 / 回城上下文
```

## 14. 完成口径

`T0-02` 只有同时满足以下条件，才算实现完成：

- 玩家能通过正常 UI 从第一层入口进入浅层起点。
- 首次基础战斗或基础事件调用真实服务或等价领域规则，不由 UI 直接伪造结果。
- 玩家至少完成一次行动，并看到可验证的人偶状态 / 资源变化。
- 成功路径至少生成一件真实战利品，且拾取 / 放弃 / 取舍能写回背包或携带状态。
- `T0-03` 能读取本切片输出的战利品状态、人偶消耗状态和回城 / 结算上下文。
- 相关 UI / 美术表达符合日系二次元地底奇幻冒险主轴，第一层浅层风格可读，不回到黄铜 / 暖灯 / 蒸汽朋克默认风格。
- 有 smoke、P0、人工流程、截图验收或 `validation_limited:*` 证据。
- 实现 Owner 已回写受影响状态页；外部主策 / 主程 / 主美或游戏导演验收结论已记录。
