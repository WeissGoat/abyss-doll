# T0-03 回城出售到维护 / 休整闭环

> 归档说明：本文是 2026-06-14 的早期拆分稿，已被 `版本规划/0-12小时细案/T0-01_序章首次循环.md` 合并替代，不再作为实现 Owner 开工依据。

## 1. 细案状态

`T0-03` 细案完成，下一步由实现 Owner 读取本文后做证据审计和本切片具体落地方案。

本切片仍是设计细案，不代表出售、维护、日程推进、配置源或 Unity 运行时已经完成。

## 2. 玩家结果

玩家从 `T0-02` 带着第一次下潜结果回到小镇后，在 0-30 分钟内完成第一轮“深渊结果转成下一轮理由”的后半段：

1. 看到回城摘要，理解这次下潜带回了什么、消耗了什么。
2. 把第一笔战利品通过最简出售口径转成金币，或在没有带回战利品时看见明确原因。
3. 看到人偶状态因下潜产生维护 / 休整压力，并完成一次基础维护、选择跳过维护，或看到需要休整的原因。
4. 结束时获得下一轮下潜理由：还缺钱、缺材料、状态已修复可以再下潜，或状态不佳需要休整。

本切片完成后，玩家应该能回答：“为什么回城不是结束，战利品能换成什么，她现在还能不能再下去，下一轮我为什么要下去。”

## 3. 前后关系

输入状态：

- `T0-02` 已产生一次下潜结果，并保留携带战利品、未携带原因、人偶消耗和是否准备回城。
- 当前存在小镇回城入口或结算上下文。
- 背包 / 携带状态能区分已带回、已放弃、替换掉、未获得等结果。
- 人偶状态至少存在 HP、SAN、AP、磨损或等价消耗中的一种可读变化。

输出状态：

- 若有可出售战利品，至少一件物品进入已出售 / 已消耗状态，金币发生可验证变化。
- 若没有可出售战利品，系统记录无收入原因，并仍展示人偶状态和下一步建议。
- 人偶状态经过基础维护 / 休整预览 / 跳过维护后，留下再次下潜许可或阻断原因。
- 小镇状态留下可供 `T1-01` 或后续实现切片读取的下一轮目标：再次下潜、先维护、先休整、继续赚钱或寻找材料。

## 4. 玩家路径

1. 玩家从首次下潜返回小镇。
2. 回城摘要显示本次结果：携带战利品、未带回原因、人偶消耗和当前金币。
3. 系统把携带战利品转入小镇可处理状态，优先进入最简出售入口。
4. 玩家选择快速出售，或在没有物品时看到“本次无可出售战利品”的原因。
5. 系统通过真实经济 / 物品服务结算金币，并把物品标记为已出售或已消耗。
6. 界面显示金币变化、物品去向和一句短反馈。
7. 系统进入人偶状态复盘，展示下潜前后 HP / SAN / 磨损等变化。
8. 玩家看到一个基础维护 / 休整入口：可执行基础维护、跳过维护继续准备，或在硬阻断时被引导休整 / 深度处理。
9. 系统结算维护消耗或记录跳过结果，并刷新下潜许可。
10. 界面给出下一轮下潜理由和主行动，例如“状态稳定，可以再下潜”“金币不足，继续找可卖物”“磨损过高，先维护”。

## 5. 系统开放深度

| 系统 | 本切片开放深度 | 不开放内容 |
|---|---|---|
| 回城结算 | 只展示一次下潜的带回物、未带回原因、人偶消耗和当前金币变化。 | 完整日报、周报、月租、债务、经营事件。 |
| 小镇出售 | 只开放快速出售 / 倾倒箱语义，用于第一笔战利品变金币。 | 橱窗、顾客、传闻、黑市、典当、完整订单结算。 |
| 物品生命周期 | 至少支持带回物从背包 / 携带状态转为可出售，并在出售后进入 `Sold` / `Consumed` 等明确去向。 | 完整仓库经营、违禁品隔夜代价、复杂污染物处理。 |
| 人偶维护 | 只开放基础维护、维护压力提示和再次下潜许可刷新。 | 完整底盘、义体、天赋、换装、长期成长树。 |
| 休整 / 日程 | 基础维护默认零时耗；真正停工休息 / 深度疗愈才作为推进天数的核心抉择。 | 周 / 月周期、订单期限、长线休息日剧情和危机事件队列。 |
| 再下潜目标 | 只要求给出下一轮理由和许可状态。 | 完整路线目标、订单目标、传闻目标和多层选择。 |
| UI / 美术 | 需要回城摘要、出售反馈、人偶状态复盘、维护 / 休整提示和再下潜 CTA 可读。 | 完整经营大屏、复杂账本、完整工坊界面和房间长期记忆。 |
| 验证 | 要求正常 UI 可达、真实物品去向、金币变化、人偶状态 / 许可变化和固定样例。 | 不要求 3-5 轮主循环回归。 |

## 6. 回城摘要规则

回城摘要不是奖励播片，而是把 `T0-02` 的结果翻译成小镇可处理状态。

必须展示：

- 本次带回的战利品列表，至少包含名称、类型和价值倾向。
- 本次未带回或放弃的原因，例如未拾取、背包替换、战败丢失或没有生成。
- 人偶状态变化，例如 HP、SAN、AP、磨损、侵蚀或等价消耗。
- 当前金币和出售后预计金币变化。

结果状态机：

```text
下潜结果 -> 回城摘要 -> 战利品入小镇处理状态 -> 出售 / 保留 / 无可售 -> 人偶状态复盘 -> 维护 / 跳过 / 休整提示 -> 再下潜许可
```

设计要求：

- 不允许把 `T0-02` 已放弃的战利品在回城时重新显示为已获得。
- 不允许静默删除战利品；出售、放弃、保留、丢失都要有明确去向。
- 如果首次下潜没有带回物，也要让玩家看到“为什么没有收入”，并继续展示状态压力和下一步行动。
- 回城摘要文本保持短句，避免把经济、维护和日程规则一次性长篇教学。

## 7. 首次出售规则

首次出售只承担“战利品能变成钱”的第一印象，优先简单、真实、可验证。

基础规则：

- 默认使用快速出售 / 倾倒箱语义，结算一件或少量普通战利品。
- 售价可以使用基础价值、阶段保底价值或配置中的早期售价字段，但必须来自真实配置或服务，不由 UI 文案伪造。
- 出售后金币增加，物品从背包 / 携带 / 小镇暂存状态进入已出售或已消耗状态。
- 售出反馈必须同时显示金币变化和物品去向。

首次出售不要求：

- 顾客匹配。
- 橱窗拼图。
- 传闻涨跌。
- 黑市 / 违禁品渠道。
- 月租日报。

推荐早期售卖口径：

| 情况 | 处理 |
|---|---|
| 带回 1 件普通战利品 | 默认给出快速出售按钮，出售后金币增加。 |
| 带回多件普通战利品 | 可以一键出售全部普通物，也可以先只要求出售一件；实现 Owner 根据现有 UI 决定。 |
| 带回物可用于维护 | 售出前可显示“也可保留作维护材料”的轻提示，但不要求完整材料系统。 |
| 无可出售物 | 不给假金币，显示无收入原因，并把压力转到“再下潜 / 先维护 / 先休整”。 |

## 8. 维护 / 休整规则

维护和休整在本切片只做最小闭环：让玩家理解人偶状态会影响下一轮下潜，并且金币 / 材料会被人偶状态吃掉。

维护规则：

- 基础维护默认零时耗，发生在小镇准备窗口，不推进 Day。
- 维护可以消耗金币、材料或早期保底资源。
- 维护至少改善一种状态、解除一个警告，或明确提示“资源不足，无法维护”。
- 维护后必须刷新再次下潜许可。

休整规则：

- 普通“休整 / 深度疗愈”属于推进天数的核心抉择，不应被包装成免费按钮。
- 在 T0-03 中，休整可以先作为硬阻断时的解决路径或下一步建议露出；只有实现切片明确承接日程推进时，才实际执行休整并写回 Day。
- 若玩家状态已经严重到无法下潜，界面必须显示原因和可操作解决路径，例如基础维护、休整或深度处理。

跳过维护：

- 跳过维护允许存在，但不能静默抹掉风险。
- 如果跳过后仍允许下潜，下一轮入口必须保留风险提示。
- 如果跳过后不允许下潜，必须显示阻断原因和建议行动。

## 9. 再下潜许可与下一轮理由

T0-03 的核心完成信号不是卖完东西，而是回城后自然出现下一轮目标。

下一轮理由至少来自以下一种：

| 理由来源 | 玩家可见表达 |
|---|---|
| 金币不足 | 刚赚到钱，但还不够维护或更大目标。 |
| 状态已修复 | 她可以再下去，但这次要更小心。 |
| 状态仍有风险 | 允许下潜但有警告，玩家知道这是选择代价。 |
| 需要维护材料 | 钱不是唯一资源，下次要找能修复她的东西。 |
| 无收入 | 本次没带回有价值物，下次要真正带东西回来。 |

许可口径：

- T0-03 可以复用 `T0-01` 的下潜许可检查，但输入状态变成首次下潜后的状态。
- 许可结果必须区分允许、警告但允许、阻断。
- 再下潜 CTA 只负责把玩家带回“下一轮准备 / 第一层入口选择”的状态，不要求在本切片内展开完整第一层节点网络。

## 10. UI / UX 表达

本切片 UI 要让玩家依次读到四层信息：带回什么、换到什么、她怎么了、下一步做什么。

必须表达：

- 回城摘要：战利品、未携带原因、人偶消耗。
- 出售入口：可出售物、出售按钮、金币变化、物品去向。
- 人偶状态复盘：至少显示一种下潜前后状态变化。
- 维护 / 休整入口：维护成本、预计改善、资源不足或休整代价。
- 再下潜状态：允许、警告或阻断，以及下一轮理由。

表达约束：

- 不使用长教程解释完整经济系统；用短反馈和状态变化教玩家。
- 不把“维护”和“休整”做成两个视觉同等的免费按钮；休整涉及天数推进时必须有代价提示。
- 快速出售可以是强引导，但不能隐藏物品是否被消耗。
- 再下潜按钮必须带状态，不要只在失败时弹错误。

## 11. 美术与氛围

本切片第一次把小镇从入口菜单变成压力转换器。视觉重点是“回到地底小镇、把深渊小物摆上桌面、照看脆弱人偶”。

- 小镇出售语义可使用地下小摊、布面账本、木箱、称量台、旧纸签、简单记账板。
- 维护语义可使用护理台、药剂、绷带、简洁工具、发光矿粉、修补布和奇幻材料。
- 人偶反馈要能看出“刚经历了一次下潜”，例如轻微疲惫、划伤、SAN 不稳或磨损提示。
- 整体仍服从日系二次元地底奇幻冒险主轴；旧工具和工坊道具只是局部语义，不回到黄铜、铜件、暖灯、蒸汽朋克或棕金机械 UI 默认风格。
- 首次出售和维护图标优先清楚可读，避免复杂账本装饰压过玩家下一步行动。

## 12. 配置与数据意图

实现 Owner 需要审计现有配置源，确认是否已有以下意图。如果没有，应先补配置设计再落源：

- 回城摘要文案：带回物、无带回物、放弃物、状态消耗、下一步建议。
- 快速出售规则：可出售物筛选、早期基础售价、金币变化、物品去向。
- 物品生命周期：`Carried` / `Returned` / `Sold` / `Consumed` / `Kept` / `Lost` 等早期所需状态。
- 基础维护方案：目标状态、恢复量、金币 / 材料成本、资源不足文案、维护后许可刷新。
- 休整提示：休整是否推进 Day、恢复效果、不可执行原因、硬阻断解决路径。
- 再下潜许可：允许、警告、阻断阈值和原因。
- UI VisualID：回城摘要、战利品、金币、出售入口、人偶状态复盘、维护入口、休整提示、再下潜许可。

配置源必须是 `配置表(JSON)`；运行时副本只通过同步生成。

## 13. 程序接入意图

实现 Owner 需要把回城、出售、维护和再下潜许可接到真实领域服务或等价运行时规则，不允许只做静态结算面板。

关键接入点：

- 读取 `T0-02` 输出的下潜结果上下文。
- 把携带战利品转入小镇可处理状态。
- 通过真实物品 / 经济服务执行出售，写回金币和物品去向。
- 通过真实人偶状态 / 维护服务执行基础维护或资源不足裁决。
- 按局外时间规则处理基础维护零时耗；若实现休整，则通过日程服务推进天数。
- 调用再次下潜许可检查，并输出允许、警告或阻断。
- 把下一轮目标和状态留给后续 `T1-01` 或实现切片读取。

如果当前工程已有经济、物品、维护或许可服务，只补正常 UI 路径、配置绑定和缺口；如果当前只有 debug 面板或静态账单，本切片按玩家正常 UI 可达补强处理。

## 14. 实现切片边界

实现 Owner 可在本切片内处理：

- 首次回城摘要和下潜结果读取。
- 一次快速出售 / 倾倒箱语义的真实金币结算。
- 物品从带回状态到已售出 / 保留 / 无可售原因的去向记录。
- 人偶状态复盘、基础维护、维护资源不足或跳过维护。
- 再次下潜许可刷新和下一轮理由展示。
- 对应配置、文案、VisualID、smoke / 固定样例和状态回写。

实现 Owner 不在本切片内处理：

- 完整第一层节点网络、撤离选择和路线扩展；这些属于 `T1-01`。
- 完整战斗意图强化和失败原因层级；这些属于 `T1-02`。
- 第一层 Boss、安全区和第二层露出；这些属于 `T1-03`。
- 完整账单、月租、橱窗、顾客、传闻、黑市、典当和订单系统；这些从 `T2-01` / `T2-02` 逐步展开。
- 完整底盘、义体、天赋、换装和房间长期记忆。

## 15. 验收样例

固定样例 A：带回战利品并快速出售。

```text
给定：T0-02 已带回一件普通第一层战利品，当前金币为 0
当：玩家在回城摘要中选择快速出售该战利品
则：系统通过真实经济 / 物品服务结算金币，金币增加，物品进入已出售 / 已消耗状态，UI 显示金币变化和物品去向
```

固定样例 B：没有带回战利品。

```text
给定：T0-02 的战利品被放弃、替换或未获得
当：玩家回到小镇
则：回城摘要显示无可出售物和原因，不增加金币，并仍进入人偶状态复盘和下一步建议
```

固定样例 C：基础维护改善状态。

```text
给定：首次下潜后人偶出现轻度磨损或 HP / SAN 下降，玩家拥有足够金币 / 材料
当：玩家选择基础维护
则：系统扣除对应资源，改善目标状态，刷新再次下潜许可，并显示维护前后变化
```

固定样例 D：跳过维护但保留风险。

```text
给定：人偶存在轻度风险但未达到硬阻断
当：玩家跳过维护并准备再次下潜
则：系统允许或警告允许下潜，但下一轮入口保留风险提示，不静默清除状态
```

固定样例 E：状态硬阻断需要休整 / 深度处理。

```text
给定：首次下潜后人偶状态低于硬阻断阈值
当：玩家尝试再次下潜
则：系统不进入深渊，显示阻断原因，并引导基础维护、休整或深度处理；如果选择休整并实现了日程推进，必须写回 Day 变化
```

## 16. 完成口径

`T0-03` 只有同时满足以下条件，才算实现完成：

- 玩家能通过正常 UI 从首次下潜结果回到小镇回城摘要。
