# 版本规划阅读入口

> 本文件只做目录导航和文档治理，不替代 `09` 路线或 `11` 批次矩阵。

## 当前 Active 文档

| 文档 | 职责 | 是否事实来源 |
|---|---|---|
| `09_正式版核心纵切开发路线.md` | 当前开发核心：正式版纵切阶段目标、功能优先级、A1-A4 里程碑和 PM 工作包口径。 | 是 |
| `11_设计文档纵切批次矩阵.md` | GDD 批次矩阵：说明 `设计文档/GDD_00` 到 `GDD_12` 何时进入纵切，以及按什么正式口径完成。 | 是 |
| `12_版本规划需求文档承接审计.md` | 需求文档门禁：审计 `09` / `11` 中提到的功能、系统、工具和验收项是否已有详细文档承接。 | 是 |

## 已移除的重复文档

`10_正式版核心纵切版本节点规划.md` 已删除，不再维护。

删除原因：它和 `09` 的阶段 / 里程碑、`11` 的 GDD 批次关系高度重复，容易造成三份版本规划互相抢事实来源。后续需要判断阶段、优先级、A1-A4 里程碑或工作包拆分时，直接维护 `09`；需要判断某份 GDD 的批次和完成口径时，维护 `11`。

`12_版本规划需求文档承接审计.md` 不是新的执行层节点规划，不重复拆 A1-A4。它只检查版本规划里出现的需求是否已经有 GDD、规则卡、承接清单、配置 README、开发文档、美术规格或验收方案支撑。

## 归档文档

旧 MVP 规划文档已移动到：

```text
版本规划/_archive/mvp_2026-05/
```

归档文档只用于追溯 MVP 阶段验证过程、旧调参依据和自动化试玩复盘。它们不是当前开发目标，也不覆盖当前 GDD、`09` 路线或 `11` 批次矩阵。

## 判断顺序

如果文档之间发生冲突，按以下顺序判断：

```text
当前 GDD 具体规则 > 09 正式版路线 > 11 GDD 批次矩阵 > 12 需求文档承接审计 > 状态页 > 归档 MVP 文档
```

状态页用于记录当前事实和交接，不承载完整系统规则；具体规则仍回到 GDD、开发文档、美术文档或配置 README。
