# 战斗界面重做（2026-10-26）

制作人：现在的战斗界面看着简陋、像半成品；请参考同类游戏发挥。布局稿在 `tmp/art_explore/20261026_combat_layout/`（不进 git），三个方向：A 挎包托盘（《杀戮尖塔》《Backpack Hero》）、B 舞台 + 工作台分屏（《Backpack Battles》）、C 深渊手账（《暗黑地牢》《邪恶冥刻》）。制作人同意推荐：**A 的骨架，借 C 的蜡烛和提灯**。

## 原来的问题

- 最该看的信息最不显眼：怪物意图是脚下一行灰字，血条很细。
- 中间三条文字横条（敌方伤害预告、操作提示、徒手 / 取消 / 结束回合）像调试信息。
- 背包 4×4 摆在正中，像弹窗，把零号和怪物推到两边。
- 零号状态是四行「HP: 100/100」的表格，压住她的脚。
- 「玩家回合」一直占着顶部。

## 布局（1920×1080 参考分辨率）

| 区域 | 位置 | 内容 |
|---|---|---|
| 战场 | 上面约 60%（脚底 y≈605） | 零号在左（中心 x≈470），怪物在右（单只中心 x≈1420），比原来更近；两三只时从 x≈1110 到 1730 并排站，中间那只靠后一点，不再互相挡住 |
| 零号血条 | 她脚下 | 粗血条，数字在条里；左端护盾徽章（有护盾时显示数值）；敌方这回合要打的部分在条上闪，旁边一个「-9」小签，会倒下时变红写「会倒下」 |
| 怪物 | 脚下血条（数字在条里、护盾数字）、名字；头上**意图徽章**：图标 + 数值（攻击 9、6×2、护盾 8、2格……），不是攻击时徽章下面一行短说明 |
| 背包托盘 | 下方正中 | 格子高度不超过 370 px（缩放 = min(0.89, 370 / 格子高)），放在一只打开的皮挎包里（九宫格，按屏幕像素画，边和扣子不随底盘变形），包的下沿贴着屏幕底边 |
| 左下 | 托盘左边 | AP：一排提灯（亮 / 灭，「精神好」多出来的那盏也画）；SAN：蜡烛 + 数字 + 细条 |

| 回合横幅 | 顶部正中 | 只在敌方行动、选目标、AP 用完自动结束、己方回合开始的头 1.2 秒出现，其余时间隐去 |
| 操作提示 | 挎包右边、按钮上方 | 这场战斗还没出过手、或正在选目标时才出现（放在战场和托盘之间会被挎包的翻盖挡住） |

战场下半到托盘之间压一层从透明到半透明的暗色渐变，让托盘和底部数字读得清。

## 背包上限

估计 **7 宽 × 5 高**（35 格）。理由：

- 现在底盘 1 是 4×4（16 格），底盘 2 是 5×5（25 格）。物品多数 2–6 格（2×2 18 件、2×3 10 件、1×2 21 件），35 格大约装 8–10 件，构筑有空间，捡战利品仍然要取舍（GDD_01 的核心压力）。
- 最高的物品是 1×4 和 3×3，高 5 行放得下；往宽长，不往高长，托盘高度不变，格子不会再缩：5 行时格子约 71 px（1080p），7 列时格子区宽约 520 px。注意：7 列时挎包左缘到 x≈615，会碰到零号的血条，做到 6×5 / 7×5 底盘时要把血条左移或让挎包右移。
- 以后的底盘按 4×4 → 5×5 → 6×5 → 7×5 设计；不规则形状用 `GridMask` 在 7×5 里挖。

## 分批

1. **布局和信息层级**（只用现有素材）：上面整张表；`HUDController` 重排；意图徽章的数值由后端给（`CombatReadabilityTextService`），界面只显示。
2. **素材**：皮包托盘、蜡封按钮、提灯亮灭、蜡烛、血条框、护盾徽章、意图皮签（红 / 棕）和一套意图图标（攻击、削弱武器、塞废料、护盾、净化、自爆、震乱、锁格、SAN 压力、未知）。gpt-image 一次出一整张（图标一张、零件一张、挎包一张）保证同一画风，抠白底后切开；原来的格子（帆布 / 锁住）够用，没换。
3. **物品格和出手**：物品以图标为主，左上一盏小提灯 + AP 费用，右下关键数值（伤害 / +回血 / +SAN / +护盾 / +加成% / 战利品价钱，被相邻加成抬高的伤害变绿），名字放到悬停说明；底色压暗成类型色的暗调。相邻加成：后端 `GridSolver.AdjacencyLinks` 给出互相起作用的物品对（效果指向某一侧或数四周带标签的邻居，按效果的 Tag 过滤，伤害倍率只连有伤害的物品），界面在两件物品相接的每条格边上画一道发光的缝。选中武器（或徒手）后，从它的格子到鼠标一条点状弧线和箭头。物品格的样子在工坊、整备、战利品界面也一样。

## 检查

`LayoutCheck()`、`Occlusion()` / `DragCheck()`、`RealDragPlayScenario`、`CombatMotionPlayScenario`、`CombatHUDIntentBindingSmokeTest`（跟着新布局改）、打包自检的战斗截图。都还是 UGUI，检查工具照常覆盖。

## 第二轮：融进场景（2026-10-27）

制作人看了第一轮（`bug/6`）：背景和人物位置比例融得不好，图标风格不统一，下面的背包、按钮、提示像 P 上去的。选了方案 B，并要求人物缩小、三层都重画、素材我自己判断。

- **舞台**：每层一张有地面的战斗背景（第 1 层原地重画，第 2 / 3 层新增 `bg_combat_layer_2/3`），由层配置的 `CombatBackgroundID` 指定；所有人站在同一条脚底线（y 720）上，怪物按最低的不透明像素落地（`HUDController.EnemySpriteRestPosition`）。
- **人物缩小**：零号 260×404，怪物 230×280（大型 270×330），参考同类游戏人物占屏高约三分之一。
- ~~**统一光照**~~：曾按层给人物乘环境色、加青色轮廓光，制作人对比旧包后觉得零号像裹了一层绿膜，2026-10-28 整个去掉，人物保持原图颜色。
- **长凳**：底部整条木长凳（`ui_combat_bench`，1920×282），挎包、蜡封、徒手拳头按钮（`ui_combat_unarmed_button`）、SAN、提示都放在凳上；上沿一层暗色渐变过渡。战斗中格子压暗，挎包读成皮革而不是贴上去的面板。挎包往左挪（x -60），怪物都在挎包右边。
- **图标重画**：62 个物品图标、10 个意图图标和战斗界面零件，按 5×2 一张的参考图用 Gemini 图生图整批重画（保留原形状，统一线条、光源和色板；gpt 太亮太塑料，没用）。回合横幅换成木牌（`ui_combat_banner_plate`）。
- 已知：7 列底盘时挎包会碰到左边怪物的血条和零号的「-9」小签，做到那时再挪。

## 第三轮：人偶底盘（2026-10-27）

制作人看了第二轮：背包融合还不自然；意图图标太复杂，要简单图标（剑、盾）+ 数值；零号这边不用显示会扣多少；AP 和 SAN 的图标不融合；下方要贴主题——零号是人偶，「背包」其实是她的底盘。出了两个方向稿（`tmp/art_explore/20261028_chassis_concept/`）：A 机芯底盘（黄铜骨架 + 白瓷板）、B 人偶匣（天鹅绒木匣 + 瓷底盘板）。制作人选 **A1 的结构、面板和图标，网格用 B2 的白瓷格，物品不要底色**。

- **底盘**：挎包换成零号打开的身体内框。长凳上横着一块黄铜 + 白瓷的底盘面板（`ui_combat_chassis_wings`，齿轮、弹簧、缝里透青光），网格放在黄铜框里（`ui_combat_chassis_frame`，九宫格），框顶正中是装着发光心核的小笼子（`ui_combat_core_cage`，设定里的核心仓）。
- **网格**：战斗中空格是白瓷浅槽（`ui_inventory_slot_porcelain`，`VisualUIHelper.InventorySlotRestSkinID`），工坊等其它界面仍是帆布格。物品格去掉类型色底，只留图标和一道淡阴影（各界面一样）。
- **AP / SAN / 按钮**：AP 是发条桶 + 青色晶体（亮 / 灭），SAN 是紫色安瓿，结束回合是她背后的发条钥匙（字在钥匙下的铜牌上），徒手是铜圈里的瓷手。ID 沿用（`ui_combat_ap_lantern_*`、`ui_combat_san_candle`、`ui_combat_end_turn_seal`），图原地换。
- **意图**：红（这回合会打她）/ 石板灰（其余）的六边形铜边牌，上面一个白色剪影（剑、断剑、废料、盾、星、炸弹、循环箭头、锁、螺旋眼、问号）+ 数值。
- **零号这边**：去掉「-9」小签和血条上闪的那段（`IncomingDamagePreview` 后端还在，自动跑局和测试用）。
