# 全局叙事播放系统开发方案

本文定义 P3 的全局对白 / 过场 / 剧情触发播放系统。它不是 T0-01A 序章的一次性控制器，而是日程、人偶互动、工坊、深渊、战斗、休息区、Boss 和特殊节点共同使用的叙事播放底座。

当前 Unity 代码里只有 `scenario_event` 展示面板和 `VisualQueue` 表现队列，没有完整的 galgame / AVG 式对白播放系统。`开发文档/00_程序开发大纲.md` 中的 `DialogueSystem / ChapterSystem` 仍是规划项。因此本方案把叙事播放作为一个正式程序模块补齐。

## 1. 外部运行时选型

首版建议以 Yarn Spinner 作为对白脚本运行时做接入 spike。Yarn Spinner 负责对白脚本、节点跳转、选项、变量、命令和行内容输出；P3 负责触发、调度、UI、游戏状态、存档旗标和领域服务调用。

外部参考：

- Yarn Spinner Unity 文档：`https://docs.yarnspinner.dev/using-yarnspinner-with-unity`
- Yarn Spinner Unity 仓库：`https://github.com/YarnSpinnerTool/YarnSpinner-Unity`
- Yarn Spinner Unity License：`https://raw.githubusercontent.com/YarnSpinnerTool/YarnSpinner-Unity/main/LICENSE.md`

接入前必须确认精确版本、Unity 兼容性、导入方式、许可证随包记录、回滚 diff 和最小样例能否通过当前工程编译。没有完成 spike 前，不把 Yarn Spinner 写入正式依赖锁定。

备选方案：

| 方案 | 用途 | 取舍 |
|---|---|---|
| Yarn Spinner | 对白脚本、选项、命令回调、节点播放 | 推荐。适合作为脚本运行时，不接管 P3 游戏主流程。 |
| ink | 更复杂的分支叙事和长线 story 状态 | 适合重分支剧情；当前 T0 / 主循环触发成本略高。 |
| 自研 JSON / YAML | 最小对白播放和触发 | 可控但会重复实现脚本语言、分支、变量和编辑工具。 |
| Naninovel / 完整 VN 引擎 | 完整视觉小说制作管线 | 不推荐作为首版；容易接管 UI / 输入 / 存档 / 主流程。 |

## 2. 职责边界

Yarn Spinner 只做“对白脚本虚拟机”：

- 加载 Yarn Project / Yarn 脚本。
- 运行指定节点，例如 `T0_01A_Prologue_Start`、`Day_001_Morning_No0`、`Dungeon_L1_FirstEnter`。
- 输出对白行、说话人、选项、标签、命令。
- 处理脚本内部跳转、分支和临时变量。
- 将命令交给 P3 注册的命令处理器。

P3 自研系统负责“游戏内叙事调度”：

- 监听日程、人偶互动、工坊、深渊、节点、战斗和结算事件。
- 判断某段对白是否满足触发条件、是否已看过、是否冷却中、是否被更高优先级剧情压制。
- 决定立即播放、排队、延后、丢弃、替换低优先级播放，或改为轻量气泡。
- 控制播放期间的输入锁、战斗暂停、地图节点禁用、UI 变暗、快进 / 跳过。
- 使用 P3 的纯 UGUI 对白层展示，而不是使用第三方默认 UI。
- 执行白名单叙事命令，例如打开状态卡、解锁浅层入口、暂停战斗、开始 Boss 战、写入旗标。
- 写入 P3 存档中的叙事状态和已播放记录。

任何玩法系统不得直接调用 Yarn Runner。玩法系统只发布 P3 事件，叙事触发服务自行判断是否要播放。

### 2.1 Yarn Spinner 与 P3 自研系统职责矩阵

接入 Yarn Spinner 后，P3 不把它当成完整 VN 引擎，而是当成“对白脚本执行器”。所有与游戏进度、系统开放、输入锁、存档和资源解析有关的职责仍留在 P3。

| 问题 | Yarn Spinner 负责 | P3 自研系统负责 |
|---|---|---|
| 这段对白写在哪里 | 读取 `.yarn` 节点，输出行、选项、命令、跳转。 | 决定 `.yarn` 由对白表导出还是短文本手写，并校验节点清单。 |
| 什么时候触发 | 不判断日程、人偶状态、副本节点或 Boss 阶段。 | `NarrativeTriggerService` 根据事件、flag、条件、概率、冷却和优先级判断。 |
| 是否一定播放 | 不决定。 | 通过 `once`、`chance`、`required_flags`、`forbidden_flags`、`cooldown` 和 `if_busy_policy` 决定立即播、延后或丢弃。 |
| 播放期间能不能点 UI | 不接管 P3 输入。 | `NarrativeScheduler` / `P3DialogueOverlayController` 控制全局或局部输入锁。 |
| 选项有什么后果 | 输出玩家选了哪个选项。 | `NarrativeCommandBridge` 只允许白名单命令写叙事 flag 或调用领域服务。 |
| CG / 立绘 / Live2D 怎么显示 | 只发出 `play_visual`、`show_character` 等命令。 | 通过 `VisualAssetService`、UGUI Overlay 和资源 fallback 解析并显示。 |
| 存档恢复 | 可以从节点播放状态层面支持恢复，但不懂 P3 存档语义。 | `NarrativeStateStore` 保存已播放、延后队列、选择记录和必要叙事 flag。 |

完整调用链固定为：

```text
玩法 / 流程系统发布事件
  -> NarrativeTriggerService 选出候选 trigger
  -> NarrativeScheduler 决定播放时机和输入锁
  -> NarrativePlaybackService 启动 Yarn node
  -> Yarn Spinner 输出 line / option / command
  -> P3DialogueOverlayController 用纯 UGUI 展示
  -> NarrativeCommandBridge 执行白名单命令
  -> NarrativeStateStore 记录完成、选择和 flag
```

例如日程切换、人偶点击、副本进层和 Boss 节点全部走这条链路；区别只在事件上下文、trigger 条件和 `blocking_mode`，不为每类场景写一套独立对话系统。

## 3. 运行时模块

### 3.1 NarrativeEventBus 接入层

复用当前表现层事件总线口径，为叙事系统提供统一事件输入。事件只携带上下文快照，不允许携带可被 UI 直接修改的领域对象。

首批事件：

| 事件 | 来源 | 用途 |
|---|---|---|
| `DayStarted` | 日程系统 | 每日开始、月租压力、特殊日期、序章后的第一天对白。 |
| `DayEnded` | 日程 / 经营结算 | 夜间情绪窗口、噩梦、欠租、周结算剧情。 |
| `DollInteractionResolved` | 人偶交互服务 | 点击、触摸、普通对话、整理、擦灰、送礼后的反应。 |
| `WorkshopEntered` | 工坊 UI / 流程控制 | 首次进入工坊、下潜归来、状态异常时的短句。 |
| `DungeonRunStarted` | 深渊管理器 | 进入副本、首次进入层、低 SAN 下潜提醒。 |
| `DungeonNodeEntered` | 地图节点控制 | 休息区、事件节点、Boss 门、特殊遗迹节点。 |
| `CombatPhaseChanged` | 战斗系统 | 首次遇敌、Boss 现身、低血量、濒死、胜利 / 失败。 |
| `DungeonRunEnded` | 深渊结算 | 撤离、战败、带回特定物品后的回城对白。 |

### 3.2 NarrativeTriggerService

负责从配置中筛选可播放条目。它只做判定，不播放 UI。

处理顺序：

```text
收到事件
  -> 找到 event_type 匹配的 Trigger
  -> 读取 Player / Doll / Dungeon / Combat / Time 快照
  -> 过滤 required_flags / forbidden_flags / once / cooldown / 今日上限
  -> 计算 condition 结果
  -> 计算 chance / weight
  -> 输出候选 NarrativeRequest
```

条件表达首版可以先复用现有配置校验思路，避免引入任意脚本执行。复杂条件先由 C# 白名单 evaluator 支持，例如：

- `FlagEquals`
- `FlagNotSet`
- `DayEquals`
- `DayGreaterOrEqual`
- `DollSanBelow`
- `DollHpBelow`
- `LayerEquals`
- `NodeTypeEquals`
- `CombatPhaseEquals`
- `HasItem`
- `FirstTime`

### 3.3 NarrativeScheduler

负责同一时刻多个对白候选的排队和互斥。所有播放请求都必须经过它。

调度字段：

| 字段 | 说明 |
|---|---|
| `priority` | 主线 / 危机 / Boss 高于日常闲聊。 |
| `blocking_mode` | `modal`、`modal_light`、`bark`、`background`。 |
| `if_busy_policy` | `defer`、`drop`、`queue_once`、`replace_lower_priority`。 |
| `context` | `workshop`、`dungeon_map`、`combat`、`rest_area`、`settlement`。 |
| `pause_policy` | 播放时暂停哪些输入或系统。 |
| `max_queue_size` | 防止同一帧或异常循环堆积对白。 |

同一上下文内，默认只允许一个 `modal` 播放。`bark` 可以与非关键 UI 共存，但不能遮挡核心按钮，也不能在同一人偶上连续刷屏。

### 3.4 NarrativePlaybackService

负责把 P3 的 `NarrativeRequest` 转换为 Yarn 节点播放。

职责：

- 检查 Yarn 节点是否存在。
- 设置播放上下文，例如 `context=workshop`、`doll=no0`、`layer=1`。
- 启动 Yarn Runner。
- 接收播放完成、取消、跳过、错误。
- 通知 Scheduler 播放结束。
- 写入 `seen_count`、`last_played_day`、`last_played_run`、`completed_flags`。

禁止：

- 禁止在 PlaybackService 里直接扣金币、改 HP / SAN、增减背包。
- 禁止让 Yarn 脚本直接访问领域对象。
- 禁止绕过 Scheduler 直接弹 UI。

### 3.5 P3DialogueOverlayController

纯 UGUI 对白表现层。它消费 Yarn 输出的行、选项和标签，只负责显示。

首版支持四种表现：

| 表现 | 用途 | UI 行为 |
|---|---|---|
| `modal` | 主线、序章、Boss、关键人偶剧情 | 锁输入，半透明遮罩，对白框、立绘、背景 / 过程 CG、点击继续。 |
| `modal_light` | 休息区、日程短剧情、结算后插话 | 锁局部输入，不全屏切走当前界面。 |
| `bark` | 人偶短句、低 SAN 自语、战斗中提示 | 气泡或底部短句，自动淡出，不要求玩家确认。 |
| `background` | 图鉴 / 物品 lore / 旁白记录 | 不打断操作，只写入日志或信息面板。 |

UI 控制器不做触发判定，也不写游戏状态。它只向 PlaybackService 回报“行显示完成 / 玩家点继续 / 选择项被点击 / 跳过请求”。

### 3.6 NarrativeCommandBridge

Yarn 命令必须经过白名单桥接，命令只调用 P3 允许的服务入口。

首批命令：

| 命令 | 效果 |
|---|---|
| `set_flag <flag>` | 写入叙事旗标。 |
| `clear_flag <flag>` | 清理允许清理的叙事旗标。 |
| `open_panel <panel_id>` | 打开受控 UI 面板，例如状态小卡。 |
| `unlock_ui <gate_id>` | 解锁序章或新手阶段允许开放的 UI 入口。 |
| `pause_combat` / `resume_combat` | 请求战斗暂停 / 恢复。 |
| `start_combat <encounter_id>` | 只在 Boss / 事件节点授权上下文中可用。 |
| `start_dungeon_layer <layer>` | 只在下潜确认上下文中可用。 |
| `play_visual <visual_id>` | 播放已登记的表现意图，不直接读素材路径。 |
| `record_choice <choice_id>` | 记录玩家叙事选择。 |

每个命令需要声明允许上下文。比如 `start_combat` 只能在 `DungeonNodeEntered` 产生的 Boss 过场中执行；`start_dungeon_layer` 只能在首潜确认或合法下潜确认中执行。

### 3.7 NarrativeStateStore

存档侧保存叙事状态，不依赖 Yarn 内存变量作为长期事实来源。

最小字段：

```text
flags: Dictionary<string, bool>
seen_nodes: Dictionary<string, int>
seen_triggers: Dictionary<string, NarrativeSeenRecord>
cooldowns: Dictionary<string, int>
last_played_by_context: Dictionary<string, string>
pending_queue: List<NarrativePendingRecord>
```

`pending_queue` 只保存可以安全恢复的延后对白。战斗中、Boss 起手、结算中这类强上下文对白不跨存档恢复，读档后由事件重新判定。

## 4. 配置结构

叙事触发配置建议新增在 `配置表(JSON)/Narrative/`。首批可拆为：

```text
Narrative/
  narrative_triggers.json
  narrative_flags.json
  narrative_commands.json
  narrative_contexts.json
```

`narrative_triggers.json` 示例：

```json
{
  "trigger_id": "day_001_morning_no0",
  "event_type": "DayStarted",
  "yarn_node": "Day_001_Morning_No0",
  "priority": 80,
  "blocking_mode": "modal_light",
  "if_busy_policy": "defer",
  "context": "workshop",
  "once": true,
  "chance": 1.0,
  "required_flags": ["No0Started"],
  "forbidden_flags": ["Day001MorningSeen"],
  "conditions": [
    { "type": "DayEquals", "value": 1 },
    { "type": "FlagEquals", "key": "FirstDiveUnlocked", "value": false }
  ],
  "set_flags_on_complete": ["Day001MorningSeen"]
}
```

Validator 必须检查：

- `trigger_id` 唯一。
- `event_type` 属于白名单。
- `yarn_node` 在导入的 Yarn 节点清单中存在。
- `blocking_mode`、`if_busy_policy`、`context` 合法。
- `priority` 在允许范围内。
- `chance` 在 0 到 1。
- `required_flags` / `forbidden_flags` 引用存在或符合命名规则。
- `conditions.type` 属于白名单且参数完整。
- `set_flags_on_complete` 不写入受保护系统状态。
- 命令白名单和上下文授权完整。

## 5. 策划 / 文案配置口径

叙事内容采用三层事实来源，避免同一句对白和同一个触发条件在多个地方重复维护：

| 层级 | 写什么 | 不写什么 | 维护方 |
|---|---|---|---|
| 剧情母版 | 故事阶段、情绪功能、角色关系、关键信息释放顺序。 | 不写运行时触发字段，不写逐行脚本。 | 剧情 Owner / 细案 Owner |
| 对白表 / 剧本表 | 大批量对白正文、说话人、情绪、表情、演出动作、line key、choice_id 的文案编辑源。 | 不写触发概率、日程条件、冷却、优先级，不直接写资源路径。 | 文案 / 策划 |
| Yarn 脚本源 | Yarn Spinner 实际导入的可运行脚本：对白行、选项、节点内跳转、行级标签、对白节奏命令。可由对白表导出，少量短对白也可直接手写。 | 不作为长文本唯一手写入口，不写运行时触发条件，不直接写资源路径。 | 文案 / 策划 / 工具导出 |
| JSON 配置源 | 节点清单、触发条件、播放模式、优先级、冷却、旗标、命令白名单、VisualID 引用。 | 不重复写对白正文。 | 策划 / 配置 Owner |

首版建议目录：

```text
配置表(JSON)/Narrative/
  source_tables/
    t0_01a_prologue.dialogue.csv
    day_001_workshop.dialogue.csv
  scripts/
    t0_01a_prologue.yarn
    day_001_workshop.yarn
    doll_no0_interactions.yarn
    dungeon_layer1.yarn
  narrative_nodes.json
  narrative_triggers.json
  narrative_speakers.json
  narrative_flags.json
  narrative_commands.json
  narrative_contexts.json
```

`source_tables/*.dialogue.csv` 是大批量对白的文案编辑源。`scripts/*.yarn` 是 Yarn Spinner 的运行时导入源和可运行镜像；少量短对白可以直接手写 Yarn，但正式长文本优先由对白表导出。`narrative_nodes.json` 是节点资产和审校清单。`narrative_triggers.json` 是运行时触发清单。程序导入后可生成 Yarn 节点索引和本地化 string table，但生成物不作为手写事实来源。

### 5.0 内容生产链路与手写边界

剧情母版、对白表和 Yarn 脚本不是同一种文档：

```text
剧情母版
  -> 写这一场戏为什么存在、情绪怎么走、信息怎么释放、玩家应该理解什么
对白表 / 剧本表
  -> 写玩家实际会看到的对白正文、说话人、情绪、表情、演出动作、line key
Yarn 脚本源
  -> Yarn Spinner 可导入的运行时脚本，可由对白表导出，也可少量手写
JSON 配置源
  -> 写什么时候触发、是否触发、如何排队、播完写什么 flag
```

剧情母版决定“这段戏应该是什么”，对白表决定“玩家实际看到什么”，Yarn 脚本决定“运行时怎样播放”，JSON trigger 决定“什么时候看到它”。如果只是改一句台词，优先改对白表并重新导出 Yarn；如果改剧情意义、信息释放顺序或玩家动作节奏，先改剧情母版，再同步对白表和 Yarn。

Yarn 不应成为商业量级文本的唯一手写入口。短 bark、测试节点、极少量一次性短对白可以直接手写 `.yarn`；序章、多人长对话、日程剧情、副本过场等正式内容，优先使用对白表 / 剧本表作为文案编辑源，再由工具导出 `.yarn`。导出的 Yarn 文件可以进入版本管理，作为 Unity / Yarn Spinner 的导入源，但不得绕过对白表长期手改；如需临时修正导出 Yarn，必须反向回写到对白表。

官方 Yarn node 的基本形态是：

```text
title: Start
---
Player: Hello there!
NPC: Oh, hello! How can I help you today?
-> I need information.
    NPC: What would you like to know?
-> I'm just browsing.
    NPC: Feel free to look around!
===
```

一个 `.yarn` 文件可以包含多个 node。P3 的文件粒度按章节 / 场景组织，不按每个 node 建一个文件。例如 `day_001_workshop.yarn` 可以同时包含 `Day001_Debt_Intro`、`Day001_Debt_Conflict` 和 `Day001_Debt_Close`。长段多人对话不要写成一个超长 node，也不要拆成大量零散文件；推荐按镜头、情绪转折、交互点或可保存检查点拆成同一 `beat_id` 下的一组 node，由入口 node 通过 `jump` 串联。

对白表字段建议：

| 字段 | 用途 |
|---|---|
| `scene_id` | 场景 / 小章节，例如 `day001_debt_pressure`。 |
| `beat_id` | 剧情拍点，例如 `day_001_debt_pressure`。 |
| `node_id` | 目标 Yarn node。 |
| `row_type` | `line`、`choice`、`command`、`jump`、`comment`。 |
| `speaker_id` | 说话人，对应 `narrative_speakers.json`。 |
| `text` | 玩家可见正文或选项文本。 |
| `emotion` / `expression` / `pose` | 角色表现意图，不直接指向文件路径。 |
| `visual_action` / `visual_id` | CG、立绘、VFX、转场等表现命令引用。 |
| `choice_id` | 玩家选项 ID，有长期影响时必须记录。 |
| `line_key` | 稳定 line tag，本地化、校对、配音和回归测试使用。 |

对白表字段在首版不要做成自由发挥的 Excel。至少拆成以下几类列，便于导出工具和 Validator 固定读取：

| 字段组 | 字段 | 说明 |
|---|---|---|
| 归属 | `scene_id`、`beat_id`、`node_id`、`row_order` | 决定这一行属于哪场戏、哪个拍点、哪个 Yarn node，以及导出顺序。 |
| 内容 | `row_type`、`speaker_id`、`text`、`line_key` | `row_type=line` 时必须有说话人和正文；关键正文必须有稳定 `line_key`。 |
| 选项 | `choice_id`、`choice_text`、`choice_target_node` | `row_type=choice` 时使用；长期影响选择必须有 `choice_id`。 |
| 流程 | `jump_target`、`command_name`、`command_args` | `jump` 和 `command` 行使用；命令必须能映射到白名单。 |
| 表现 | `expression`、`pose`、`slot`、`visual_action`、`visual_id`、`transition` | 只写表现意图或 VisualID，不写文件路径。 |
| 审校 | `review_note`、`locked`、`source_ref` | 记录剧情母版来源、审校意见和是否锁行。 |

一行只能有一个主要意图：对白就是 `line`，选项就是 `choice`，表现命令就是 `command`。不要把“台词 + 播 CG + 写 flag”塞进同一行，否则导出 Yarn、回归测试和配音对表都会变得不可控。

对白表可以导出为 Yarn：

```text
title: Day001_Debt_Intro
---
<<play_visual cg_workshop_morning_after_no0 transition=fade_in>>
<<show_character no0 expression=weak slot=right>>
零号: 你一直在看门。 #line:day001_debt_intro_001
主角: 我在听雨。 #line:day001_debt_intro_002
<<play_visual vfx_debt_terminal_blink target=terminal>>
债务代理: 工坊编号七一四，封存预告已进入倒计时。 #line:day001_debt_intro_003
===
```

导出工具至少要保证：

- node title、speaker、line key、choice_id、command 和 VisualID 格式稳定。
- 同一对白表反复导出不会无意义重排行号或重写未改动 node。
- 已锁定 line key 不因插入新台词而整体漂移；新增行追加新 key。
- 导出 Yarn 后同步刷新 `narrative_nodes.json` 可审校字段，或输出差异报告供配置 Owner 手动确认。

导出工具的输入 / 输出边界：

```text
输入：source_tables/*.dialogue.csv
输出：scripts/*.yarn
输出：narrative_nodes.generated.preview.json 或导出差异报告
不输出：narrative_triggers.json、narrative_flags.json、正式美术 Manifest
```

`narrative_triggers.json` 不建议从对白表自动生成。触发条件、概率、冷却、优先级和完成 flag 属于配置 Owner 判断，应独立维护；导出工具最多提示“这个 node 还没有 trigger”。

手写 Yarn 的边界：

| 内容类型 | 推荐方式 | 原因 |
|---|---|---|
| 序章主线、多人长对白、日程剧情、副本过场 | 对白表维护，导出 Yarn。 | 文本量大，需要校对、改稿、line key 稳定和多人协作。 |
| 人偶短句池、战斗 bark、临时测试样例 | 可直接手写 Yarn。 | 行数少，结构简单，改动成本低。 |
| 带复杂选择和长期影响的节点 | 对白表维护正文，Yarn 保留可读结构，JSON 配 choice / flag。 | 需要 QA 追踪选择和存档影响。 |
| 程序 spike 样例 | 直接手写 Yarn。 | 只验证运行时，不作为正式内容源。 |

### 5.1 剧情母版到脚本节点

细案或剧情文档先拆到“剧情拍点”，再转成 Yarn 节点。每个节点只承接一个清晰的玩家时刻，不把一整段系统开放流程塞进一个超长节点。

节点拆分规则：

| 类型 | 节点粒度 | 示例 |
|---|---|---|
| 主线开场 | 一个镜头段或一个交互前后段 | `T0_01A_Opening_CG`、`T0_01A_StartDoll` |
| 新手引导 | 一个 UI 解锁或一次玩家动作反馈 | `T0_01A_FirstStatusCard`、`T0_01A_FirstCoreWipe` |
| 日程对白 | 一个日程时点的一段短剧情 | `Day_001_Morning_No0` |
| 人偶互动 | 一个交互结果池，不写成长篇主线 | `Doll_No0_Touch_LowSan` |
| 副本节点 | 一个进层、休息区、Boss 门或特殊节点 | `Dungeon_L1_FirstEnter`、`Dungeon_L1_BossIntro` |
| 战斗插话 | 一个阶段短句或一组 bark | `Combat_No0_FirstLowHp` |

节点命名使用大驼峰，触发器使用小写下划线，旗标使用稳定语义名：

```text
Yarn node: T0_01A_StartDoll
trigger_id: t0_01a_start_doll_button
choice_id: choice_t0_01a_start_no0
flag: No0Started
line tag: t0_01a_start_doll_001
```

### 5.2 Yarn 脚本文案规范

Yarn 脚本只写玩家实际会读到的文本和节点内叙事节奏。每一行必须能独立归属到说话人，关键行必须带稳定 line tag，方便后续本地化、校对和录音 / 音效对接。

示例：

```text
title: T0_01A_StartDoll
---
<<play_visual cg_t0_01a_find_no0 transition=fade_in>>
主角: 还有热量。不是废件。 #line:t0_01a_start_doll_001
主角: 如果核心没碎，就还有一次启动机会。 #line:t0_01a_start_doll_002

-> 启动人偶 #choice:choice_t0_01a_start_no0
    <<play_visual vfx_no0_core_glow intensity=weak>>
    <<set_flag No0Started>>
    <<jump T0_01A_No0Wake>>
===
```

脚本规则：

- 说话人使用 `narrative_speakers.json` 中登记的 ID 或显示名映射，不在脚本里临时造角色名。
- 过程 CG、立绘、表情、音效和转场只引用 VisualID 或表现意图 ID，不写文件路径。
- 节点内可以写 `jump`、选项和表现命令；是否触发该节点，由 JSON trigger 决定。
- 脚本内不得写 `DayEquals`、`DollSanBelow`、`LayerEquals` 这类运行时触发条件。
- 脚本命令不得直接扣钱、改 HP / SAN、增减背包或改深渊结算。需要影响游戏状态时，只能调用白名单命令，由 P3 服务判断是否合法。
- 日常 bark 文案要短，默认 8 到 18 个汉字；`modal` 主线对白可以更长，但单行仍应避免超过 UI 设计可读宽度。
- 选项必须有 `choice_id`。有长期影响的选择必须在 `record_choice` 或节点完成旗标中登记。

### 5.3 节点清单配置

`narrative_nodes.json` 让策划、程序、美术和 QA 不用打开 Yarn 文件也能知道某个节点需要什么。

示例：

```json
{
  "node_id": "T0_01A_StartDoll",
  "script_file": "scripts/t0_01a_prologue.yarn",
  "beat_id": "t0_01a_04_start_doll",
  "content_type": "mainline",
  "default_blocking_mode": "modal",
  "speaker_ids": ["player", "no0"],
  "visual_intents": [
    "cg_t0_01a_find_no0",
    "vfx_no0_core_glow"
  ],
  "allowed_commands": ["play_visual", "set_flag", "jump"],
  "choice_ids": ["choice_t0_01a_start_no0"],
  "line_tag_prefix": "t0_01a_start_doll",
  "review_status": "locked_for_implementation"
}
```

`review_status` 建议只使用：

| 状态 | 含义 |
|---|---|
| `draft` | 文案草稿，可改结构和行文。 |
| `content_review` | 待剧情 Owner / 细案 Owner 审。 |
| `locked_for_implementation` | 可进入程序 / UI / 美术接入。 |
| `implemented` | 已有运行时证据。 |
| `deprecated` | 不再触发，但保留历史引用。 |

### 5.4 触发配置和脚本的关系

触发配置只回答“什么时候播、播不播、怎么排队”。Yarn 节点只回答“播出来是什么”。例如每日开始对白：

```json
{
  "trigger_id": "day_001_morning_no0",
  "event_type": "DayStarted",
  "yarn_node": "Day_001_Morning_No0",
  "priority": 80,
  "blocking_mode": "modal_light",
  "if_busy_policy": "defer",
  "context": "workshop",
  "once": true,
  "required_flags": ["No0Started"],
  "forbidden_flags": ["Day001MorningSeen"],
  "conditions": [
    { "type": "DayEquals", "value": 1 }
  ],
  "set_flags_on_complete": ["Day001MorningSeen"]
}
```

同一个 Yarn 节点可以被多个 trigger 引用，但首版不建议这样做。更安全的做法是公共台词拆成小节点，由不同触发器指向各自入口节点，避免 QA 难以判断是谁触发了它。

```json
{

  "display_name_key": "speaker.no0",
  "default_portrait_visual_id": "portrait_no0_neutral",
  "default_voice_bleep": "voice_bleep_no0_soft",
  "default_text_style": "doll_soft"
}
```

文案 key 分三类：

| key 类型 | 用途 | 示例 |
|---|---|---|
| line tag | 对白行、本地化、校对 | `t0_01a_start_doll_001` |
| choice_id | 玩家选项、选择记录 | `choice_t0_01a_start_no0` |
| ui_text_key | 非对白 UI 文案、阻断原因 | `ui.dive.block.first_core_dirty` |

对白正文不再复制到单独 JSON 文本表。后续本地化或配音需要的 string table 由 Yarn 导入流程从 line tag 生成。

### 5.5.1 美术素材关联口径

对白、Yarn 和对白表永远不写真实文件路径，只写 VisualID、角色表现参数或表现意图 ID。真实素材由美术 Manifest、VisualAssetRegistry 和 `VisualAssetService` 映射。

禁止写法：

```text
<<show_cg Assets/Art/Approved/CG/workshop_morning.png>>
```

推荐写法：

```text
<<play_visual cg_workshop_morning_after_no0 transition=fade_in>>
<<show_character no0 expression=weak pose=sitting slot=right>>
<<play_visual vfx_debt_terminal_blink target=terminal>>
```

运行时解析链路：

```text
Yarn command / 对白表 visual_id
  -> NarrativeCommandBridge 校验命令和上下文
  -> P3DialogueOverlayController 接收表现请求
  -> VisualAssetService 按 VisualID / 角色表现参数查资源
  -> UGUI 显示 CG、立绘、Live2D / Spine Prefab、VFX、音效或 fallback
```

美术侧交付链路：

```text
剧情母版
  -> 说明需要工坊晨间 CG、零号虚弱表情、债务通信器闪烁
对白表 / Yarn
  -> 引用 cg_workshop_morning_after_no0、no0 expression=weak、vfx_debt_terminal_blink
narrative_nodes.json
  -> 汇总 visual_intents
美术 / UI
  -> 根据 visual_intents 生成或登记 Approved 素材、Live2D 表情、VFX、UI 皮肤和 fallback
程序
  -> 通过 VisualAssetService 解析 VisualID，不从 Yarn 读取文件路径
```

`visual_intents` 是叙事侧提出的表现需求，可以先是待制作状态；`VisualID` 是运行时能解析的正式资源 ID。状态口径如下：

| 阶段 | 美术关联要求 |
|---|---|
| `draft` | 可以只有表现意图，例如“工坊晨间 CG”“零号虚弱表情”。 |
| `content_review` | 需要列出拟用 VisualID 或待制作 VisualID，不要求素材已入库。 |
| `locked_for_implementation` | 关键 VisualID 必须已有 Approved 素材、Live2D / Prefab 映射或明确 fallback。 |
| `implemented` | 运行时必须能通过 VisualAssetService 解析成功，并有截图、smoke 或人工验收证据。 |

Live2D / Spine / 静态立绘由资源系统决定，脚本只写角色表现参数：

```text
<<show_character no0 expression=weak pose=sitting slot=right>>
```

解析优先级建议：

```text
no0 + weak + sitting
  -> 首选 Live2D / Spine Prefab 表情动作
  -> 其次静态 weak_sitting 立绘
  -> 最后 fallback 到 portrait_no0_neutral
```

对白框、姓名牌、选项按钮、终端噪声皮肤等 UI 素材不应逐行写入 Yarn。默认样式由 `speaker_id`、`blocking_mode` 和 `context` 决定；特殊段落才通过白名单命令覆盖。

```json
{
  "speaker_id": "debt_agent",
  "display_name_key": "speaker.debt_agent",
  "default_portrait_visual_id": "portrait_debt_agent_terminal",
  "default_text_style": "terminal",
  "default_nameplate_style": "terminal_noise",
  "default_voice_bleep": "voice_bleep_terminal"
}
```

#### 美术侧具体工作包

全局叙事播放系统不会要求美术改变素材事实来源；它改变的是“剧情如何提出素材需求”和“程序如何引用素材”。美术侧仍按 Manifest、Approved、UI 规格和 VisualID 工作。

| 素材类型 | 美术侧需要交付 | Yarn / 对白表怎么引用 | 程序运行时怎么取 |
|---|---|---|---|
| 过程 CG / 背景 | Approved 背景图或 CG 图，登记 VisualID，例如 `cg_t0_01a_find_no0`。 | `<<play_visual cg_t0_01a_find_no0 transition=fade_in>>` | `VisualAssetService.Resolve("cg_t0_01a_find_no0")`。 |
| 静态立绘 / 头像 | 角色默认头像、情绪立绘、fallback VisualID。 | `speaker_id=no0` 或 `show_character no0 expression=weak`。 | 先查角色表现映射，再 fallback 到 `default_portrait_visual_id`。 |
| Live2D / Spine / DollPuppet | Prefab / 表情 / 动作 / fallback 映射，不在对白表写 prefab 路径。 | `show_character no0 expression=weak pose=sitting slot=right`。 | 资源层按 `no0 + expression + pose` 选择动态 Prefab 或静态 fallback。 |
| VFX / 音效 | 可播放的 VisualID / AudioID，例如 `vfx_debt_terminal_blink`。 | `play_visual` 或后续 `play_sfx` 白名单命令。 | CommandBridge 校验上下文后交给表现层播放。 |
| 对话 UI 皮肤 | 对白框、姓名牌、选项按钮、终端噪声皮肤、bark 气泡样式。 | 默认不逐行引用；由 `speaker_id`、`context`、`blocking_mode` 决定。 | UGUI Overlay 根据 style key 绑定 Sprite / Prefab / 动效。 |

美术侧看到 `narrative_nodes.json.visual_intents` 后，按以下顺序处理：

1. 先判断是否已有可复用 VisualID。
2. 没有可复用项时，登记待制作 VisualID 或表现意图。
3. 对 `locked_for_implementation` 节点，补齐关键 VisualID 的 Approved 素材、动态 Prefab 映射或明确 fallback。
4. 只在素材真实入库、Manifest / Registry 刷新并有验收证据后，才把该素材视为可运行时接入。

CG、立绘和 Live2D 不因为接入 Yarn Spinner 而改变制作格式。Yarn 只影响“调用语言”：原来程序可能写死某张图，之后统一改成 Yarn 命令或节点清单里的 VisualID；真实图片、Prefab、Manifest、Registry 和截图验收仍走现有美术流水线。

示例映射：

```json
{
  "character_id": "no0",
  "expression": "weak",
  "pose": "sitting",
  "preferred_dynamic_visual_id": "doll_no0_puppet_weak_sitting",
  "fallback_portrait_visual_id": "portrait_no0_weak",
  "fallback_fullbody_visual_id": "stand_no0_weak_sitting"
}
```

如果 `preferred_dynamic_visual_id` 缺失，运行时必须降级到静态 fallback，而不是让对白卡死。Validator 对 `locked_for_implementation` 节点要把“既没有动态资源也没有静态 fallback”判为错误。

### 5.6 策划交付流程

每批剧情 / 对白进入开发前，策划交付必须包含以下内容：

1. 剧情拍点来源：来自细案、剧情母版或内容包，说明这个节点服务哪个玩家时刻。
2. 对白表 / Yarn 脚本：大批量正文优先提供对白表并导出 Yarn；短对白可直接提供 Yarn。必须有节点名、说话人、对白正文、选项、line tag、必要表现命令。
3. 节点清单：`narrative_nodes.json` 中登记脚本文件、内容类型、VisualID、说话人、命令和审校状态。
4. 触发配置：`narrative_triggers.json` 中登记事件、条件、优先级、播放模式、冷却、once 和完成旗标。
5. 旗标 / 选择清单：新增 flag、choice_id 必须说明用途、写入时机和是否进存档。
6. 美术 / UI 依赖：列出 CG、立绘 / DollPuppet 表情动作、VFX、对话框皮肤、按钮样式和 fallback。
7. 验收样例：至少给一个固定玩家路径，例如“新档 -> 启动人偶 -> 苏醒 -> 状态小卡 -> 擦灰 -> 首潜确认”。

未提供 Yarn 脚本和 trigger JSON 前，只能说“剧情设计完成”或“文案草案完成”，不能说“对白配置完成”。未同步到 `配置表(JSON)` 并通过 Validator 前，不能标记为配置完成。

### 5.7 Validator 对策划配置的检查

除第 4 节的触发检查外，叙事 Validator 还要覆盖文案生产错误：

- `narrative_nodes.json.node_id` 必须能在 Yarn 节点清单中找到。
- `script_file` 必须存在，且不能引用 `UnityClient/Assets/StreamingAssets/Configs` 生成副本。
- 如果节点来自对白表，`source_table` / 导出报告必须能追溯到对应 `node_id`、`line_key` 和 `choice_id`。
- line tag 在项目内唯一，并符合节点前缀。
- `choice_id` 唯一，且被 Yarn 选项实际引用。
- `speaker_id` 必须存在于 `narrative_speakers.json`。
- `visual_intents` 必须是 VisualID 或已登记表现意图，不允许原始文件路径。
- `locked_for_implementation` 的关键 `visual_intents` 必须能解析到 Approved 素材、Live2D / Spine Prefab 映射或明确 fallback。
- Yarn 命令必须属于 `narrative_commands.json` 白名单。
- `locked_for_implementation` 的节点不得缺少 trigger、VisualID fallback 或必要说话人。
- `implemented` 的节点必须有运行时 smoke、截图或人工验收记录引用。

## 6. 典型链路

### 6.1 每日开始对白

```text
TimeScheduleService.AdvanceDay()
  -> EventBus.Publish(DayStarted)
  -> NarrativeTriggerService 读取 Day / Week / Rent / Doll 快照
  -> 筛选 day_001_morning_no0 等触发器
  -> NarrativeScheduler 按 priority 排队
  -> NarrativePlaybackService 播放 Yarn 节点
  -> P3DialogueOverlayController 显示对白
  -> NarrativeCommandBridge 执行 set_flag
  -> 播放完成后恢复工坊输入
```

适用规则：

- 第一天、月租日、特殊纪念日可以 `once` 或 `once_per_period`。
- 普通每日闲聊用 `chance` 和 `cooldown` 控制，不每天强播。
- 如果当天开场已有主线剧情，普通闲聊默认 `drop` 或延后到夜间。

配置样例：

```json
{
  "trigger_id": "day_003_morning_no0_rent_pressure",
  "event_type": "DayStarted",
  "yarn_node": "Day003_Morning_RentPressure_No0",
  "priority": 70,
  "blocking_mode": "modal_light",
  "if_busy_policy": "defer",
  "context": "workshop",
  "once": true,
  "required_flags": ["No0Started"],
  "forbidden_flags": ["Day003RentPressureSeen"],
  "conditions": [
    { "type": "DayEquals", "value": 3 },
    { "type": "DebtPressureAtLeast", "value": "medium" }
  ],
  "set_flags_on_complete": ["Day003RentPressureSeen"]
}
```

### 6.2 点击人偶互动对白

```text
DollInteractionService.TryTouch(dollId, touchType)
  -> 领域服务先结算触摸结果
  -> EventBus.Publish(DollInteractionResolved)
  -> NarrativeTriggerService 根据 touchType / SAN / 好感 / 当日次数筛选
  -> bark 或 modal_light 播放
```

规则：

- 对白不决定触摸结果；触摸服务先结算，叙事系统只读取结果。
- 高频点击默认走 `bark`，不锁界面。
- 里程碑、低 SAN、崩溃边缘、首次擦灰等才升级为 `modal_light` 或 `modal`。
- 同一人偶同一交互短句应有日内冷却，避免刷屏。

配置样例：

```json
{
  "trigger_id": "no0_touch_low_san_warning",
  "event_type": "DollInteractionResolved",
  "yarn_node": "Doll_No0_Touch_LowSan",
  "priority": 45,
  "blocking_mode": "bark",
  "if_busy_policy": "drop",
  "context": "workshop",
  "once": false,
  "cooldown": { "scope": "doll_day", "turns": 1 },
  "chance": 0.35,
  "required_flags": ["No0Started"],
  "conditions": [
    { "type": "DollIdEquals", "value": "no0" },
    { "type": "InteractionTypeEquals", "value": "touch" },
    { "type": "DollSanBelow", "value": 35 }
  ]
}
```

### 6.3 进入副本后对白

```text
DungeonManager.StartRunAtLayer(layer)
  -> EventBus.Publish(DungeonRunStarted)
  -> NarrativeTriggerService 判断首次进入 / 层数 / 人偶状态
  -> Scheduler 锁地图节点输入
  -> PlaybackService 播放 Dungeon_L1_FirstEnter
  -> 播完后恢复地图输入
```

规则：

- 首次进入第一层可强制播放。
- 再次进入同层只允许短版或按条件触发。
- 低 SAN、低 HP、携带特殊物品可触发特殊提醒。
- 刚播过日程主线时，非关键下潜闲聊默认延后或丢弃。

配置样例：

```json
{
  "trigger_id": "dungeon_l1_first_enter_no0",
  "event_type": "DungeonRunStarted",
  "yarn_node": "Dungeon_L1_FirstEnter_No0",
  "priority": 80,
  "blocking_mode": "modal_light",
  "if_busy_policy": "queue_once",
  "context": "dungeon",
  "once": true,
  "required_flags": ["Layer1FirstDeparted"],
  "forbidden_flags": ["DungeonL1FirstEnterSeen"],
  "conditions": [
    { "type": "LayerEquals", "value": 1 },
    { "type": "DollInParty", "value": "no0" }
  ],
  "set_flags_on_complete": ["DungeonL1FirstEnterSeen"]
}
```

### 6.4 休息区 / Boss / 特殊节点对白

休息区：

```text
DungeonNodeController.EnterNode(rest_area)
  -> EventBus.Publish(DungeonNodeEntered)
  -> 低 HP / 低 SAN / 首次休息区 / 特定 flag 条件判定
  -> 播放 modal_light 或 bark
  -> 不改变休息收益，休息服务仍由领域系统执行
```

Boss：

```text
DungeonNodeController.EnterNode(boss)
  -> BossNodeEntered
  -> 播 Boss 前过场
  -> Yarn 命令 start_combat boss_layer1
  -> CombatService.StartBossCombat()
  -> CombatPhaseChanged(BossLowHp) 可触发中途台词
  -> CombatEnded 可触发胜利 / 失败对白
```

Boss 前配置样例：

```json
{
  "trigger_id": "layer1_boss_intro_first_time",
  "event_type": "DungeonNodeEntered",
  "yarn_node": "Dungeon_L1_BossIntro",
  "priority": 100,
  "blocking_mode": "modal",
  "if_busy_policy": "replace_lower_priority",
  "context": "boss_intro",
  "once": true,
  "required_flags": ["DungeonL1FirstEnterSeen"],
  "forbidden_flags": ["Layer1BossIntroSeen"],
  "conditions": [
    { "type": "NodeTypeEquals", "value": "boss" },
    { "type": "LayerEquals", "value": 1 }
  ],
  "set_flags_on_complete": ["Layer1BossIntroSeen"]
}
```

Boss 中段台词配置样例：

```json
{
  "trigger_id": "layer1_boss_low_hp_no0_bark",
  "event_type": "CombatPhaseChanged",
  "yarn_node": "Combat_L1Boss_LowHp_No0",
  "priority": 65,
  "blocking_mode": "bark",
  "if_busy_policy": "drop",
  "context": "combat",
  "once": true,
  "conditions": [
    { "type": "CombatPhaseEquals", "value": "BossLowHp" },
    { "type": "DollInParty", "value": "no0" }
  ]
}
```

特殊事件节点：

- 节点事件服务先决定事件类型和奖励 / 风险。
- 叙事系统读取节点标签，例如 `ancient_ruin`、`memory_echo`、`rest_area`。
- 重要揭示走 `modal`，环境碎片走 `background` 或 `bark`。
